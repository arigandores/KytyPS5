## 6. Требуемые изменения

**RC1 (м1, м3, м5) — `rts_inj_nos` = 0 — член формы печати F30q, нарушение — дефект кода, не «К_S не определено».**
- Что не так. п. 664(з)(3) ловит только Σ `rts_inj` = 0; правило (и)(1) читает `rts_inj_nos` > 0 как «К_S сцены не определено». Но на исправном коде `_nos` > 0 недостижим [c §3] — это подпись мутантов м1, м3 (и м5 в ветви `_nos`), т. е. дефекта кода или бинаря, а не свойства сцены.
- Сценарий отказа. Бинарь с м1/м3 (или дефект, которого статика не видит) проходит допуск: Σ `rts_inj` ≈ 3 200–5 200 на тег (Σ `rts_pb` у `c5` s1–s9 — 13,2…21,2·10⁶ [c F30m]), `rts_inj_s` = 0, `_nos` = `rts_inj` на 9 из 9 сцен → по (и)(1)/(и)(4) живого контроля 0 из 9 ⇒ (δ) ⇒ Б28 и половина B Б14 — `ТУПИК`, маршрут закрыт навсегда («третьей итерации нет») — из-за дефекта кода.
- Что изменить. Печать F30q: у `f30_s1_w6` и каждого `f30_s<k>_c6` член «Σ `rts_inj_nos` = 0»; нарушение — `NOT_ADMITTED` «код или инструмент неисправен», стоп серии и пункт лида (как Σ `rts_inj` = 0 в (з)(3)). Проверка на `f30_s1_w6` (первым) ловит м1/м3 до девяти тегов `c6`. Правило (и)(1) — см. RC6.

**RC2 (м4) — тождество исходов по суммам процесса.**
- Что не так. Тождество `rts_inj_s` + `rts_inj_race` + `rts_inj_nos` = `rts_inj` (п. 664(е)(2), «по построению») в члены печати (з)(4) не входит — печатаются только значения.
- Сценарий отказа. Мутант м4 (или ошибка ридера, путающего `rts_inj_s` с `rts_bad_s`) на сцене с естественным S даёт `rts_inj_s` > `rts_inj`; К_S «жив» по (и)(1) читается из естественных S, а не из возмущения.
- Что изменить. Член: тождество точно в точке закрытия п. 662 (последняя строка `FrameTrace-x` со всеми отклонениями 0), с допуском 1 на хвосте (`rts_inj` прибавляется в месте B, исход — в посте того же draw; флип может их разрезать); по строкам — справка; нарушение — `NOT_ADMITTED`. Имена — целым токеном (`rts_inj` — префикс четырёх других), фикстура на этот край; 5 новых имён — обязательные поля строки `FrameTrace-x` (нет поля — `NOT_ADMITTED` `missing field`, не 0) — порт RC2 F30l.

**RC3 (м5; положительный контроль не тавтологичен) — связь К_S с цепью `RtsReport` → счётчик → печать.**
- Что не так. `rts_inj_s` прибавляется **в посте до `RtsReport`** по тем же `bits` — он доказывает «бит S вычислен и фильтр гонки (его копия) не погасил», но не то, что отчёт дошёл до `RtsReport`, `rts_bad_s` и печати; п. 664(д)(2) называет К_S контролем всей цепи «… → `RtsReport` → счётчик → печать». Без сверки с независимым счётчиком К_S по последнему звену — тавтология по построению.
- Сценарий отказа. Предикат-копия разошёлся с фильтром `RtsReport` (м5, или будущая правка одного из двух мест): возмущённый отчёт погашен, `rts_inj_s` ≥ 1, `rts_bad_s` = 0 — К_S «жив», а вердикт (В) «Σ `rts_bad` = 0» опирается на цепь, которая ни разу не донесла S до счётчика.
- Что изменить. Члены печати F30q: Σ `rts_bad_s` ≥ Σ `rts_inj_s` и Σ `rts_bad` ≥ Σ `rts_inj_s` (естественный S = разность ≥ 0, п. 664(з)(4)); Σ `rts_race` ≥ Σ `rts_inj_race`; нарушение — `NOT_ADMITTED`. Справка — число строк `RtSkipVerify: MISMATCH … mode=6` с битом `0x040` (≥ 1 при Σ `rts_bad_s` ≥ 1; предел 40 на поток) — свидетель записи в лог.

**RC4 (м6) — вилка числа кандидатов по `rts_pb`; разбор `rts_inj` = 0.**
- Что не так. Ничто в печати не проверяет, что N считается по PA∧PB, а не по всем draw.
- Сценарий отказа. Мутант м6: возмущения идут, К_S «жив», но на другой популяции и с другой частотой; печать этого не называет.
- Что изменить. Член: ⌊Σ `rts_pb` / 4 096⌋ ≤ Σ (`rts_inj` + `rts_inj_none`) ≤ ⌊Σ `rts_pb` / 4 096⌋ + 1 на любом непрерывном отрезке строк (оба прибавляются в месте B одного draw — флип их не режет; в окне из k кандидатов кратных 4 096 — ⌊k/4 096⌋ или на 1 больше); нарушение — `NOT_ADMITTED`. Разбор (з)(3): Σ `rts_inj` = 0 при Σ `rts_inj_none` ≥ 1 — «форма не нашла цели» (К_S сцены не жив, данные), при Σ `rts_inj_none` = 0 и Σ `rts_pb` ≥ 4 096 — дефект кода (стоп). Справка — Σ `rts_xb_ser` у `c6` (у `c5` s2–s6 — 0 [c F30m `read.json`]; у `=6` ожидается > 0 — следующий draw контекста отвергается п. 4 PB после сдвига `state_serial` возмущением [c F30o §1 (а)]) — свидетель исполненного `Transit`, независимый от `rts_inj*`.

**RC5 (м1b, м2, м7) — связь прогона со статикой.**
- Что не так. Эти мутанты в счётчиках прогона `=6` не видны или эквивалентны (§5).
- Сценарий отказа. Тег на другом бинаре с тем же пределом ручки (пересборка из грязного дерева) — м1b даёт «живой» К_S, который не проверяет обратный переход захвата; (Д1) проходит.
- Что изменить. (Д7) — sha256 **запущенного** файла = `505969510fb20f7ce56a5195b3b6d2209af812bc0c2c85eccb6368a712b1bf34` у каждого тега; строка версии, если лог её печатает, = `…-1908-gea38426b`; печать F30q называет основанием статики `code_f30o.py` C2–C4b и `chk_f30p.py` D2–D7 на `ea38426b` (оба `ALL OK`) и строку `RtSkip: mode 6` в логе тега.

**RC6 (к правилу п. 664(и)(1); владелец — лид, до данных F30q).** Прочтение «`rts_inj_nos` > 0 — К_S сцены не определено» заменить на «`rts_inj_nos` > 0 — тег `NOT_ADMITTED` (RC1), сцена не засчитывается до повтора на исправном бинаре; в счёт (и)(4) такая сцена не идёт». Основание — [c §3]: `_nos` > 0 недостижим на исправном коде. Сценарий отказа без правки — RC1 (закрытие маршрута `ТУПИК`ом по дефекту кода). Печатаю оба прочтения; до решения лида печать F30q считает по букве (и)(1) и рядом — по RC6 с пометкой «вариант исполнителя».
