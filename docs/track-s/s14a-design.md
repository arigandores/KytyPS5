## 5. Достигает ли (е)(2) одна трансляция — число

Модель: трансляция снята с кадра целиком (лучший случай половины 1), создание — как сейчас, ставится на первом draw.

| Оценка потерянных кадров серии | Σ по 6 событиям | к наблюдённым 57 |
|---|---|---|
| по стене: (стена − трансляция) / стена | — | **76,5 %** |
| ceil(max-задержка / средняя длина кадра той же серии) | 12 + 15 + 2 + 1 + 6 + 6 = 42 | **74 %** |
| ceil(max-задержка / 16 667 мкс) — кадры станут короче | 26 + 18 + 11 + 4 + 17 + 16 = 92 | **161 %** |
| нижняя граница механики (создание > 4 мс ⇒ ≥ 1 кадр) | 6 | 10,5 % — недостижима при `us` 61–287 мс |

**Ответ: нет.** Половина 1 без половины 2 оставляет 74–161 % потерянных кадров при пороге 20 % [I модели, c входов]; в 6 из 6
событий есть создание дольше окна 4 мс [c]. Она убирает трансляцию из первого кадра серии (38–163 мс из 132–280 мс), но не
серию. Счёт кадров может даже вырасти: та же стена создания делится на более короткие кадры.

Следствие для любой формы без знания модуля заранее: серия ≥ ceil(`us` / кадр) — при `us` 61–287 мс это 4–18 кадров на серию.
Ускорение воркеров (приоритет, число) меняет `us` и очередь, но не убирает компиляцию с первого использования — в (е)(2)
оно не ведёт [I]; не предлагается.

| хвост ` q_host_us= b_host_us= e_host_us=` | строка `AvTrace: pipeline gfx … async` (`:5517`), только при DIAG=1 | мкс хоста: постановка, начало, конец |

Счётчиков `FrameTrace-x` фаза A не добавляет (пути холодные; покадровая атрибуция — по положению строк, как в скорере S9).
Времени под `Scope` нет — от `KYTY_FRAME_TRACE` / `lite` инструмент не зависит; моменты — `HostMicros`.

**Тождества скорера (расхождение — `diag_bad`, обязано быть 0):**
- T1: число `SEarlyKey src=compile` = число строк `AvTrace: shader ShaderRecompiler` (по всему логу и после строки входа);
- T2: число `SEarlyPipe` = число строк `AvTrace: pipeline gfx … async` + незавершённые на выходе (≤ числа воркеров);
- T3: у каждой асинхронной строки `e_host_us − b_host_us` = `us` и `b_host_us − q_host_us` = `wait_us` (точно, те же отсчёты);
- T4: число `SEarlyReg` = число `ShaderRegister:` (один сайт; при `KYTY_SHADER_REGISTER_TRACE=1`);
- T5: `SEarlyKey` — разбиение по `src`: `compile` + `cache` + `resolve` = все строки (подмножеств нет).

**Положительный контроль:** в каждом плече — `SEarlyReg` ≥ 1 000 (в S10 строк `ShaderRegister:` 1 516–1 640 [c]), `SEarlyKey src=cache`
≥ 1 (каталог снимка загружен), после строки входа `SEarlyKey src=compile` ≥ 1 и `SEarlyPipe` ≥ 1 (то же, что гейт холода).
**Нулевой контроль:** плечо того же уровня с `KYTY_S_EARLY_DIAG=0` — 0 строк `SEarly`, кроме строки состояния; SPIR-V корпуса T1
байт в байт = родительской сборке; ревью — все сайты за одним `static const bool`.
**Цена инструмента:** ≈ 1 600 строк `SEarlyReg` на запуск (залп 3–5 с до сцены), ≈ 3 500 строк `SEarlyKey src=cache` на стартовом
precache (3 456 источников в S10), единицы строк на событие; на горячем пути draw — 0. Цена не сокращается почленно
(плечо с DIAG и без — не пара): фаза A счёт кадров с `=0` не сравнивает, она читает содержимое строк.

**Чтения фазы A — вариант исполнителя (константы — лиду, до данных):**
- A1 (раскладка по стене, [c]): для каждой серии — трансляция (Σ `translate_us` + `compile_us`), стена создания =
  max `e_host_us` − min `q_host_us`, стена удержания; закрывает [U] п. 414(а) «раскладка стены удержания».
- A2 (очередь): число VS/PS с `known=0`, зарегистрированных до первого использования нового модуля, × 16 мс против
  опережения события; сколько воркеров нужно, чтобы очередь успела.
- A3 (предсказуемость модуля): для каждого нового модуля после строки входа — есть ли более ранний `SEarlyKey` **другого** хэша
  того же класса (`cls_a`, затем `cls_b`), у которого `key`, `spec` и `push` равны фактическим. Считается офлайн скриптом по
  логу; предсказатель «класс заголовка → последний наблюдённый ключ» кода не требует. Отдельной строкой — доля пар
  `SEarlyPipe`, у которых `SEarlyMap` той же пары пришёл раньше постановки, и на сколько.
- A4 (покрытие): C = Σ кадров серий, **все** новые модули которых предсказаны точно, / Σ кадров всех серий. Серия с хотя бы
  одним непредсказанным модулем длится до его компиляции — польза считается «всё или ничего» [I].
  **C ≥ 0,8 ⇒ фаза B открывается; C < 0,8 ⇒ (е)(2) предсказанием на регистрации не достигается.**
- Сила выборки: 34 новых модуля VS/PS, 6 событий (не редкое событие: оно есть на 5 из 5 уровней, P(0) ≈ 0). C квантуется
  шестью сериями с весами 18 / 17 / 2 / 1 / 9 / 10 кадров: порог 0,8 требует предсказать обе серии `hero_kratos` и обе
  `fragile_battle`; серия в 13 модулей предсказана целиком с вероятностью p¹³ — нужна точность p ≈ 0,98 на модуль.

### 6.2. Фаза B — `KYTY_S_EARLY=1` (умолчание 0): прототип. Это не измерение

Меняет, какие модули и пайплайны существуют к первому draw и когда занят CPU воркеров; состояние гостя, его память и
часы не трогает. При 0 — прежний путь байт в байт (ни потока, ни выделений, ни строк, кроме строки состояния).

1. **Постановка** — `TraceShaderRegistration` (`:6316`), на потоке гостя, без `m_mutex` (как `:6364`): копия кода (≤ 128 КиБ),
   класс заголовка, предсказанные `input_info`, специализация и начало push-данных из таблицы «класс → последний наблюдённый
   ключ» (таблица пополняется на трёх сайтах `SEarlyKey`, под `m_mutex`; читается под своим мьютексом). Нет записи класса или
   `known=1` — не ставится.
2. **Воркер трансляции** — обобщение `ComputePretranslation` на стадии VS/PS (свой поток, те же пределы: 1 024 записи, 8 МиБ
   кода, 192 МиБ готового; `TranslationBudget`; перехват фаталов `:212`): `TranslateProgram` + `CompileProgram` с предсказанной
   специализацией → IR и SPIR-V. Vulkan, `ProgramCache` и живые дескрипторы не трогает.
3. **Прогрев драйвера (вторая половина)** — §10: по готовому SPIR-V на воркерах `EnqueueJob` — в очереди ниже приоритетом, чем
   настоящие создания (настоящее задание не ждёт спекулятивного дольше одной идущей компиляции; ≥ 2 воркеров остаются за
   настоящими).
4. **Первое использование** — `Compile` (`:3998`, место `prepared`): точное равенство ключа программы (`static_state`),
   специализации, начала push-данных **и байтов кода** (`Take` `:94` сверяет код) — берётся готовое; иначе — прежний путь без
   ожидания воркера. Ключ ручка не читает дважды: решение «взять / не взять» принимается один раз в `Compile` под `m_mutex`.

**Строки и счётчики фазы B:**

| Имя | Тип | Смысл |
|---|---|---|
| `SEarly: ready hash= stage= us= kb=` | мкс, КиБ | трансляция воркером готова |
| `SEarly: hit hash= stage= kind=<ir\|spv> saved_us=` | мкс | взято на первом использовании |
| `SEarly: miss hash= stage= reason=<absent\|not-ready\|static-key\|spec\|push\|code-changed> word=` | шт. | не взято; `word` — первое расходящееся слово ключа |
| `SEarly: warm vs= ps= us= kind=` | мкс (сумма по воркерам, не стена) | прогрев драйвера завершён |
| `SEarly: summary queued= ready= failed= dropped= hits= missed= warm= bad=` | шт. | на выходе |
| `FrameTrace-x`: `se_hit`, `se_miss`, `se_bad` | шт. (сырые) | покадрово, для атрибуции скорера |

**Нулевые инварианты:** `se_bad` / `bad` = 0 — при `KYTY_S_EARLY_VERIFY=1` на каждом попадании дополнительно идёт обычная
трансляция, SPIR-V сравнивается байт в байт (форма `srtmemocheck`); `diag_bad` = 0 (T1–T5).
**Тождества:** T6 — `queued` = `ready` + `failed` + `dropped` (разбиение); T7 — у каждой строки `AvTrace: shader` VS/PS ровно одна
предшествующая строка `SEarly: hit` или `SEarly: miss` того же хэша (`hits` + `missed` = число `Compile` VS/PS); T8 — Σ `se_hit` по
кадрам = `hits`, Σ `se_miss` = `missed`.
**Положительный контроль (инструмент вооружился):** стенд `KYTY_S_EARLY_ORACLE=<файл>` — таблица «хэш → ключ, специализация,
push, пара» из строк `SEarlyKey` / `SEarlyPipe` прежнего прогона **того же уровня** вместо предсказателя: попадания гарантированы
(`hits` ≥ числа новых модулей `=0`-плеча − 1). Он же — **измерение потолка маршрута**: если при идеальном предсказании сумма
(е)(2) не падает до ≤ 20 %, маршрут мёртв при любом предсказателе, и код предсказателя не пишется. Плечо оракула читает
артефакт — по общему правилу 32 несёт контроль «файл оракула отличается от пустого по sha256 и `hits` > 0», иначе `NO_POWER`.
**Нулевой контроль:** `=0` — 0 строк `SEarly:` кроме состояния, корпус T1 байт в байт; `=1` на тёплом Sky Garden — `queued` = 0
(все `known`), счёт кадров в шуме пары.

## 8. Сборка плеч и снимок холода (п. 414(б))

1. **Сборка.** Плечи `=0` и `=1` — один бинарь из чистого worktree от дерева последнего принятого лидом бинаря отгрузки на момент
   звена кода (правило п. 410(г)(6); сегодня — FS4 `3d0e46da`, подпись `56189185`, каталог `variant_fixb26_fixb1b`; после FS5 —
   каталог `variant_fixb26_fixb1b_fixf10`). База T2 S10 (`f3b3aa3b`, подпись `699c1e4b`) — только справка и список пяти уровней.
2. **`snap0` не годится — довод [c кода, не прогона]:** кэш трансляции ищется в каталоге варианта
   (`shaderTranslationCache.cpp:565`–`:591`: каталог — по токенам варианта, подпись — по хэшу исходников транслятора); файлы
   `snap0` лежат в корне `_ShaderCache/PPSA21564` (строка лога S10 `Shader translation cache: _ShaderCache\PPSA21564`) с подписью
   `699c1e4b`. Сборка с каталогом варианта их не откроет, а файл рецептов чужой подписи отбрасывается (F4b). Результат — пустой
   каталог: холодны все шейдеры игры, а не пять уровней, форма APP («тёплая база + невиданный уровень») не воспроизводится.
3. **Форма — новый снимок `snap1`** той же процедурой, что `snap0` (п. 229(г)(2), 241): кэши сборки плеч после входа в те же
   19 известных уровней (9 `inventory141.md` + 10 `sc142`), копия `_ShaderCache/PPSA21564/<вариант>`, `_PipelineCache` и
   `GLCache` (`snap1_drv`), манифест sha256. Источник: (а) **каталог сбора S13b**, если его бинарь имеет ту же строку
   `ShaderSeed: compatibility=` (подпись и вариант), что сборка плеч, — цена снятия 0 замка (копия и манифест); (б) иначе
   свой сбор — 19 входов ≈ 1,5 ч замка [I по длине тега S10 ≈ 5 мин]. Код S-early вне `src/graphics/shader/**` подписи не
   меняет — снимок базовой сборки служит обоим плечам.
4. **Контроль по общему правилу 32** (без него исход — `NO_POWER`): в логе каждого плеча `PipelinePrecache: N recipes` с N =
   числу рецептов `snap1` (> 0), `Vulkan pipeline cache: loaded B bytes` с B = размеру блоба `snap1`, строка
   `ShaderSeed: compatibility=` = строке `snap1`; манифест возвращённого каталога = манифесту `snap1` и ≠ манифесту каталога до
   возврата; пять уровней в `snap1` отсутствуют — гейт холода скорера на плече `=0` (после строки входа ≥ 1 новая перестановка,
   ≥ 1 новый рецепт, ≥ 1 `skipped draw`).

## 9. A/B и кандидат критерия кода
