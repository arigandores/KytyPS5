  `progmemo=0` на входе, которым отличались удачные заходы, этим объясняется и уликой не является.
  Правило: **после сборки первый вход в Sky Garden — прогревочный**; воспроизвести с чекпоинтами
  на свежей сборке — первый пункт следующей сессии.
- Базы: **6,64–6,98 мкс CPU на draw (полоса 4700–5100, поток записи включён), 29–30 FPS до
  троттлинга; CPU потока GuestGpu 32–34 мс, GPU 13,6–15 мс, ~4 850 draw.** 60 FPS нет.

## 3. Правки M1: `dawitptr`, `daqpre`, потолок `dawitness`

**`dawitptr`** (`KYTY_DRAW_AHEAD_WITNESS_PTR`, default 0). Воркер записывает в лог чтений хостовый
указатель каждого live-слова (`SrtReadLog::Entry::backing`), свидетель хранит его на прогон
(`Witness::Run::backing`, прогоны склеиваются только при непрерывных указателях) и эпоху карты
гостевой памяти `BackingMapEpoch()` на момент до чтений (`Witness::map_epoch`). На проверке, пока
эпоха та же, live-прогоны сравниваются прямо по указателям (сначала префетч всех строк), без
поиска страницы в кэше страниц на каждый прогон; clean-прогоны и одиночные чтения — как раньше.
Memo `srtmemo` (построение на потоке draw) эпоху не передаёт, прямой путь там не берётся.
Самопроверка — прежний `smemocheck`: пустыня `rp2`/`val` — 0 расхождений.

**`daqpre`** (`KYTY_DRAW_AHEAD_QUEUE_PREFETCH`, default 0). В `QueueAhead` для запроса на 4 позиции
вперёд префетчатся две первые строки обоих пробных слотов (тот же ключ, что у цикла: класс плана
при `daclass`, иначе отпечаток; источник без построенного класса пропускается).

**`dawitness=0`** (`KYTY_DRAW_AHEAD_WITNESS`, default 1) — результат берётся без проверки слов.
**Небезопасно** (запись гостя между чтением воркера и draw остаётся незамеченной), только потолок.

Свип `sky61c` (23 фазы по 500 present, три повтора; **поток записи выключен** — заход шёл с
NV-чекпоинтами, §6; базы 8,6–9,0 мкс/draw в полосе 4700–5100, спред ±1,6 % без `base1`):

| гейт | 4300–4700 | 4700–5100 | 5100–5500 | счётчики |
|---|---|---|---|---|
| `dawitptr` | −4,1 / +0,9 / −0,2 | **−2,9 / +0,4 / −1,5** | −3,9 / +0,7 / −2,2 | `da_take_us` 3,9 → 3,5–3,6 мс, `da_direct` = `da_hit` |
| `daqpre` | −1,5 / −2,7 / +0,8 | −0,3 / −0,8 / −1,4 | −1,8 / −0,9 / −0,6 | `da_queue_us` 1,2 → 0,8 мс |
| оба | −3,3 / −0,9 / −1,7 | **−2,7 / −1,7 / −1,2** | −2,4 / −1,8 / −0,2 | |
| `dawitness=0` (потолок) | −5,3 / −7,9 | **−6,9 / −3,4** | −4,9 / −4,7 | `da_take_us` 3,9 → 1,6 мс |

## 4. Запись: `recpubn`, `recrelax`

`EndRecord` 4,9 % профиля — `m_head.store(seq_cst)` = `xchg` на линии, которую поток записи
непрерывно читает с другого CCD (`rec_ccd_x` ≈80 % проверок; `recpin` в сессии 58 порога не
держал). Ручка **`recpubn`** (`KYTY_RECORD_PUBLISH_N`, default 0): записи draw-потока (`PassEnd` и
выше) публикуются не чаще чем раз в N записей; всё, что требует записи видимыми сейчас, само
публикует хвост (`Handle()` перед прямой записью, `Drain()` на потоке-производителе — добавлено,
`Reserve` при полном кольце, `Stop`, submit — `EndBuffer` ниже `PassEnd` и не задерживается).
Счётчик `rec_throttle`. Пустыня: `recpubn=16` **+2,5 %**, `+recrelax` +2,2 % — 780 прямых
`Handle()` на кадр теперь ждут отставший поток записи (`rec_direct_busy` 39 → 98).

Sky Garden `sky61d` (чистая половина, полоса 4700–5100 / 4300–4700): `recpubn=16` +1,7 / +0,6,
второй повтор −0,8 / −1,2; `recpubn=4` −2,9 / −1,6 (один чистый повтор); `recrelax` −1,0 / −0,2,
−0,8 / −0,2, +0,2 / +1,3 (троттлинг); `recpubn=16 recrelax=1` −1,1 / −0,7; `rec_direct_busy`
31 → 204–215 на кадр. **Цена `xchg` переезжает в дренажи прямых записей** — выигрыша нет, все три
остаются 0. Чтобы взять эти 4,6 %, нужно убрать сами прямые записи (`rec_direct` ≈780 на кадр:
загрузки буферов, барьеры, transit'ы вне пакета) — тогда публикация могла бы быть редкой.
