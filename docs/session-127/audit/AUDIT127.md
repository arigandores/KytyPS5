## 4. Что НЕ доказано

1. **Выигрыш против установленной сборки.** Δ −386,4 мкс — это плечо 1 против плеча 0 ОДНОЙ сборки `98d98eee`. Плечо 0
   «побайтно прежний путь» по поведению. Но цена самой ручки при 0 (защёлка раз на draw, код в горячем пути) против
   сборки без ручки (`d3a981a2`) не измерена.

   Межпрогонная разность баз `98d98eee` (33 095,6, с. 127) и `14bead6f` (32 067,2, с. 126) = +1 028 мкс. Это НЕ
   измерение: разные прогоны, сборки, прогрев. Её нельзя цитировать ни как цену ручки, ни как регресс. Но и отсутствие
   такой цены она не доказывает. Правило отгрузки п. 76(з)(5) определено через Δ против плеча 0 — по букве этого
   достаточно.
2. **Режим OLD.** Пар OLD — 0. Число отгрузки — только NEW. Корректность при 1 в OLD видела только валидация `s6s127` (API,
   не значения).
3. **Корректность `rtskip=1` на траектории режима 1** проверена значениями только по индукции. Самопроверка (режим 2)
   сравнивает один шаг пропуска со свежим путём из верного состояния и дальше берёт свежий результат. Цепочку подряд
   пропущенных draw в режиме 1 значениями не сравнивает никто — только видео (глитч-детектор и глаз, 120 с) и валидация
   (API). Довод индукции верен, пока пропуск оставляет то же состояние, что полный путь (RC1 ред. 2). Прогоном это
   проверено только в режиме 2.
4. **Полнота источников инвалидации** — свидетельство, не доказательство: `rts_bad` 0 на 39,8 млн сверок одной сцены за
   300 с, плюс 150-секундные дымы опоры и пустыни. Источник, который в этих сценах не сдвигается, не проверен.
5. **Другие сцены.** Время мерено только на опоре; пустыня — только дым самопроверки (vblank, 707 draw). Δ — не прогноз.
6. **Картинка** — без попиксельного сравнения; лист — 9 моментов, разные фазы анимации.
7. **Скорость игры.** Среднее `dt` ≈ 33,1 мс ≈ 2 вблэнка. Δ сдвигает СРЕДНЕЕ (с. 122 `sky122`). По базе этой сборки 50,36 %
   → 50,96 % (≈ +0,6 п. п., ряд). 60 FPS не обещаются.
