### 3.2 «Та же выборка 1/8, что `rb_slow_ns`» — довод

`RebindBuffers` читает решение первой итерации `rb_sel = t_rb.next` в прологе (`descriptors.cpp:4258`), а `SlotEnd` итерации i пишет
`t_rb.next = Weyl(++k)` и возвращает его как `rb_sel` итерации i + 1 (`frameStats.h:3767–3768`, `descriptors.cpp:4291`). Между S0 и
S1 итерации i `t_rb.next` никто не пишет (`SlotBegin` `:3725–3732` его не трогает; вложенных `RebindBuffers` нет) ⇒ **внутри
итерации `t_rb.next == rb_sel(i)`**, т. е. `t_rb.next` = «эта итерация выбрана» ровно для той итерации, чей t1 − t0 книжит `SlotEnd`
в `rb_slow_ns`. Итерация, прошедшая `:1570–1591`, пишет класс `Slow` (`:1592`); её класс может быть переписан после возврата только
выровненной копией const-bank (`descriptors.cpp:666`, `Cbank`) или попаданием A `b2reuse` (`:618`) — тогда `SlotEnd` книжит время в
`rb_cbank_ns`, и **части выбрасываются** (книжение частей — в `SlotEnd` при `rb.cls == Slow`, §3.3). Так части и `rb_slow_ns` имеют
одно множество итераций и одни штампы S0/S1. Вложенный `ObtainBuffer` (в дереве нет, защита RC9(а) с. 133) видит `slot == 2` и не
отмечает.

### 5.4 Сверка `rs_bf_diff` на каждом «попало бы»

**[RC3] Предикат — одна функция, два вызова:**

```
  inline bool RsDiff(BufferId res_id, BufferId rem_id, uint32_t sync, uint64_t e_post, uint64_t pre) {
      return res_id != rem_id || (sync == 2 && e_post == pre);
  }
  // POST, шаг 2 (только t_rb.cls == Slow):  would ⇒ rs_bf_diff  += RsDiff(res_id, rem_id, sync, e_post, pre)
  //                                          xchk  ⇒ rs_bf_xdiff += RsDiff(res_id, rem_id, sync, e_post, pre)
```

`rem_id` — `slot.id`, прочитанный PRE при совпавшем ключе (одинаково для `would` и `xchk`); `e_post` — одно чтение шага 0 POST (§5.2),
не поле слота. Первый член — попадание отдало бы не тот буфер (`buffastcheck` `:1427` `full_id != remembered_id`); второй — полный путь
загрузил байты, а свидетель не сдвинулся (`buffastcheck` `:1416–1418`, `dirty && unchanged`): попадание пропустило бы нужную загрузку.
Загрузка при сдвинутом свидетеле — гонка (запись CPU после PRE), не расхождение — в `rs_bf_diff` не считается (как `:1413–1415`);
**[RC4, п. 168(б)] её считает `rs_bf_race` (`would ∧ t_rb.cls == Slow ∧ sync == 2 ∧ e_post ≠ pre`), и такие итерации исключены из
`rs_bfw_ns`/`rs_bfw_k`.** Сверка идёт по результату полного пути, который и так исполнен (перепись ничего не пересчитывает). Строки
`RbSlowVerify: MISMATCH addr= size= memo= full= up=` — первые 32 (как `BufFastVerify` `:1429–1435`); строк для `xdiff` нет.

**[RC3] Популяция `xchk` (контроль сверки, п. 167 В4) — полностью:** `elig ∧ t_rb.cls == Slow ∧ slot.instance == m_instance ∧
slot.vaddr == address ∧ slot.size == size ∧ slot.registration == m_registration_epoch ∧ try_get(slot.id) ≠ nullptr ∧ ¬is_deleted ∧
pre ≠ 0 ∧ slot.region_epoch ≠ pre` (всё, кроме `pre` и `t_rb.cls`, — в PRE; `t_rb.cls` — в POST). `xchk` и `would` не пересекаются
(последний член). **Решение по `pre == 0`: исключено.** Довод: при `pre == 0` свидетеля нет — `buffast` не отвечает попаданием ни на
каком `region_epoch` (`:1398` `fast_epoch != 0`), а `remember` никогда не пишет слот с `region_epoch == 0` (`:1451`) ⇒ при `pre == 0`
любой совпавший ключ «протух» тривиально, и такая популяция не проверяет чтение сдвинутого свидетеля. На протухшем ключе (`pre ≠ 0`)
запись CPU легла ДО PRE ⇒ `e_post == pre` обычно истинно, и загрузка полного пути видна второй половиной ТОГО ЖЕ выражения ⇒ `rs_bf_xdiff`
> 0 доказывает, что второй член `RsDiff` читает `e_post` и `sync` и сравнивает их верно. Первый член (`res_id ≠ rem_id`) на `xchk`
почти всегда ложен (регистрация не сдвинута ⇒ буфер тот же) — **живого контроля не имеет** (§14).

**Не входит в `rs_bf_diff`, но то же нарушение:** «попало бы» на итерации, чей `ocls == Stream` (полный путь сделал обязательную копию
в кольцо, а попадание вернуло бы буфер) — не итерация `slow`, в знаменатель `rs_bf_would` не входит; **[п. 167 В5, RC2]** — счётчик
`rs_bf_strm` (POST, шаг 3; по `ocls == Stream`; при правиле RC2 слот `would` на выходе `Stream` не очищается, так что серия вызовов
того же ключа без сдвига эпохи считается каждым вызовом).

## 7. Тождества и неравенства для скорера — форма п. 168(а) **[RC1]**

**Почему не «= 0 по тегу плеча 0» и не «0 ≤ R ≤ 1».** Строка `FrameTrace` — разность двух снимков накопленных сумм; снимок не
мгновенен: поток презентации читает счётчики ПО ОДНОМУ по возрастанию индекса (`videoOut.cpp:1294–1296`, цикл `FS::Read`;
`frameStats.cpp:216–225` — одна загрузка под замком реестра, писатель `Add` `frameStats.h:2847–2858` замка не берёт). `rs_*` стоят в конце
`enum Counter` (индексы ≥ 1955, §15 п. 4), `rb_slow_*` — 1910/1911 ⇒ `rs_*` читаются позже на ≥ 44 вызова `Read`; итерации, завершённые
за это время, есть в `rs_*` и нет в `rb_slow_*` ⇒ невязка `rb_slow` − `rs` бывает **отрицательной на m итераций** (m [I] ≈ единицы–
десятки: ≈ 44–80 вызовов × 50–100 нс против ≈ 24 000 итераций `Slow` на ≈ 12 мс привязки) и **положительной не больше чем на одну
итерацию в полёте** (между `Add(RbSlowN)`/`Add(ns)` `SlotEnd` `:3765`/`:3772` и `Add` `RsSlotEnd`, или между `RsSlotEnd` и POST). Сумма
по подмножеству строк (плечо 0, окно 10–88) не телескопируется: каждая граница несёт свою невязку. Поэтому (п. 168(а)):

- **R_n** — бегущая сумма разности связи по ВСЕМ строкам `FrameTrace` тега подряд (оба плеча, порядок лога, с первой строки лога;
  строка n = F относится к уходящему блоку только для печати — в сумму входят все строки), т. е. невязка снимка n.
- **Тождество:** |R_n| ≤ K на КАЖДОЙ строке. **Неравенство:** R_n ≥ −K на КАЖДОЙ строке и R_last (сумма по тегу) ≥ −K.
- **Константы (п. 168(а)):** **K = 64** (штуки: И1, И2, Н1–Н3); **K_ns = 10⁸ нс** (И0, Н5; больше суммы t1 − t0 любых 8 выбранных
  итераций с ожиданием GPU [I]). **И0 — дополнительно дрейф:** |R_last| ≤ 5·10⁻⁴ · Σ_тег `rb_slow_ns` (сырые нс; дефект книжения
  ≥ 0,05 % уровня `rb_slow` падает, меньший — не ловится, §14). [I]: Σ_тег `rb_slow_ns` сырой ≈ 275 мкс/кадр × ≈ 8 800 кадров ≈

## 8. Положительный и нулевой контроль

- **Вооружение:** строка `RbSlow: mode 1`; в `s1s135` `rs_ro_n`, `rs_sync_noop_n`, `rs_bf_n` > 0 на каждой строке окна (не редкие:
  ≈ 23 000 итераций read-only `slow`/кадр [c `kp134`]), `rs_*_ns` > 0; **[RC1] И0–И2 в форме п. 168(а) (§7)** при ненулевых
  популяциях — доказательство, что части и счёт книжены на тех же итерациях, что `rb_slow` (не мест отметок, п. 167(ж)).
- **Живость рукопожатия загрузки:** `rs_sync_n` > 0 (загрузки на медленном пути; `rb_sync_up` ≈ 50–80 пар/кадр [c с. 133]).
- **Живость сверки `rs_bf_diff` — [п. 167 В4, RC3]:** `rs_bf_xchk` — популяция §5.4 (совпавший ключ, живой `try_get`, `pre ≠ 0`,
  `region_epoch ≠ pre`, класс `Slow`); на ней `rs_bf_xdiff` — **тот же вызов `RsDiff`, что `rs_bf_diff`**. Запись CPU в регион между
  запросами легальна и ожидаема ⇒ `rs_bf_xdiff` > 0 доказывает, что второй член `RsDiff` (`sync == 2 ∧ e_post == pre`) читает и
  сравнивает верно. **Чтение (п. 167 В4):** условие доли расхождения проверено только при `rs_bf_xchk` ≥ 1 000 ∧ `rs_bf_xdiff` > 0 по
  плечу 0; иначе «сверка не доказана» ⇒ B3 (1) отбора НЕ проходит, строка вопросов закрытия. Первый член (`res_id ≠ rem_id`) живого
  контроля не имеет (§14).
- **Нулевой контроль:** при 0 — прежний путь (§9.1), `rs_*` = 0, строк `RbSlow:` нет (Z2); при `rbcen=0 ∧ rbslow=1` (`s2s135`) —
  строка отказа, `rs_refuse` > 0, остальные `rs_*` = 0. Цена значения 0 — не измеряется (A/B не планируется), [I] ≤ 1 нс на итерацию
  (§9.1).

## 14. Риски и что проект НЕ доказывает

1. **Контрфактуальность (§5.1):** «попало бы» мерится в мире `buffast=0`; в мире `buffast=1` попадания не переписывают интервал загрузки
   буфера, и классы последующих итераций могут отличаться — U3 не равен тому, что снял бы прототип, даже без цены пробы.
2. **Свидетель PRE раньше `:1387`** (до головы `NativeStorageBuffer`): запись CPU в щели делает «попало бы» переписи оптимистичнее
   `buffast` на гонках; такие попадания видит сверка (загрузка при сдвинутом свидетеле не считается расхождением — они уходят в
   «попало бы» без расхождения). Окно ≈ десятки нс на слот; частота [U], ожидаемо ≪ 10⁻³ попаданий [I]. **[RC4, п. 168(б)]** Гонку
   считает `rs_bf_race`; её итерации исключены из `rs_bfw_ns`/`rs_bfw_k` (U3 без них), доля гонки — строкой рядом с U3 (> 0,05 —
   вопрос закрытия). Гонка с записью ДО `:1387`, но ПОСЛЕ PRE, без загрузки (`sync ≠ 2`) остаётся в «попало бы» — её цена в U3 мала
   (загрузки нет), частота [U].
3. **Поправка фантома опирается на c ≈ ĉ** (§6.2): уровень `rb_slow` при `rbslow=1` — ±6,6 % на 1 нс ошибки; уровни частей и ряды B2
   — нет.
4. **Режим `lite`** — условие; при полном трейсе уровни частей несравнимы (§2.3).
5. U3 — **не** снимаемое B3 и не потолок (§5.3); доля «попало бы» — не доля времени; `rs_bf_diff` = 0 — не корректность B3 (гонки
   `buffast` вне переписи, `rs_bf_strm` [В 5], контрфактуальность).
6. Правила (д)(3) классифицируют механизм надбавки только при его форме, предусмотренной правилом (§12).
