### 1.1 Выбор цветовых вложений, маска PS, экспорт (`renderDraw.cpp`, 30 строк)

База #883 — upstream после `b594f8c83` (см. §5): вложения там уже привязываются по МРТ-выходам PS (`mrt_mask` из
`program->info.outputs`, вид `Mrt`), а таблица отображения экспорта строится по регистрам цели до привязки. #883 добавляет:

- `DrawHasActivePixelShader` заменена на `DrawColorOutputMask(ctx)`: бит слота ставится, только если
  `sh_regs.target_output_mode[slot] != 0` (это `SPI_SHADER_COL_FORMAT` поля `slot`) **и** `render_target_mask_slot(CB_TARGET_MASK & CB_SHADER_MASK, slot) != 0`.
- `ps_active` = адрес PS ≠ 0 и (`color_output_mask != 0` или побочные эффекты глубины/покрытия) — «skip inactive pixel shaders»:
  PS, у которого ни один записываемый слот не имеет ненулевого формата, считается неактивным (кроме kill/Z-export/маски).
- `RefreshShaders(..., color_output_mask, ...)`: `target_export_mapping[slot]` заполняется только для слотов из `color_output_mask`
  (было: `rt.base.addr != 0 && CB_TARGET_MASK[slot]`).
- `mrt_mask &= color_output_mask` — **вложение привязывается, только если формат слота ≠ 0**. Именно эта строка теряет траву в форке.

## 3. Правка форка `26d62f80` (2026-09-29, только `renderDraw.cpp`, +21 / −4)

- Вводит `DrawColorWriteMask(ctx)` = слоты, где `render_target_mask_slot(CB_TARGET_MASK & CB_SHADER_MASK, slot) != 0` (формат не важен).

- Форк больше `renderDraw.cpp` не менял и `21a1346e2` не сливал (последний коммит файла в форке — `26d62f80` [c API]).

**Восстановит ли траву при переносе #883 к нам.** Ханки #883 в `renderDraw.cpp` на наш код не ложатся: они опираются на `mrt_mask` из выходов PS
(`b594f8c83`), которого у нас нет; наш `PrepareDrawRenderState` иной (`ResolveColorTargets` внутри, правило `slot == 0`, `t_rts`, пути `:3634`/`:3676`).

**Почему формат читается 0 — гипотезы [I], для M1c:**
(H1) нумерация экспортов. `21a1346e2` (upstream, 2026-10-07 — после правки форка) вводит модель железа: порядковый номер экспорта MRT идёт по
ненулевым полубайтам `CB_SHADER_MASK`, поле `SPI_SHADER_COL_FORMAT` индексируется номером экспорта, а не слотом (тест upstream: `CB_SHADER_MASK = 0xf000`,
`exp mrt0` пишет физический MRT3). Код форка/#883 проверял `target_output_mode[slot]`; при «дырявой» маске или «спящих» экспортах сверх маски
(их же упоминает `73615c31f`) поле по номеру слота может быть 0, хотя игра консистентна. (H2) регистр `SPI_SHADER_COL_FORMAT` к draw не отслежен
эмулятором. Какая верна — по данным не различить [U]. Важно для нас: если H1 верна, то наш маршрут «выход PS = номер экспорта» на draw с маской,
не плотной от слота 0, расходится с железом (пишем не в тот слот / не пишем в нужный) — это вопрос `21a1346e2`, не #883 (§4, §5).

**Совместимость с Б35 (dual-source).** Наш Б35 (`register:§15:Б35` `FIXED`) — перепись SPIR-V на уровне пайплайна: `Location 1 → Location 0 Index 1`,
