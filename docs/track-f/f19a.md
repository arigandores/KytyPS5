## 3. Исход по правилу п. 441(з) — кандидат

| Вариант | Что говорит свидетельство |
|---|---|
| (а) путь эмулятора на главном потоке | обработчик удаления эмулятора не блокирует [c кода, §1.2]; стенды `detach` и `event` проходят его целиком. Ожидание: кадр < 1 с ⇒ (а) в буквальной форме не подтверждается |
| (б) вызов SDL/ОС на главном потоке, стенд исполняет его тем же путём | да для перечисления HID: `enum` заставляет SDL выполнить `SDL_hid_enumerate` на главном потоке под замком джойстиков тем же путём, что после удаления (`SDL_hidapijoystick.c:871` → `SDL_hidapijoystick.c:1327` → `SDL_hidapijoystick.c:1114`). Что настоящая потеря Bluetooth блокирует именно его — [I]; ещё три кандидата §1.3 стендом не исполняются |
| (в) ни одна форма не проходит путь блокировки | верно для самого блокирующего вызова ОС: без умирающего устройства он не блокируется |
| (г) стоп-кадры иного происхождения, путь не блокирует | верно для 4 логов из 5 и для 7 новых; **неверно** для `edes122` |

Свидетельство не ложится в один вариант, потому что у остановки два звена: **причина** (кто-то 23,8 с держит замок джойстиков SDL — [I], без оборудования не воспроизводится) и **усилитель** (эмулятор ждёт этот замок потоком гостя под `m_mutex` — [c кода], [c лога], воспроизводится стендом `hold` без оборудования). Усилитель — единственное, что делает событие K2: без него та же остановка главного потока даёт `ctl114b` (игра идёт).

**Предложение (не вердикт):** `дефект`; итерация кода 1 под `KYTY_FIX_B24` — только член А §5.1; критерий «ИСПРАВЛЕНО Б24» — на стенде `hold` с положительным контролем `=0` и контролем `sleep`; слова строки реестра «остановка главного потока при отключении HID» заменить механизмом «поток гостя ждёт замок джойстиков SDL под `m_mutex`; замок 23,8 с держал путь SDL при потере Bluetooth-пульта [I]». Что настоящая потеря пульта после правки не останавливает игру — останется [I] до лога пользователя с отключением (для него — строка удаления §4.3).

## 4. Проект стенда `KYTY_TEST_HIDLOSS=<с>[:<режим>]` (только стенд; умолчание — выключен)

Стенд — **не измерение**: он меняет состояние хоста, видимое гостю (подключает и отключает виртуальный пульт — как настоящий). Чтение раз на процесс (`getenv` + статический флаг, форма `KYTY_TEST_MINIMIZE`, `window.cpp:1047`); плечом расписания быть не может.

### 4.1 Режимы

| Режим | Действие в момент `fire` (главный поток, задачей `PostToMainThread`) | Что проходит |
|---|---|---|
| `detach` (умолчание) | `SDL_JoystickDetachVirtual` (`SDL_joystick.c:934`, `SDL_joystick.h:435`) виртуального пульта | SDL: `SDL_PrivateJoystickRemoved` (`SDL_virtualjoystick.c:256`, `SDL_joystick.c:1890`) → наблюдатель (`SDL_gamecontroller.c:382`, `SDL_gamecontroller.c:397`) → событие; эмулятор: обработчик §1.2 целиком; закрытие — `SDL_virtualjoystick.c:561` |
| `event` | `SDL_PushEvent` события `SDL_CONTROLLERDEVICEREMOVED` с идентификатором открытого виртуального пульта | только обработчик эмулятора: `Disconnect` + закрытие **открытого и ещё присоединённого** контроллера |
| `enum` | смена и возврат значения `SDL_HINT_JOYSTICK_HIDAPI_COMBINE_JOY_CONS` — обратный вызов сбрасывает счётчик перечисления (`SDL_hidapijoystick.c:583`) | SDL: настоящее `SDL_hid_enumerate` на главном потоке под замком джойстиков (§1.3, строка «Перечисление HID») на здоровом хосте; побочно — пересборка пар Joy-Con (на хосте без них — ничего) |
| `hold` | `SDL_LockJoysticks()`; сон `HOLD_MS`; `SDL_UnlockJoysticks()` | модель причины: замок джойстиков занят `HOLD_MS` на главном потоке; путь гостя §1.5 — настоящий |
| `sleep` | сон `HOLD_MS` без замка | контроль: остановка главного потока без замка (форма `ctl114b`, но с пультом) |

Иное значение режима — строка `TestHidLoss: config invalid …`, стенд выключен.

### 4.2 Расписание и константы (предложение; константы решает лид до кода)

- Взвод — первая строка гостя `Level has started: <непустое имя>` (та же функция, что у F5).
- `PRE_S` = 10 с: в `armed + max(0, <с> − PRE_S)` — `SDL_JoystickAttachVirtualEx` (`SDL_joystick.c:920`, `SDL_joystick.h:424`): тип `SDL_JOYSTICK_TYPE_GAMECONTROLLER` (раскладка — `SDL_virtualjoystick.c:581`), 6 осей, 15 кнопок, имя `KYTY test pad`, обратные вызовы `Rumble` / `SetLED` / `SendEffect` — только счётчики (`SDL_virtualjoystick.c:432`, `SDL_virtualjoystick.c:494`). Событие добавления (`SDL_virtualjoystick.c:240`) проходит обычным путём: эмулятор сам открывает пульт и делает его активным (`window.cpp:360`, `window.cpp:375`, `controller.cpp:509`).
- В `armed + <с>` — `fire` по режиму. `HOLD_MS` = 3000 (как `ctl114a` / `ctl114b` — сравнимость).
- Пробы главного потока: вспомогательный поток стенда каждые `PROBE_MS` = 20 мс в окне [`fire` − 1 с; `done` + 2 с] ставит пустую задачу главному потоку и меряет её возраст.
- Через 2 с после `done` — строка итога. В режимах `hold`, `sleep`, `enum` виртуальный пульт остаётся подключённым до конца процесса.

### 4.3 Строки

Это единственное изменение пути по умолчанию во всём проекте — одна печать на редком событии; решает лид (вариант: только при стенде или `=1`).

### 4.4 Что стенд не проходит

Драйвер HIDAPI для устройства (чтение, «щекотка», снятие, закрытие с ожиданием `hid.c:978`, очередь вибрации), RawInput, WGI, перечисление DirectInput по `WM_DEVICECHANGE`, и главное — вызов ОС к устройству, которое не отвечает. Режим `hold` заменяет его сном под тем же замком; что настоящий вызов держит именно этот замок и именно на главном потоке — [I].

## 5. Проект правки `KYTY_FIX_B24` (умолчание 0; чтение раз на процесс)

Ручка — переменная окружения (`static const bool`, форма `KYTY_FIX_F8`), не гейт: имён в `KNOB_DEFINITIONS` / `DEFINITIONS` нет, `check_gate_order.py` не затрагивается. Строка `FixB24: mode=1` один раз при `=1`. Сайты — `src/libs/controller.cpp`, `src/libs/controller.h`, `src/graphics/presentation/window/window.cpp` — вне набора подписи трансляции: подпись и каталог варианта не меняются. Код ложится поверх F18c `10a4800b` (тот же файл).

### 5.1 Член А — поток гостя не ждёт SDL

При `=1` `SetVibration`, `SetLightBar`, `SetTriggerEffect` не зовут SDL: под собственным коротким мьютексом (не `m_mutex`) кладут последнее значение в слот (вибрация, цвет, эффект курков — по одному значению каждого рода, новое затирает старое, у каждого счётчик поколения) и будят поток `PadOutput`. Поток `PadOutput` (один на процесс, создаётся при `=1`) забирает слот и делает те же вызовы SDL, что сейчас (`controller.cpp:778`…`controller.cpp:785`, `controller.cpp:792`…`controller.cpp:794`, `controller.cpp:822`…`controller.cpp:824`), без `m_mutex`; идентификатор активного пульта и признак «PS5» — копия, которую под `m_mutex` обновляет `CheckActive`. Ответ `SetTriggerEffect` гостю не меняется (возврат функции от `*sent` не зависит; `*sent` при `=1` — «пульт PS5 активен»).

Инвариант правки: **при `=1` на потоках гостя нет ни одного вызова SDL из `controller.cpp` под `m_mutex` и вне его**, кроме порта вибрации-звука (§1.6). При `=0` — прежний путь байт в байт.

Что меняется для гостя: ничего в возвращаемых значениях; вывод на пульт запаздывает на время пробуждения потока (ожидание < 1 мс) и схлопывается до последнего значения, если поток стоит.

### 5.2 Член Б — главный поток (не предлагается в итерацию 1)

Вынос `SDL_JoystickUpdate` с главного потока (`SDL_HINT_AUTO_UPDATE_JOYSTICKS=0` + собственный поток опроса) оставил бы окно живым при блокировке стека HID. Не предлагается: (1) одна остановка главного потока игру не останавливает [c лога `ctl114b`]; (2) окно обнаружения HIDAPI привязано к потоку инициализации (`SDL_hidapi.c:381`), перечисление DirectInput и RawInput на чужом потоке в SDL2 под Windows не проверялось — риск без стенда. Остаток после члена А при настоящей блокировке: окно не отвечает, ввод стоит, пересоздание поверхности (`swapchain.cpp:632`) ждёт — на время блокировки; игра идёт. Паркуется до свидетеля.

### 5.3 Чего правка не делает

Не снимает блокировку в SDL; не делает пульт снова рабочим; `ReleaseHostPads` на выходе — без изменений (§1.6).

## 6. Счётчики, тождества, контроли

### 6.1 Строка `TestHidLoss: stat` (одна, через 2 с после `done`; счётчики окна [`fire` − 1 с; `done` + 2 с]; в `FrameTrace-x` не входят)

| Поле | Тип | Что |
|---|---|---|
| `main_late_max_us` | мкс | наибольший возраст пробной задачи главного потока |
| `probes_posted`, `probes_run` | штуки | поставлено и исполнено проб |
| `pad_calls` = `pad_vib` + `pad_led` + `pad_trig` | штуки | входы гостя в `SetVibration` / `SetLightBar` / `SetTriggerEffect` |
| `pad_wait_max_us` | мкс | наибольшая стена одного такого вызова на потоке гостя (вход → возврат) |
| `po_applied` | штуки | применений слота потоком `PadOutput` |
| `po_wait_max_us` | мкс | наибольшая стена одного применения на потоке `PadOutput` |
| `guest_sdl` | штуки | вызовы SDL из трёх функций вывода, сделанные не потоком `PadOutput` |

Все счётчики — `std::atomic<uint64_t>` `relaxed`; записей в состояние гостя нет.

**Обязаны быть 0 (инварианты):** `probes_posted − probes_run` (все пробы исполнены к строке итога); `guest_sdl` при `=1`; `po_applied` и `po_wait_max_us` при `=0`.
**Тождества для ридера:** `pad_calls = pad_vib + pad_led + pad_trig`; `probes_run ≤ probes_posted`; `removed` = 1 в `detach` и `event`, 0 в `hold`, `sleep`, `enum`; `t_us` строк `armed` < `attach` < `fire` ≤ `done`.

### 6.2 Цена

Стенд выключен, `=0`: на путь вывода пада добавляется одна проверка статического флага на вызов (вызов — раз в кадр, §2.2) — цена ниже шума любого замера. Стенд включён: два чтения часов на вызов вывода пада (раз в кадр) и проба раз в 20 мс в окне ≈ `HOLD_MS` + 3 с (≈ 300 задач главному потоку) — возмущение есть только в окне стенда и одинаково у `=0` и `=1`, в разности плеч сокращается. `=1` без стенда: один захват короткого мьютекса и пробуждение потока на вызов вместо двух захватов замка джойстиков.

### 6.3 Положительный и нулевой контроль

- **Стенд вооружился:** строки `config on`, `armed`, `attach`, строка эмулятора `Controller <id>: "KYTY test pad" …`, `fire`, `done`, `stat`.
- **Замок действительно был занят** (`hold`): `main_late_max_us` ≥ 0,9 · `HOLD_MS`; при `=1` дополнительно `po_wait_max_us` ≥ 0,9 · `HOLD_MS` — блокировка никуда не делась, она переехала с потока гостя на поток `PadOutput`. Без этого члена «кадр < 1 с при `=1`» ничего не значит.
- **Гость действительно зовёт вывод пада в окне:** `pad_calls` ≥ 1 (ожидание — ≈ 60 в секунду, §2.2).
- **Нулевой контроль:** прогон без обеих переменных — строк `TestHidLoss:` и `FixB24:` нет; путь по умолчанию.
