## 2. Семантика (ISA RDNA2, `C:/kyty/s49/rdna2-official.txt`, своё чтение)

- 12.3 SOP1, опкод 12 (`0x0c`): `S_BREV_B64` «Reverse bits. D.u64[63:0] = S0.u64[0:63].» (строки 4084–4085); строки «SCC =» нет — SCC не
  меняется. Правка (`ba3be480:…/translate/Scalar.cpp:172`): `lo' = BitReverse32(hi)`, `hi' = BitReverse32(lo)` — это и есть разворот 64 бит.
- 12.9 VOPC, опкод 227 (`0xe3`): `V_CMP_LE_U64` «D[threadId] = (S0 <= S1). // D = VCC in VOPC encoding.» (6241–6242); маска EXEC —
  «V_CMP_* ⇒ VCC[n] = EXEC[n] & (test passed for thread[n])» (строка 914). Правка (`…/translate/Vector.cpp:109`) — `NOT(UGreaterThan64)` по
  дорожке до `LogicalAnd(EXEC, value)` (`…/translate/Compare.cpp:11`): для беззнаковых `!(a > b) ≡ a ≤ b`, NaN нет — верно.
- 6.2.1 «Literal Expansion to 64 bits»: «64-bit unsigned integer: zero extended» (1747–1751). `ReadU32Pair` (`…/translate/Translate.cpp:451`):
  литерал — старшая половина 0; отрицательная целая инлайн-константа — `0xffffffff` (знаком, как у соседей).
- **Независимое подтверждение по самому шейдеру игры [c]** (дизассемблер `C:/kyty/f287/f1a/rdis.py` по `C:/kyty/f287/f2a/blob_57c4.bin`):
  в `57c4d5848e02ecdc` две ветки заполняют одну пару `s[10:11]` перед общим продолжением `0x170`: ветка `0x150` — `s_mov_b32 s10, s70`,
  `s_mov_b32 s11, 0x16204`; ветка `0x168` — `s_brev_b64 s[10:11], 0x20468000`. Разворот 64 бит литерала `0x00000000_20468000` даёт
  `s10 = 0`, `s11 = 0x00016204` — то же слово `0x16204`, что ставят соседние ветки в dword 3 дескрипторов (`0x90`, `0xc8`, `0xf4`, `0x128`).
  Компилятор игры использовал `s_brev_b64` как короткую запись пары {0, `0x16204`}; перестановка половин (не «каждая половина на месте»)

## 4. RC5 и `=0` байт в байт
