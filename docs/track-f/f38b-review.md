## 7. Замечания «читать так» (не RC)

- **Н1.** `SysFileSize` (Windows) не проверяет возврат `GetFileSizeEx`: при отказе (возможен при той же ошибке устройства, что даёт двойной
  отказ чтения) `LARGE_INTEGER s` не инициализирован, и решение `pos < Size()` произвольно (`EIO` или 0 — обе прежние формы). Путь не нов
  (то же `Size()` считает `remaining` в начале входа); для чтения F38d.
- **Н2.** Правка переводит в `EIO` любую причину двойного отказа, в том числе чтение дескриптора, открытого только на запись
  (`Mode::Write` → `CreateFileW(GENERIC_WRITE | DELETE)`, `ReadFile` — `ERROR_ACCESS_DENIED` оба раза): при `=0` гость получает 0, при `=1`
  — `EIO`; на PS5 ожидался бы `EBADF` [I]. Оба ответа неверны; `=1` не хуже. Не в критерии п. 691(д).
- **Н3.** Строка `Seek(pos)` нового пути `KernelRead` стендом не проверяется (m4c — YES): внесённый отказ «всё или ничего» указатель не
  двигает, поэтому позиция верна и без неё. Член (в)(3) «позиция = `pos`» доказан только в этой форме отказа; движение указателя
  настоящим отказом `ReadFile` — [U] (п. 691(м) это и не заявляет).
- **Н4.** В E позиция ровно = размеру — 0 из 300 испытаний (у F38a тоже 0 из 300; вероятность 1/4 097 на испытание). Путь кода тот же
  (`remaining` = 0); для издания 3 дешевле взять `offset` = размер явно в части испытаний.
- **Н5.** Буква п. 691(д)(1) для E — только «`ret` 0 без кода ошибки»; ридер F38a `sum_f38a.py` читает E строже (1 вызов, буфер, позиция)
