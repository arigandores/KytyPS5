# Сессия 47 — GS triangle fan и регрессия галактики после слияния

Дата: 2026-09-12. База: `7259103`, ветка `merge-upstream`.

Следующий краш из HANDOFF сессии 45:
`unsupported GS assembly: input=5 output=2 vertices=8 GE=32/32 max_output=256`.
`PrepareProgram` отвергал `kTriFan`; простого разрешения топологии недостаточно,
поскольку существующая сборка ES/GS предполагала списки или полосы треугольников.

## Исправление

- `ShaderMeshInputInfo::InputPrimitiveStep`: веер добавляет одну вершину на примитив,
  поэтому N входных вершин дают N−2 примитива и P примитивам нужны P+2 вершины.
- `PrepareProgram` принимает `kTriFan` при сохранении остальных ограничений GS.
- Mesh-пролог собирает локальные ссылки GS `[0, lane+1, lane+2]`.
  Каждая группа загружает входные вершины `[0, chunk+1, chunk+2, ...]`:
  центр берётся из начала всего draw, а не из начала группы. Для индексных draw
  это первый элемент исходного индексного буфера. Base vertex прибавляется после
  чтения индекса, как и прежде; чётность полосы на веер не переносится.
- Следующая проверка на настоящем draw обнаружила включённый fixed-index restart:
  `unsupported mesh draw: primitive=5 indexed=1 restart=1`. Добавлено разделение
  исходных индексов на диапазоны между маркерами. Перед разбором на GPU command lane
  выполняется актуальный readback; он стоит до подготовки привязок, поскольку может
  перезапустить command buffer. Пустые и слишком короткие диапазоны не рисуются.
  Каждый диапазон получает собственную базу индексного буфера, центр веера/чётность
  полосы сбрасывается; base vertex сохраняется. Экземпляры идут внешним циклом,
  чтобы сохранить порядок отрисовки и исходные instance IDs.
  Обычные mesh draw без restart сохраняют один dispatch.
  Restart для indirect mesh draw остаётся явно неподдержанным, custom restart
  values по-прежнему ограничены существующим ResolvePrimitiveRestart.

## Регрессия галактики и пересмотр слияний

Первый прогон с исправленным GS пользователь остановил на галактике: снова 1 fps.
До конфигурации GS с восемью выходными вершинами прогон не дошёл. Лог подтверждает
прежний PS `d6fb5f22c689ceff`, `conditional block 41 has no structured merge`,
dispatcher fallback, 26321 слово SPIR-V. Офлайн повтор на исходном дампе из s45
воспроизвёл отказ. Видео `rec_fan.mp4`: 14214 кадров, 0 однокадровых кандидатов,
decode exit 0; отсутствие кандидатов не означает нормальную производительность.

Причина в `f767843`: апстрим перенёс откат графа внутрь структуризатора,
а при объединении с нашим повторным проходом оставили `graph.unsupported=true`
от первой попытки. Вторая попытка с разрешённым клонированием эпилогов немедленно
выходила в начале `StructurizeImpl`. Сама правка `3fe9b23` сохранилась в исходниках,
но этот путь перестал выполняться.

Теперь только для исходно поддерживаемого и приводимого графа перед повтором
сбрасываются диагностические поля первой попытки. При повторной неудаче сохраняется
первая диагностика и первоначальная топология. Входные ошибки декодирования не стираются.

Тест `TestCfgTerminalCloneRetryClearsFailure` использует уменьшенный до 99 инструкций
граф галактики: 52 блока, 5 циклов, арифметика заменена заполнителями. Офлайн на коде
до правки тот же отказ, после — 61 блок и успешная структуризация; тест дополнительно
проверяет покрытие инструкций, отсутствие OpSwitch, валидность SPIR-V и сохранение
ранее установленной ошибки. Настоящий дамп s45 также снова даёт 61 блок/5 циклов.
Корпус `_Shaders/gcn`: 301 файл, 296 структурируются; один прежний отказ
`ps_93015cc3f6029cd9`, три неподдерживаемых mesh-декодирования и один пустой файл.

Офлайн-перекомпиляция с ресурсами из кэша этого прогона: 26321 → 21060 слов SPIR-V.
Драйверный стенд `s16_sass.py --ps`: 72 регистра, 1591 инструкция, 10 STL/LDL —
те же показатели, что после исправления в сессии 45. Поле Local Memory Size у
pipestat явно некорректно (огромное число), оно не используется как метрика.
Повторный игровой лог также подтвердил 61 блок/5 циклов и EmitProgram=21060.

По просьбе пользователя пересмотрены переносы в `f767843` и `7259103`: CFG rollback,
входные метаданные и требования эмиттера, depth comparison, BDA/SRT, sparse MRT,
слияние GpuResourceManager в RenderContext, readback/dirty ranges, защита страниц,
загрузка мипов и image views, изменения Vulkan feature chain, pthread keys/condition
variables и Json2 clear. Проверено сохранение всех идентификаторов KYTY-переключателей
в src; само по себе это не доказывает сохранение поведения. Вторая merge-правка
SPIR-V enums меняет явные преобразования типов; дополнительных подтверждённых
регрессий игрового кода в рассмотренных участках не найдено. Это не доказательство
отсутствия любых ошибок во всех 106 изменённых файлах и во всех играх.

Найдена отдельная ошибка объединения тестов: добавленная апстримом проверка blending
в общем `CheckPolygonModeRasterization` меняла регистры MRT0, хотя наши вызовы того же
метода используют MRT2/MRT7. Тест падал на `enabled blend pipeline cache` до проверки
результата смешивания активного слота. Теперь используется `color_slot`.

Фокусные GPU/host проверки с `KYTY_ASYNC_PIPELINES=0`, Vulkan validation и sync validation:
sparse MRT2/MRT7, polygon mode/packed vertex, read-only depth reuse, BDA dirty,
packed textures, image-view cache, scheduler, draw offsets, shader-data storage прошли.
Есть ожидаемые предупреждения неиспользуемых fragment outputs у sparse-тестов.
Первый запуск sparse без выключения async остановился на неготовом pipeline — неверный
режим синхронного стенда, затем повторён с нужным переключателем.
`memory_tracker_tests` и `resource_materialization_tests` прошли.
`--buffer-cache-range-only` сохраняет старое падение `partial-page readback values`,
уже описанное в `docs/local-sessions-34-39.md`; оно не объявляется новой регрессией.

Повторный прогон `rec_fixed.mp4` дошёл до перевода GS `3f716cc2835a4c3f`:
178 блоков/16 циклов, EmitProgram=64205. Прежний `unsupported GS assembly` пройден,
после него проявился restart, описанный выше; финальный present 19292.
Видео этого прогона: 19292 кадра, 0 однокадровых кандидатов, decode exit 0.
Третий прогон `rec_restart.mp4` остановился на present 16809 с
`vkWaitSemaphores: ErrorDeviceLost`, ticks 16829/430292. Пользователь сообщил,
что компьютер завис на карте галактики и он нажал Ctrl+Alt+Shift+B; поэтому
DeviceLost может быть следствием сброса графики, а не исходной причиной зависания.
Вход в restart в этом логе не подтверждён. Туманности перед этим уже быстрые:
frame 15149 — пять draw `d6fb5f22` суммарно 1897 мкс GPU, frame 15150 — 1856 мкс.

Добавлена ограниченная диагностика MeshRestartBegin перед readback.
Четвёртый прогон `rec_diagnostic.mp4` выполнен с `KYTY_GPU_CHECKPOINTS=1`
(breadcrumbs и NV diagnostic checkpoints подтверждены логом), чтобы установить

Пятый прогон `rec_normal.mp4` без KYTY_GPU_CHECKPOINTS также загрузил уровень,
прошёл место краша и завершён пользователем, exit 0, final present 16965.

низкий fps; первоначальное предположение, что 9–10 fps вызваны ими, не подтвердилось.

**Остаток — CPU при 5–6 тысячах draw в underwater_aerial_garden.** Ускорение этой
