## 5. Требуемые изменения

**RC1 (MINOR; вне буквы п. 245(б); владелец решения — лид, код — Emu Engineer; S6 не блокирует).** Что не так: строка RC3 охватывает только

строки не даёт (признано отчётом S5c §1, замечание 2; моя формулировка RC3 в S5b была узкой). Места создания воркером без пометки:
`2ce6326e:pc:5715` «CreatePipelineInternal(m_graphics, *target, *job, module, m_driver_cache);» (+1 «EXIT_NOT_IMPLEMENTED(target->pipeline ==
nullptr);», задача предвыборки cs `:5713`), `:5447` (задача gfx `:5445` «EnqueueJob([this, job, target, vs_id, ps_id, pair_key, queued_at] {»),
предкэш `:6602`, `:6677`. **Сценарий отказа** (`pcw_int`, окружение T, `=1`): предвыборка ставит cs-пайплайн в кадре k−1; воркер 80 мс стоит за
внутренним замком кэша, пока поток записи читает ≈ 90 МБ; запись кончается в кадре k−1 (строка `saved` — в группе k−1); диспатч кадра k ждёт
остаток компиляции 60 мс → `dt` ≥ 100 мс; `gen0 = gen1`, чётны → строки `wait cs` нет; по (в)(3) кадр k не PCW (строка записи не в группе k/k+1).
Печать `pcw_int` «ожиданий, перекрывшихся с записью, 0» читается лидом S8 как «замок драйвера через воркер не участвует» → вторая итерация
(з)(7) нацелена на `m_mutex` без основания. **Что изменить (вариант рецензента):** под `PcwOverlapTrace()` в задачах воркера и предкэша —
`gen0` до `CreatePipelineInternal`, `PcwNoteOverlap("worker gfx|worker cs|precache gfx|precache cs", …, время создания)` после — только локальные
переменные, `=0` не меняется, правило то же; либо, без кода, правило чтения `pcw_int`: «отсутствие строки `wait …` ≠ отсутствие перекрытия»,
член печатается «не определено», не 0.
