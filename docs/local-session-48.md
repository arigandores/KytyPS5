# Сессия 48 — CPU во входном пролёте underwater_aerial_garden

Дата: 2026-09-12. База: cbb5b7d, ветка merge-upstream.

## Профиль и изменения

Приоритет взят из актуального HANDOFF сессии 47: пролёт с птицами нового уровня,
около 5800 draw, 11,41 fps в прежнем обычном прогоне с записью и подробными таймерами.
Повторное доказательство низкого FPS не было отдельной задачей.

Семплер текущей сессии: log_profile.txt, before.map, samples_level_final.txt.
Окно sampler t=310…370 с: 17046 семплов, 6 дампов. Окончание сборки первой
экспериментальной правки предшествует этому окну. Работа семплера сама замедляет игру;
этот прогон не является базой численного A/B общего FPS.

- 16,4% семплов: FrameStats::NowNs (сами подробные таймеры).
- 10,4%: TrackingSpinLock::lock; основной вызывающий путь — синхронизация BDA/буферов.
- 7,7%: EvaluateRuntimeSourcesImpl, включая встроенный EvaluateCompiled.
- 6,5%: ResolveTexture; 4,5%: ResolveRenderColorTarget.
- Дизассемблирование горячих адресов 0x92700…0x92730 подтвердило цикл побайтового FNV
  в ResolveRenderColorTarget; 0x2c749a — загрузку MemoryInfo при вычислении SRT-адреса.

Правки:

1. SRT: Address48 разделяет общий базовый адрес scalar loads; MemReadScalar хранит
   постоянное знаковое смещение прямо в узле. Чтения памяти остаются отдельными,
   выполняются при каждом вызове, сохраняют порядок и разделение live/clean.
   Динамические смещения и const-buffer сохраняют прежний путь.
   Контроль: KYTY_SRT_ADDRESS_PLAN=0.
2. TrackingSpinLock: после неудачного acquire ожидание использует relaxed loads
   и процессорную pause/yield, вместо непрерывных атомарных записей в линию владельца.
   Владение по-прежнему выдаёт acquire test_and_set; освобождение — release clear.
   Диагностика рекурсии/владельца сохранена. Контроль: KYTY_TRACKING_RELAXED_SPIN=0.
3. Render memo: XXH3 вместо побайтового FNV, пустые цветовые слоты возвращаются до
   поиска в кэше с сохранением исходного номера слота. Сравнения регистров и проверки
   поколений/регистрации/rebind изображений сохранены. Debug dump проходит прежний путь.
   Это временные lookup-хеши, не формат постоянных pipeline cache keys.
   Контроль: KYTY_RENDER_MEMO_FAST=0.

## Проверки

- ResourceMaterializationTests: прошли, также с KYTY_SRT_VERIFY=1, без SrtVerify mismatches.
  Добавлены 128 последовательных scalar reads: знаковое невыравненное смещение,
  48-битная маска, смена user data и памяти, неудача reader, порядок обращений.
- Микростенд SRT после завершения сборки: 1 млн итераций, 128 чтений/итерацию;
  off 978,6 / 984,7 / 992,8 нс, on 940,1 / 913,3 / 944,2 нс. Это синтетический стенд,
  не выигрыш общего FPS. Временные измерения во время компиляции не использованы.
- MemoryTrackerTests: прошли; новый тест 6 потоков / 120000 захватов проверяет
  публикацию связанных значений и отсутствие потерянных обновлений.
  Короткий стенд: off 10,009 / 11,669 мс, on 8,268 / 6,612 мс; игровой выигрыш отдельно.
- Shader suite: 123 прошли, прежний IMAGE_SAMPLE_C падает, 4 не собраны для Windows.
  Полная suite не объявляется чистой.
- Sparse MRT2/MRT7, image views, read-only depth reuse, BDA dirty и packed textures
  прошли Vulkan + synchronization validation. Sparse имеет ожидаемые unused-output
  warnings; слой также предупреждает об устаревшем способе включения sync через
  VK_LAYER_ENABLES. Фильтров ошибок не использовали.

## Игровое сравнение

Вход в уровень выполняет пользователь. Окна привязаны к первому MeshRestartBegin,
а не ко времени меню: смещения +120, +420, +720, по 300 present-интервалов.
Число draw и времена вложенных CPU-фаз рассматриваются отдельно; вложенные таймеры
не суммируются с внешними. Подробные таймеры сохраняются в обоих сравниваемых прогонах.

Один и тот же бинарь: on — три оптимизации по умолчанию, off — три контрольные
переменные равны 0. Без семплера, без GPU checkpoints, Vulkan validation в игре выключена.
Оба прогона завершены штатным закрытием окна (exit 0), не крашем.
Первый MeshRestartBegin: on 15778, off 15844. Последние FrameTrace: on 17073, off 17152.

targets 3,96 → 1,67 мс, BDA 6,03 → 4,64 мс, spin GPU-thread 2,38 → 1,35 мс.
Общий CPU GPU-thread 83,76 → 82,02 мс, но on содержит больше draw.
Отношение суммарного CPU GPU-thread к суммарным draw: 14,85 → 13,77 мкс/draw
в первом окне; в следующих 14,63 → 13,29 и 14,31 → 13,11 мкс/draw.
Это нормализация нагрузки, не независимый таймер одной операции draw.

SRT Evaluate в первом окне 11,27 → 11,78 мс: отдельный игровой выигрыш SRT
этой парой не установлен, несмотря на улучшение синтетического стенда.
GPU busy 27,03 → 23,12 мс не объявляется ускорением шейдеров: GPU-код не менялся,
расписание/нагрузка и частоты отличаются. Разовые снимки: on 2137 MHz / 64°C,
off 2257 MHz / 71°C, без других игр в списке GPU-процессов.

Ограничения сравнения: по одному запуску каждого режима; число draw у on больше на
3,5–5,9%, траектория и частицы немного различаются. В on в трёх окнах ещё были
3/2/2 новых shader events и freeze scopes 106982 / 31741 / 99315 мкс, всего 238 мс;
в off их нет. Поэтому пара не называется полностью тёплой или статистически устойчивой.
Тем не менее профиль показывает конкретное сокращение затрат на memo/targets и spin;
наблюдавшийся общий выигрыш пары — около 8–9%, не исправление всей просадки.

**60 fps не достигнуты.** Остаток — около 80–82 мс CPU GPU-thread и 23 мс GPU busy
при ~6000 draw; в SRT порядка 0,5 млн live/clean обращений на present-интервал.
Следующий фокус: дальнейшее сокращение повторной работы при materialization/bindings,
стоимость тысяч draw/descriptor commits; GPU остаётся отдельным ограничением.
Из семплера известно, что подробные таймеры тоже заметно вмешиваются в профиль,
поэтому облегчённый замер без них нужен перед выводами о скорости обычного запуска.

Новый shader source hash: 8bb01a8a65d88dfb5c85b1d60a245f1b86f8e82f.
