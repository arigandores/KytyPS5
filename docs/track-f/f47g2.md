## 2. RC

### 2.1. RC1 — номер показа `q`

- `q` = число флипов, поставленных разбором GuestGpu (`NoteFlip` в четырёх местах постановки), + 1, на потоке разбора (`QueuedShow`).
  Поле `q` — в строках `draw/img/buf/srt/reg/vk`, в записи загрузки (`sq`, `pq`) и в `srcres` (`q_res`); прежний `n`
  (`GpuTimeProfiler::Frame()`) — отдельным полем во всех строках. Окно `KYTY_DIAG_F47DT_FRAMES` и `g_frames` — по `q`; `d` — номер draw в
  показе `q`.
- `F47dt: kind=flip q=<q> path=<0..3> rid=<id запроса> n=<n>` — при каждом поставленном флипе (все, не только окно).
- **Решение исполнителя (на проверку F47h2):** строка `F47dt: kind=shown n=<flip_status.count> rid=<id>` на потоке показа сразу после
  `count++` (`videoOut.cpp:1245`) — без неё член допуска F47i («`q` строк flip = `n` `FrameTrace` тех же флипов», п. 742(е)) не может
  сопоставить «тот же флип»: строка `FrameTrace` id запроса не печатает. Ридер: `dt_f47g2.py flips <лог> --window A-B` — `ADMISSION OK`,
  если `q` флипов в окне идут подряд, у каждого есть строка `shown` того же `rid` с `n = q`, и `n` есть среди строк `FrameTrace: n=`;
  иначе `ADMISSION FAIL` с причиной.
- Флип CPU (`PrepareCpuFlip`) считается в порядке GuestGpu; запрос CPU резервируется на потоке гостя — если порядок резервирования и
  постановки разойдётся, член допуска это покажет (`shown n ≠ q`) [I частоты].

### 2.2. RC2 — запись (ii) по образу

- Ключ записи — `ImageId` (индекс и поколение слота); `CompletePendingUpload` передаёт настоящий id (`IdOfImageForDiag`).
- Строка `img`: `sid=<индекс>:<поколение>` записи, по которой взят (ii), и `rlast=` — образ последней загрузки этого диапазона. Записи
  образа нет, а у другого образа того же диапазона есть — `sid=<другой> sk=other_image cmp=und`; нет ничьей — `sid=- sk=norecord`.
- Ридер: `sk=other_image` или `sid` ≠ `id` привязки — «не определено».

### 2.3. RC3 — кольцо Stream

- (б) Глобальный сторож `AsyncCopyCompleted() < AsyncCopySequence()` для кольца Stream снят: кольцо наполняют только `memcpy`
  (`StreamBuffer::Copy`, `ObtainBuffer`, копии const-bank из памяти гостя) [c кода] и копия на ГП ветви `gpu`; пул копий наполняет только
  кольцо staging образов.
- (а) Ветвь `gpu` const-bank (`descriptors.cpp:1018`) — нота диапазона кольца в поколении обёртки; поиск `OnDraw` (тот же
  `RingGivenLocked`, что у стенда) по пересечению с нотами текущего поколения — `gvh=unmeasured:gpu_copy`. Нового пути нет: только запись
  ноты. Других копий на ГП в кольцо Stream по коду не найдено (`CopyFrom` в `bufferCache.cpp` пишет в буферы кэша, staging и выгрузки) —
  [I] вне прочитанного.
- (в) У строки `buf` — `ggpu=<0|1>`: диапазон гостя записан ГП (`IsRegionGpuModified || HasGpuDirtyBytes` — то же решение, что `gpu`
  const-bank, запрос с замком без счётчиков). Ридер: `ggpu` ≠ 0, `gvh` не хэш (буфер и SRT), `given` SRT не `ring_copy`/`none` —
  «не определено» (`cmp_srt` больше не пропускает молча).

### 2.4. RC4 — бинарный член источника (ii)

- Плечо S: копия гостя в staging, байт staging изменён до ноты ⇒ `cmp=ne`, `sh` = хэш байт staging (стенд печатает свой XXH3).
- Плечо A2: копия пулом, ожидание, байт копии изменён до разрешения ⇒ `sst=hashed`, `cmp=ne`, `sh` = хэш копии.
