## 2. Правки

### 2.1 RC1 — `wr_after=large`

- `BufferCache::LargeGpuWriteSeq()` — чтение `m_large_write_seq` (`ed4f96d8:src/graphics/host_gpu/renderer/cache/bufferCache.h:493`); его
  ставит только запись > 16 МиБ (`ed4f96d8:src/graphics/host_gpu/renderer/cache/bufferCache.cpp:2856`, без изменений).
- `F5IdNoteFceMiss` (`ed4f96d8:src/graphics/host_gpu/renderer/pipeline/descriptors.cpp:3859`): `large = exact.seq == 0 && LargeGpuWriteSeq() > since`
  (`:3887`); порядок значений — `exact`, затем `large`, затем `fallback`, иначе `none` (буква (б)(1): «точный ответ пуст» — нет пересекающей записи
  корзины; `large` старше `fallback`, оба читаются «не определено»). Имя — `WrAfter::Large`, последнее в перечислении
  (`ed4f96d8:src/graphics/host_gpu/renderer/diagF5.h:299`), строка печатает `large` (`ed4f96d8:src/graphics/host_gpu/renderer/diagF5.cpp:388`).
- `m_large_write_seq` — один номер на процесс без адреса: `large` значит «после `since` была запись > 16 МиБ где угодно» — завышение в сторону
  «не определено» [c кода]. Решение `PendingDccFillStale` не тронуто (корзинная проверка и раньше шла с `include_large=false`).

### 2.2 RC2 — `cpu_mod` по эпохе записи CPU с заливки

- Штамп: `StampPendingDccFill` передаёт в `DiagF5Id::NoteFillSeq` третьим аргументом `F5IdRangeWriteEpoch(адрес, размер)` заливки
  (`ed4f96d8:src/graphics/host_gpu/renderer/cache/textureCache.cpp:3477`, `:3479`); модуль хранит её рядом с номером заливки — карта
  `fill_cpu_epoch` (`diagF5.cpp:354`, запись `:968`, чтение `FillCpuEpoch` `:982`, сброс только в `ResetForTest` `:1109`).
- `BufferCache::F5IdRangeWriteEpoch` (`bufferCache.cpp:2906`) — `MemoryTracker::RangeWriteEpoch` (`ed4f96d8:src/graphics/host_gpu/memoryTracker.h:35`,
  без замка) с защитой: пустой или негодный диапазон — 0, без `EXIT` `ValidateRange` на диапазоне из регистров.
- Событие (`descriptors.cpp:3896`, `:3898`): `cpu_mod = 1`, если `IsRegionCpuModified(dcc, dcc_size)` (прежний член, зовётся первым, как раньше),
  или заливки по адресу `dcc` модуль не штамповал, или эпоха штампа 0 (диапазон не отслеживался), или текущая `F5IdRangeWriteEpoch(dcc, dcc_size)`
  ≠ запомненной; иначе 0.
- **Место начальной эпохи [c]:** у трекера есть только начальная эпоха *региона* — `m_epoch {1}`
  (`ed4f96d8:src/graphics/host_gpu/regionManager.h:618`), а регион создаётся лениво при первом обращении (`GetOrCreateRegion`,
  `ed4f96d8:src/graphics/host_gpu/memoryTracker.cpp:59`) сразу со всеми страницами «грязными от CPU» (`m_cpu_dirty.Fill()`, `regionManager.h:129`);
  неотслеживаемый регион — эпоха 0 («грязный по определению», `memoryTracker.h:45`). Записи CPU до создания региона в эпоху не попадают, поэтому
  «эпоха = начальной» не свидетельствует «записи CPU со старта процесса не было». **Эпохи старта процесса код не даёт ⇒ без заливки `cpu_mod=1`**
  (буква (б)(2), ветка «иначе»).
- Грубость [c кода]: эпоха — на регион 4 МиБ (любая запись CPU в регион двигает её), её двигает и выгрузка с отложенным взводом
  (`regionManager.h`, ветка `provisional`); диапазоны заливки и события на разных наборах регионов дают разный хэш — всё в сторону `1`,
  «не определено». Поздний штамп (RC3) берёт эпоху позже заливки — запись CPU между ними пропускается; это покрыто правилом (б)(3)
  (ключи «не определено» при `stamp_late` > 0).

## 3. Тождество п. 496(б)(5) по коду

Утверждение: на последней строке `DiagF5:` плеча `KYTY_FIX_F5CMU=1`, `KYTY_DIAG_F5=1`, пока ни один вид строк не исчерпал свой предел 64, число строк

1. Счётчики `f5cmu_*` движутся только в деструкторе `F5CmuScope` при `m_decide && DiagF5::On()`; `m_decide = fce && FixCmuOn()`; `fce=true` —
   только у вызова `PrepareCmaskClear` из `FindRenderTarget` (`textureCache.cpp:2599`, один вызов на захват) с `fce_materialize=true`, а его даёт
   только FCE-скан (`descriptors.cpp:3942`, один вызов на слот). Значит, каждое приращение — ровно один FCE-захват, и тот же деструктор пишет тот же
   `fix` в `f5_cmu` (указатель передаётся при `DiagF5::On()`).
2. После захвата ровно одна из ветвей: `b42.kind == Hit` ⇒ строка `cmask_fce` с этим `f5_cmu` при любом `fix` (`descriptors.cpp:3967`);
   иначе ⇒ строка `cmask_fce_nohit` при `fix` ∉ {`off`, `fresh`} (`:3995`). Значения `kept`, `kept_applied`, `exact_stale`, `fallback` ∉ {`off`, `fresh`},

3. Ни один другой путь эти строки не печатает и эти счётчики не двигает (`NoteCmuEvent` и `NoteCmuNoHit` зовутся только в этих двух местах).
   Нарушение тождества при непревышенных пределах — дефект кода (форма контролей п. 492(д)).
