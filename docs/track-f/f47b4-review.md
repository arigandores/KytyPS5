## 4. Требуемые изменения

**RC1 (компаратор (а) §4.1 определён для UNORM8 / float16; на sRGB-цели (и других форматах без названного приведения) оба прочтения дают ложное
«не равно» ⇒ (в)(4) `дефект`).** `631f57ec:docs/track-f/f47a4.md:175` — допуск «1 младший разряд: UNORM8 — 1/255, float16 — ulp», прочтения Q0 /
Q1 (`631f57ec:docs/track-f/f47a4.md:168`), К-вид — только на цели UNORM8. Эмулятор создаёт sRGB-вложения цвета: тип числа `kSrgb`
(`ea6c6e9e:src/graphics/guest_gpu/gpu_defs.h:91`) → `k8_8_8_8Srgb` (`ea6c6e9e:src/graphics/guest_gpu/gpu_format.cpp:138`) → `eR8G8B8A8Srgb`
(`ea6c6e9e:src/graphics/host_gpu/renderer/image/imageInfo.h:340`), sRGB — в списке форматов цветовой цели (`ea6c6e9e:src/graphics/host_gpu/renderer/colorRenderTarget.cpp:35`).
На sRGB-вложении «приведённое к формату» значение — это либо закодированный байт E = round(enc(v)·255)/255, либо его линейное L = dec(E); К-вид на
UNORM8 не говорит, какое из них отдаёт RenderDoc. **Сценарий [c `f47b4/srgb.out`]:** К-вид на UNORM8-событии ответил Q1 ⇒ (а) на sRGB-цели
читается «только Q1» = round(v·255)/255. Литерал 0,5: `Shader Out` = E = 0,7373 ⇒ |Δ| = 60 / 255 ⇒ «не равно»; литерал 0,9955: `Shader Out` = L =
0,99110 ⇒ |Δ(Q0)| = 1,12 / 255, |Δ(Q1)| = 1,27 / 255 — «не равно» **при обоих** прочтениях (по L таких литералов 69 из 10 001 на сетке шага 10⁻⁴; по E —
почти все). Итог — (в)(4) `дефект` при верном эмуляторе, без члена СО, в F47e / F47f — худший исход формы по п. 722(г). То же у «своего смешения ≠
`Post-Mod`» §4.3 (смешение sRGB-цели идёт в линейном виде). **Изменить:** (а) и своё смешение §4.3 — только на цели, для которой издание называет
приведение и младший разряд (UNORM-n, SNORM-n, float16 / float32, целые — точно); цель с видом `*_SRGB` (или `NUMBER_TYPE` = SRGB в величине (i)
`CB_COLOR<t>_INFO`) и прочие форматы — «не определено», пока К-вид не ответил на событии той же цели **и** того же формата (на sRGB — три прочтения
Q0 / E / L, «не равно» — только при различии > 1 младшего разряда своего домена во всех трёх). Строкой пункта лида — достаточно.

**RC2 (правило §4.2 «до величины (i)» не исполнимо для 1- и 3-канальных целей — F называет две перестановки из четырёх; ложное «не равно»).**
`631f57ec:docs/track-f/f47a4.md:186` — «не равно», если V_g ≠ `Shader Out` при **каждой из четырёх** перестановок `COMP_SWAP` числа каналов цели; таблица
F (`631f57ec:docs/track-f/f47a4.md:232`) для 1 канала — только STD (R → X) и ALT_REV (A → X), для 3 — STD и STD_REV; своя `perm` для пар вне F —
`UNDETERMINED` (свои пробы `perm 1 1`, `perm 1 4`, `perm 2 4`). **Сценарий:** D_b на цели R8 (1 канал), гость поставил `COMP_SWAP` = ALT (на этой паре
канал берёт другую компоненту экспорта, напр. G — [I], у F пары нет); F47e без величины (i) проверяет только две названные перестановки: R ≠ X, A ≠ X ⇒
«не равно» ⇒ (в)(4) `дефект`, хотя G = X. Буквально «четырёх» на 1 канале проверить нечем — исполнитель либо считает по двум (ложный `дефект`), либо
сам решает «не определено» (решение вне формы). **Изменить:** до величины (i) на цели с числом каналов, для которого F называет меньше четырёх
перестановок, «не равно» — только если V_g ≠ `Shader Out` при **любом** назначении компонент экспорта каналам цели (1 канал — каждая из R, G, B, A;
3 канала — каждая перестановка трёх из четырёх), иначе «не определено»; либо такая цель до (i) — «не определено» целиком.

**RC3 (классификатор берёт у 32-битных SOP1 / SOP2 лишний источник `s+1`; на D_b с настоящим udc простейшая форма C-buf печатается «не определено» ⇒
ложный `ТУПИК`).** `631f57ec:docs/track-f/f47a4/cls_f47a4.py:252` (SOP2 — `s0+1`, `s1+1` у всех кодов) и `631f57ec:docs/track-f/f47a4/cls_f47a4.py:274`
(SOP1 — `s0+1` у всех, кроме ширины); `weak` снимает лишнюю ширину только у определений, не у источников. **Сценарий [c `own_n4.out` x5, x15]:**
`s_load_dword s100` → `s_mov_b32 s102, s100` → `v_mov v0, s102` → `exp` при udc 0: `s101` не определён и выше udc ⇒ лист `OTHER` ⇒ класс «не определено»
(и при `b5`), хотя по данным это C-buf ⇒ D_b уходит в (в)(6) `ТУПИК`, а не в (в)(5). То же x15 (`s_and_b32` — 32-битная SOP2). Направление — только в
сторону «не определено», `НЕ ДЕФЕКТ` не открывает; на T1 точное прочтение не меняет ни одного класса (§3), частота на D_b — [U]. **Изменить:** либо
классификатор берёт `s+1` только у 64-битных кодов (тогда новая sha В3 и `n4` заново), либо строка чтения F47e: D_b «не определено» ⇒ до (в)(6)
печать источника каждого `OTHER`; если все `OTHER` — второй регистр 32-битной SOP1 / SOP2 — класс по точному прочтению (`probe_pair_f47b4.py`,
