### `hit` (п. 351(в)(2)) — по коду

Ветка уже требует `rt.base.addr != 0 && rt.cmask.addr != 0 && cmask_fast_clear_enable && !dcc_compression_enable` (`descriptors.cpp:3705–3706`).
`FixB42Probe` добавляет: `color.image_id` есть (без `desc` нет экстента — предусловие исполнителя, называю), `metadata.kind == None` (при
условиях ниже и без DCC это тождественно: `kind` ставит только DCC-ветка или 1024-ветка `colorRenderTarget.cpp:431–450`), `samples == 1`,
`resources.levels == 1`, `!IsVolume()`, НЕ (`width % 1024 == 0 && height % 1024 == 0`); `N = width·height·layers/128` (`layers =
desc.info.resources.layers` = `view.image_layers` для не-volume, как `colorRenderTarget.cpp:426`, `:447–448`), `N != 0`; запрос по `rt.cmask.addr`:
запись есть, `type == PendingDcc`, `fill_value == 0`, `fill_size ≥ N`. Цели, кратные 1024 по обеим осям, `hit` не ловит — их ведёт старый путь.
Для T6 по числам F9e: 960·540/128 = 4 050 ≤ 0x2000, 480·270/128 = 1 012 ≤ 0x1000.

### `applied` — по коду

Только при `=1`. До `FindRenderTarget` запомнен `clear_mask` записи `PendingDcc` (для заливки значением 0 `TrackDccFill` ставит `UINT32_MAX`,
`4414e235:…/textureCache.cpp:3182–3203`). После — второй запрос; `applied`, если запись теперь `CMask`, `fill_value == 0` и хотя бы один бит
`clear_mask` снят. Довод, что это ⇔ «`PrepareCmaskClear` вызвал `ClearImage` хотя бы одного слоя» [c по коду `PrepareCmaskClear`,
`4414e235:…/textureCache.cpp:1959–2020`]: бит снимается только строкой `:2012` сразу после `ClearImage` `:2010`; несвежая заливка

`:1991` обнуляет маску только при `fill_value != 0` — исключено `hit`; отказ `DecodePackedColorClear` (`:2004–2005`) или проверки вида (`:2007`)
