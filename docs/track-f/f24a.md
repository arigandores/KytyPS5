## 1. Б13 — порядок эпох `ChangeState<Cpu,true>`

### 1.1 Место есть в обоих кодах

`RegionManager::ChangeState<Cpu, true>` публикует глобальную эпоху раньше эпохи региона:
`707e0d7d:src/graphics/host_gpu/regionManager.h:230` («`m_cpu_epoch.fetch_add(1, std::memory_order_release);`», +1 —
«`m_epoch.fetch_add(1, std::memory_order_release);`»); у S18 — `0005e11f:src/graphics/host_gpu/regionManager.h:222`
(тот же текст; разница `0005e11f..707e0d7d` в `regionManager.h`/`memoryTracker.h` — только метки `KYTY_DIAG_B32` коммита
`2cde5ef2`). Биты CPU-dirty ставятся раньше обеих эпох (`707e0d7d:src/graphics/host_gpu/regionManager.h:202`), бит карты
`bdabits` — после обеих (`707e0d7d:src/graphics/host_gpu/regionManager.h:237`, +1 — `BdaNoteRegionWrite`). Писатели —
потоки гостя из обработчика записи: `InvalidateRegion` (`707e0d7d:src/graphics/host_gpu/memoryTracker.h:160`),
`InvalidateWriteFault` (`707e0d7d:src/graphics/host_gpu/memoryTracker.h:206`), `MarkRegionAsCpuModified`; все — под
замком региона (`TrackingSpinLock`).

### 1.2 Читатели и их синхронизация

| поле | чтение | замок | порядок памяти |
|---|---|---|---|
| глобальная `m_cpu_epoch` | `CpuWriteEpoch` (`707e0d7d:src/graphics/host_gpu/memoryTracker.h:30`) | нет | acquire |
| эпоха региона `m_epoch` | `Epoch` (`707e0d7d:src/graphics/host_gpu/regionManager.h:150`) через `RegionWriteStamp` (`707e0d7d:src/graphics/host_gpu/memoryTracker.h:77`), `RangeWriteEpoch` | нет | acquire |
| то же | `CollectCpuModifiedRangesStamped` | замок региона | — |

Читатель, сочетающий обе эпохи, — один: подготовка BDA. `RenderContext::PrepareBda` читает глобальную эпоху до обхода
(`707e0d7d:src/graphics/host_gpu/renderer/renderContext.cpp:330`), отвечает «из кэша» при равенстве трёх эпох
(`707e0d7d:src/graphics/host_gpu/renderer/renderContext.cpp:333`) и после обхода запоминает прочитанную до него
(`707e0d7d:src/graphics/host_gpu/renderer/renderContext.cpp:399`). Обход `BufferCache::SynchronizeBuffersByRegion`
(гейт `bdastamp`, по умолчанию 1 — `707e0d7d:src/common/gates.cpp:28`; выбор пути —
`707e0d7d:src/graphics/host_gpu/renderer/cache/bufferCache.cpp:3641`) решает «пропустить регион» БЕЗ замка: по биту
`bdabits` (`707e0d7d:src/graphics/host_gpu/renderer/cache/bufferCache.cpp:3506`; гейт по умолчанию 0 —
`707e0d7d:src/common/gates.cpp:199`) или по штампу региона
(`707e0d7d:src/graphics/host_gpu/renderer/cache/bufferCache.cpp:3530`, сравнение —
`707e0d7d:src/graphics/host_gpu/renderer/cache/bufferCache.cpp:3532`). Замок региона берётся только после решения «обходить»
(`707e0d7d:src/graphics/host_gpu/renderer/cache/bufferCache.cpp:3571` →

(`707e0d7d:src/graphics/host_gpu/regionManager.h:228`: «A BDA scan observing these epochs still acquires this lock before
it reads dirty bits, so the order does not matter to it») верен для чтения битов, но не для решения о пропуске [c кода].

с ней не смешивают, биты публикуются раньше обеих эпох — для них порядок двух эпох не важен.

### 1.3 Сценарий чередования

Предусловие: прошлый обход запомнил глобальную эпоху `E` и штамп региона R `{mgr, r}`; регион R лежит в
зарегистрированном BDA-буфере. W — поток гостя с отказом записи в странице R (внутри `ChangeState<Cpu,true>` под замком
R); G — поток GuestGpu в `PrepareBda`.

1. W ставит биты CPU-dirty страницы (`707e0d7d:src/graphics/host_gpu/regionManager.h:202`).
2. W: `m_cpu_epoch` `E → E+1` (`707e0d7d:src/graphics/host_gpu/regionManager.h:230`).
3. G читает глобальную эпоху `E+1` (`707e0d7d:src/graphics/host_gpu/renderer/renderContext.cpp:330`) ≠ `E` — промах кэша, обход.
4. G доходит до R: штамп `{mgr, r}` (W ещё не сдвинул `m_epoch`) равен запомненному — регион пропущен без замка
   (`707e0d7d:src/graphics/host_gpu/renderer/cache/bufferCache.cpp:3530`, `707e0d7d:src/graphics/host_gpu/renderer/cache/bufferCache.cpp:3532`).
5. G запоминает `E+1` (`707e0d7d:src/graphics/host_gpu/renderer/renderContext.cpp:399`).
6. W: `m_epoch` `r → r+1` (`707e0d7d:src/graphics/host_gpu/regionManager.h:231`), бит `bdabits`, `UpdateProtection` — страница доступна на запись,
   гость пишет.
7. Следующий `PrepareBda`: глобальная эпоха `E+1` = запомненной — ответ из кэша (`707e0d7d:src/graphics/host_gpu/renderer/renderContext.cpp:333`), R не
   обходится. Буферы BDA над R остаются со старыми байтами до следующего сдвига глобальной эпохи (любой отказ записи в
   любом регионе), регистрации буфера или смены карты гостя.

Модель памяти: acquire-чтение `E+1` синхронизируется с release-записью `m_cpu_epoch` и упорядочивает только то, что
было до неё (биты), а запись `m_epoch` идёт после — шаг 4 не запрещён ничем. На x86 видимый порядок = порядку программы,
поэтому шаг 4 требует, чтобы чтение штампа попало между двумя записями W: окно — несколько инструкций, если W не вытеснен
между ними (W держит спин-замок; вытеснение ОС не запрещено). С `bdabits` = 1 окно шире: бит ставится после обеих эпох
(`707e0d7d:src/graphics/host_gpu/regionManager.h:237`), и регион пропускается по чистому биту вплоть до шага 6. Последствие в игре — устаревшие байты
BDA-буфера у draw до следующего сдвига эпохи [I]; частота в игре — [U]; сигнатуры в логе нет (реестр).
