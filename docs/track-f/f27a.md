### 5.2. Проект проверки «держится на установленном» (для звена серии, если лид её назначит)

**Что меряется:** кадры ≥ 100 мс на удержании Day and Night, перекрывающие окно записи блоба драйвера [t − us, t] (метод `savewin_f27a.py`), на FS10 `abfded5e` при умолчаниях (`KYTY_S_PCW=1`) — против контроля `KYTY_S_PCW=0` той же формы. Единица — число таких кадров на сохранение; вывод — да/нет по правилу ниже.

**Как дать холодный по пайплайнам вход без порчи кэшей пользователя** [c кода, I поведения — проверяется членами P3–P5]:

- `KYTY_PIPELINE_PRECACHE=0` — нет стартового precache и записи рецептов: `RecordGraphicsRecipe` выходит сразу (`dc5d4712:src/graphics/host_gpu/renderer/pipeline/pipelineCache.cpp:6204` «const char* value = std::getenv("KYTY_PIPELINE_PRECACHE");», +1 «return value == nullptr || value[0] != '0';»; `…:6212` «void PipelineCache::RecordGraphicsRecipe(const GraphicsPipelineKey&   key,», +1 «const ShaderVertexInputInfo& vs_input_info,») ⇒ все пайплайны уровня создаются в игре, `pipelines.bin` пользователя не пишется.
- `KYTY_PIPELINE_SALT=f27_<тег>` — блоб драйвера — отдельный файл `_PipelineCache/PPSA21564.<xxh3>.bin` (`…:4883` «m_driver_cache_path = std::filesystem::path("_PipelineCache") /», +1 «fmt::format("{}.{:016x}.bin", title_id, XXH3_64bits(salt, std::strlen(salt)));»), модули солятся ⇒ драйвер компилирует заново; блоб пользователя `PPSA21564.bin` не открывается.
- Сила: свежий солёный блоб мал (в папке лежат прошлые солёные файлы по 21,2–21,6 МБ) — запись ≈ 20 мс, порога 100 мс не достигнет и при `KYTY_S_PCW=0`. Поэтому перед тегом — копия блоба пользователя (`PPSA21564.bin`, 127 690 373 байта, sha256 `8981ffb7…`) под солёным именем; после тега солёный файл переносится в папку прогона.
- `KYTY_CACHE_MODE=prepare-cold` не годится: он ставит `KYTY_PIPELINE_CACHE=0` (`dc5d4712:src/emulator.cpp:210` «SetCacheTestEnvironment("KYTY_PIPELINE_CACHE", "0");», +1 «if (selected == "cold") {») — кэша драйвера и сохранений нет, проверять нечего (так шли `u_09` S13/S15).
- Снимок: до каждого тега — манифест sha256 (форма `cachemf146.py`) `_ShaderCache/PPSA21564/**`, `_PipelineCache/PPSA21564.bin`, `_ShaderSeeds/PPSA21564/**` и копия этих каталогов в папку прогона; после — сверка; расхождение ⇒ возврат из копии с проверкой sha и тег — помеха. Дисковый кэш шейдеров драйвера NVIDIA получает солёные записи и может вытеснить записи пользователя [I]; снимок его каталога (практика S2, `snap0_drv`) — решение лида и Harness Engineer.

**Форма тега** — форма `fs10_v` (V, `KYTY_FRAME_TRACE=lite`, `KYTY_REC`, `-lvl rotating_level_day_and_night`) + два ключа выше; удержание 120 с от `stable` (сохранения на удержании у Day and Night в истории — на 25–35 с после `stable`; при `PRECACHE=0` создания идут всё удержание). Плечи: `f27_v0` — `KYTY_S_PCW=0` (положительный контроль формы), затем `f27_v1a`, `f27_v1b` — умолчание.

**Члены силы (каждый тег):** (P1) ≥ 1 строка `Vulkan pipeline cache: saved` с окном записи на удержании и размером ≥ 80 000 000 байт; (P2) строка `S-pcw: KYTY_S_PCW=<плечо>`; (P3) строка `Pipeline cold-test namespace: f27_<тег>` и `Vulkan pipeline cache: loaded <N> bytes from _PipelineCache\PPSA21564.<h>.bin` с N = размеру копии; (P4) нет `PipelinePrecache: saved` (рецепты не писались; ожидание по коду [I], при нарушении решает P5); (P5) манифесты кэшей пользователя до и после равны. Нет P1 ⇒ тег `NO_POWER`; нет P5 ⇒ помеха.

**Чтение (предложение лиду, решение — F27b):** контроль `f27_v0` обязан дать ≥ 1 кадр ≥ 100 мс на окне записи (иначе форма без силы ⇒ «держится» — «не определено», [I]); `f27_v1a` и `f27_v1b` с P1 и 0 кадров ≥ 100 мс на окнах записи ⇒ «Б33 держится на FS10 на Day and Night» (N = 2 сохранения — критерий строки Б33); ≥ 1 такой кадр ⇒ остановка, «не держится», атрибуция — новым пунктом по записанному логу.

**P(0) контроля до данных** [I]: на пути под `m_mutex` кадр ≥ 100 мс у 6 из 7 сохранений блоба ≥ 80 МБ (5 из 6 на `9235a7ac`, реестр строка Б33; 1 из 1 `ednn122`); блоб копии 127,7 МБ длиннее (запись ≈ 130–160 мс по `s18_c09`) ⇒ P(нет кадра | 1 сохранение) ≲ 1/7 ≈ 0,14 > 0,1.
