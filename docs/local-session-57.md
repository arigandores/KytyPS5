# Сессия 57 — трек A, окно write-fault'а, измерения E1/E2/E8/E9

База: `merge-upstream`, HEAD сессии 56 — `b9fc0d9`. Промежуточный WIP-коммит `0429068`, итоговый
коммит — см. HANDOFF. Push нет.

## 1. Главный результат

**Окно write-fault'а 64 КиБ (A3, ручка `faultkb`, теперь по умолчанию 64) — крупнейший выигрыш сессии.**
Гость пишет большие буферы постранично, и каждая страница давала отдельный fault с `VirtualProtect`,
ожиданием `ApplyGuard` и инвалидацией. Один fault теперь открывает выровненное окно (прогон обрывается
на GPU-грязных страницах, кэш текстур по-прежнему видит один байт).

Sky Garden, два свипа с пользователем (`sky1`, `sky2`), фазы по 600 present:

| | база | окно 64 КиБ | всё включено |
|---|---:|---:|---:|
| FPS, `sky1` (вся фаза) | 22,4–23,5 | **25,9** | **26,8–27,6** |
| CPU потока GuestGpu, мс (медиана) | 46,8–48,4 | 34,1 | 33,1–33,2 |
| CPU на draw в одной полосе draw, `sky1` | 8,0–8,3 (4300–4700) | 7,23 (−11 %) | 7,04–7,07 (−12…13 %) |
| CPU на draw, `sky2`, полоса 4700–5100 | 9,25–9,59 | 8,61 (−9 %) | 7,91–8,10 (−15…17 %) |
| write-fault'ов на кадр | 8,2–8,4 тыс. | 1,25 тыс. | 1,27 тыс. |
| время fault'ов, все потоки, мс/кадр | 73–78 | 13,8–15,9 | 12,6–16,0 |
| ожидание `ApplyGuard`, все потоки, мс/кадр | 59–61 | 8,2–10,9 | 7,1–11,0 |
| ожидание `ApplyGuard` на GuestGpu, мкс/кадр | 2 200–2 800 | 38–134 | 17–119 |

`sky2` целиком медленнее `sky1` (базы 9,2–9,5 против 8,4–8,9 мкс/draw при тех же draw) — сравнивать
только внутри свипа.

**Размер окна (`sky2`, против средних соседних баз, две полосы draw):** 16 КиБ — в шуме; **64 КиБ −9 / −8 %;
256 КиБ −9 / −8,5 %** (fault'ов 394, время fault'ов 7,6 мс); 1024 КиБ −7,4 % (заливки 48,6 МБ/кадр против
20,3); **4096 КиБ — выигрыша нет** (заливки 132 МБ/кадр, `prot_gpu_us` 4,9 мс). Умолчание 64 — измерено в
двух свипах и провалидировано; 256 — равный кандидат по одному свипу.

**Наблюдение, которое надо знать при замерах:** при FPS выше ~25 игра меняет рисунок нагрузки по кадрам
(цикл 2 кадра → 3 кадра, медиана draw 5300 → 4700, p90 5900 → 6400). Кадры видео одинаковы. Поэтому
полосу draw для сравнения таких фаз брать несколько и смотреть по каждой.

## 2. Трек A — что сделано и что измерено

| A6 | `TouchImage` не пишет равные значения | без гейта | — | — |
| A7 | `TouchBuffer` пропускает `Touch` в том же GC-тике | `buflru` = **1** | в составе B | — |

**Разбор `EndRecord` (A4):** 79 % его семплов — одна инструкция, `xchg` при `m_head.store(seq_cst)` на
линии, которую непрерывно опрашивает спинящий поток записи. Мьютекс на горячем пути не брался вообще.
После правок `EndRecord` в профиле 4,8 → 1,8 %.

**Почему A1 закрыт:** `stk_flt_same` = 3 370 из 8 277 fault'ов — это повторные fault'ы той же страницы в
том же кадре (две записи гостя подряд до снятия защиты / несколько потоков), а не страницы, которые
перевзводятся после заливки: `stk_arm_hot` = 164 из 4 978 перевзводов. Эти fault'ы и снимает A3.

## 5. Вылет при входе в Sky Garden — не регрессия

Второй свип дважды падал `ErrorDeviceLost` сразу после загрузки `underwater_aerial_garden`. Бинарь
сессии 56 (собран из `b9fc0d9`) упал точно так же. С момента удачного `sky1` на диске изменились только
`_PipelineCache/PPSA21564.bin` (кэш пайплайнов драйвера, 64 МБ) и `pipelines.bin`; сейвы — нет. **С
`KYTY_PIPELINE_CACHE=0` вход прошёл.** Файл перенесён в `C:/kyty/s57/bad_pipeline_cache/`; игра создаёт
кэш заново. Запись файла атомарна и с хэшем, то есть содержимое — это то, что отдал драйвер. Если вход
снова начнёт падать — первым делом `KYTY_PIPELINE_CACHE=0`.

## 6. Проверки

- **Vulkan + sync-валидация** на пустыне со всеми новыми гейтами и самопроверками (`pbcheck`, `sfcheck`,
  `texfastcheck`, `smemocheck`, `KYTY_RECORD_CHECK=1`, `drawstat`, `stkstat`), четыре конфигурации
  (`faultkb` 64 / 4096 / 4 / 16, переключение `applyskip`/`recbatch`/`recrelax` на лету): **0 ошибок,
  0 sync hazards**, `pb_bad`/`pb_bad_rw`/`sf_bad`/`tf_bad`/`texfast_bad`/`pb_stuck`/`pb_inflight_bad` = 0
  на 1,8 млн проб `pbcheck`; 10 известных предупреждений `out_mrt_1`.
- **Видео:** `rec_f1.mp4` 15 621, `rec_val.mp4` 11 225, `rec_sky1.mp4` 30 560 кадров — **0 однокадровых
  глитчей**; `rec_sky2.mp4` — один кандидат (present 33 980), это переход сцены при перелёте корабля до
  начала фаз, как в сессии 56.
- **Ревью** пятью агентами (A2+A3, A4, B, E1+A5+A6/A7, A1): **дефектов корректности не найдено**.
  Доработки по ревью: `pbcheck` проверяет саму сбойную страницу; окно не ждёт чужих чтений импорта
  (`HasPendingHostReads`); `armed` считается только под трассировкой; `Region::inflight` → `applying_run`;
  IPI `FlushProcessWriteBuffers` только после первого relaxed-store и только у рекордера GuestGpu, вне
  мьютекса; проверка потока-производителя в `PublishStaged`; серии E1 рвутся жёсткой работой между
  draw'ами (`dp_between_hard`), метки смены типа DCC/CMASK, барьер долга прохода — граница E2, таблица
  E9 16 384; «горячая» страница A1 — только при реальном fault'е, счётчики A1 только под трассировкой.
- **Тесты:** `bit_array`, `memory_tracker`, `virtual_memory_allocation`, `resource_materialization`,
  `image_page_table` проходят; `resource_tracking_tests` падает как прежде («SRT runtime: runtime
  evaluation failure was not transactional»).
- **Контроль умолчаний (`fin`, пустыня):** новые умолчания против старых −3,3 % CPU на draw, fault'ов
  716 → 104, без сбоев.
