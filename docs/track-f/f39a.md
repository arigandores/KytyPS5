## 0. Механизм [c кода FS12 `730ed40a` и исходника SDL2 `4b69833b`] — раздел до выводов (коммит раньше описи логов §3)

### 0.1 Что главный поток исполняет под замком джойстиков SDL и что там ждёт ОС

**(а) Насос событий.** Главный цикл (`730ed40a:src/graphics/presentation/window/window.cpp:882` `DrainMainThreadTasks()`, `:891` `HostInputWaitEvent`, `:894` `ProcessEvent`) ждёт событие в `SDL_WaitEvent` / `SDL_WaitEventTimeout` (`730ed40a:src/graphics/presentation/window/hostInput.cpp:424`, `:432`). Каждое пробуждение качает видео (`4b69833b:src/events/SDL_events.c:917` `_this->PumpEvents`) и, пока флаг `SDL_update_joysticks` поднят (`4b69833b:src/events/SDL_events.c:99`, умолчание — да; флаг читается из подсказки `SDL_HINT_AUTO_UPDATE_JOYSTICKS`, `4b69833b:src/events/SDL_events.c:1326`), зовёт `SDL_JoystickUpdate()` (`4b69833b:src/events/SDL_events.c:922`, `:923`). `SDL_JoystickUpdate` (`4b69833b:src/joystick/SDL_joystick.c:2167`) берёт замок джойстиков (`:2177`) и под ним исполняет `HIDAPI_UpdateDevices()` (`:2185`), `Update` каждого открытого джойстика (`:2193`) и `Detect()` каждого драйвера (`:2225`); замок отпускается в `:2228`. Вызовы ОС под этим замком без предела времени — таблица F19a §1.3 (тот же коммит SDL): перечисление HID (открытие каждого интерфейса и синхронные запросы строк), удаление устройства HIDAPI — ожидание отменённого чтения (`4b69833b:src/hidapi/windows/hid.c:978` `GetOverlappedResult(…, TRUE/*wait*/)`) и очереди вибрации (`4b69833b:src/joystick/hidapi/SDL_hidapijoystick.c:998`), открытие нового устройства HIDAPI с чтением описателей, перечисление DirectInput (`4b69833b:src/joystick/windows/SDL_windowsjoystick.c:548` → `4b69833b:src/joystick/windows/SDL_dinputjoystick.c:555` `IDirectInput8_EnumDevices`; сам SDL пишет, что «`IDirectInput8_Initialize` / `_EnumDevices` can take a minute even with no controllers» — `4b69833b:src/joystick/windows/SDL_dinputjoystick.c:404`) и XInput (`4b69833b:src/joystick/windows/SDL_windowsjoystick.c:551`).

**(б) Вызовы эмулятора на главном потоке.** Событие добавления (`730ed40a:src/graphics/presentation/window/window.cpp:384` `SDL_GameControllerOpen`, `:389` включение датчиков, `:399` `Controller::Connect`, который при `KYTY_FIX_B24=1` читает тип пульта `SDL_GameControllerFromInstanceID` — `730ed40a:src/libs/controller.cpp:882`, до `m_mutex` — `:885`); событие удаления (`730ed40a:src/graphics/presentation/window/window.cpp:405` строка `Controller <id>: removed` — печатается всегда, `:407` `Controller::Disconnect` — без SDL, `:408` `SDL_GameControllerClose(SDL_GameControllerFromInstanceID(id))`). Обе функции SDL берут тот же замок (`4b69833b:src/joystick/SDL_gamecontroller.c:2853`, `:3034`), закрытие доходит до `Close` драйвера (`4b69833b:src/joystick/SDL_joystick.c:1601`). Тот же обработчик исполняется и на экране подготовки (`730ed40a:src/graphics/presentation/window/window.cpp:1021`, `:1034`).

**(в) Выход.** `WindowShutdown` → `Controller::EmergencyShutdown` (`730ed40a:src/graphics/presentation/window/window.cpp:1066`): поток `PadOutput` останавливается (`730ed40a:src/libs/controller.cpp:869`), затем `ReleaseHostPads` (`:872`) держит `m_mutex` (`:1153`) через вызовы SDL, паузу (`:1176`) и закрытие пультов (`:1178`).

**(г) Стенд.** Режим `hold` держит замок на главном потоке (`730ed40a:src/graphics/presentation/window/window.cpp:1199`…`:1201`) — модель «замок занят», не модель «вызов ОС внутри `SDL_JoystickUpdate`» (RC15 F32b: контроль пути, не причины).

### 0.2 Договор SDL2 о потоках [c заголовков и исходника]

1. **Насос видео — только на потоке, который инициализировал видео:** «**WARNING**: This should only be run in the thread that initialized the video subsystem» (`4b69833b:include/SDL_events.h:716`). Перенести `SDL_PumpEvents` / `SDL_WaitEvent` с главного потока нельзя — это и окно, и клавиатура, и мышь (`4b69833b:src/video/windows/SDL_windowsevents.c:1953` — `PeekMessage(&msg, NULL, …)` всех окон потока).
2. **Обновление джойстиков отделяется от насоса договором:** подсказка `SDL_HINT_AUTO_UPDATE_JOYSTICKS` — «"0": You'll call SDL_JoystickUpdate() manually» (`4b69833b:include/SDL_hints.h:327`), «can be toggled on and off at runtime» (`:332`). При `0` насос не зовёт `SDL_JoystickUpdate` (`4b69833b:src/events/SDL_events.c:922`) и не трогает замок ради интервала опроса: условие `SDL_WasInit(SDL_INIT_JOYSTICK) && SDL_update_joysticks` (`:967`) стоит раньше `SDL_NumJoysticks()` (`:968`), а та берёт замок (`4b69833b:src/joystick/SDL_joystick.c:666`). Поток вызова `SDL_JoystickUpdate` документ не ограничивает (`4b69833b:include/SDL_joystick.h:792`).
3. **Многопоточный доступ к API джойстиков разрешён замком:** «Locking for multi-threaded access to the joystick API … If you are using the joystick API or handling events from multiple threads you should use these locking functions» (`4b69833b:include/SDL_joystick.h:132`, `:134`); под замком «joystick and game controller events will not be delivered» (`:139`). Каждая функция джойстиков / пультов берёт этот замок сама (`4b69833b:src/joystick/SDL_joystick.c:2177`, `4b69833b:src/joystick/SDL_gamecontroller.c:2853`, `:3034`) — поток `PadOutput` (F19c) уже зовёт SDL не с главного потока (`730ed40a:src/libs/controller.cpp:346`).
4. **События, поставленные другим потоком, будят ждущий насос:** постановка события зовёт `SDL_SendWakeupEvent` (`4b69833b:src/events/SDL_events.c:846`), который в Windows — `PostMessage` окну (`4b69833b:src/video/windows/SDL_windowsevents.c:1939`), а ожидание — `MsgWaitForMultipleObjects(…, QS_ALLINPUT)` (`:1895`).

**Привязки к потоку в Windows-пути джойстиков (проверено по каждому драйверу, который включён по умолчанию):**

| Что | Где создаётся / кто доставляет | Привязка к потоку `SDL_JoystickUpdate` |
|---|---|---|
| Окно обнаружения HIDAPI | создаётся при первом `SDL_hid_device_change_count` — в `HIDAPI_JoystickInit` на потоке инициализации (`4b69833b:src/hidapi/SDL_hidapi.c:240`); сообщения раздаёт обычный насос (`:379` — разбор внутри обновления выключен `#if 0` «just let the usual SDL_PumpEvents loop dispatch these», комментарий `:380` «We'll only get messages on the same thread that created the window») | **нет**: оконная процедура поднимает глобальный счётчик (`:158`), обновление на любом потоке читает его (`:1226`, `:1235`). **Поправка к F19a §1.4 / §5.2:** ссылка `SDL_hidapi.c:381` стоит внутри `#if 0`; окно привязано к потоку создания только доставкой сообщений, а их раздаёт насос главного потока — при любом потоке обновления |

**Вывод §0.2:** договор SDL2 **не требует**, чтобы блокирующие пути шли на потоке событий: обновление джойстиков (HIDAPI, перечисление, закрытие — всё внутри `SDL_JoystickUpdate` и `SDL_GameControllerClose`) можно вести с отдельного потока при `SDL_HINT_AUTO_UPDATE_JOYSTICKS=0` [c заголовков]; на главном потоке остаётся только насос видео. Единственная привязка, которую исходник SDL не снимает, — COM-квартира объекта DirectInput [I].
