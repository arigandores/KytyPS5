## 1. Требуемые изменения

**RC1 (MAJOR) — защёлка «последнего опубликованного слова» систематически теряет вблэнки хитчей.** Проект: на M0 пишется k последнего
учтённого флипа (`c3036573:docs/track-p/p12-pvar.md:234`, якорь «Запись — в этом вызове, ДО перевода фазы в 1; значение — последнее
опубликованное слово.»; +1 — 235), и «в сумме потерь нет» (`:241`, якорь «**Задержка k:**»; +1 — 242 «k шаг не равен интервалу показа»).
**Сценарий отказа [c-form по коду `PresentThread`/`Flip`, `4fc501f4:src/graphics/presentation/videoOut.cpp:842`, якорь «bool presented =
m_flip_queue.Flip(0);»; +1 — 843 «if (!presented && m_presenter.NeedsSystemOverlayRefresh()) {»]:** кадр N тяжёлый на GPU — флип N приходит через 3+ тика (kraw = 3…12); за это время главный поток, идущий
на 2–3 кадра впереди показа (задержка §4), проходит M0 кадров N+1, N+2 со старым словом (`pvar_dup`, шаг повторён); затем очередь
выдаёт флипы N+1, N+2 подряд, по одному на тик (kraw = 1, 1), и к следующему M0 опубликовано уже слово флипа N+2: **kraw = 3…12 флипа N не
доходит до игры ни разу** (`pvar_skip`), а вместо него дважды взят прежний k ≈ 2. Потеря — ровно в кадрах ≥ 3 вблэнков, то есть механизм
RC10 / п. 276(г)(2), который P-var снимает «по построению», возвращается через защёлку; dup и skip не «блуждают без смещения»
(`:377`, якорь «При записи по значению 1 и в обоих режимах при `pvar_dup`/`pvar_skip` ≠ 0»; +1 — 378): skip выбрасывает именно
раннее (длинное) значение. Оценка [I]: при 4–5 % хитчей Sky Garden и потере ≈ 1 вблэнк на хитч — недогон 2–3 %; гейт (ж)(3) [0,95; 1,05] это
пропускает, `SPEED_OK` по (ж)(1) — тоже (RC2), а лист покажет рывок героя после хитча. **Изменить:** (а) вариант исполнителя [вопрос лиду —
буква п. 276(е)(1) «между двумя предыдущими флипами»]: k = clamp(`vblank_status.count` сейчас − его значение на прошлом M0, 1, 3) — длительность
кадра главного потока в тиках; dup/skip исчезают, задержка 1 кадр вместо 2–3, сумма точна до клампа; (б) вариант в букве: k = clamp(`vb`
опубликованного слова − `vb` слова прошлой защёлки, 1, 3) — сумма kraw **всех** флипов с прошлой защёлки (поле `vb` в слове уже есть, биты
16–39); `vb` не изменился — k = 1 и `pvar_dup` + 1; (в) в любом варианте P15 печатает **сохранение C = Σ `pvar_k` / Σ `pvar_kraw` удержания**
(счётчики, а не строки — строки skip не видят) и долю kraw ≥ 3 среди пропущенных флипов против доли среди всех; §3.4 и §4 проекта поправить
(«в сумме потерь нет» — только при `pvar_skip` = 0). Если не внести: недогон на хитчах читается как «P-var жив, но медленный» — ложный ход к
итерации 2 или ложный `SPEED_OK` вместе с RC2.

**RC2 (MAJOR) — `SPEED_OK` по п. 283(в)(3) почти круговой: правило целостности пары меряет тем же числом, что и скорость.** Пара цела, если
Σ k/60 строк `PVar:` между `Play` и `Finished` = D(X) ± (2 % + 3/60 с) (`d1a1b49f:docs/ROADMAP.md:14822`, якорь «(3) [В 3] — принято для
`qv_`»; +1 — 14823). Но Σ k/60 — счёт эмулятора, который по построению ≈ стене (k — тики того же генератора, что и `dt_us`, с точностью до C
из RC1). Для прошедших пар стена ≈ Σ k/60 / C ≈ D / C, скорость = Σ D / Σ стены ≈ C ∈ [0,97; 1,0] — **почти независимо от игры**. **Сценарий
ложного `SPEED_OK`:** часть имён часов шагает не по ячейкам (таймер на счётчике кадров — класс RC5 P1; в коде есть счётчики кадров
`[obj+0x58]` `0x2a3626` и `[obj+0x1e4]` `0x2a3520`, мигание `0x2a8633` = кадры·π/60 — [c-form]; или собственная копия 1/60): у них при 30 FPS
Σ k/60 ≈ 2·D → пара «не цела» и **выбрасывается**; остаются только имена, шагающие по ячейкам, — скорость ≈ 1,0 в двух из двух, хотя
половина анимаций идёт вдвое медленнее. Признак r̂ (`:14821`, якорь «**r̂ = 1 / (среднее k строк `PVar: n=` удержания `qv_i`)**»; +1 — 14822)
на отфильтрованных парах тоже выполняется по построению (кадров пары ≈ D·60 / k̄). **Изменить [константы — лида]:** (а) целостность пары — по
признаку, не зависящему от k: порядок `Play`/`Finished` того же экземпляра и число кадров пары в [D·60/3 − 1; D·60 + 1] (кламп k ≤ 3), а Σ k/60 —
печать рядом; (б) доля целых пар по каждому имени в `qv_i` против `qa_A` — гейт: имя, у которого в `qa_A` пар ≥ 5 и в `qv_i` доля целых ниже
доли `qa_A` больше чем на 20 п. п., — «не определено» для `SPEED_OK` (вариант исполнителя); (в) таблица скорости по имени (стена против D по
каждому имени), признак r̂ — на всех парах до фильтра. Если не внести: `SPEED_OK` 2 из 2 возможен при игре, где значимая часть систем
шагает не по P-var, — ложное «ИСПРАВЛЕНО» по п. 226(г)(1).

**RC3 (MAJOR) — гейт (ж)(3) «Σ s / Σ `dt` ∈ [0,95; 1,05]» — самопроверка счёта, игру не видит; нужны жёсткие нули.** T6

идёт). **Сценарий ложного прохода:** игра перезаписывает ячейки своим значением на каждом кадре (второй писатель
шага, не найденный реверсом; или `SetFrameRate` из другого пути) — строки `PVar:` и T6 = 1,00 те же, уровень «самосогласован», а шагает игра
по 1/60. Проект ловит это `pvar_foreign`, но называет нули «обязаны быть 0» (`:305`, якорь «**Обязаны быть 0:**»; +1 — 306), а в гейтах п.
276(ж) и п. 283 их нет. **Изменить [лиду]:** в печать P15 — **гейт целостности каждого тега с ручкой**: строка `PVar: armed` с ячейками образа,
`lim` и `hav` = байтам п. 283(в)(6); на удержании `pvar_foreign` = `pvar_bad` = `pvar_k0` = 0; `pvar_inupd` = `pvar_tear` = `pvar_tail` = 0; иначе
тег — «не определено», а не данные гейтов (ж)(1)–(3). В отчёте P18 (ж)(3) называть «самосогласие счёта эмулятора», не «скорость уровня»;
скорость игры на уровнях без ≥ 3 имён часов — «не доказано». Если не внести: (ж)(3) уровней проходит при любой игре, и (г)(3) п. 226
засчитывается без единого игрового свидетельства.

**RC4 (MINOR) — ХРАПОВИК: после развязки остаётся читатель шага в работе, растущей с k, а детектор (ж)(2) — одна выборка без положительного
контроля механизма.** (1) Бюджет `0xd254b3` (`LevelContext.cpp`, 13 вызывающих) = `1400 − 1300·min(1, X_мс / шаг_мс)` [c, `out/dis_d25470.txt`]:

кадра (подгрузка, LOD), он растёт с k и удлиняет следующие кадры: обратная связь k → время кадра → k, то есть храповик без ограничителя [I];
сон длиной в шаг `0x103e92e`/`0x103e9fb` (циклы ожидания) — то же, если ожидание стоит в пути кадра [U; прямых вызывающих `0x103e680` нет —
косвенный вызов]. (2) Детектор — доля кадров ≥ 3 вблэнков `qv_i` против **одного** `qa_A` + 5 п. п. (`d1a1b49f:docs/ROADMAP.md:14473`, якорь

конфигурации C — 6,02 и 15,56 % (P12 §4). **Сценарии:** `qa_A` выпал на 11,7 % — порог 16,7 %, храповик в 4–8 п. п. не виден (ложное «нет»);
`qa_A` 3,6 %, `qv_i` без храповика 9 % — ложный ХРАПОВИК. Положительного контроля нет: вооружение без развязки отказывает (п. 283(в)(7)), а
пересчёт порога на `pr_C` против `pa_A` (15,56 против 3,98) проверяет только арифметику — тавтология. **Изменить:** P15 печатает (не гейт) тест
механизма, не зависящий от уровня доли: Δ_L = P(бин кадра n+L ≥ 3 при k защёлки кадра n = 3) − P(бин n+L ≥ 3 при k ≤ 2) для L = 1…4 в `qv_i`
против той же условной вероятности на бинах `qa_A` со сдвигом, равным задержке k (P12 §3.4) — храповик = избыток Δ_L над `qa_A`; плюс доля
≥ 3 вблэнков по отрезкам 60 с (тренд внутри тега). Решение по расхождению `qv_1`/`qv_2` (один ХРАПОВИК из двух) — лиду; вариант
исполнителя — «не определено», а не дефект. Если не внести: исход (ж)(2) — жребий выборки `qa_A` (P12 сам даёт P(ложный) ≈ 0,1–0,2).

различаются только `KYTY_PVAR`. Либо оставить букву и записать «правки при ручке 0 не измерены» в «не доказывает».

**RC6 (MINOR) — источник k: тики не равны интервалу показа, а пауза гостя не считается.** `dt_us` строки `FrameTrace` — разность моментов
снимка после `Present()` (снимок `cur.host_ns` в `FlipQueue::Flip`), а kraw — число тиков петли, которая догоняет пропущенные тики без
сна: после задержки Present несколько тиков идут подряд, и флип, вышедший на первом из них, получает kraw больше, чем его стена, а следующий —
меньше. Сумма kraw = тики стены [c-form], но по кадру kraw ≠ бин `dt` (T7 у P12 — [I], проекция §4 построена на бинах `dt`, а не на kraw).
Ветка `IsGuestPaused` (`PresentThread`, до `VblankBegin()`) тиков не считает, а `dt` следующей строки содержит паузу. **Сценарий:** окно
удержания с паузой гостя (оверлей, сворачивание — ср. Б37) — T6 уходит вниз и читается как НЕДОГОН записи. **Изменить:** P15 печатает T7 (доля
kraw = бин) как меру, а не допущение; строки `FrameTrace` с `dt_us` > 1 с и их соседей исключать из T6 и печатать их число; в §3.2 проекта
«Σ `kraw` = вблэнки стены» уточнить: «вне пауз гостя».

(double, float, u64, float, float, float), набор не атомарен. Поток рендера рисует кадр N параллельно M0 кадра N+1 (рукопожатие
`[obj+0x168]`, P12 §3.1), задания хвоста кадра N могут идти после M0 [U]. **Сценарий:** на кадре смены k задача, читающая `0x3530` (double) и
