## 3. RC и RC-M

**RC-T306-1 (тема T306; код теста, не код темы).** Сторож правильности T306 — равенство маски записи смещения маске выборки
(`MResolveSampleOffset`: `write->Arg(0).Resolve() == exec`) — не проверен ни одним тестом: мой мутант `t306_mask` (условие снято — смещение,
записанное под ЛЮБОЙ маской, принимается как константа) проходит GPU-кейсы T306 и `shader_cfg_tests` (`mut.out.txt`). **Сценарий отказа:** программа
пишет VGPR смещения под частичной маской (`s_and_saveexec_b64` → `v_mov_b32 v0, 0x0101` → возврат `exec`), затем `image_sample_lz_o` под полной
маской; дорожки вне маски записи держат прежнее смещение. Правильный код идёт прежним путём со строкой `MTexOffset:`; код с потерянным сторожем
(правка, рефакторинг, перенос волны 2) даёт `ConstOffset` (1, 1) всем дорожкам — неверные тексели на дорожках со старым смещением, и тесты это
пропустят. **Изменить:** тест (форма `shader_cfg_tests` — в SPIR-V нет `ConstOffset`, есть строка/признак прежнего пути; или GPU-кейс с двумя группами
дорожек), на котором мутант `t306_mask` (`C:/kyty/m657/m2c/mut_m2c.py`) ловится; повтор `run_mut_m2c.py` для T306 — `CAUGHT`.

**RC-T032-1 (тема T032; только текст отчёта/пункта).** Решение исполнителя «не упакованные форматы пишут только переданные компоненты» **принимаю**:
описание ISA (`…_FORMAT_X` — «into 1-component formatted data», `_XY` — 2-component …) [c XML] читается в пользу записи переданных компонент;
комментарий upstream `81f31263` «RDNA2 formatted stores transfer the entire format, zero-filling missing VGPRs» описанием не подтверждён [I]; в игре
функционального отличия нет (п. 758(д)). Но отчёт M2a неполон и в одном месте неверен: (а) отличие от upstream двойное — кроме дозаливки нулями,
`81f31263` проверяет границы по **всей записи формата** (`PrepareFormattedMemory(…, info.component_count, …)`, переименовал наши кейсы
`BufferStoreFormatX[y]ChecksOnlyTransferredComponent[s]` в `…RejectsPartialRecord` с `expected = initial`), а M2a проверяет границы по переданным
компонентам (как FS15) — этого в §2 нет; (б) таблица §0 «23 формы upstream `de9c15fa` … — EQUAL» скрывает, что у 4 форм (8 кейсов
`MW1T032*Partial*`) эталон заменён нашим правилом (upstream `BufferStoreSnorm8ZeroFillX` ждёт `0x00000081`, наш `MW1T032Snorm8PartialX` — `0xffffff81`).
**Сценарий отказа:** читатель M3/M4 или волны 2 считает T032 = upstream и (i) переносит остаток `81f31263` поверх, ломая 8 кейсов без понимания
причины, или (ii) при свидетельстве игры о дозаливке нулями/отбрасывании частичной записи ищет причину не там. **Изменить:** строка-поправка
(отчёт M2a или пункт лида): обе части отличия названы, 8 кейсов `…Partial…` — «эталон = наше правило по описанию ISA, не upstream», переоткрытие —
свидетельство железа/игры о дозаливке или о границах по записи. Кода правка не требует.

**RC-M1 (правилу печати M3a и отката M4; не теме, M2d не блокирует).** При всех `KYTY_M_*=0` бинарь с кодом M2a пишет в **тот же каталог**, что
FS15 (`variant_fixb26_fixb1b_fixf10_fixf19`), с **другой подписью** (`aac6db69…` против `9177b426…`); файл с чужой подписью кэш отвергает и
перезаписывает (`shaderTranslationCache.cpp` — сравнение `m_signature` при чтении, запись поверх) [c кода]. **Сценарий отказа:** (а) любое плечо M3
или проверка M2d бинарём `main`/MS1 со всеми ручками `=0` на кэшах пользователя (или откат M4 «ручки `KYTY_M_*=0`») перетрансляет и перезаписывает

**Изменить (печать M3a / текст M4):** прогоны бинаря с кодом M2a при всех `KYTY_M_*=0` — только на копии `_ShaderCache` с возвратом по манифесту,

  `address` обновляется при каждом растре); `assign` перевыделяет только при росте; гость, сохранивший само значение `address` между вызовами, читал бы
  освобождённую память — как у upstream [I], свидетельства нет (Н4). Копирование в поверхность гостя обрезано шириной/высотой поверхности и

- **T231, независимость эталона стенда** — эталон = алгоритм upstream на том же stb_truetype; он доказывает «`=1` = алгоритм upstream», не консоль [I];
  мутанты исполнителя и мой `t231_lim` его различают.
- **T265, ID не переиспользуются, `ENFILE`** — принято: счётчик только растёт под `g_mutex`, не сбрасывается; 0 не выдаётся; `ENFILE` при
  `0xffffffff` (недостижимо практически) записывается в кэш пути [c]; повторное разрешение отдаёт сохранённый ID без новой регистрации [c, стенд].
- **Две строки версии в бинаре M2b** — [U], к ревью кода не относится.
