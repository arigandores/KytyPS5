## 1. Что меряется и каким числом выражается вывод

**Вопрос:** из чего состоит время потока GuestGpu вне render mutex на опоре (плечо 0 `kp137`, NEW) — остаток
`pl_proc − a_hold − a_wait − именованные` 2 261,6 мкс/кадр [c-арифм., с инструментом; п. 210(в)(1)] — и есть ли в нём группа опкодов
PM4 с уровнем ≥ 400 мкс/кадр.

**Число вывода — уровень группы g в прогоне k (мкс/кадр):**

    L_g,k = mean_r∈W_k [ Σ_{s∈g} raw*_s,r  −  ĉ_k · Σ_{s∈g} n_s,r / 1000  −  A_g,r ]

- `raw*_s,r` = мкс площадки s в строке r (целое, `dn / 1000u` — усечение на каждом флипе, `videoOut.cpp:3492`) **+ 0,5 мкс**, если
  s напечатана в строке r (поправка среднего усечения, [I] при равномерной дробной части; [В5]);
- `n_s,r` = число исполнений обработчика (`dc`, `videoOut.cpp:3490`); пакет, приостановленный `SuspendPm4` и исполненный повторно,
  считается каждый раз (`graphicsRun.cpp:555`);
- `ĉ_k` — цена отметки внутри интервала на пакет, нс, калибровка §7 в строках того же прогона (п. 210(е)(5)(ii));
- `A_g,r` — вычет по карте для смешанных групп и групп с именованными участками внутри (§6.4); для чистых «вне mutex» `A = 0`;
- `W_k` — окно строк прогона k (§9).

Рядом с каждым `L_g,k` печатаются: `Σ raw*`, `n_g`/кадр, `ĉ_k · n_g / 1000`, `A_g`, `L_g` при ĉ = 22,9 и при ĉ = 0, 2SE по блокам
90 строк (п. 210(е)(5)(iii), RC2 с. 139). **Уровень группы — [c] одного прогона с инструментом (п. 65(в)); не цена и не снимаемое.**

## 3. Как ручка читается

`EnvFlagOn` (`envFlag.h:35`) читается **один раз на процесс** (локальный `static const` при первом входе в цикл). **Не может быть
плечом расписания** — поэтому форма п. 210(е)(4): 4 прогона 0, 1, 1, 0 (порядок гасит линейный дрейф для справки о цене). Значение
«0»/`false`/`off`/`no` и отсутствие переменной — выкл. **[В7]:** в `pm4c140a`/`d` — `KYTY_PM4_TRACE=0` явно, в `b`/`c` — `=1`;
`KYTY_FRAME_TRACE=lite` как в `kp137`; `KYTY_GATE_SCHEDULE` нет (строка ручек плеча 0 `kp137` — в файле гейтов).
При 0 инструмент стоит одну проверку `static const bool` на пакет и ветвь `pm4_trace ? … : 0` — поведение игры и что видит гость не
меняются ни при 0, ни при 1 (только время).

- **Нулевой (N1):** в `pm4c140a`/`d` ни одна строка `FrameTrace-pm4:` не несёт имени `op*`/`nop*` (только `gc`/`prefetch`/

  прогонами нельзя (0 против 0), поэтому «ничего не стоит при 0» — [I] по коду, не [c].
- **Положительный (P1):** в `b`/`c` ≥ 99 % строк окна несут ≥ 1 имя `op*`/`nop*`.
- **Положительный (P2, счёт удержек — точная форма):** каждый пакет из S1 = {`op27`, `op35`, `op3a`, `op2d`, `op24`, `op25`, `op15`,
  `op16`} проходит ровно одну удержку `MutexMark` (в `RenderExecutor::DrawIndex`/`DrawAuto`/`DispatchDirect` нет возврата до замка:
  `renderDraw.cpp:4938–4976`, `:5170–5205`, `renderCompute.cpp:383–417`), `op2c`/`op38` — от 0 до `draw_count` удержек

### 6.2 Смешанные MIX_MM — как отделяется вне-mutex часть

Удержка `MutexMark` — интервал от `lock_t0` до деструктора (`frameStats.h:2965–2981`); `lock_t0` берётся только при `mutsite` или
`amut` (`renderDraw.cpp:4971`) — в строке ручек плеча 0 `mutsite=1`. Интервал целиком внутри вызова обработчика ⇒ внутри площадки.
Поэтому: **вне-mutex часть draw+dispatch** = Σ raw* − ĉ·n − (`a_hold_us` + `a_wait_us`) — **точно** (группа MM_out). Раздельно:
dispatch-удержка = `mh_disp_us` (`HoldLap` внутри `MutexMark`, `renderCompute.cpp:420–`), draw-удержка ≤ `a_hold_us − mh_disp_us`;
`a_wait_us` не делится по видам ⇒ вычитается целиком из каждой (DRAW_out и DISP_out — нижние границы). Вне-mutex часть draw — это
CP-сторона (`graphicsRun.cpp:3011–3026`, `3043–3249`, `3362–3372`: разбор, `CheckBuffer`, чтение аргументов косвенных draw из гостевой
памяти с возможной ошибкой страницы) и пролог `RenderExecutor` до замка (`Rk3Latch`, `RtsLatch`, `PopPendingOperationsLazy`,
`SetDebugInfo`; `renderDraw.cpp:4941–4970`).

### 6.3 Смешанные MIX_PF — «не отделяется»

`nop17` → `CommandProcessor::Flip` (`graphicsRun.cpp:4048`) → `Sync::PrepareVideoOutFlip` (`sync.cpp:228`, при полной очереди флипов —
ожидание `WaitForSubmitSlot` `:244`) → `SubmitFlipFromGpu` (`videoOut.cpp:3840`) → `FlipQueue::Prepare` (`:964`) →
`Presenter::PrepareFrame` (`:1042` → `swapchain.cpp:748`, замок `:759`) — на потоке GuestGpu, внутри площадки `nop17`. Удержка не в
`a_hold_us` (комментарий `swapchain.cpp:752` «the present thread is the only other taker» по коду HEAD неверен для этого пути); она в
`mh_pres_us` вместе с `Present` потока present (`:896`). **Вне-mutex часть флипа не отделяется**; печатается нижняя граница
`FLIP_low = Σ raw* − ĉ·n − mh_pres_us`. У `nop00` плоский NOP и маркеры делят имя — тоже не отделяется. **Следствие для таблицы фаз

## 7. Калибровка ĉ_in [В3]

**Что это.** Площадка пишет `NowNs()_2 − NowNs()_1`; внутри интервала — хвост первого `NowNs` после `rdtsc` (преобразование,
возврат, запись `pm4_t0`), косвенный вызов обработчика, тело, вызов второго `NowNs` до `rdtsc`. Для пустого тела среднее на пакет =
ĉ_in + тело (≥ 0).

**Набор E (O(1) по карте, `E=1` в `opmap140.tsv`):** `op2a`, `op2f`, `op13`, `op26`, `op11` (сравнение + вызов однострочного сеттера
`graphicsRun.cpp:2946–2968`), `op42`, `op58`, `nop14` (сравнение + `RbCen::Reset`: три relaxed-загрузки при `rbcen=1`,
`b2reuse=0`, `bindlean=0`, `frameStats.h:3780–3800`), `op84`, `op85` (+ инкремент). Не в E: `nop00` (маркер флипа), `nop0b`/`nop0c`
(RMW-атомик + лог первых 64/128), всё с циклом, чтением гостя или логом.

**Правило:** для прогона k кандидаты C_k = {s ∈ E : среднее C_s ≥ 1 000/кадр по окну} ∪ {E целиком, если Σ_E C ≥ 1 000/кадр};
`ĉ_s = 1000 · Σ_r raw*_s,r / Σ_r n_s,r` (нс); **ĉ_k = min по C_k**. Каждый кандидат ≥ истинной ĉ_in (тело ≥ 0) ⇒ ĉ_k — верхняя граница
⇒ L_g занижены ⇒ поправка консервативна к `NAMED`. Порог 1 000 — чтобы смещение усечения (≤ 0,5 мкс/строку после поправки, §1)
было ≤ 0,5 нс/пакет. **C_k пуст ⇒ `INSTRUMENT_FAIL` (IF5)** (п. 210(е)(5)(ii) «без калибровки»). **Санитарная полоса [I]:**
ĉ_k ∉ [3, 100] нс ⇒ IF5b (пара `rdtsc` + деление с плавающей точкой не может стоить < 3 нс; > 100 нс — обработчики E не пусты).
**22,9 нс** (`pl_cmd` 600,5 / 26 208 [c], п. 210(в)(2)) печатается рядом с каждым уровнем; по коду это внутриинтервальная цена пары
`PathSpan` c `Add(n,1)` внутри (`frameStats.h:3145–3150`) плюс тело насоса (`graphicsRun.cpp:159–174`) — **не нижняя граница ĉ_in
площадки PM4** (там нет `Add` внутри). Исход читается на ĉ_k; если исход при ĉ = 22,9 другой — строка `ĉ-SENSITIVE` рядом, исход не
меняется.

## 8. Тождества для скорера и допуски [В6]

Средние — по окну W_k (§9) прогона с 1; все в мкс/кадр, кроме оговорённых.

1. **Покрытие времени (с явным членом цены отметок):**

        pl_proc = S_pm4 + (pl_cmd + pl_pref + pl_gc + pl_sub) + prefetch* + stream-prefetch* + K_marks + G_glue − pl_sub_in

   где `S_pm4 = Σ_{op*,nop*} raw*`; `K_marks` = цена отметок ВНЕ интервалов: хвост второго `NowNs` + `Pm4OpName` + `AddSite`
   (линейный поиск ≤ 56 указателей `frameStats.cpp:103–109` и два `fetch_add` `:258–259`) на пакет, плюс внеинтервальные части пары
   `PathSpan` `pl_cmd` на итерацию (RC1–RC2 с. 139); `G_glue` — голова `Process`, проверки цикла, заполнители, снятия буферов;
   `pl_sub_in ≤ pl_sub` — часть `pl_sub` внутри площадок `nop18`/`nop06` (вычтена дважды). `gc` ⊂ `pl_gc` — не добавляется.
   Скорер печатает `I = pl_proc − S_pm4 − (pl_cmd + pl_pref + pl_gc + pl_sub) − prefetch* − stream-prefetch*` и **g = 1000·I / pl_cmd_n
   (нс на итерацию)**. **Допуск: −(1000·pl_sub/pl_cmd_n) − 0,5 ≤ g ≤ 250 нс.** Ожидание [I]: g ≈ 40–130 нс (K ≈ 30–80 нс/пакет по
   коду + склейка ≈ 10–50 нс). Нижний край ловит двойной счёт (вложенность, дубли строк); верхний — только грубую потерю площадок
   (≥ ≈ 3 мс сверх оценки склейки) — честно: слабый край; потерю площадок ловят F и разбор (фикстуры).
2. **Покрытие числа пакетов:** `F = pl_cmd_n − Σ_{op*,nop*} C` = итерации без обработчика (заполнители, снятия, отложенные шаги,
   пропуски по предикату) ≥ 0. **Допуск: −0,005·pl_cmd_n ≤ F ≤ 0,5·pl_cmd_n.**
3. **Вложенность удержки (P3):** `M = Σ_{MIX_MM} raw* − (a_hold_us + a_wait_us)`; **допуск M ≥ −5 мкс.**
4. **Счёт удержек (P2):** `H = a_hold_n − Σ_{S1} C`; **допуск H ≥ −0,005·a_hold_n**; если Σ C(`op2c`,`op38`) = 0 во всех строках окна —
   ещё **|H| ≤ 0,005·a_hold_n**.
5. **Разбиение:** Σ_групп §6.4 Σ raw* = Σ_{op*,nop*} raw* (точно); каждое имя — в одной группе.
6. **Справка, не гейт (п. 210(е)(5)(v)):** цена инструмента `Δdt_us = mean(b,c) − mean(a,d)`, `Δостатка` (формула п. 210(в)(1)) и
   `Δpl_proc / (Σ C)` нс на пакет — [c, между прогонами].

## 10. Условия `INSTRUMENT_FAIL` / `DEBT` и порядок

**DEBT (п. 210(е)(4)):** прогон с < 4 000 NEW-строк окна — `DEBT` прогона. Оба прогона с 1 `DEBT` ⇒ исход `DEBT`. **[В4]:** один
прогон с 1 `DEBT` ⇒ исход `DEBT` (`NAMED` по определению требует двух прогонов; `SPREAD` по одному не печатается). Прогон с 0 `DEBT` —
исход не меняется; N1 читается на всех его строках; справка о цене не печатается.

**INSTRUMENT_FAIL** (любое в любом прогоне):
- IF0 окружение/сборка: не `05431dad`, строка ручек ≠ плечу 0 `kp137`, `KYTY_PM4_TRACE` ≠ 0,1,1,0 (проверяет харнесс; скорер
  читает json);
- IF1 N1: имя `op*`/`nop*` в `a` или `d`;
- IF2 P1: < 99 % NEW-строк окна `b`/`c` несут имя `op*`/`nop*`;
- IF3 имя вне 56 списка §6.1;
- IF4 `nest_n` > 0 (`op3f` в окне `b`/`c`: площадка содержит вложенные — двойной счёт). Прошлые данные: 0 строк `indirect buffer:`
  (печать первых 128 вызовов на процесс, `pm4Handlers.cpp:2029`) и 0 строк `branch:` (печать каждого вызова, `:1569`) в 8 логах
  `kp137` [c] ⇒ P(IF4) ≈ 0;
- IF5 C_k пуст; IF5b ĉ_k ∉ [3, 100] нс;
- IF6 g вне допуска §8.1; IF7 F вне §8.2; IF8 M < −5 мкс; IF9 H вне §8.4;
- IF10 > 1 % строк `b`/`c` без строки `FrameTrace-pm4:` на своём месте;
- IF11 нет `pl_proc_ns`/`pl_cmd_ns`/`pl_cmd_n`/`a_hold_us`/`a_wait_us`/`a_hold_n`/`mh_disp_us`/`mh_pres_us` в строках окна (не
  вооружены `pathlap`/`mutsite`).

**Порядок:** IF (любой) → `INSTRUMENT_FAIL`; иначе DEBT по правилам выше → `DEBT`; иначе **`NAMED`**, если есть кандидат g из 10
(§6.4) с `(L_g,b + L_g,c)/2 ≥ 400` **и** `min(L_g,b, L_g,c) ≥ 325` (п. 210(е)(6)); иначе **`SPREAD`**. При `NAMED` печатаются все
прошедшие кандидаты, по убыванию среднего, с классом («ожидание» — рядом).
