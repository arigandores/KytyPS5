### §0.3 Гонка RC1 и её предел

**Место.** `SDL_WaitEventTimeout_Device`: выборка очереди (`4b69833b:src/events/SDL_events.c:1008`) стоит раньше публикации окна пробуждения (`:1035`); `SDL_SendWakeupEvent` шлёт `PostMessage` (`4b69833b:src/video/windows/SDL_windowsevents.c:1939`) только опубликованному окну (`4b69833b:src/events/SDL_events.c:748`), а постановка события зовёт его из `SDL_PeepEventsInternal` (`:846`). Событие, поставленное `JoyPump` (или любым другим потоком: заголовок, задачи главного потока, стенд) между `:1008` и `:1035`, не будит `MsgWaitForMultipleObjects` (`4b69833b:src/video/windows/SDL_windowsevents.c:1895`) — главный поток спит до `loop_timeout` (`4b69833b:src/events/SDL_events.c:1036`).

**Предел при `=0`** — интервал опроса SDL (`:1029`): 1 мс при подключённых джойстиках (`:970`), 3 000 мс без них (`:973`); условие — `SDL_update_joysticks` (`:967`). **При `=1` без правки** интервала нет (`SDL_update_joysticks` = 0) — `SDL_WaitEvent` (`730ed40a:src/graphics/presentation/window/hostInput.cpp:424`) ждёт без предела (RC1).

**Правка (п. 692(в)(3)).** `HostInputWaitEvent` при `=1` ждёт `SDL_WaitEventTimeout` с пределом `t` = 1 мс, если `JoyPump` опубликовал атомиком число открытых пультов > 0, иначе 3 000 мс; путь мыши (`730ed40a:src/graphics/presentation/window/hostInput.cpp:432`) — `min(timeout_ms, t)`. Внутри `SDL_WaitEventTimeout_Device` `loop_timeout` ≤ `t` (`4b69833b:src/events/SDL_events.c:1029`) ⇒ **потерянное пробуждение держит главный поток не дольше `t` — тот же предел, что SDL даёт при `=0`**. Главный поток не зовёт `SDL_NumJoysticks`. Возврат 0 (истёк предел) — `HostInputWaitEvent` отдаёт «нет события», цикл `Run` идёт на следующий оборот (`730ed40a:src/graphics/presentation/window/window.cpp:891`). Пути без мыши при `=1` ошибка ожидания — строка `FixF24: wait error` (предел 32), не фатал (возврат 0 у `SDL_WaitEventTimeout` неотличим от истечения, кроме строки ошибки; путь мыши сохраняет свой `EXIT` — `730ed40a:src/graphics/presentation/window/hostInput.cpp:436`). Пробуждение окна из `JoyPump` не добавляется — предел достаточен и проверяем.

Число открытых пультов — `std::atomic<int>`, пишет только `JoyPump` (открытие +1, закрытие −1), читает главный поток `relaxed`: устаревшее значение меняет только предел следующего ожидания (1 мс ↔ 3 000 мс) на один оборот.

### §0.4 Правила RC2 и RC4

**RC2 — открытие по номеру экземпляра.** После каждого своего `SDL_JoystickUpdate` `JoyPump` под `SDL_LockJoysticks` обходит индексы `0 … SDL_NumJoysticks()−1`, для каждого пульта (`SDL_IsGameController` — тот же набор, что даёт события `SDL_CONTROLLERDEVICEADDED` наблюдателя, `4b69833b:src/joystick/SDL_gamecontroller.c:375`) с номером экземпляра, которого нет в своём наборе виденных, зовёт `SDL_GameControllerOpen(i)` — индекс годен, список под замком не меняется (`4b69833b:src/joystick/SDL_joystick.c:795`). `nullptr` — строка `FixF24: open failed instance=<id> error="…"` (предел 32) и пропуск, не фатал. После снятия замка — датчики, строка `Controller <id>: "…" type=…` (текст прежний), проверка остановки, `Controller::Connect(id)`, затем `SDL_GameControllerGetAttached`: пульт уже отсоединён — `Controller::Disconnect(id)` на `JoyPump` (иначе удаление, поставленное **другим** потоком — стенд, обратный вызов WGI — между снятием замка и `Connect`, могло бы разобраться главным потоком раньше `Connect` и оставить в `Controller` закрытый пульт; повторный `Disconnect` безвреден — строка `disconnect of unknown id`). Удаление: строка и `Disconnect` — главный поток (как F39a Ч3), `SDL_GameControllerClose(SDL_GameControllerFromInstanceID(id))` — задача `JoyPump`. Порядок «`Connect` раньше `Disconnect`» для отсоединений, рождённых в `SDL_JoystickUpdate` `JoyPump` (настоящие устройства), — [c построением]: событие удаления ставит `Detect` того же потока позже `Connect` (открытие и `Connect` — до следующего обновления).

*Почему индекс события стареет только после выборки [c].* Пока событие добавления стоит в очереди, SDL правит его индекс при каждом удалении (`4b69833b:src/joystick/SDL_joystick.c:1923`), виртуальные пульты добавляются в конец своего списка (`4b69833b:src/joystick/virtual/SDL_virtualjoystick.c:236`). Устаревание (сценарий RC2) — между выборкой события главным потоком и открытием на другом потоке. Отсюда форма плеча `flap` (ниже): чтобы мутант m1 («открытие по индексу события задачей `JoyPump`») ловился наверняка, стенд в плече `flap` при `=1` придерживает исполнение задач `JoyPump` на `FLAP_TASK_DELAY_MS` = 50 мс после постановки (только стенд; обход и открытие по номеру экземпляра не придерживаются), а пульты плеча меняются каждые `FLAP_STEP_MS` = 20 мс — индекс любой задачи открытия к её исполнению устарел.

**RC4 — остановка.** Оба пути выхода — `Controller::EmergencyShutdown`: (а) обычный конец игры — `WindowRun` → `std::quick_exit(0)` (`730ed40a:src/emulator.cpp:498`) → `at_quick_exit(EmergencyShutdownActive)` (`:547`) → аварийный обход подсистем (`730ed40a:src/common/subsystems.cpp:54`; у `Graphics` аварийного вызова нет — `730ed40a:src/libs/agc.h:29`, первым из имеющих стоит `Controller`); (б) фатал — та же `EmergencyShutdownActive` из `DbgReport`/`DbgExit` (один владелец при `KYTY_FIX_F21=1`); (в) путь `Shutdown` (`Graphics::Shutdown` → `WindowShutdown` → `Controller::EmergencyShutdown` — `730ed40a:src/libs/agc.cpp:75`, `730ed40a:src/graphics/presentation/window/window.cpp:1066`; затем `Controller::Shutdown` → `EmergencyShutdown` и `delete g_controller` — `730ed40a:src/libs/controller.cpp:855`) исполняется только `~Subsystems`, а на пути игры до него не доходит (`Execute` кончается `std::quick_exit(0)`).

Правило при `=1`: `Controller::EmergencyShutdown` **первым** останавливает `JoyPump` — флаг остановки (атомик), пробуждение, ожидание конца потока с пределом `T_JP` = 2 с; по истечении — строка `FixF24: pump_stop_expired` и выход без `join` (поток отсоединяется), затем как сейчас — тактильный звук, `PadOutput` (`:869`), `ReleaseHostPads` (`:872`). `JoyPump` проверяет флаг перед каждой задачей очереди, после каждого `SDL_JoystickUpdate`, перед каждым `Controller::Connect`/`Disconnect` обхода; после флага он не исполняет задач, не зовёт `Controller` и SDL и выходит. Повторный вход остановки безопасен: объект потока забирается под мьютексом один раз (форма `PadOutput::Stop`, F19c2), второй вход сразу возвращается; вход с самого `JoyPump` (фатал на нём) — флаг и `detach`, без ожидания себя. С одним владельцем Ф21 совместимо: владелец ждёт `JoyPump` ≤ `T_JP`, `JoyPump`, вошедший в аварийную последовательность не владельцем, ждёт владельца (≤ 12 с) — ожидание владельца истекает через `T_JP`, взаимного ожидания нет. Путь (в): `delete g_controller` не исполняется, если `JoyPump` не завершился (истёкшая остановка) — объект остаётся до конца процесса, задача после выхода не может обратиться к освобождённой памяти. Выход подсистемы джойстиков: путь (а)/(б) не выходит из подсистем SDL и при `=0`; путь (в) при `=1` в `~WindowContext` выходит только из видео (`730ed40a:src/graphics/presentation/window/vulkanWindow.cpp:1320` при `=0` прежний) — подсистема джойстиков, созданная на `JoyPump`, не разбирается с главного потока (иначе окна `JoyPump` и объект DirectInput его квартиры разрушались бы чужим потоком).

### §0.5 Достижимость плеча `cls` — **недостижимо** [c исходника SDL2]

Плечо требует, чтобы закрытие отсоединённого виртуального пульта с активной вибрацией вызвало обратный вызов `Rumble` стенда. `SDL_JoystickClose` действительно зовёт `SDL_JoystickRumble(joystick, 0, 0, 0)` при `rumble_expiration` ≠ 0 (`4b69833b:src/joystick/SDL_joystick.c:1595`), и истечение вибрации у отсоединённого пульта не обрабатывается (обновление пропускает `!attached` — `:2189`, сброс по истечению — `:2202` только для присоединённых) — `rumble_expiration` к закрытию ненулевой **достижимо**. Но отсоединение виртуального пульта (`SDL_JoystickDetachVirtual` → `VIRTUAL_FreeHWData`, `4b69833b:src/joystick/virtual/SDL_virtualjoystick.c:255`) обнуляет `joystick->hwdata` открытого пульта (`:73`), а `VIRTUAL_JoystickRumble` зовёт описатель только при `joystick->hwdata` ≠ `NULL` (`:429`), иначе возвращает ошибку «device disconnected» (`:437`); `SDL_JoystickRumble` дальше идёт к драйверу только через `4b69833b:src/joystick/SDL_joystick.c:1419`. Закрытие драйвера (`4b69833b:src/joystick/SDL_joystick.c:1601` → `4b69833b:src/joystick/virtual/SDL_virtualjoystick.c:567`) обратных вызовов не имеет. Пульт эмулятор закрывает только по событию удаления (`730ed40a:src/graphics/presentation/window/window.cpp:408`) и на выходе (`730ed40a:src/libs/controller.cpp:1178`) — у виртуального пульта удаление бывает только отсоединением. **Ни один код стенда на закрытии отсоединённого виртуального пульта не исполняется** ⇒ по п. 692(в)(7) плечо `cls` не ставится, `f24_c0`/`f24_c1` — нет; мутант m4 ловит `f24_d1` по `jp_tasks` (закрытие — единственная задача `JoyPump` на удалении).
