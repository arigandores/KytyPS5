## 2. Требуемые изменения

**RC1 (строки 15–17, 25–27, 62, 165–167; Б3б — буква п. 748(д)(1)).** Опись по букве задания — «по последней строке каждого номера»; у Б3б
единственная строка таблицы — §4:146 «открыт; …», строки таблицы с исходом нет ни одной (свой разбор, §1 (1)); исход `НЕ ДЕФЕКТ` стоит только
в тексте (§12:345, §48.1:817) и в п. 237(б). Строка 15 печатает «у всех 60 есть исход», строка 25 — «условие (в)(6) выполняется». **Сценарий
отказа:** F48c пишет пункт закрытия трека «у каждой строки K1–K4 исход», а реестр по последней строке таблицы даёт «открыт» у Б3б — любая
следующая опись (в том числе моим скриптом) печатает 1 строку без исхода, и закрытие трека расходится с реестром по букве своего же
условия. **Изменить:** печатать оба прочтения — «по букве (д)(1): без исхода 1 (Б3б)» и «по тексту и п. 237(б): 0»; замечание 1 §3 — не
пожелание, а условие: строка-поправка Б3б в таблице реестра (исход `НЕ ДЕФЕКТ` по п. 237(б), без нового доказательства) пишется пунктом
F48c ДО применения (в)(6); без неё (в)(6) по букве не наступает.

**RC2 (строки 36–37 и `census_f48a.py:7–8`, колонка `outcome_line` `census_f48a.tsv`).** Член (а) — «строка реестра вне сводок с номером и
словом исхода есть» — проверяется по любой строке файла, а не по строке таблицы этого номера. У 36 из 77 номеров `outcome_line` — чужая строка:
Ф10 → §115:1621 (строка Ф20), Б27 → §90:1362 (строка Б12, «форма Б27»), Б1б и Ф9 → §92:1379 (строка Б1а), Б14 и Б28 → §101:1459 (строка Б29),
Б8-H → §111:1574 (строка Б8), Б9 / Б2 / Б7 / Б13 / Ф4 → строки «Поправка очереди §48.2», Б26б и Б35 → строка дельты курса §21:462, K5-номера →
таблица рангов §5 (`outline_f48b.out.txt`). Коды описи от этого не ложны: свой разбор подтверждает исход строкой таблицы у 60 из 63 (§1 (1)).
**Сценарий отказа:** (а) ADJ48 — ручная таблица; ошибочный код номера X проходит член (а), если любая другая строка упоминает X рядом с любым
словом исхода (так «форма Б27» в строке Б12 подтвердила бы Б27 и при неверном коде) — член не ловит то, ради чего написан; (б) пункт F48c,
сославшийся на `census_f48a.tsv` как на «строку исхода», цитирует строку другого номера (Ф10 — `дефект` Ф20). **Изменить:** член (а) — строка
таблицы, первая ячейка которой несёт номер, со словом исхода в ячейке класса / вердикта / статуса; фикстура «номер и слово исхода в строке
другого номера ⇒ не засчитано»; колонка `outcome_line` пересчитана; до правки пункт F48c ссылается на строки исхода по `census_f48b.tsv`
(своя последняя строка с исходом у каждого номера).

**RC3 (строки 21, 101–103 §2.2; строка 143 §2.6, Ф21).** «Вне маски — 0 логов эмулятора» ложно: `scope_f48a.py` (= `scope_f32b.py`) смотрит
только `*.txt`/`*.log` ≥ 200 000 байт, а прогоны стенда `KYTY_TEST_EXITFATAL` пишут 6 539 логов процесса эмулятора `*.log`/`*.out` по
0,6–1 КБ (§1 (3в)). Свой свип их (§1 (3г)) вывод F48a не меняет — новых K1–K4 0, — но меняет две строки отчёта: в стендовых логах вне маски —
11 сигнатур вне таблиц F0 ∪ F32a ∪ F32d ∪ F48a, 280 логов с двумя `--- Fatal Error ---` и 12 рваных строк `LogAsync`. Строка Ф21 §2.6
«стенд: 1 лог с 2 строками (`f33d`)» неполна в 280 раз, а сам свидетель выбран неверно: условие переоткрытия Ф21 (§108:1542) — «второй
аварийный обход … при `=1` на стенде или в игре», а плечо CN при `=1` печатает второй заголовок по замыслу (`walks` 1, F33d2). **Сценарий
отказа:** (а) короткий лог раннего падения игры (K1 на старте пишет < 200 КБ, а stdout — не `log_*.txt`) с mtime > T0 не попадёт ни в свип, ни
в проверку полноты, и отчёт напечатает «вне маски 0»; (б) F48c пишет в условия переоткрытия Ф21 счёт заголовков — и следующий прогон CN при
`=1` «переоткрывает» исправленную строку. **Изменить:** §2.2 — без порога размера и с `*.out`/stdout (как `scope_f48b.py`), напечатать 6 539
стендовых логов и их 11 сигнатур с классом «печать стенда»; рваные строки `LogAsync` — справка Ф21 при `=0` (только плечи `=0` и мутант m2),
не строка; свидетель Ф21 на стенде — поля ридера стенда (`walks`, `second`, `crash`, `hang`, `cut`), а не число заголовков; в игре — второй
обход в `log_*.txt` без плеча CN.

**RC4 (строки 69, 76–77 §1.4, Ф5; `forma_f48a.py:4`, `:40`).** (а) «ни один [остаток] не лежит на исполняемом пути с наблюдаемым
срабатыванием в дельте [c §1.4]» ложно для Ф5: остаток Ф5 — это и есть 5 ключей формы (А) ветви 2 до сцены (п. 504(д)), и в дельте они
сработали в 11 логах из 11 (55 ключей, те же адреса; §1 (4)) на пути входа `-lvl`. По букве п. 672(б)(1) («лежит на исполняемом пути [c]»)
такой остаток — отдельная строка; частью строки его сделал п. 673(д) на тех же фактах (п. 504(г): 4 из 4; п. 506 — кадры входа чёрные).
(б) Граница «в сцене» `forma_f48a.py:40` — первая строка с `Level has started`, а в логах F46c первая такая строка — пустая
`GuestOut: Level has started: ` (`log_f26s_0.txt:192778`), строка уровня — `:229331`; чтение (E) от этого только строже (лишние события
в «сцене»), вывод 0 держится. (в) Довод «`texture + target − cleared` = 0» покрывает одного потребителя из 359 событий (`texture=1 none=0
exit=0`); закрывает все 359 запись `fce_next … cleared=1 merged=358` после строки уровня — форма (Б) п. 492(д)(2), как `f5id_sg` п. 504(г).
**Сценарий отказа:** F48c кладёт в пункт закрытия [c]-утверждение «остатки на исполняемом пути не срабатывают», которое опровергается
55 срабатываниями в тех же логах, — основание (в)(5) для Ф5 ложно, хотя исход верен. **Изменить:** §1.4 и строки 76–77 — «остаток Ф5 в дельте
сработал в 11 из 11 логов (55 ключей до сцены); частью строки — по п. 673(д) и п. 506 (видимого последствия нет [c листов])», оба прочтения
(б)(1) рядом, выбор — F48c; граница сцены — строка уровня с именем (как 'L' F0); основание (Б) ключа сцены — запись `fce_next … merged=358
cleared=1`, не счётчик ключа.
