## 5. Требуемые изменения

**RC1 (C-imm проверяет цвет выхода шейдера, а не то, что видно: смешение, dual-source, охват; §3 шаг 1, §4 пп. 2–4).**
`e63d6339:docs/track-f/f47a2.md:100` — V_s = «цвет, который D_b записал в точке (история пикселя, «после шейдера»)»; `:98` — экспорт
**MRT0**; `:102` — «равно» по V_g = V_s и потоку данных шейдера. Значение в цели после D_b — результат смешения (`Post-Mod`), а состояние
смешения, маска записи, вторая выходная величина dual-source и положение квада (VS из буферов, user-data) — тоже входы, которые отдаёт
эмулятор. **Сценарии отказа (каждый ⇒ (в)(3) `НЕ ДЕФЕКТ` при дефекте):** (а) квад затемнения с литералом (0, 0, 0, 0) и у гостя
`SRC_ALPHA / ONE_MINUS_SRC_ALPHA` — невидим; эмулятор потерял смешение (или маску) ⇒ непрозрачный чёрный прямоугольник; V_g = V_s =
(0, 0, 0, 0) ⇒ «равно». (б) программа с переписью выхода п. 262 (`ea6c6e9e:src/graphics/host_gpu/renderer/pipeline/shaders.cpp:345`,
модуль подменяется на `:587`): MRT0 — литерал чёрного, множитель `SRC1_*` — экспорт MRT1 из выборки (устаревшей, форма Б42) или
переписан неверно (форма Б35) ⇒ MRT0 «равно», виден чёрный. (в) квад, который гость увёл за экран / сжал в 0 по данным буфера, а эмулятор
отдал устаревшие (форма Б12 / Б13) ⇒ чёрный прямоугольник, цвет — литерал, «равно». **Изменить:** (1) V_s — `Post-Mod` и `Shader Out`
обоими значениями; «равно» C-imm — только если `Post-Mod` = своё смешение V_g с состоянием смешения D_b из снимка и итог **не зависит** ни
от одного нелитерального операнда (смешение выключено при полной маске; либо множители дают итог по одним литералам) — иначе класс
по вкладу операнда (цель ⇒ R, `SRC1` из выборки ⇒ T); для `SRC1_*` экспорт MRT1 — тоже по §4 п. 2; (2) член «охват и смешение»: тот же
прямоугольник той же программой (тот же H) с тем же состоянием смешения в снимке другого цвета (П1 по цвету, п. 715(г)) — тогда охват и
смешение — свойство видимого элемента, а не только чёрного состояния; нет такого снимка — либо (в)(5) с величиной «регистры смешения и
входы VS гостя на D_b» в звене кода, либо `НЕ ДЕФЕКТ` (в)(3) читается **только как «цвет — литерал игры»** с явной строкой «охват и
смешение не проверены» — выбор лида, до тега. Без правки (в)(3) закрывает строку при классической форме дефекта смешения.

**RC2 (сличение модуля снимка с каталогом не определено при 0 совпадений; п. 262 даёт 0 по построению; §4 п. 1).** `:93` — «запись
`ps_<H>_<ключ>.bin`…, чей SPIR-V равен модулю снимка по словам; равных записей с разными H нет — иначе «не определено»». (а) Файл

**RC3 (таблица класса не полна: user-SGPR, зависимость по управлению, «× 0», нет строки «иначе»; §3 шаги 1–2, §4 п. 4).** `:71` — C-imm,

загрузка: шага для него нет, исполнитель отнесёт к C-imm по «цепочке `s_mov`». (в) выборка × 0: `v_mul_legacy_f32` даёт 0 при NaN, IEEE
