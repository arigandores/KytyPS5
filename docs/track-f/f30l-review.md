Цена — [I]. Требуется:

**RC5 — (а2) — контроль цепи бита S, исход которого предрешён кодом; «годна» без этой оговорки читается шире, чем доказывает.**

Нарушение — `NOT_ADMITTED` (дефект кода), не 0.

**RC2 (м4) — тождества по суммам процесса, нарушение — `NOT_ADMITTED` («инструмент неисправен»).** Точные (порядок прибавлений в `RtsReport`: `rts_bad` → `rts_bad_b` → `rts_bad_rx` → 8): каждый из 8 ≤ `rts_bad_b` ≤ `rts_bad`; `rts_bad_r` ≤ `rts_bad_rx`; `rts_bad_xr`, `rts_bad_xc`, `rts_bad_xe` ≤ `rts_bad_rx`. С допуском 1 (отчёт, разрезанный последним флипом процесса, [I]): `rts_bad_rx` ≤ `rts_bad_r` + `rts_bad_xr` + `rts_bad_xc` + `rts_bad_xe` + 1; `rts_bad_b` ≤ Σ 8 + 1. По строкам — справка (флип может разрезать отчёт). Имена — целым токеном (`rts_bad_r` — префикс `rts_bad_rx`), фикстура на этот край; 8 новых имён — в списке обязательных полей строки `FrameTrace-x` (нет поля — `NOT_ADMITTED` `missing field`, не 0; порт RC4 F30f). Сценарий отказа без члена: счётчик бита, прибавленный до проверки гонки, даёт `rts_bad_s` ≥ 1 при `rts_bad` = 0 — К_B″ «жив» по (ж)(1) из погашенного отчёта.

**RC3 (м1, м3, м5) — связь прогона со статикой.** (Д7) — sha256 **запущенного** файла (не копии в `bin/`) = `bba692c6c161afc0cd2bd3245cea574f7fb82e7a4aae4c065826898403107163` у каждого тега; если лог печатает строку версии — она = `…-1907-g6fbdcf67`. Статические члены, которые эти мутанты ловят, — `chk_f30l.py` D2–D6 и `code_f30k.py` C2–C4c на `6fbdcf67` (оба `ALL OK`); печать F30m ссылается на них как на основание. Сценарий отказа без члена: тег на другом бинаре с тем же пределом ручки (пересборка из грязного дерева) — мутанты м1/м3/м5 в счётчиках не видны, (Д1) проходит.

**RC4 — `rts_bad_noreg` = `rts_bad` у тегов значений ≠ 3 (`c5`, `f30_cy_v`, `f30_cy_c4`).** [c]: при `t_rts != 3` PA отвергает draw со сдвинутыми регистрами (`:3497`), отчётов с `reg=1` не бывает. Нарушение — `NOT_ADMITTED`. Сценарий отказа без члена: значение 3 у тега контроля (окружение, зажим) — R/X по регистровому источнику (как у `c3` F30f: Σ `rts_bad_rx` > 0 при `noreg` 0) читаются К_B″ «жив» по (ж)(1). (Д1) ловит то же по строке режима; член по счётчикам — независимая вторая сеть.

## 8. Наблюдения и вопрос

- **Н1.** `code_f30k.py` не ловит м3а (`xc` ↔ `xe`): C2 сверяет вставки как строки с отступом (у `2u` и `4u` он один), C4c — только «после `bits |= 0x020u;`». Код верен (D5); правки кода не требует — основанием источника X считать `chk_f30l.py` D5.
- **Н2.** Ложный S от другого потока — см. §3; при живости одного S у `c5` на сцене с `rts_chk_b` ≫ 10⁷ — справка: S-события той же сцены у `v` F30f = 0.
- **Q1 (лиду, до данных F30m).** П. 655(ж)(3) называет «биты B, у которых К_B″ жив», а п. 655(в) считает X одним битом при трёх источниках (`xr`, `xc`, `xe`). Прочтение (i): X жив по любому из трёх ⇒ «X» в перечне вывода. Прочтение (ii): по источникам — жив только тот, чей счётчик ≥ 1. Сценарий расхождения: у `c5` жив только `xe` (протяжённости прохода вне закреплённого прохода — ожидаемо при снятом п. 6) ⇒ (i) объявит `НЕ ДЕФЕКТ` и по `xc` — пути HTile, названному классом Б28 (F30k §2), без его контроля. Рекомендую (ii). Печатаю оба прочтения; до ответа считаю по букве (i).
