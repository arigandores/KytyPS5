## 3. Задача (з)(3): доводы CD и CR по коду

- **CD верен.** Все установщики бита грязи CPU — `ChangeState<Cpu, true>` (`regionManager.h:184–192`) — зовутся только под

  `UnsetRange` до конца `UpdateProtection` (`memoryTracker.h:330` → `:345`). Порядок: запись снятия → `c1` (RMW) → `g_h`
  (RMW, читает цепочку `G`) → чтение `dk_до` куска ⇒ снятие видно; чтение `dk_до` → `g_k` → `m` → отпуск замка O3 → любой
  установщик ⇒ чтение `dk_до` не может увидеть установку. (а)∧(б) ∧ `dk_до` = 1 невозможно — **при моментах СВОЕЙ хватки
  события (иначе — RC4)**.
- **CR верен.** Одна пометка страницы на проход: `UpdatePageWatchersForRegion` зовёт `UpdateRegionWatchers` один раз на
  область (`pageManager.cpp:2790–2800`), внутри — один проход страниц (`:597–631`); `ExtendSlot` уже помеченных страниц
  пометку не ставит (`:617–621`). Пометка той же операции после `g_k` невозможна ⇒ Σ`lw_crp` = 0 на исправном коде.
  Замечание: при D1 условие «`clr_k.op` = O» в снимке S_k часто ложно (слово `clr` ещё старое) — популяция CR сжимается, но

## 6. Требуемые изменения

**RC1 (MAJOR) — порядок штампа снятия и правило «без (а) — сразу».** Что не так: §2.3 (последняя строка таблицы), L5 и §8.3
ставят запись слова `clr` ПОСЛЕ `UpdateProtection`, т. е. после пометок; §5.2 решает кандидата без (а) немедленно. Сценарий
отказа (`lwin=1`, опора): O3 сняла бит p, ждёт `region.lock`, который держит S_k куска K; K отпускает S_k (`g_rel`) и опрашивает —
слово `clr(p)` ещё от прошлого снятия (`c0` < `g_take`) ⇒ (а) ложна ⇒ `lw_xnc`, решено за микросекунды; O3 затем метит и
пишет `clr`. Каждое настоящее Р8 — X ⇒ Σ`lw_x` > 0 при 2 ⇒ **`LW_LOSS`, `ARMCOPY_INCORRECT` по ложному основанию**. При
`lwin=2` все события R7, превращённые спином в H, — `lw_xnc` ⇒ Σ`lw_p8` = 0 ⇒ контроль Р8 мёртв ⇒ `NOT_RESOLVED`; при `lwin=3`
Σ`lw_open` = 0 ⇒ контроль X мёртв ⇒ `NOT_RESOLVED`. Что изменить (одно из двух, решает лид): (а) слово `clr` (`c0`, режим, op;
Δ = 255 «ещё неизвестно») пишется МЕЖДУ `UnsetRange` и взятием `c1`, Δ дописывается сразу после `c1` (и до спина) — тогда
`c1` < `g_h` гарантирует, что снимок S_k и опрос видят слово с `c0`; кандидат с `c0` ∈ (`g_take`, `g_h`) и Δ = 255 ждёт Δ (срок тот
же); цена — одна-две расслабленные записи на страницу в окне «снятие → пометка» (У5, сказать вслух, отменяет довод §8.3
«записи вынесены»); или (б) кандидат без (а) не решается до срока: ждёт `T_poll` каждый (H редки: ≈ 9 за 150 с опоры [M c. 130];
при `lwin=2|3` — контрольные теги). В обоих случаях «решено сразу» допустимо только для кандидата, чьё слово `clr` уже несёт
снятие ПОЗЖЕ `g_h` (окончательно не (а)). Без правки трек L даёт `LW_LOSS` при любом исходе на Р8.

**RC2 (MAJOR) — порядок читателя И0 для контрольных рядов.** Что не так: §7.3 («То же — для подстрок `lw_x` … и для
контрольных рядов») неверно для CR и С3: их надмножества (`ac_cbm_pend`, `ac_cbm_bad`, `ac_cbm_left`) пишутся ДО них и

после `g_rel` каждой хватки, срок кандидата — `rel_ns` его хватки + 3 мс; опрос начинается после последней пачки куска (разница
— микросекунды). Иначе D3.

**RC7 (MINOR) — строка `ArmCopyLossLate:` под `region.lock`.** L8/§5.3 пишут строку в `LwStampMark` внутри хватки
`region.lock` O3, а §8.2 обещает под замками только RMW, расслабленные записи, `NowNs` и скан. `LOGF` (файловый вывод) под
спин-замком удлиняет хватку, которую ждут куски (S_k) и фолты — возмущение гонки при `lwin=1` (У5). Изменить: в хватке — только
`lw_late` и запись в локальный буфер, строка — после выхода из `UpdateRegionWatchers`.

**RC8 (MINOR) — вид переполнения.** `lw_ovf` один на четыре таблицы (§7.1); мёртвый контроль от переполнения таблицы
кусков в полёте неотличим от слепого классификатора (D6). Имён счётчиков не добавлять (п. 126(г)); добавить строку
`LossWin: overflow kind=inflight|open|cand|block` один раз на вид на процесс; в дыме шага 7 — строка о каждом виде.

**RC9 (MINOR) — спины во время загрузки в тегах без расписания.** `lw3s131`/`lw6s131` защёлкивают `lwin=2|3` с начала: каждый
проход, пересекающий кусок в полёте, держит GuestGpu 1/6 мс и `RegionManager::lock` области; при загрузке уровня таких
проходов много [I] ⇒ опора может не наступить за 150 с (ΣH = 0 ⇒ контроль мёртв), фолты крутятся на замке (D5). Изменить: дым
шага 7 печатает Σ`lw_spin_n`, Σ`lw_spin_ns`, `LockSpinNs`/`LockSpins` и номер кадра входа в опору при `lwin=2` и 3; если опора не
достигнута или Σ`lw_spin_ns` > 50 % стены — вопрос лиду до запечатывания тегов (например, включать спин только после входа в
опору). Порог 50 % — предложение, константа — у лида.

**RC10 (MINOR) — плечо по блоку против режима куска.** Кусок плеча 4, опубликованный после смены плеча, попадает в блок плеча
2 (и наоборот; Р9 `cbad130.md` §6.2″). Правило (ж)(5) считает Σ`lw_x` «при `armcopy=2`» по блокам `GateArm:` ⇒ событие X куска
режима 4 на стыке даёт `LW_LOSS`, событие X куска режима 2 на стыке может выпасть. Опора дала H₄ = 0, так что на опоре редко
[M c. 130]. Изменить: скорер сверяет Σ`lw_x` блоков плеча 2 со строками `ArmCopyLoss: mode=2 cls=X` (предел 256 ≥ ΣH) и
печатает расхождение; если расхождение ≠ 0 — решение лида (правило записано по блокам).

**RC11 (MINOR) — края слов.** (1) Поколения в словах — 34 бита, `g_*` — 64: сравнения только в одной ширине, при `G` ≥ 2³⁴ —
отказ классификатора громко (`EXIT` или строка и `lw_ovf`), не молчаливый перенос. (2) Указатель блока `g_lw_blocks[i]` —
публикация release, чтение acquire; пустой указатель при чтении — «штампа нет» (к `lw_xnc`), не разыменование.

## 7. Что проект НЕ доказывает (дополнение к §10 проекта)

- Т1 держится без В2 (вооружения O3) — но только при доставке копии O3 в тот же буфер (A1–A3); дефект этой доставки — У3.
- Порядок И0 после RC2 доказывает построчность для `lw_*` и контрольных рядов только при однопоточной публикации каждого
  события (так и есть: группа куска публикуется одним потоком, `bufferCache.cpp:358–383`).
- Контроль С3 проверяет отказ по (а) на страницах, снятых до передачи; «всегда Р8» он ловит, слепоту на пути H — нет
  (для этого `lw6s131`, п. 126(в)).
