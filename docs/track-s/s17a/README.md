**Форма K** — порт `VertexFromKey` / `PixelFromKey` / `ComputeFromKey` из `tests/S16dProbe.inc` (`1d8d9aa6`) в `shaderReplay.cpp`; перестройка
принимает вход только если `BuildStageStaticKey(вход) == ключ` (иначе `rej_key`).

**Как устроена форма без экспорта (вариант исполнителя — вопрос лиду §6.1).** R-SPEC хранит не слова «по ресурсам плана», а
**канонический путь чтения** одной материализации: база шейдера (2 слова), слова user data и каждое прочитанное обходом SRT слово —
по порядку, у каждого роль. Синтетический `SrtRuntime` отдаёт эти слова по порядку (адрес не смотрится; чтение сверх пути или не тем
читателем — расхождение, отказ). Роль слова определяется при записи на потоке-писателе: две пертурбации (бит 8, бит 0) с полным
повтором материализации — сдвиг запрошенного адреса на ±δ / ±δ·2³² ⇒ указатель; изменение ровно на δ одного слова дескриптора снимка
⇒ копия этого слова (роль по номеру слова V#/T#); иначе — `KEEP`, если меняется путь или специализация, или `INERT`. Затем
**самопроверка**: канонический путь через синтетический runtime даёт живую специализацию — иначе запись не пишется (`canon_self`,
в лог — слова-виновники). Цена: 2·(слов пути) повторов на запись, на потоке-писателе (приоритет ниже обычного), предел пути 4 096 слов
(`canon_big`). Следствие для К4: правка транслятора, меняющая путь чтения SRT, даёт `rej_shape` (путь не совпал), а не мёртвые записи.

**Захват** (`=1`, `=2`): R-SRC и R-SPEC — на первом в прогоне попадании `Get` в перестановку (путь мемо, путь `find_if`) и при создании
перестановки в `Compile`; запись пути — одна дополнительная материализация через живые читатели этого `Get` (журнал мемо на это время
отцепляется и возвращается); R-PIPE — в `RecordGraphicsRecipe` / `RecordComputeRecipe` и в `PrecachePipelines` после `Resolve`.
**Перестройка** (`=1`, `=3`): в потоке precache до `PrecachePipelines` и до гостя, если каталог совместим и в папке варианта нет
`pipelines.bin` текущей подписи (совместимый seed — быстрый путь, ставится раньше); по R-PIPE: PS, затем VS (с 6 у mesh), курсор
нового транслятора; найденная или новая перестановка; файлы кэша трансляции — каждые 128 рецептов и в конце; `pipelines.bin` — только
после полного цикла; список перестроенных перестановок — для счётчика попаданий. Папка каталога — `_ShaderCache/<title>/replay/`
(рядом с папками вариантов). Совместимость `KytyReplay1:<title>:<APP_VER>:key1:canon1:input1:pod<размеры POD>` — без подписи
транслятора и без модели GPU.

**Строки лога** (все — только при `≠ 0`): `ShaderReplay: mode=… dir=… compat=ok|mismatch|absent|corrupt generation=… corrupt=…
sources= specs= pipes= test=…` (раз); `ShaderReplay: capture sources= specs= pipes= canon_mismatch= dropped_queue= bytes= gen=
canon_self= canon_residual= canon_base= canon_big= pipes_waiting= catalogue_*= at=save|stop` (на каждое поколение — после 256 новых
записей или 30 с — и на остановке); `ShaderReplay: rebuild records= prepared= rejected= pending= rej_src= rej_fused= rej_key=
rej_version= rej_shape= rej_translate= rej_emit= rej_val= rej_write= rej_ref= translate_ms= wall_ms= perms_new= perms_cached=
rb_push_moved= rb_spec_changed= groups_same_pc= group_sources= pipelines_bin=…` (единица — R-PIPE, RC6); `rebuild-src …`,
`rebuild-spec …` (свои records/prepared/rejected по виду, RC6); `ShaderReplay: hits rb_used= rb_marked=` (попадания в
перестроенные перестановки: первые 4 и каждое 64-е, и `at=save` с `cap_skip`); `rebuild skipped reason=…`; строки стендов
`stand … applied`. Тождество: `prepared + rejected + pending = records`, причины — разбиение. Манифест перестройки для сверки К4 —
`replay/rebuild_manifest.tsv` (файл кэша, индекс, хэш специализации, старт, XXH3 SPIR-V).

**Стенды** `KYTY_S_REPLAY_TEST`: `canon` — в одной записи канонический T# (база 1) делается нулевым до самопроверки ⇒ `canon_mismatch`
> 0; `spec` — одна новая перестановка перестройки эмитируется из изменённой специализации (swizzle) и хранится под верной (только если
SPIR-V отличается и проходит проверку) ⇒ сверка с живой трансляцией видит `rb_live_mismatch` > 0; `addr` — одна запись пишется со
словами как прочитаны (роли верные) ⇒ `R_ADDR` > 0; `stop` — на середине перестройки событие закрытия окна (`SDL_QUIT`), путь
выключения ставит `m_precache_stop` (с S17a2 — `PipelineCache::ReplayCloseStop` до `std::quick_exit`; в S17a не ставил, RC1 S17b); `corrupt` — при загрузке испорчен байт текущего поколения ⇒ проверка суммы, откат на предыдущее.

## 6. Вопросы лиду и известные пределы

1. **Форма R-SPEC (вариант исполнителя):** путь чтения вместо слов «по тождеству ресурса GCN» (S16a §2.2). Причина — без экспорта
   `BuildResourceSpecialization` синтетический runtime может отдать слова только по пути чтения (RC10(б)); сопоставления по
   `(вид, first_use_pc, номер)` нет, число групп с одним `(вид, first_use_pc)` печатается из нового плана (`groups_same_pc`). Принять
   или назначить иное.
2. `canon_mismatch` = `canon_self` + `canon_residual` (ошибки канонизации). `canon_base` (сырой путь не дал живую специализацию —
   недетерминизм записи) и `canon_big` (путь > 4 096 слов) печатаются отдельно и в `canon_mismatch` не входят — решить, входят ли в
   член К3.
3. Причина `rej_ref` (R-SPEC, на который ссылается рецепт, не найден) добавлена к списку S16a §7; писатель не публикует R-PIPE без всех
   R-SPEC, поэтому в норме 0.
4. [I] `rej_translate` / `rej_emit` в коде не наступают: транслятор при отказе завершает процесс (`EXIT`), а не возвращает ошибку —
   перестройка транслирует только GCN, уже транслированный прошлой подписью; `rej_fused` не наступает: R-SRC хранит обе половины.
5. [I] Пертурбации записи на потоке-писателе могут печатать в stderr строки `shader resource specialization failed` (отказы
   повторов — ожидаемые); в `_kyty.txt` не идут.
6. [I] При `KYTY_SHADER_PREPARE=0` (не по умолчанию) гость стартует до конца перестройки: запись одного файла кэша трансляции из
   перестройки и из `Compile` гостя не согласованы (тот же временный файл). По умолчанию гость ждёт `FinishPreparation`.
7. Экран подготовки счёта перестройки не показывает (S16a §3 п. 3 — вариант); перестройка однопоточная [I: 1 214 перестановок × 8–23 мс].
8. Сверка К4 «живая трансляция против перестройки» (`live_perms`, `rb_hit`, `rb_dead`, `rb_live_mismatch`) — по двум папкам кэша;
   инструмента сверки этот код не несёт (манифест `rebuild_manifest.tsv` — вход для скорера S17c).
