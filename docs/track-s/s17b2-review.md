## 3. Ожидание `join` при закрытии (вопрос 1 лида, п. 533(б))

Поток precache (`pipelineCache.cpp:6751`–`6759`) исполняет `ReplayRebuild` (если перестройка назначена), затем `PrecachePipelines`
только при `!m_replay_rebuild || (!m_precache_stop.load() && …)` (`:6755`, +1 `PrecachePipelines();`).

1. **Фаза перестройки.** Цикл по R-PIPE проверяет флаг в начале каждой итерации (`:7410` `if (m_precache_stop.load()) {`, +1
   `break;`); итерация конечна: ≤ 2 стадии × (`prepare` с одной трансляцией + `permutation_for` с одной компиляцией; при стенде
   `spec` — ещё одна); ожиданий других потоков внутри нет. После цикла: `save_dirty()` (запись файлов), `m_mutex` на `:7550`
   (держат только задания воркеров — коротко; главный поток в `ReplayCloseStop` его не держит), строка `rebuild … pipelines_bin=stopped`;
   затем `:6755` ложно — `PrecachePipelines` не идёт. Граница — один R-PIPE плюс запись файлов грязных источников [c].
2. **Фаза `PrecachePipelines`** (перестройка не назначена при `1`/`3` — `recipes_current` и др., или закрытие после её конца):
   цикл рецептов проверяет флаг (`:6815`), затем **`WaitForPendingPipelines()` безусловно** (`:7041`, +1 строка `all pipelines
   created`), а она ждёт `m_jobs.empty() && m_jobs_active == 0` (`:5052`). **Утверждение лида п. 533(б) верно [c]:** `join` ждёт

3. **Взаимной блокировки нет [c]:** (а) воркеров ≥ 1 всегда (`:250` `std::max(1u, …)`, по умолчанию `:256` `std::clamp(hw / 4u, 2u,

   регистрация шейдеров гостя (`TraceShaderRegistration`) до старта гостя не идёт]. Значит, ожидание кончается, когда кончатся

## 8. RC

**RC1 (чтение стенда `canon`, печать S17c; решение — лиду).** Буква п. 532(д)(а) («флаг ставится, когда самопроверка отвергла
испорченную запись») не отличает отказ из-за порчи от отказа самой записи: `rejected` (`:687`) — исход самопроверки испорченной
копии, исход неиспорченной копии в этой ветви не считается.
*Сценарий отказа:* в теге стенда первая подходящая запись R (T# не нулевой) имеет собственную ошибку канонизации (класс X, `self`);
стенд портит её T# → `rejected=1`, флаг поставлен, `canon_mismatch` = 1 — член К3 «стенд ⇒ `canon_mismatch` > 0» читается ✓, хотя
чувствительность самопроверки к нулевому T# не показана (порча на исход не повлияла). Парный тег `=2` с `canon_mismatch` 0 этого не
исключает: это другой прогон (другие записи, сброс кольца). Член становится тавтологией ровно на том случае, против которого он
поставлен.
*Изменить (один из двух, выбор лида):* (а) **чтение, без кода** — член стенда ✓ только при паре строк одного `hash`: `stand canon
applied hash=H rejected=1` и `capture reject why=self … culprit=<i>:role6:<raw>->00000000 … hash=H` (диагностика `:708` называет
слово, одно восстановление которого даёт проход; при отказе только из-за порчи это слово стенда, роль `ROLE_T_LO` = 6,
`shaderReplay.h:73`); нет такой строки (в т. ч. потому, что строки отказов печатаются только первые 20, `:1169`) — «не определено»,
не ✓; печать формы `role6` — [I], фикстура скорера S17c на строку тега; (б) **кодом** — при `rejected=1` один `Run` неиспорченной
копии, строка стенда несёт `natural=0|1`, флаг — только при `natural=0`. Если не внести — К3 может засчитать положительный контроль
без силы.
