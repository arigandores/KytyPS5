### (а) Что `CloseAll` на аварийном пути даёт сверх ОС

`CloseAll` (`src/kernel/fileSystem.cpp:243`–`255`) для каждого непустого слота: при `opened` — `f->f.Close()` (`Common::File::Close`, `src/common/file.cpp:156`–`161` ⇒ `SysFileClose`), затем `delete f` и `nullptr`. Сверх того, что ОС делает при конце процесса (закрытие всех описателей), он может дать только сброс данных, которые лежат в памяти процесса, а не в ядре ОС.

1. **Windows (бинарь проекта).** Объекты `File` ядра получают хост-файл только через `file->f.Create` (`fileSystem.cpp:511`) или `file->f.Open` (`:516`) ⇒ `SysFileCreate`/`SysFileOpenR`/`SysFileOpenW`/`SysFileOpenRw` (`src/common/platform/sysWindowsFileIO.cpp:148`, `:164`, `:207`, `:227`) — все дают `SYS_FILE_FILE` с `HANDLE` от `CreateFileW` без `FILE_FLAG_NO_BUFFERING`/`WRITE_THROUGH`. Запись — `SysFileWrite` (`:109`–`115`): `WriteFile(f.handle, …)` сразу, буфера пользователя нет; данные после возврата `WriteFile` — в кэше ОС и переживают `_Exit` процесса (описатель закрывает ОС). `SysFileClose` (`:250`–`258`) для `SYS_FILE_FILE` — только `CloseHandle`, сброса на диск (`FlushFileBuffers`) нет. ⇒ на Windows `Close` не даёт ни одного байта сверх ОС [c кода; поведение ОС при конце процесса — по документации Windows, I].
2. **Типы `sys_file_t`, кроме `SYS_FILE_FILE`** (`SYS_FILE_MEMORY_STAT`, `SYS_FILE_MEMORY_DYN`, `sysWindowsFileIO.cpp:20`–`25`): создаются только `File::OpenInMem`/`CreateInMem` (`file.cpp:126`–`154`); в `src/kernel/fileSystem.cpp` ни одного вызова (`grep "InMem"` — 0) ⇒ у объектов `File` ядра этих типов нет; их `Close` — только освобождение памяти (`:253`–`257`), на диск они ничего не пишут [c кода].
3. **Linux** (`src/common/platform/sysLinuxFileIO.cpp`): `sys_file_t` держит `FILE*` (`:38`–`41`), открытие — `fopen` (`:164`, `:183`, `:226`, `:248`), запись — `fwrite` (`:120`–`122`) ⇒ **буфер пользователя stdio есть**; `SysFileClose` — `fclose` (`:267`), который его сбрасывает; `SysFileFlush` — `fflush` (`:421`–`423`). `std::quick_exit` после обработчиков `at_quick_exit` зовёт `_Exit`, который буферы stdio не сбрасывает (C11 7.22.4.7, 7.22.4.5) ⇒ на Linux без `Close`/`Flush` теряется хвост записи, ещё не ушедший из буфера `FILE` (кроме файлов `sync_writes`: `KernelWrite` после каждой записи зовёт `f.Flush()`, `fileSystem.cpp:879`–`881`) [c кода; потеря — I, Linux-сборку проект не собирает].

**Итог (а): (A′) по букве п. 412(в) — данные, которые без `Close` теряются, есть, но только на хосте с буфером пользователя (Linux).** Предлагаемая форма (пишется кодом после ответа лида по (в)): при `=1` `EmergencyShutdown` под `m_mutex` обходит слоты и для `opened && writable && !directory && special == None` зовёт `f.Flush()` — **только если у хоста есть буфер пользователя** (`constexpr bool`, ложь на Windows); без `Close`, `delete` и `nullptr`.
