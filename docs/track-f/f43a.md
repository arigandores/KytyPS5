## 0. Механизм [c кода FS12 `730ed40a`] — раздел до выводов (коммит раньше описи §2)

### 0.1 Счётчик разборщика и предел

Разборщик `fault_buffer_process.comp` — один поток на слово карты: читает слово (`730ed40a:src/graphics/host_gpu/shaders/fault_buffer_process.comp:22`) и **сразу пишет 0** (`:23`); затем на каждый установленный бит — `store_index = atomicAdd(download_buffer32[0], 1u) + 1u` (`:26`), проверка `store_index >= MAX_PAGE_FAULTS` (`:27`) ⇒ `return` (`:28`), иначе запись адреса страницы `page << CACHING_PAGEBITS` в `download_buffer[store_index]` (`:33`). Предел — `-DMAX_PAGE_FAULTS=1024` (`730ed40a:CMakeLists.txt:310`); на стороне C++ — отдельная константа `MaxPageFaults = 1024` (`730ed40a:src/graphics/host_gpu/renderer/cache/faultManager.cpp:24`), равенство двух констант держится руками [c]. Ячейка 0 области — счётчик (младшие 32 бита 64-битного слова `faults[0]`; старшие — 0 после `memset`, разборщик их не пишет: `download_buffer32` — то же хранилище, `730ed40a:src/graphics/host_gpu/shaders/fault_buffer_process.comp:17`), записи — индексы 1…1023.

Пусть в проходе `B` установленных битов в `W` ненулевых словах. Каждый вызов `atomicAdd` либо даёт индекс ≤ 1023 и запись, либо индекс ≥ 1024 и конец потока [c :26–:28]. Отсюда [c арифметики кода]:

- `B` ≤ 1023 ⇒ счётчик `c` = `B`, все страницы записаны;
- `B` ≥ 1024 ⇒ записаны ровно 1023 страницы (индексы 1…1023 выданы по одному разу), счётчик `c` = 1023 + `T`, где `T` — число потоков, получивших индекс ≥ 1024 (каждый — один раз, затем `return`); 1 ≤ `T` ≤ min(`B` − 1023, `W`). При раскладке «один бит на слово» `T` = `B` − 1023 и `c` = `B` точно; при плотной раскладке (32 бита на слово) `c` может быть 1024.

**Поправка к RC6 F41b:** счётчик растёт не «до числа всех битов прохода», а до 1023 + `T` (верхняя граница — `B`); вывод RC6 («`c` > 1023 при `B` > 1023») держится [c]. Незаписанные `B` − 1023 битов **теряются** — слово уже обнулено на `730ed40a:src/graphics/host_gpu/shaders/fault_buffer_process.comp:23` (механизм (н2) F41a §0.5): страница вернётся в карту только новым промахом.

### 0.3 Что лежит за областью и за концом буфера выгрузки

- **Область `a` < 7:** индекс 1024 — слово `faults[0]` области `a + 1` (её счётчик `c′`), индексы 1025… — её записи, дальше — области `a + 2`… (`T` ≤ `W` ≤ 2²¹ слов ⇒ до 16 МиБ за областью) [c арифметики]. ### 0.5 Какие пути ещё ограничивают число битов прохода

Предела `B` < 1024 раньше разборщика в коде нет [c]:

1. **Писатель** (режим нулевой страницы, умолчание `KYTY_BDA_NULLPAGE` ≠ `0`, `730ed40a:src/graphics/shader/recompiler/backend/spirv/spirvEmitterMemory.cpp:1901`): исполнение пишет не больше одного бита, на возврате (`EmitBdaFaultFlush`, `:1913`; вызов в хвосте возврата, `730ed40a:src/graphics/shader/recompiler/backend/spirv/spirvEmitterProgram.cpp:132`) — граница на число **исполнений**, не на число страниц: dispatch k03 F12g — 131 072 исполнения (F41a §0.3).
2. Адрес вне таблицы даёт страницу 0 и не пишется (`730ed40a:src/graphics/shader/recompiler/backend/spirv/spirvEmitterMemory.cpp:2013`, `:2042`) — таблица покрывает 2⁴⁰ адресов (2²⁶ страниц), т. е. всё адресное окно `GuestRange`.
3. `KYTY_BDA_LEAN` (по умолчанию выкл.) — PS не пишут (`:1974`).
4. Зарегистрированная страница не промахивается: `B` ≤ числа **ещё не зарегистрированных** страниц, которых BDA-программы коснулись между двумя проходами.
5. Частота проходов: проход взводится каждым `PrepareBda` (`730ed40a:src/graphics/host_gpu/renderer/renderContext.cpp:332`) и исполняется сборщиком после каждой завершённой подачи и при подготовке флипа (§0.2) — биты копятся за одну подачу; числа подач не ограничивает.
6. Ожидание при обороте 8 областей (`730ed40a:src/graphics/host_gpu/renderer/cache/faultManager.cpp:99`) — задерживает, не ограничивает.

Итог §0: при проходе с `B` ≥ 1024 (1024 и более незарегистрированных страниц, задетых BDA-программами за одну подачу, — 16 МиБ адресов) счётчик > 1023 и отложенная операция читает за областью [c кода]; что такой проход бывает в игре — [U] (числа поля — §2). **Сайт** — отложенная операция `FaultManager::ProcessFaultBuffer`, строка `count` (`730ed40a:src/graphics/host_gpu/renderer/cache/faultManager.cpp:213`) и цикл (`:214`); поток — GuestGpu (исполнение `PopPendingOperations`, §0.2), замков нет. Файлы правки — `faultManager.cpp`/`.h` (`src/graphics/host_gpu/renderer/cache/`): вне `src/graphics/shader/**` и вне списка `SHADER_CACHE_EXTRA_FILES` (`shaderTranslationCache.cpp`, `gpu_format.h`, `gpu_defs.h`, `imageInfo.h` — F41a §1, строка `SHADER_CACHE_EXTRA_FILES` `CMakeLists.txt` FS12) ⇒ **подпись трансляции не меняется** (`9177b426…`, каталог `variant_fixb26_fixb1b_fixf10_fixf19` и каталог повтора прежние) [c списка]; разборщик `fault_buffer_process.comp` не меняется.

**Что меняется.**

1. Разбор области выносится в функцию `ParseFaultArea(const uint64_t* area, bool clamp, Visitor visit)` в `faultManager.cpp` (объявление в `faultManager.h`, чтобы стенд звал **тот же код**, не копию): `raw = static_cast<uint32_t>(area[0])`; `count = clamp ? min(raw, MaxPageFaults − 1) : raw`; для `index = 1 … count` — `visit(index, area[index])`; возврат `{raw, count}`. Отложенная операция зовёт её с визитором, делающим ровно прежние `fault_ranges.Add` и `LOGF` в прежнем порядке.
2. Ручка — переменная окружения `KYTY_FIX_F29` (`0` — умолчание, `1` — предел), не гейт; читается **один раз на процесс** (статическая, форма `KYTY_BDA_NULLPAGE`); строка `FixF29: mode=<0|1>` один раз в конструкторе `FaultManager`. Плечом расписания быть не может и не должна (поведение, не измерение).
3. При `=1` и `raw` > `MaxPageFaults − 1`: строка `FixF29: overflow pass=<n> area=<a> count=<raw> read=<count> total=<k>` (не больше 32 строк на процесс; `n` — номер прохода, счётчик `uint64` в `FaultManager`, растёт в `ProcessFaultBuffer` только при `=1`; `k` — число проходов с переполнением с начала процесса). При `=0` строк `FixF29:` кроме `mode=` нет.

**Значения.** `=0` — путь прежний: `clamp = false`, визитор тот же, счётчика прохода и строки переполнения нет; член ревью — дифф пути `=0` против FS12 (вынос в функцию не меняет ни порядка, ни числа вызовов `Add`/`LOGF`/`FindBuffer`). `=1` — читаются не больше 1023 записей; при `B` ≥ 1024 разбираются ровно записанные разборщиком 1023 страницы.

**Типы счётчиков (все — штуки, `uint32`/`uint64`, не время):** `count`/`raw` (`uint32`, из `faults[0]`), `read` (`uint32`), `pass` (`uint64`), `total` (`uint64`). Инвариант при `=1`: `read` = min(`raw`, 1023) в каждой строке; при `raw` ≤ 1023 строки нет.

**Чего правка не делает (не заявляется):** (н2) незаписанные `B` − 1023 битов по-прежнему теряются (слово обнулено разборщиком, §0.1) — страница ждёт нового промаха; вариант «разборщик возвращает в слово незаписанные биты перед `return`» меняет шейдер разборщика и путь регистрации страниц — не Ф29, в проект не входит (строка лиду). (н1), (н3)–(н5) F41a/п. 694(в)(9) не трогаются. Равенство `MAX_PAGE_FAULTS` (шейдер) и `MaxPageFaults` (C++) правка не связывает — его проверяет член G2 стенда (§3).

**Цена.** Одно сравнение на проход; строка — только при переполнении (≤ 32). Отгрузка умолчания `=1`: кэши и каталоги не меняются, прогрева нет (подпись прежняя) [c §1 выше].

**Риски.** (а) Вынос в функцию — единственное изменение пути `=0`; ревью сверяет построчно. (б) Предел `MaxPageFaults − 1` верен, только пока шейдер собран с тем же `MAX_PAGE_FAULTS` — член G2. (в) `area[0]` читается как `uint64` и усекается до `uint32` — как сейчас; старшая половина — 0 [c §0.1].
