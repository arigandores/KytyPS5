### §0.4 Проект правки `KYTY_FIX_F25` (умолчание 0; в этом звене не пишется)

1. `ReadGuestWithRetry` получает выход «отказ обоих чтений» (`bool* failed`): истина, когда прямое чтение дало 0 при `nbytes` > 0 и `remaining` > 0 и чтение обхода тоже дало 0. Сама логика обхода не меняется.
2. `KernelRead`, `KernelPread` (после `file->mutex.Unlock()`, на месте проверки `is_invalid`): при `KYTY_FIX_F25=1` и `failed` — `return KERNEL_ERROR_EIO` (форма пути пустого дескриптора на том же входе, §0.1). Обёртки переводят без правок: `read`/`_read`/`pread` — `-1`, `errno` = 5 (`POSIX_N_CALL`); AIO — `return_value` = `0x80020005`, `state` = `ABORTED`, вызов — `OK`.
3. Позиция — как у пути ошибки (без изменения): `KernelRead` — `Seek(pos)` ещё раз под `failed` (страховка от отказа, сдвинувшего указатель, [I]); `KernelPread` уже восстанавливает `pos` (`:991`). Буфер гостя не пишется (копии нет).
4. Строка лога `FixF25: mode=<0|1>` при `FileSystem::Initialize` и `FixF25: read failed twice d=<fd> size=<n> pos=<p>` под пределом 32 строки; повторная инвалидация по `bytes_read` = 0 не исполняется (как сейчас).
5. Край: если между измерением `remaining` и обходом файл укоротили другим процессом, второй 0 может быть настоящим концом файла — проект перед `EIO` перечитывает `Size()`: `pos` ≥ размера ⇒ отдаётся 0 (конец файла), иначе `EIO`. [I] — в игре файлы данных только читаются.
6. Подпись трансляции не меняется (правка вне `src/graphics/shader/**`); кэши не холодеют.
