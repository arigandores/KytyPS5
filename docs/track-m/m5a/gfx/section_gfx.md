## T021 — MIN_LOD T# (`f38d738ee` против нашего `e0045fe90`)

**Наш код.** `dd73d04d:src/graphics/host_gpu/renderer/pipeline/descriptors.cpp:1952` — `view.min_lod = descriptor.MinLod();`
(поле T# слово 1, биты 19:8, `shaderBindings.h:80`; применяется при `!storage && MinLod() != 0 && view_levels > 1`, :1943).
`dd73d04d:src/graphics/host_gpu/renderer/image/imageView.cpp:387` —
`min_lod.minLod = std::min(normalized.min_lod / 256.0f, normalized.level_count - 1u)`. Комментарий
`imageInfo.h:169` называет `min_lod` «relative to base_level», но в Vulkan он уходит без прибавки `base_level`.

**Upstream** (`f38d738ee`, TextureViewInfo и FindView). Если `M` > 256·`B`, то `view.min_lod = M − 256·B`, затем
`minLod = B + view.min_lod/256` = **`M/256`**. Иначе `minLod` не ставится. Upstream тоже не прибавляет `base_level` к
значению T#: сначала вычитает, потом прибавляет. Строка M1a2 («наш без прибавки `base_level` против `base_level` +
MIN_LOD») сформулирована неточно: значения совпадают, различается только предел.

**Решающий вопрос: `minLod` в Vulkan абсолютный или от `baseMipLevel`?** [c] Текст `VUID-VkImageViewMinLodCreateInfoEXT-minLod-06456`
(`validusage.json` SDK 1.4.357): «minLod must be less or equal to the index of the last mipmap level accessible to the
view». Сообщение слоя в `VkLayer_khronos_validation.dll` — «(%f) must be less or equal to the index of the last mipmap level
accessible to the view (%f)», то есть предел — номер уровня образа, `baseMipLevel + levelCount − 1`. Вывод **[I, сильный]**:
`minLod` абсолютный. Довод — текст VUID. Подкрепление [I, по памяти, локального источника нет]: radv пишет `minLod` прямо в
поле T# `MIN_LOD` рядом с `BASE_LEVEL = baseMipLevel`, vkd3d-proton отображает в него абсолютный `ResourceMinLODClamp` D3D12.
Спецификацию целиком (раздел выбора уровня) офлайн не прочитал.

**Следствие (модель `minlod_model_m5a.py`).** При абсолютном чтении наше значение T# верно. Неверен только предел
`count − 1`: это относительный предел, наложенный на абсолютное значение. Расхождение с железом и upstream — в 80 из 256
случаев сетки, и **все 80 удовлетворяют `B` > 0 и `M/256` > `count − 1`**, вне этой области — 0. В расходящихся случаях мы
недозажимаем: например, `B` = 1, `count` = 3, `M` = 3,0 → наш `minLod` 2,0 (читается уровень 2), железо и upstream — 3,0.

`base_level` на целые `M`) относительный, но не исполняется: `Vulkan VK_EXT_image_view_min_lod: enabled` в 3 из 3 логов [c].

**Путь отложенных мипов** (`textureCache.cpp:2662–2670`): `min_lod = pending_levels − base_level` — относительный, уходит в
тот же абсолютный `minLod`. Чтение неподгруженного уровня — 11 случаев модели, все при `pending` ≥ 2. По умолчанию
`KYTY_MIP_DEFER_LEVELS` = 1 (`textureCache.cpp:327`), `pending` ∈ {0, 1}, ненулевой зажим только при `B` = 0 — расхождения
нет [c кода]. Путь исполняется: `img_minlod` 31 343 / 1 187 / 5 059 видов за прогон [c, `framesum_m5a.out.txt`], всё в
безопасной области.

**Исполнение игрой.** Путь T# исполняется [c]: одноразовая строка `Texture: T# MIN_LOD 1024/256 applied to a sampled view

## T109 — `depthClampEnable` (`2aaf0c9ba`)

**Наш код.** `dd73d04d:src/graphics/host_gpu/renderer/pipeline/shaders.cpp:536` — `clip_ext.depthClipEnable =

устройства `depthClamp` не включена (`vulkanWindow.cpp:645` включает только `depthBounds`). `depth_clip_enable =

`pm4Handlers.cpp:122–123`). `DB_RENDER_OVERRIDE` разбирается только на биты 27–30 (`pm4Handlers.cpp:329–336`), бит 16
`DISABLE_VIEWPORT_CLAMP` не читается [c]. Диапазон Vulkan-вьюпорта берётся из `zscale/zoffset` (`renderDraw.cpp:445–447`), а не
из `PA_SC_VPORT_ZMIN/ZMAX`.

**Железо [I].** По раскладке регистров GFX10 и коду radv (по памяти, локального источника нет) DB зажимает Z в
[`PA_SC_VPORT_ZMIN`, `ZMAX`] после смещения полигона и для Z из шейдера, пока `DB_RENDER_OVERRIDE.DISABLE_VIEWPORT_CLAMP` = 0. radv
реализует `depthClampEnable = FALSE` именно этим битом. Отсечение по Z (`PA_CL_CLIP_CNTL`) — отдельная настройка.

**Когда ответы расходятся.** Только если у фрагмента Z вне [minDepth, maxDepth]. Это бывает в трёх случаях:
- (а) отсечение по Z выключено;
- (б) смещение полигона (`setDepthBias`, `renderDraw.cpp:500–517`);
- (в) экспорт Z из PS.

Для D16 при диапазоне [0, 1] преобразование в UNORM зажимает и так. Значим D32 (D32S8/D32F). Upstream (всегда TRUE)
тоже неточен: он зажимает по диапазону из `zscale/zoffset`, а не по ZMIN/ZMAX, и игнорирует бит 16. Точная форма —
`depthClampEnable = !DISABLE_VIEWPORT_CLAMP` плюс `VK_EXT_depth_clamp_control` с диапазоном [ZMIN, ZMAX]. Эта структура в
SDK есть: строки `VkPipelineViewportDepthClampControlCreateInfoEXT` в `layerstr_m5a.out.txt`.

**Исполнение.** Случай (а) недостижим на каталоге [c, `recipes_m5a.out.txt`]: `depth_clip_enable = 0` в **0** из 1 842 рецептов

Форматы глубины: D32S8 1 578, D32F 62, D16 50, нет 152. Случаи (б) и (в): смещение и экспорт Z в игре возможны, но

**Исход: паркуется** до свидетельства: счётчика под замком draw с ненулевым смещением полигона или экспортом Z на цели D32

- 0 таких draw ⇒ «НЕ ДЕФЕКТ».
- Тексель вне диапазона ⇒ «А» в точной форме выше, не в форме upstream.

## T188 — `InvalidateMemoryFromGPU`: только при совпадении базы (`ebe401d05`)

**Наш код.** `dd73d04d:src/graphics/host_gpu/renderer/cache/textureCache.cpp:3393–3409`: для каждого образа (кроме глубины),
пересекающего записанный диапазон байтов, выполняется `ClearGpuModified()` и `MarkBufferModified()`. Вызывают его запись
буфера хранения (`descriptors.cpp:1073–1075`), заливка DMA (`bufferCache.cpp:2307`) и копия DMA (`bufferCache.cpp:2376`).
Запись `ObtainBuffer(..., is_written = true)` образ в буфер не скачивает: синхронизация из образа только при `!is_written`,
`bufferCache.cpp:1154–1155`. Поэтому при **частичной** записи по образу с `IsGpuModified` повторная загрузка образа из буфера
теряет отрисованное содержимое вне записанного куска [c кода; «буфер не содержит отрисованного» следует из определения
`IsGpuModified` — I].

**Upstream** заменяет пересечение на `image.info.data.address == address`. Тогда запись **внутрь** образа со смещением
(мип по смещению, подпрямоугольник, потоковая подгрузка мипов DMA/CS по смещениям) образ не инвалидирует, и образ
читается устаревшим [I].

**Кто прав.** Оба частично. Upstream чинит «чужую» запись, задевшую образ, ценой пропуска настоящей записи по смещению.
Для ASTRO с потоковыми мипами это риск регрессии. Верная форма — перед частичной записью по образу с `IsGpuModified`
скачать образ в буфер (`SynchronizeBufferFromImage`), затем пометить буфер изменённым. Форму upstream не брать.

**Исполнение.** Не наблюдаемо офлайн [U]: `TraceWatchedImage("gpu-invalidate")` печатает только для отслеживаемых образов
(0 строк в 3 логах), а счётчиков частичного пересечения нет.

**Исход: паркуется** до счётчика под замком в `InvalidateMemoryFromGPU` по (`IsGpuModified`, запись покрывает образ целиком
или нет, база совпала или нет).
- «частичная по образу ГП» = 0 ⇒ «НЕ ДЕФЕКТ» на линии курса.
- ≥ 1 ⇒ «А» с правкой «скачать, затем пометить».
- «запись внутрь со смещением» ≥ 1 ⇒ доказательство, что форма upstream регрессирует.

## T258 — `NativeStorageBuffer`: признак texel для сырого чтения (`743fdc699`)

**Наш код.** `dd73d04d:src/graphics/host_gpu/renderer/pipeline/descriptors.cpp:903` —
`ObtainBuffer(address, size, resource.written, resource.formatted, id, true)`. Синхронизация буфера из образа ГП
(`SynchronizeBufferFromImage`, `textureCache.cpp:3220`) идёт только при `is_texel_buffer && !is_written`
(`bufferCache.cpp:1097`, :1154–1155). Значит, **сырое (неформатное) чтение** диапазона, в котором лежит образ с `IsGpuModified`,
читает буфер без отрисованного содержимого [c кода].

**Upstream** передаёт `resource.read || resource.formatted`. Синхронизация срабатывает только если база буфера равна базе
образа (`FindImageFromRange`, `textureCache.cpp:2542`) и образ безопасно скачать.

**Цена.** Признак texel выключает быстрый путь `buffast` (`BufFastSkip`, `bufferCache.cpp` перед :1500) для каждой сырой
привязки чтения — заметная доля привязок кадра, это риск для G5 [I].

**Исполнение.** Не наблюдаемо офлайн [U]: счётчика совпадения базы сырой привязки чтения с образом ГП нет, `skc3_sync_img`
считается только при `skipceil` = 3.

**Исход: паркуется** до счётчика под замком: сырые привязки чтения (`!written && !formatted`), у которых
`FindImageFromRange(address, size)` даёт образ с `IsGpuModified`.
- 0 ⇒ «НЕ ДЕФЕКТ».
- ≥ 1 ⇒ «А»: признак texel только для таких привязок, чтобы не платить `buffast` за все, под `KYTY_M_T258`, умолчание 0.
