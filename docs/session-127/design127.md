## 2. Множество пропуска — п. 76(з)(2)

### 2.1 Регистровые источники (группы п. 64(б))

Поколения групп `G_mask`, `G_slot[0..7]`, `G_dact`, `G_depth` на контекст — те же крючки, что у `rk3cen` (с. 126, в
`main`): сеттеры `HW::Context` (`hardwareContext.h:869–915` — 12 сеттеров `CB_COLORn_*` → `G_slot[slot]`; `:928–931`
`CB_TARGET_MASK` → `G_mask`; `:937–985` глубина → `G_depth`, `DB_STENCIL_INFO` `:949–952` → `G_dact`; `:1097–1100`
`DB_RENDER_CONTROL`, `:1108–1111` `DB_DEPTH_CONTROL` → `G_dact`; `:1119–1127`, `:1140–1143`, `:1149–1152` → `G_depth`),
запись объекта `Context::Reset` (`:864–867`) и `m_ctx = m_saved_ctx` (`graphicsRun.cpp:393–394`) — все группы. Таблица
вызовов сеттеров D_census — 47 мест `pm4Handlers.cpp` (п. 68(б), `C:/kyty/s126/n3prime_table.txt`).

**Относимость для пропуска (строже п. 64(б)):** у пропуска нет выходов резолюции ТЕКУЩЕГО draw (её и снимают), поэтому
относимость берётся не «по выходам текущего или записанного draw», а по тому, какие группы МОЖЕТ прочесть резолюция
при неизменной маске:

Rel_skip(C) = {`G_mask`, `G_dact`, `G_depth`} ∪ {`G_slot[0]`} ∪ {`G_slot[n]` : n ≥ 1, `render_target_mask_slot(mask, n) ≠ 0`},

где `mask` — `CB_TARGET_MASK` записи (= текущей: `G_mask` в Rel_skip всегда, поэтому пропуск возможен только при
несдвинутой маске). **Довод Rel_skip ⊇ Rel п. 64(б):** цикл резолюции посещает слот 0 всегда, слот n ≥ 1 — только при
`render_target_mask_slot(mask, n) ≠ 0 && base.addr ≠ 0` (`renderDraw.cpp:2572–2574`); слот, давший цель в текущем
или записанном draw, посещён, значит, при несдвинутой маске его бит маски ≠ 0 (или n = 0) ⇒ `G_slot[n]` ∈ Rel_skip.
`G_depth` в Rel_skip всегда (п. 64(б) — только при глубине в текущем или записанном draw). Лишняя относимая группа
сужает множество пропуска — сторона «безопасно» (для корректности, не для числа). Пропуск по регистрам: ни одна
группа из Rel_skip(C) не сдвинулась с записи (сравнение 11 поколений, как `Rk3Post`, `renderDraw.cpp:1192–1197`).

значений в том же порядке; поля `state.color_info`/`depth_info` — те же, §4.4), поэтому следующее сравнение с той же
записью так же верно, как первое. Самопроверка `rtskip=2` сверяет один шаг (d против записи); многошаговая цепочка при
`rtskip=1` держится этой индукцией [I] — это названо в §11.

(5) **Что довод не покрывает:** (а) запись в `HW::Context` в обход сеттеров, если она появится в будущем коде; (б)
изменение смысла memo-попадания (например, выключение `rtfast` посреди draw — гейты защёлкнуты на draw, базе он
пришпилен 1); (в) гонка потоков по `bind_stamp` — та же, что у быстрого пути `rtfast` сегодня (запись CPU после
проверки видна следующему draw в обоих путях), считается отдельно `rts_race` (§5.3); (г) другие сцены. Пробелы (а)–(б)
закрывает только самопроверка на тех сценах, где она шла.

## 4. Ручка `rtskip` (`KYTY_RT_SKIP`)

### 4.1 Значения, чтение, защёлка

- `{"KYTY_RT_SKIP", "rtskip", 0, 3}` — ПОСЛЕДНЯЯ строка `KNOB_DEFINITIONS` (`src/common/gates.cpp`), `Knob::RtSkip` —
  последний элемент перед `Count` (`gates.h`); **`check_gate_order.py` после патча и ДО сборки** (порядок компилятор не
  проверяет). В `gates_base.txt` имени нет — плечи называют его явно, **заменой на месте**.
- **Чтение — ОДИН раз на draw** (п. 76(з)(1), ловушка с. 97): на входе `RenderExecutor::DrawIndex` (`renderDraw.cpp:3991`,
  рядом с `Rk3Latch`) и `DrawAuto` (`:4209`) — одна relaxed-загрузка ручки и TLS-проверка, как `Rk3Latch` (`:993–998`);
  значение защёлкивается в TLS `t_rts` на весь draw; места A, B, пост, закрепление и крючки читают только `t_rts`.
  Поэтому ручка может быть плечом расписания ABBA.
- **Вооружение** (медленная половина защёлки, как `Rk3LatchSlow` `:940–990`): только на потоке GuestGpu
  (`Common::SkipCeil::t_gpu`, иначе `rts_xthr`++ и 0); при `rk3cen`, `spine`, `spcen`, `slicecen`, `skipceil`,
  `bindfloor`, `m4baton` ≠ 0, `rtfast` = 0, `graphics_debug_dump`, `KYTY_RENDER_MEMO_FAST=0` — отказ: строка
  `RtSkip: refused reason=<имя>` ОДИН раз на причину и 0 (§4.2). **`KYTY_FRAME_TRACE` не требуется** (прототип
  отгружаемый; без трассы `Add` — пустой).
- **Выход из вооружения** (1/2/3 → 0 или отказ) обнуляет таблицу записей; первая вооружённая после этого draw каждого
  контекста — без записи (`rts_xa_rec`). Смена между 1, 2 и 3 записи не обнуляет. Крючки проверяют ту же TLS-защёлку:
  запись между последним draw при 0 и первым при ≥ 1 не видна — и не нужна, потому что записи в этот момент нет.

### 4.2 Отказы

| причина | почему несовместимо |
|---|---|
| `rk3cen ≠ 0` | общие крючки и общая TLS-маска вооружения крючков (§4.5); перепись с. 126 классифицирует выходы захвата, которого при пропуске нет |
| `spine ≠ 0` | теневой процессор пишет теми же сеттерами (RC9 с. 126) — поколения двигались бы чужими записями |
| `spcen ≠ 0` | своя память целей той же сессии и свои проверки вокруг того же `AcquireRenderTargets` (`:3396–3430`) |
| `slicecen ≠ 0`, `skipceil ≠ 0` | переписи внутри `AcquireRenderTargets` (`:2011–2067`) и `AcquireTargetView` (`:1290`); `skipceil=1` пропускает draw целиком |
| `bindfloor ≠ 0` | другой вызов захвата (`:3412`) и своя защёлка на операцию |
| `m4baton ≠ 0` | PM4 и draw на втором потоке — крючки GuestGpu не видят его записей (Н14) |
| `rtfast = 0`, `graphics_debug_dump`, `KYTY_RENDER_MEMO_FAST=0`, `m_readback_linear_images` | фаза B пересказывает быстрый предикат `rtfast`, фаза A — memo-семантику при включённом быстром memo (Н6) |

Отказ — строка раз на причину; счётчик `rts_refuse` на каждый отказанный draw при ручке ≠ 0.

### 4.3 Алгоритм

**Место A** (вместо вызова `PrepareDrawRenderState` в `DrawIndex` `:4167–4169` и `DrawAuto` `:4342–4344`; при
`t_rts = 0` — ровно прежний вызов). Предикат `PA` (первое несработавшее — причина, счётчики `rts_xa_*`, разбиение):

1. `rec` — запись контекста, изъятая на защёлке (§4.4), есть и закреплена — иначе `rts_xa_rec`;
2. конфигурация (Н6) — иначе `rts_xa_cfg`;
3. ни одна группа Rel_skip не сдвинулась (§2.1) — иначе `rts_xa_reg` (**значение 3 этот пункт пропускает**, §6);
4. `render_target_slice_offset` == записи (Н7) — иначе `rts_xa_arg`;
5. `GetColorControl().mode != 3` и `bit_cast` границ глубины == записи (Н9) — иначе `rts_xa_unh`;
6. все слоты memo записи (посещённые цвета через memo и глубина) `valid` и той же `version` (Н8) — иначе `rts_xa_memo`;
7. каждая цель записи: `try_get` ≠ null, `!(!registered && !Empty)`, `!needs_rebind` (Н1) — иначе `rts_xa_img`.

При `t_rts = 1` и `PA`: копия выходов из записи (§3.2), `ps_active` свежий, воспроизведение Touch/`BindRenderTarget`,
решение «framebuffer skip» тем же условием `:2588`; TLS-флаг `t_rts_a = 1`. Иначе — полный `PrepareDrawRenderState`.
В цикле резолюции полного пути (только при `t_rts ≠ 0`): после каждого `ResolveRenderColorTarget` черновик записи
получает (слот, `memo_slot`, `memo_version`, `image_id ≠ 0`, индекс записи), после `ResolveRenderDepthTarget` —
то же для глубины. Снимок поколений контекста на месте A — для стража `rts_acqw`.

**Место B** (вместо вызова `AcquireRenderTargets` `:3411–3415`, только если `t_rts_a`; иначе прежний вызов). Предикат
`PB` (разбиение `rts_pa` = `rts_pb` + Σ `rts_xb_*`):

1. цели после привязок == записи: `color_count`, наличие глубины, у каждой `image_id`, `target_slot`, `desc.view_info`
   (Н1; привязки могли переписать цель-алиас) — иначе `rts_xb_ids`;
2. весь быстрый предикат `rtfast` против записи и живых `m_color_view_fast[slot]`/`m_depth_view_fast`, пересказ
   `kSpRtLive` (`:1499–1512`), плюс условие повторного поиска захвата (`:1766–1767`, `:1857`) (Н1, Н2) — иначе `rts_xb_live`;
3. `MetaEpoch()` == записи (Н2, Н4) — иначе `rts_xb_meta`;
4. `backing.state_serial` каждой цели == записи (Н3) — иначе `rts_xb_ser`;
5. `is_bound` каждой цвета == записи; у глубины `!is_bound` (Н3, Н5) — иначе `rts_xb_bound`;
6. `IsRendering()` и `PassBeginSerial()` == закреплённому проходу записи (Н10, Н11) — иначе `rts_xb_pass`.

При `t_rts = 1` и `PB`: воспроизведение §3.2 (захват), `RenderState` записи. Иначе — полный `AcquireRenderTargets` на
восстановленных (или свежих) выходах.

**Пост** (сразу после места B, в ветке `spcen = 0`, `:3431–3440`; при `t_rts = 0` — ничего): страж `rts_acqw`; при
2/3 — сверка §5; обновление записи §4.4. **Закрепление** (после `BeginRendering`/`BeginRenderingPacket`, рядом с
`SpRtAfterBegin`, `:3669–3674`, `:3837–3841`): черновик записи закрепляется `pass_serial = PassBeginSerial()`; у
пропущенного draw запись перезакрепляется тем же способом (проход мог перезапуститься на `BeginRendering` по причинам
вне захвата — например, `CommitBindings` закрыл его переходом сэмплируемого образа).

### 4.4 Запись контекста

Таблица ≤ 8 контекстов по адресу `HW::Context` (TLS, выделяется при первом вооружённом draw; переполнение — `rts_ovf`,
draw без записи). Запись: 11 поколений на момент записи; `slice_offset`; `mask`; границы глубины (биты); выходы
резолюции `color_info[0..k]`, `color_count`, `depth_info`; посещённые слоты памяти (слот, `memo_slot`, `memo_version`);
по каждой цели — `backing`, вид, `bind_stamp`, `source_size/first_level`, `state_serial`, `htile_clear_mask`,
`is_bound`, `attachment_layout/access`, экстент для счётчиков; `RenderState`; `g_pass_extents`; `MetaEpoch()`;
`pass_serial`. Размер записи печатается в строке `RtSkip: mode … rec_bytes=`.

**Изъятие на защёлке (Н12):** вооружённый draw ищет запись своего контекста и снимает с неё флаг годности, держа
указатель в TLS; флаг возвращает только пост этого draw (полным обновлением или перезакреплением). Любой ранний возврат
оставляет контекст без записи.

**Строгое взятие записи (полный путь):** записывается, только если захват этого draw был «чистым» — ни одного
медленного пути `AcquireTargetView` и повторного поиска, `MetaEpoch` не сдвинулся за время захвата, нет
`depth_clear_enable`/`depth_load_clear_enable`, глубина не `is_bound`, у каждой цели `memo_slot ≠ UINT32_MAX`, каждый
посещённый слот цвета — либо неактивный по регистрам (`colorRenderTarget.cpp:113–118`), либо через memo; иначе — `rts_rec_x`
и контекст без записи. Это правило строгой записи `spcen` (`:1644–1656`), перенесённое на две фазы. Первый draw после
барьера цели записью не становится — следующий становится.

### 4.5 Крючки

Крючки `Common::Rk3::NoteWrite/NoteSlot/NoteObject` (`src/common/rk3Census.h`) сегодня проверяют `t_rk3 != 0`. Проект
требует: **одна TLS-маска вооружения крючков** (бит `rk3cen`, бит `rtskip`), горячая проверка — одна TLS-загрузка,
как сегодня; холодная половина (`renderDraw.cpp:4444–4449`) раздаёт запись в таблицу `rk3cen` или `rtskip` по биту и
считает свой счётчик (`rk3_wr_*` — только при бите `rk3cen`, `rts_wr`/`rts_wr_obj` — только при бите `rtskip`), поэтому
нулевые контроли обеих ручек сохраняются. Раскладка `HW::Context` не меняется (RC8 с. 126); `hardwareContext.h` не
правится. Правок в `src/graphics/shader/**` нет — подпись кэша трансляции не меняется.

## 5. Самопроверка `rtskip=2` — п. 76(з)(3)

### 5.1 Что делается

На каждом вооружённом draw предикаты `PA` и `PB` вычисляются ТОЛЬКО ЧТЕНИЕМ (`try_get`, без `GetImage`, без Touch, без
записи в запись и в состояние), затем полный путь (резолюция + захват) выполняется всегда и его результат используется
дальше — эмуляция при 2 корректна по построению. Если `PA` был истинен, выходы полного пути сравниваются с тем, что
дал бы пропуск (`rts_chk`++); если истинен и `PB` — сравнивается и захват (`rts_chk_b`++). Затем запись обновляется
по §4.4 из свежих выходов.

### 5.2 Сравниваемые выходы (всё, что читает путь дальше)

| бит | что сравнивается | с чем |
|---|---|---|
| `0x001` O — выходы резолюции | `color_count`; для индексов `0..k`: `image_id`, `target_slot`, `guest_mip_level`, `guest_array_layer`, `export_mapping`, `memo_slot`, `memo_version`, `desc` (все члены, `view_info` — `operator==`, прочие — почленно, float — по битам; не `memcmp` агрегата: паддинг, урок с. 83); `depth_info` — все члены `RenderDepthInfo` (`depthRenderTarget.h:21–43`, `stencil_front/back` — `operator==`, float по битам) | копия записи |
| `0x002` K — memo | после свежей резолюции `version` каждого посещённого слота записи не сдвинулся (ни записи, ни повторного поиска) | записью |
| `0x004` T — привязки целей | хвост `m_bound_images`, добавленный резолюцией, == цели записи в порядке резолюции | записью |
| `0x008` F — ветка | свежая резолюция не пошла в `ResolveColorTargets` и не вернула false иначе, чем запись | — |
| `0x010` R — `RenderState` | возвращённый захватом `RenderState` (`operator==`, как `SpRtPost` `:1574`) | запись |

| `0x040` S — барьер | `ImageStateSerial()` не сдвинулся за время захвата (как бит S `spcen`) | — |
| `0x080` P — проход | проход, открытый до захвата, не закрыт им | — |
| `0x100` M — метаданные | `MetaEpoch()` не сдвинулся за время захвата | — |
| `0x200` L — медленный путь | ни одна цель не пошла медленным путём `AcquireTargetView` или повторным поиском | — |

Биты `0x010`–`0x200` — только при `PB`. Любой ненулевой бит — `rts_bad`++ и строка `RtSkipVerify: MISMATCH frame=
bits=0x… colors= depth= pa=1 pb=<0|1> mode=<2|3>` (≤ 40 строк на процесс); дальше используется свежий результат.
**Гонка:** если медленный путь начался с `bind_stamp`, сдвинутым после проверки `PB` (решается на входе медленного пути,
как `t_sp_rt_stamp_race`, RC1 с. 120), расхождение считается в `rts_race`, а не в `rts_bad` (у быстрого пути `rtfast`
та же гонка сегодня). Счётчики `rts_bad` и `rts_race` копятся и после 40-й строки.

### 5.3 Что самопроверка доказывает и чего нет

Доказывает (на прогнанной сцене): для каждого draw, где пропуск сработал бы, его выходы и запоминаемые записи равны
полному пути относительно ОДНОГО шага (запись — выходы предыдущего полного draw на контексте). Не доказывает: полноту
источников вне прогнанных сцен; многошаговую цепочку пропусков при 1 (держится индукцией §2.3(4) [I]); отсутствие
расхождений, которых таблица §5.2 не сравнивает (например, порядок LRU при равных касаниях — не сравнивается, потому
что воспроизведение делает те же касания).

## 6. Положительный контроль `rtskip=3` — п. 76(з)(3)(б)

**Игнорируемый источник — регистровый целиком:** пункт 3 предиката `PA` (§4.3, поколения групп Rel_skip) не
проверяется; всё остальное — как 2 (полный путь всегда, сверка §5.2, свежий результат). Остальные источники
(Н1–Н12) проверяются, поэтому draw, у которого гость переписал цели или состояние глубины, проходит `PA`, если записанные
цели ещё годны и их слоты memo не переписаны, — а свежая резолюция возвращает ДРУГИЕ цели/состояние.

**Почему не тавтология (урок `texmemo8`, с. 121):** расхождение возникает не на пути счётчика, а в том же сравнении
§5.2, которое при 2 обязано молчать, и на реальных выходах: ожидаемые биты — `0x001` O (другие `image_id`/`desc`/
`depth_info`) и/или `0x002` K. Регистровый источник — самый частый (269,5 XW на строку в `k3c126` [c]; 52,7 записи
объекта на строку, каждая двигает все группы), поэтому контроль жив на опоре по построению сцены [I]. **Правило для дыма
шага 5:** `rts_bad > 0` И хотя бы одна строка `RtSkipVerify: MISMATCH … mode=3` с битом `0x001`; только биты
`0x040`/`0x080`/`0x200` (состояние, а не выходы) — контроль не засчитан.

**Почему не одна группа:** группа `G_depth` отдельно могла бы не сработать ни разу на опоре [U]; контролю нужен источник,
живость которого известна до прогона. Если лид требует ровно одну группу — вопрос В3 §12.

## 7. Счётчики, строки лога, инварианты, тождества — п. 76(з)(5)

### 7.1 Счётчики `FrameTrace-x` (все СЫРЫЕ штуки; `micros=false`; новых таймеров нет)

| имя | значения | смысл |
|---|---|---|
| `rts_n` | 1–3 | вооружённые draw, дошедшие до места A |
| `rts_pa` | 1–3 | `PA` истинен |
| `rts_pb` | 1–3 | `PA` и `PB` истинны (⊆ `rts_pa`) |
| `rts_skip` | 1 | резолюция И захват пропущены (при 1 = `rts_pb`; при 2/3 = 0) |
| `rts_skip_r` | 1 | пропущена только резолюция (при 1 = `rts_pa − rts_pb`; при 2/3 = 0) |
| `rts_chk`, `rts_chk_b` | 2–3 | сверки резолюции / и захвата (= `rts_pa` / `rts_pb` при 2/3; при 1 = 0) |
| `rts_bad` | 2–3 | расхождения §5.2 (**обязан 0 при 2; > 0 при 3**) |
| `rts_race` | 2–3 | гонка `bind_stamp` (ряд, не расхождение) |
| `rts_xa_rec`, `rts_xa_cfg`, `rts_xa_reg`, `rts_xa_arg`, `rts_xa_unh`, `rts_xa_memo`, `rts_xa_img` | 1–3 | причины непрохождения `PA` (первое несработавшее; при 3 `rts_xa_reg` = 0) |
| `rts_xb_ids`, `rts_xb_live`, `rts_xb_meta`, `rts_xb_ser`, `rts_xb_bound`, `rts_xb_pass` | 1–3 | причины непрохождения `PB` |
| `rts_rec`, `rts_rec_x`, `rts_ovf` | 1–3 | записи взяты (полный путь) / не взяты по строгому правилу / переполнение таблицы |
| `rts_wr`, `rts_wr_obj` | 1–3 | вызовы крючков: сеттеры / запись объекта |
| `rts_refuse` | ≠0 | draw с ручкой ≠ 0 и отказом §4.2 |
| `rts_xthr`, `rts_acqw` | 1–3 | **стражи, обязаны быть 0 на каждой строке** (ручка ≠ 0 на чужом потоке; запись группы внутри draw) |

### 7.2 Строки лога

`RtSkip: mode <n> ctx_slots=8 groups=11 rec_bytes=<k>` — раз на значение при первом вооружении; `RtSkip: refused
reason=<имя>` — раз на причину; `RtSkipVerify: MISMATCH …` (§5.2) — ≤ 40.

### 7.3 Тождества для скорера (на СУММАХ окна 10–88 п. 55(б) каждого блока, блоки по строкам `GateArm:`; допуск штук
256 на сумму окна — прецедент п. 64(д): флип забирает счётчики строки в разные мгновения)

- **Т1** `rts_n = rts_pa + Σ rts_xa_*`; **Т2** `rts_pa = rts_pb + Σ rts_xb_*`;
- **Т3** при 1: `rts_skip = rts_pb`, `rts_skip_r = rts_pa − rts_pb`, `rts_chk = rts_chk_b = rts_bad = rts_race = 0`;
  при 2/3: `rts_skip = rts_skip_r = 0`, `rts_chk = rts_pa`, `rts_chk_b = rts_pb`;
- **Т4** `rts_n ≤ draws` главной строки `FrameTrace` (подмножество: ранние возвраты `:4042–4092` до места A не входят);
- **Т5** `rts_rec + rts_rec_x ≤ rts_n − rts_skip` (запись берут только полные draw, дошедшие до поста).

### 7.4 Нулевой и положительный контроль (для печати)

- **Нулевой (плечо `rtskip=0`):** на строках окна 10–88 плеча 0 каждый `rts_*` = 0 (защёлка 0 ⇒ ни крючков, ни мест
  A/B, ни поста); строк `RtSkipVerify` в прогоне нет.
- **Положительный вооружения (плечо `rtskip=1`):** в окне каждого блока плеча 1 Σ`rts_n` > 0, Σ`rts_skip` > 0,
  Σ`rts_wr` > 0; в логе ровно одна `RtSkip: mode 1`, ни одной `RtSkip: refused`.
- **Стражи:** `rts_xthr` = `rts_acqw` = 0 на каждой строке окна обоих плеч; `rts_bad` = 0 при 1 по построению (Т3).

## 8. Цена, отказы, «0 — прежний путь побайтно»

### 8.1 Цена [I] (меряется дымом шага 5 и самим ABBA; в вердикт входит только через Δ)

При 1 на draw: защёлка (загрузка + TLS), поиск записи (≤ 8 сравнений адреса), `PA` (11 поколений, 2 float, 1 загрузка,
≤ 9 слотов memo по 2 загрузки, ≤ 9 `try_get`), при `PA` — копия выходов (размер [U], печатается `rec_bytes`; порядок
1–2 КиБ), Touch + `BindRenderTarget` на цель; `PB` — пересказ быстрого предиката на цель (≈ 20 сравнений),
`state_serial`, `is_bound`, `MetaEpoch`, проход; воспроизведение — ≈ 10 записей на цель. Крючки: ≈ 6 600 вызовов на
кадр [c] × (TLS + поиск контекста). Полные draw платят черновик записи в цикле резолюции и строгую запись на посте.
Оценка пропущенного draw ≈ 100–200 нс против ≈ 495 нс полного пути [c, с ценой переписи] — отсюда ≈ 150–350 нс на
пропущенный draw [I]; при `rts_pb` ≈ 80–85 % draw — ≤ ≈ 1,3 мс/кадр в лучшем случае [I, верх]. Переписи программы
завышали в 1,6–20 раз (п. 76(ж)); число не прогноз. При 2/3 — полный путь плюс предикаты и сверка: только дым и
`k3k127`, не время.

### 8.2 Довод «0 — прежний путь побайтно»

При `t_rts = 0` (ручка 0 и прошлый draw не вооружён): защёлка — одна relaxed-загрузка ручки и TLS-проверка, медленная
половина не зовётся; место A — `if (t_rts == 0) [[likely]]` → прежний вызов `PrepareDrawRenderState` с теми же
аргументами; черновик в цикле резолюции — `if (t_rts)` не выполняется; место B — прежний вызов `AcquireRenderTargets`;
пост и закрепление — не выполняются; крючки — одна TLS-проверка маски (при `rk3cen = 0` и `rtskip = 0` маска 0, как
сегодня `t_rk3 = 0`). Ни одной записи в состояние эмуляции, ни одного счётчика (`rts_*` = 0 — нулевой контроль §7.4),
ни одного выделения; ветвления эмуляции от ручки не зависят. Переход 1 → 0 (первый draw блока плеча 0) пишет только
TLS-таблицу `rtskip`. Код резолюции и захвата не меняется ни в одной строке — вызовы только оборачиваются. Отличие
измерительной сборки от `d3a981a2` — код с. 116–126 и этот; база плеча 0 — не измерение `d3a981a2` (п. 76(з)(6)).

## 11. Риски и что проект НЕ доказывает

- Не доказывает выигрыш, не даёт прогноза; 60 FPS не обещаются. R_K3⁺ и любое число §1 — не выигрыш.
- Полнота источников — довод §2.3 по коду на `57277dd1` плюс самопроверка на прогнанных сценах; будущий код, пишущий
  `HW::Context` в обход сеттеров или меняющий смысл memo-попадания, её ломает.
- Самопроверка — один шаг; многошаговая цепочка пропусков при 1 — индукцией §2.3(4) [I].
- Строгое взятие записи и Rel_skip шире п. 64(б) сужают множество пропуска относительно S_K3 — выигрыш меньше R_K3⁺
  и по этой причине тоже.
- Пропуск резолюции без захвата (фаза A без B) — снимает только резолюцию; доля — ряд `rts_skip_r`.
- Воспроизведение порядка Touch/`BindRenderTarget` делает LRU тем же; время жизни образов в GC — то же [I].
- Счётчики `rt_hits`, `rt_fast_*`, `DrawTargetsNs` в плече 1 падают по построению (§3.2) — между плечами не
  сравниваются.
- Одна сцена для времени (Sky Garden), одна сессия; режим BDA — свойство популяции.
