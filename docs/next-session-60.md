## 1. Решено измерениями — не переоткрывать

- **B9 (dynamic offsets) закрыт.** В единицах CPU потолок 1–1,4 % потока (0,45 мкс на пуловый
  набор × 1 451): с `recpack` записи дескрипторов уже на потоке записи. Не возвращаться.
- **`rtfast` включён** (−0,75 / −1,21 / −1,81 %, три повтора). Его свидетели: `bind_stamp`,
  backing, view info, метаданные desc, `TextureCache::MetaEpoch()`, запись `AssociateStencil`.
  Любая новая мутация `m_surface_metas` обязана звать `BumpMetaEpoch()`.
- **`dawalk` на пустыне −2,6…−5,3 %, в Sky Garden +4,1…+5,1 %** — обход, идущий на глубину
  очереди вперёд, строит результаты на кадр раньше, и они остывают (`da_take_us` 3,0 → 4,0 мс,
  `da_busy` ×10, `da_miss` ×2) плюс контенция `PipelineCache::m_mutex` с compute-prefetch.
  Умолчание 0. Ручка `dawalklead` (по умолчанию 1) **не мерилась в сцене**.
- **M2 — не кратный механизм:** разрешение привязок ≈20 % потока (≈7 мс); при КПД M1 ≈3 мс.
  Числа — `docs/local-session-59.md` §6. Не начинать, пока есть правки числа операций.
- Пакет B5/B7/B1d выпущен; подпись кэша трансляции сменилась в сессии 59 — новых правок в
  `graphics/shader/**` без нужды не делать (каждая стоит холодного входа пользователю).
- **Один необъяснённый прогон пустыни** (`sig1`): гостевой assert «There are too many
  objects/batches in this scene» + access violation гостя на 82-й с интро при выключенных гейтах;
  раньше не встречался, в семи прогонах не повторился. При повторении — разбирать первым.
- Прежние закрытые вопросы (`protbatch2`, `buffast`, `faultkb`, гейты записи A4, `acopyidle`)
  — см. `docs/next-session-59.md` §1.

## 2. Работы сессии (по отношению выгода/риск)

1. **`dawalklead` в Sky Garden** — одна серия A/B (`dawalk=1 dawalklead=1`, три повтора, при
   необходимости `dawalklead=2`). Смотреть `da_take_us`, `da_busy`, `da_miss`, `da_wlag_us`,
   `da_wdepth`, `da_wdrop`. Если регрессия снята — `dawalk` стоит −2…−5 %; если нет — закрыть.
2. **B3 — memo поиска программ по неизменным регистрам** (≈9 % потока: `PrepareProgram` 2,7,
   `GetGraphicsPrograms` 2,1, сравнения ключей 0,8+0,9, `BuildStageStaticKey` 0,7,
   `GetGraphicsPipeline` 0,9). `e9_adj` = 79 % наборов идут подряд с тем же pipeline. Сначала
   счётчик потолка: доля draw'ов, у которых регистровые входы `PrepareProgram` (VS/PS регистры и
   user data, `ShaderRegisters`, `ClipControl`, `ModeControl`, `GeControl`, prim type, экспорты
   целей) байт в байт равны предыдущему draw; затем memo с прямым сравнением входов (не dirty-флаги
   в обработчиках PM4 — поверхность слишком велика).
3. **B6** — дайджест `static_state` в хэше `ProgramKey` (0,8 %, нулевой риск).
4. **Защита страниц после загрузки** (`FlushRegion` → `VirtualProtect` 5,4 % + `ApplyGuard` 2,2 %
   на пути `SynchronizeBuffer`, 177 вызовов на кадр): единственная крупная нетронутая статья и
   самая рискованная (в сессии 58 ревью нашло потерю записи гостя ровно в этой области). Только с
   протоколом «вооружить → эпоха → снять грязные биты, чьи эпохи не сдвинулись» и самопроверкой.
5. M2 — только после 1–4.
