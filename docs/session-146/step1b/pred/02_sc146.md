## 5. Пропуск W пары (п. 309(к)(1) в редакции п. 316(б)–(г); заменяет букву печати 01)

`sc146.py --skip-w <w>` (функция `skip_w`) отвечает `SKIPPED_V_NOT_ENTERED` (rc 0) **только** при положительном свидетельстве, что V пары
не вошёл, — все члены сразу:
1. у V есть чтение (`runs146/<v>.score.json`, если его sha лога = строке `enter_scene end` `step2/times.txt`, иначе лог) и исход `NOT_ENTERED`
   (строки `Level has started: <уровень>` нет);
2. файл `log_<v>.txt` есть; 3. его размер > 0 байт; 4. его sha256 **сейчас** = последней строке `<chain> <v> enter_scene end … sha256` в
   `step2/times.txt` (п. 316(б); в чтении по json — файл на диске, а не sha из json);
5. ключ V — `attempt:<исход>` (V ушёл без маркера смерти и без строки входа). Ключ-маркер — K1 (`--- Error ---`, `--- Fatal Error ---`,
   `Unhandled exception:`), K2 (`GpuHangAbort:`, `ErrorDeviceLost` в логе или stdout эмулятора), `VALIDATION_STOP` — до строки входа: **W запускается**
   (п. 316(в), вариант исполнителя RC2 принят лидом).

Иначе — `RUN` (rc 1), W идёт по порядку: лога нет; лог 0 байт; sha лога ≠ строке `times.txt` (или строки нет); ключ-маркер; V вошёл; V не сделан.
Каждая строка ответа при `NOT_ENTERED` V называет ключ V (`… outcome NOT_ENTERED key <ключ> (<источник>); …`), и строка `SKIPPED` несёт размер и
sha лога; `go146a.sh` пишет строку ответа целиком в `skipped_<w>.txt` и в строку `times.txt` (п. 316(г)). Фикстуры: `test_sc146.py` F13 (ключ и
свидетельство в строке), F13b (лога нет, чтение по логу — случай A опыта `rt146_skipfx`), F13c (лога нет, чтение по json), F13d (0 байт — случай B),
F13e (0 байт и строка `times.txt` с sha пустого файла — член размера сам по себе), F13f (другой sha, по логу), F13g (лог изменён после
`score.json`, по json), F13h (нет `times.txt`), F13i (ключ `attempt:no_stable` → `SKIPPED`), F13j (семь ключей-маркеров K1 / K2 / `VALIDATION_STOP`
по логу и по json → `RUN`), F13k (опыт `rt146_skipfx` на синтетическом корне с копией `C:/kyty/s145/v145_02.json`: A и B → `RUN`); мутанты
