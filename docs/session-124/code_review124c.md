## 2. Предмет ревью п. 51

**(а) Код вне `O1..O2` на пробе и вне пауз вообще.** На пробе вне `O1..O2`: `t_p_win` на входе (одна загрузка), голова
вызова O1 до `rdtsc` (вызов, страж статики `cycles_per_ns`, сравнение); после O2 — хвост O2 (перевод в double, деление,
возврат), вычитание, сравнение, два сложения, инкремент. Итого ≈ одна `NowNs` плюс ≈ 6 простых операций, 4–10 нс на пробу
[I]. На узел D — 42,5 / 61 = 0,70 пробы ⇒ 3–7 нс из 5 530 нс `w̃` (≤ 0,13 %). На свободный узел — 8,6 / 61 = 0,14 пробы ⇒
0,6–1,4 нс из 4 554 (≤ 0,03 %). Направление: `w̃` растёт сильнее у узлов с большим числом пауз, то есть у нужных. Это
смещает `f_free` вниз — в опасную сторону, но на ≤ 0,13 % относительно: при U ≈ 500 мкс это ≤ 0,7 мкс, на два порядка
меньше 2SE. Правки не требует; в печать — строкой.
Отдельно: проверка `t_p_probe` на входе КАЖДОЙ паузы режима 3 — новый член штатного остатка, который T не видит. 0,3–1 нс
× 42,5 = 13–43 нс на узел [I] — входит в то, что должен покрыть запас 3× (N1).

**(б) Инвариант «окно не открывается и не закрывается внутри паузы» — ДЕРЖИТСЯ.** Проверены все пути.
- `WindowBegin` зовёт только `SkcCensus::SkipSiteD` (`textureCache.cpp:5711–5720`, пауз нет) из `renderDraw.cpp:3564`
  (`DrawIndex`) и `:3773` (`DrawAuto`). В этих функциях локальных `Skc3Pause` нет, а сами они не вызываются из кода
  переписи.
- `G3::OpEnd` зовёт только `SkcCensus::OpEnd` (`:5657–5662`) ДО своей паузы (`:5663`). Окно в `G3::OpEnd` закрывается
  ДО его паузы (`:4590–4602`). `SkcCensus::OpEnd` зовёт только деструктор `OpScope` (`textureCache.h:365–368`), а
  `OpScope` — это локал функций отрисовки и диспатча (`renderDraw.cpp:3517`, `:3726`, `renderCompute.cpp:291`) и
  M-операций (`bufferCache.cpp:1756`, `:1831`), где пауз нет.
- `GcSpan` стоит только в `RenderContext::RunGarbageCollector` (`renderContext.cpp:397`). Его зовут только пять мест
  `graphicsRun.cpp:1021`, `:1042`, `:1067`, `:1077`, `:1085` — между обработкой PM4, вне операций и вне пауз.
- Все 46 объектов `Skc3Pause` лежат в функциях переписи (`bufferCache.cpp:3160–3317`, `textureCache.cpp:4602–5964`,
  перечень снят `grep`), и ни одна из них не вызывает эти три точки.

**(в) `t_p_win` на границе кадра — пути нет.**
- `PWinD` поднимает только `WindowBegin`, и только при живом узле: узлы есть только при `t_mode == 3 && t_skip`
  (`OpBegin`, `:5651–5653`).
- Опускает `G3::OpEnd` из деструктора `OpScope` при `t_mode == 3` на КОНЦЕ операции. `t_mode` меняется только в
  `SkipCeilFlipBoundary` (`graphicsRun.cpp:3900`). Это обработка пакета флипа на потоке GuestGpu, вне любого `OpScope`:
  операции живут внутри вызова отрисовки/диспатча, а флип — отдельный пакет. CPU-флип идёт через `PrepareCpuFlip` после
  закрытия `GcSpan` (`:1085–1086`, `GcSpan` — локал вызванной функции).
- Вложенный `OpScope` не вооружается (`OpBegin` при `t_kind != 0` → false), но окно закрывает внешняя операция.
- `PWinGc` восстанавливается деструктором `GcSpan` всегда, когда он был поднят (`textureCache.h:503–507`).

Значит, при `G3FrameEnd` `t_p_win == 0`: 256 калибровочных пауз (`:5141–5143`) и пауза финализации (`:5159`) не
считаются в `t_p_cnt` и не становятся пробами. Слив `t_tin_*` внутри паузы финализации (`:5166–5170`) безопасен по той же
причине. Страховка предложена в N2.

## 3. Non-blocking

**N1 (вопрос лиду; посылка правила, не код).** «Не покрыта только проверка `t_mode`/флага до `O1`» (п. 50(а)) — неверно
по объёму. Вне T лежит не только это.
- Конверт вызова функции переписи: проверка в месте вызова, `call`/`ret`, пролог и эпилог (сохранение регистров, кадр)
  — у всех 46 пауз, функции переписи вне строки.
- Код переписи до объявления паузы: `SkcCensus::Upload` `:5936–5944`, `StampW3` `:5609–5617` (и обёртка `SkcStampW3`
  `:5605` — второй конверт).
- Код переписи на стороне вызывающего: `descriptors.cpp:4142–4150` — копия `view_info`, правка `level_count`, два
  вызова = две внешние паузы с двумя конвертами.

**Сценарий отказа:** настоящая цена переписи на внешнюю паузу τ_true = T + E. При E > 2·τ_ctx⁺ допущение A3
(`τ_true ≤ 3 τ_ctx⁺`) ложно. Тогда `f_t^{X+}` берётся по сетке {0, τ⁺, 3τ⁺}, не доходящей до τ_true, `f_free⁺` занижен, и
U < 500 может закрыть пропуск ложно. Оценка [I]: E ≈ 2–6 нс против ожидаемого τ_ctx⁺ порядка 10–20 нс — запас есть. Но
он не измерен, а раскрытая граница чтения (τ_ctx⁺ ≈ 35 нс ⇒ U = 500) лежит в нескольких нс.

**Что изменить (решение лида, одно из):**
- (i) записать в правило, что A3 покрывает и конверт/код вызывающего [I], и печатать E рядом с τ_ctx;
- (ii) измерить E в дыме 6а. Например, добавить к калибровке `G3FrameEnd` вторую петлю из 256 вызовов внестрочной
  пустой функции переписи с паузой внутри (`[[gnu::noinline]]`) и печатать разность петель как E на паузу. Это новый код
  и новый шаг — только если лид так решит.

**N2 (страховка (в), по желанию).** Сейчас пути нет (§2(в)), но нарушение было бы невидимым. **Сценарий:** будущая правка
вводит ранний выход из `OpScope` мимо `G3::OpEnd` или смену `t_mode` внутри операции. Тогда `PWinD` доживает до
`G3FrameEnd`, 256 калибровочных пауз горячего цикла становятся оконными, ≈ 4 пробы на кадр меряют остаток горячего
цикла, и τ_ctx смещается ВНИЗ (опасная сторона) без единого сигнала. **Правка (3 строки):** в начале `G3FrameEnd` —
`if (t_p_win != 0) { Bad(); t_p_win = 0; }` (существующий `skc3_bad`, обязан 0, новых счётчиков нет). То же — сброс
`t_p_win`/`t_p_cnt`/`t_p_probe` на ребре в `G3Latch`. Не требуется до дыма 6а, если лид считает §2(в) достаточным.

**N3 (G10 и редкие кадры).** Строка с финализацией, чьи кадры имели < 61 оконной паузы, даст `skc3_tin_n` = 0, и G10 в
редакции п. 50(а) («> 0 в каждой строке с финализацией») объявит окно НЕ ДОПУЩЕН по формальному признаку. На Sky Garden
≈ 429 млн пауз `s2s124` на ≈ 2 700 помеченных кадров — порядка 2 600 проб на кадр. Вероятность мала, но харнессу знать.
Флаг и счётчик переживают кадр, поэтому пробы кадра M могут прийти в строку финализации вместе с кадром M+2 (`open2`) —
это согласовано со сливом при финализации всех открытых.

**N4 (алиасинг, без правки).** При точной повторяемости числа оконных пауз P кадр-в-кадр и P ≡ 0 (mod 61) пробы
брали бы одни и те же ≈ P/61 сайтов каждого кадра. Это всё равно ≈ 2 600 сайтов по всему кадру, смещение τ_ctx — только
если эти сайты систематически отличаются. Проверяемо в дыме 6а: разброс `skc3_tin_n` по строкам должен быть ненулевым.

**N5 (ответ на п. 50(и), буквально).** Вне ветки `t_mode == 3` дифф меняет три вещи, все не-семантические.
- (1) `FrameTrace-x` при любом режиме печатает `skc3_tin_ns=0 skc3_tin_n=0` (`videoOut.cpp:3021–3022`; таблица
  печатает все поля с нулями). Это +2 чтения счётчика на флип, `Counter::Count` +2 — это «таблица счётчиков».
- (2) `GcSpan` получил член `m_win = 0` с инициализатором — одна 4-байтная запись на каждый вызов
  `RenderContext::RunGarbageCollector` в ЛЮБОМ режиме (`textureCache.h:513`). Цена — доли нс на кадр.
- (3) `Skc3Pause` вырос с 1 до 16 Б (`m_o1`, без инициализатора — исполняемых инструкций в режимах 0/1/2 не добавляет),

  вызываются, может отличаться раскладкой, но не путём.

Шаги, выполняемые в режимах 0/1/2, не изменились. Внутри режима 3 изменилась цена КАЖДОЙ паузы: загрузка `t_p_probe`
