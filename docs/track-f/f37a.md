### §0.2 Форма стенда — выбор и основание

**Выбор: тест в наборе тестов — отдельная цель `f25_read_fail_stand` (`tests/F25ReadFailStand.cpp`, `EXCLUDE_FROM_ALL`, без `add_test`), отказ вносится перехватом импорта `ReadFile` в таблице импорта самого исполняемого файла стенда; ручки `KYTY_TEST_READFAIL` нет.** Основания: (1) код эмулятора стенда = FS11 побайтно — в `src/` ни одной правки (ручка в `fileSystem.cpp` или `sysWindowsFileIO.cpp` сделала бы файл отличным от `ee9632be`; равенство файла печатается — §1); (2) отказ вносится ровно на границе, где он возникает в игре (`ReadFile` → `FALSE`), и проходит весь путь `SysFileRead` → `File::Read` → `ReadGuestWithRetry` → вход → обёртка гостя; (3) входы зовутся как их зовёт гость — указателем из базы символов `libkernel` этой сборки по NID через SysV ABI (`InitLibKernel_1`, `FindByNid`), включая обёртки `read`/`pread`/AIO; (4) без игры, без замка, без установленного бинаря. ### §0.3 Плечи, объём, мера

- **A** — отказ вызова 1 (прямое чтение) и вызова 2 (обход); **K** — отказ только вызова 1, обход читает файл (форма F22a); **Z** — без отказа.
- По каждому из 6 входов (`sceKernelRead`, `read`, `_read`, `sceKernelPread`, `pread`, `sceKernelAioSubmitReadCommands`): **A 200, K 50, Z 50** — 300 испытаний на вход, 1 800 всего; порядок плеч внутри входа перемешан генератором (`mt19937_64`, зерно печатается); один процесс, один файл 3 146 049 байт известного узора.
- Испытание: случайные позиция (у `pread`-входов — ещё и позиция файла `q`, отличная от смещения), размер (50 % 1–4 096 байт, 30 % до 256 КиБ, 20 % до 2,25 МиБ; 25 % — за конец файла), `remaining` > 0 всегда (на конце файла обход не берётся — F22a §2.1 п. 1). Буфер гостя с охранными байтами по 32 с обеих сторон.
- **Мера испытания:** значение, отданное гостю (`ret`; у AIO — `return_value`, `state`, код вызова), `errno` (до вызова — метка 12345), позиция файла после вызова (`KernelLseek(fd, 0, SEEK_CUR)`), число вызовов `ReadFile` и внесённых отказов, куда писал вызов 1 (буфер гостя) и вызов 2 (не буфер гостя, `nbytes` байт), совпадение первых `ret` байт с файлом, целость охранных байтов, нетронутость буфера.

Позиция: у входов `read` — `pos_after` = `pos_before` + max(`ret`, 0); у `pread`-входов — `pos_after` = `q`.
- **Живость (п. 688(ж)(3)):** K жив, если в 50 из 50 на каждом входе — полное чтение, 2 вызова `ReadFile`, вызов 2 — в буфер хоста; Z — полное чтение, 1 вызов. Иначе — одна починка стенда внутри F37a.

### §0.4 Проект правки `KYTY_FIX_F25` (умолчание 0; в этом звене не пишется)

1. `ReadGuestWithRetry` получает выход «отказ обоих чтений» (`bool* failed`): истина, когда прямое чтение дало 0 при `nbytes` > 0 и `remaining` > 0 и чтение обхода тоже дало 0. Сама логика обхода не меняется.
2. `KernelRead`, `KernelPread` (после `file->mutex.Unlock()`, на месте проверки `is_invalid`): при `KYTY_FIX_F25=1` и `failed` — `return KERNEL_ERROR_EIO` (форма пути пустого дескриптора на том же входе, §0.1). Обёртки переводят без правок: `read`/`_read`/`pread` — `-1`, `errno` = 5 (`POSIX_N_CALL`); AIO — `return_value` = `0x80020005`, `state` = `ABORTED`, вызов — `OK`.
3. Позиция — как у пути ошибки (без изменения): `KernelRead` — `Seek(pos)` ещё раз под `failed` (страховка от отказа, сдвинувшего указатель, [I]); `KernelPread` уже восстанавливает `pos` (`:991`). Буфер гостя не пишется (копии нет).
4. Строка лога `FixF25: mode=<0|1>` при `FileSystem::Initialize` и `FixF25: read failed twice d=<fd> size=<n> pos=<p>` под пределом 32 строки; повторная инвалидация по `bytes_read` = 0 не исполняется (как сейчас).
5. Край: если между измерением `remaining` и обходом файл укоротили другим процессом, второй 0 может быть настоящим концом файла — проект перед `EIO` перечитывает `Size()`: `pos` ≥ размера ⇒ отдаётся 0 (конец файла), иначе `EIO`. [I] — в игре файлы данных только читаются.
6. Подпись трансляции не меняется (правка вне `src/graphics/shader/**`); кэши не холодеют.
