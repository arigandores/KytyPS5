# F47b (`HPP-803`, Red Team): враждебный отзыв F47a (`HPP-802`, Б34 — блоки заставки уровня)

**Вердикт: `SOUND_WITH_CHANGES`, RC1–RC11.** Наблюдение (0) и фаза подтверждены своим кодом; форма снимка годна с поправкой фазы
(RC6) и члена годности (RC7); член происхождения М2 в нынешнем виде **не ловит ровно ту форму, которую требует RC14 F32b** (устаревшая
текстура / цель, форма Б42) — RC1–RC4 обязательны до тега, без них исход `НЕ ДЕФЕКТ` или `дефект` по §5 F47a может оказаться ложным.

Основание: `7df0fe5f:docs/ROADMAP.md` п. 702(ж) (F47b — враждебный отзыв), форма п. 673(ж)(7), RC14 `7df0fe5f:docs/track-f/f32b-review.md`
(«**RC14 (строка 185, Б34).**»). Вход: отчёт F47a `67722f0d:docs/track-f/f47a.md` (ссылки ниже — по `d0bfaf1f`, тот же текст), файлы
`docs/track-f/f47a/`. Звено офлайн: игра не запускалась, замок не брался, бинари и кэши не трогались; команды — в окна без чужого замка
(ожидание — `f43a/wait_f43a.py`, длинная команда — под `f47a/watch_f47a.py`). Карта ссылок — `f47b/refs_f47b.py` (§5).

### 1.2 Постоянная d и фаза — подтверждены, но фаза зависит от n старта [c]

Кадры против секунд (17 записей Sky Garden): `dn` 735–755, CV 0,95 %; секунды от строки старта до блока по `dt_us` 26,53–36,55 с, CV 8,6 %

**Но `dn` не постоянна — линейна по n старта:** `dn` = 713,0 + 0,1075 · n₀, r = 0,959, остатки −3,4…+2,8 (`f47b/fit.out`;

### 1.3 Код снимка [c]

- Граница снимка — после показа: `d0bfaf1f:src/graphics/presentation/videoOut.cpp:1274` («m_presenter.Present(*r.frame);»), затем
  `:1280` («Graphics::RenderDocOnGuestFlip(m_presenter.Renderer());»); `StartCapture` — в той же функции (`d0bfaf1f:src/graphics/presentation/renderDoc.cpp:229`,
  «if (state == RenderDocState::Requested) {»). Снимок с `KYTY_RD_FLIPS=1` содержит работу ГП между показом k и показом k+1; всё, что записано
  раньше (текстуры, цели прошлых кадров, атлас UI), в снимке — **начальное содержимое без писателя**. Миниатюра — изображение, показанное
  в конце снимка. См. RC1, RC7.
- Список `KYTY_RD_LEVEL_FRAME` разбирается и сортируется (`d0bfaf1f:src/graphics/guest_gpu/graphicsRun.cpp:921`, «KYTY_RD_LEVEL_FRAME=<n>[,<n>...]»);
  12 значений шагом 3 — та же форма, что `f12_rd` (12 снимков) — годна.
- `KYTY_DUMP_TEX` пишет **первые три** загрузки адреса, не последнюю: `d0bfaf1f:src/graphics/host_gpu/renderer/cache/bufferCache.cpp:2004`
  («if (n < 3) {»); образ, который ГП изменял, уходит раньше, без дампа (`:1966`, «if (IsRegionGpuModifiedFromGpu(vaddr, size)) {»); при
  ручке адрес обходит импорт (`:1977`, «if (vaddr != dump_tex) {»). См. RC2, RC9.

## 2. Требуемые изменения

**RC1 (класс N ⇒ `дефект`; §4.2, §4.3 «N», §5 п. 4; противоречие с «R»).** `d0bfaf1f:docs/track-f/f47a.md:213` — «R … выход за снимок (цель
записана до снимка) — «не определено»», а следующая строка — «N … писателя в снимке нет … М2 = «не равно» по определению», и §5 п. 4 — «класс N ⇒
`дефект`». Снимок в один флип (§1.3) по построению не содержит писателей ресурсов прошлых кадров. **Сценарий отказа:** заставка рисуется в
промежуточную цель один раз на смене состояния (2 + 3 кадра, §1.1) или читает атлас UI, загруженный при старте уровня; на снимке у этой
цели / атласа нет писателя; разбор относит точку к N (а не к R — правило выбора не задано) ⇒ `дефект` без дефекта эмулятора. **Изменить:**
(а) единое правило: вход без писателя в снимке — R-за-снимок («не определено»), если ресурс является целью или хранилищем хоть в одном
событии снимка, и T (с членом М2), если это образ выборки; (б) N ⇒ `дефект` только при доказанном отсутствии писателя: ни один из соседних
снимков сетки (шаг 3 — каждый третий кадр) и снимок `FLIPS=2` (если назначен) не пишет ресурс, а М2а для него «нет в памяти гостя»;
иначе N — «не определено». Без (а) исход зависит от того, как разборщик назовёт точку.

**RC2 (член М2 не ловит устаревший вход — ровно форму RC14 / Б42; §3.4, §4.3 «T»).** `:204` — «байты T# в памяти гостя (`_tex_<n>.bin` тега
`f47_dt`, последняя загрузка до показа блока) **равны** байтам файла игры». По коду (§1.3) `_tex_<n>` — копия **первых трёх** загрузок адреса,
сделанная в момент загрузки, в **другом** процессе (`f47_dt`), а не память гостя на draw блока снимка. **Сценарий отказа (форма Б42):** по
адресу A игра загрузила текстуру X, позже — Y; эмулятор не заметил записи и держит образ X; D_b читает X. Дамп `_tex_0` = X (первая загрузка)
= файл X ⇒ М2а «равно»; своё декодирование X = тексели снимка X ⇒ М2б «равно» ⇒ §5 п. 3 `НЕ ДЕФЕКТ` при дефекте. Обратный отказ: в `f47_dt`
адрес образа другой (размещение между процессами не доказано одинаковым) ⇒ дамп чужих байт ⇒ «не равно» ⇒ ложный `дефект`. **Изменить:**
(а) член М2 сравнивает три величины одного процесса: байты памяти гостя по адресу T# **в кадре блока** (дамп по номеру показа / событию draw,
не по счёту загрузок), байты последней загрузки этого образа до D_b и тексели D_b; (б) номер загрузки, номер показа и адрес — строкой лога
дампа; последняя загрузка до блока вне дампа (счёт > 3) ⇒ «не определено»; (в) адрес, формат и размер T# в `f47_dt` = в снимке (иначе
«не определено», не «не равно»); (г) файл игры — тот, что игра последним читала **в этот адрес** (строки чтения с адресом назначения), а не
любой совпавший. Если нужна ручка дампа по кадру — это код только измерения отдельным звеном; без него класс T — «не определено».

**RC3 («нет в файлах» ≠ «не равно»; §4.3 «T», §5 п. 4, Н3).** `:237` — «М2а «не равно» (байты ≠ файлу игры) … ⇒ `дефект`». Поиск по файлам не
различает «байты отличаются от файла, который игра читала в этот адрес» и «байт нет ни в одном файле». **Сценарий отказа:** текстура заставки
лежит в сжатом / упакованном контейнере (сжатие `.gnfp` F47a сам ставит [I]) или создаётся ЦП игры при работе (точечная сетка, палитра);
байты в файлах не найдены ⇒ «не равно» ⇒ `дефект`, хотя вход создан игрой. Н3 проверяет только, что поиск умеет сказать «нет», а не что «нет»
значит «эмулятор». **Изменить:** «не равно» (⇒ `дефект`) — только «файл и смещение названы по чтению игры в этот адрес, байты отличаются»;
«не найдено» — «не определено»; положительный контроль поиска — образ **того же контейнера и формата**, что вход блока (иначе П1 не
контролирует этот путь, см. RC5).

**RC4 (провенанс класса C «точные 0 / 1» обратно информативен для чёрного; §4.3 «C»).** `:211` — «член провенанса: значения — точные 0 / 1 …
[I: стечение устаревших байт в точные 0 / 1 маловероятно]». Неинициализированная, обнулённая или не синхронизированная с ГП память даёт
**ровно 0** — чёрный блок; белый блок «бело-розовый», соседние состояния голубые (§1.1) — не 0 / 1. **Сценарий отказа:** буфер констант
заставки эмулятор не досинхронизировал (форма Б12 / Б13), ГП читает нули ⇒ точный 0 ⇒ провенанс «да» ⇒ `НЕ ДЕФЕКТ`. **Изменить:** разделить
C на C-imm (литерал в коде шейдера — сравнение со словами программы из файлов игры / дампа программы гостя) и C-buf (буфер констант, вершинный
цвет — байты буфера в снимке = байты памяти гостя по адресу буфера в кадре блока, той же формой, что RC2(а)); признак «точные 0 / 1» как член
провенанса снять (оставить строкой справки).

**RC5 (положительный контроль П1 — на другом пути; §4.4).** `:221` — П1 = «значок HUD … ожидается класс T и М2 = «равно»». Значок — другая программа,
другой ресурс, другой путь загрузки; «равно» на нём не говорит, что компаратор скажет «равно» на пути D_b. **Сценарий отказа:** D_b — квад
констант (C-buf) заставки, П1 — текстура (T); П1 жив, но путь C-buf не контролирован ничем, и любой его исход читается. **Изменить:** П1 —
тот же элемент в кадре, где он цветной (белый / розовый / голубой, §1.1) или другой его состояние (2 + 3 кадра): то же место, та же программа
D_b, разный цвет — компаратор обязан различить цвета и назвать тот же класс; сетка снимков обязана накрыть такой кадр (кадры белого / голубого —
`dn` ≈ s + 7…s + 13) — член годности, иначе П1 «не определено». Значок HUD — второй контроль (П2), не замена.

**RC6 (фаза зависит от n₀ — допуск ±6 не покрывает; §3.1 «Фаза», §3.3).** `:153` — «s ∈ [735; 755] наблюдённых + допуск ±6 … ⇒ s ∈ [729; 761]»;
повтор — сетка `730,733,…,763` «сдвиг +1». По §1.2 `dn` = 713,0 + 0,1075 · n₀ (r 0,959). **Сценарий отказа:** под `--rd` загрузка медленнее
и n₀ тега 500 ⇒ ожидаемая серия на 766,8 ± 3,4 ⇒ сетка 729–762 не накрывает её ни одним снимком, повтор со сдвигом +1 — тоже ⇒ «снимок не годен
после повтора» ⇒ `ТУПИК` (§5 п. 1) из-за формы, а не из-за снимка. **Изменить:** (а) член тега — n₀ из лога тега; при n₀ вне [188; 374]
(диапазон выборки) печатается прогноз 713,0 + 0,1075 · n₀; (б) повтор `f47_rd2` — сетка от прогноза по n₀ первого тега ±8 шагом 3, не «+1»;
(в) у `f19_rd` под `--rd` n₀ = 326 (прогноз 748) — сказать это строкой, что ожидание тега внутри окна.

**RC7 (годность по миниатюре не доказывает, что блок нарисован внутри снимка; §3.1, §3.2).** `:159` — годность — детектор на миниатюре
`renderdoccmd thumb`. Миниатюра — показанный в конце снимка кадр; работа кадра k+1, сданная гостем до показа k (очередь флипов), в снимок не
входит (§1.3). **Сценарий отказа:** миниатюра чёрная, а писатель блока в снимке отсутствует (кадр гостя шёл с опережением) ⇒ снимок «годен»,
разбор находит «нет писателя» ⇒ N ⇒ `дефект` (с RC1) или «не определено». **Изменить:** член годности G′ вне замка (тем же реплеем, что
разбор): последний писатель цели показа и D_b — внутри снимка, детектор §1.3 на сохранённой цели показа после последнего события = миниатюре;
G по миниатюре — только отбор, G′ — член; снимок без G′ — «не годен», берётся соседний по сетке.

**RC8 (отрицательные контроли Н1, Н2 мертвы по построению на однотонном блоке; §4.4).** `:223` (Н1 — один изменённый байт ⇒ «не равно»), `:225`
(Н2 — соседний мип / UV со сдвигом ⇒ «не равно»). Блок однотонен (чёрный, белый — §1.1). **Сценарий отказа:** Н1 меняет байт индексов BC-блока
с равными опорными цветами — декодирование не меняется ⇒ «равно» ⇒ Н1 «мёртв» ⇒ М2 «не определено» ⇒ `ТУПИК` (§5 п. 2) без вины снимка; Н2 на
однотонной области даёт тот же цвет ⇒ то же. И наоборот, Н1 через sha256 полезной части тавтологичен (меняется любой байт — sha меняется) и
ничего не говорит о М2б. **Изменить:** Н1 — изменение, которое меняет декодированный цвет (опорный цвет BC / байт UNORM), выбранное до сравнения
по своему декодированию; Н2 — точка, у которой тексель снимка **отличается** от текселя точки блока (выбор по значениям снимка до сравнения);
член Н1 читается по М2б, не по sha.

**RC9 (исчезновение блоков под `KYTY_DUMP_TEX` — не «дамп не годен», а сигнал; §3.4).** `:183` — «член: блоки есть на видео этого тега …, иначе дамп
не годен». Ручка уводит адрес с импорта на staging (`bufferCache.cpp:1977`). **Сценарий отказа:** блоки — следствие пути импорта (форма Б42:
образ не перечитан); под ручкой staging-копия свежая, блоков нет; по F47a это «дамп не годен» ⇒ класс T «не определено» ⇒ `ТУПИК`, а
единственное прямое свидетельство пути эмулятора потеряно. **Изменить:** исход строкой правила до данных: блоков нет в `f47_dt` при живом
контроле видео (17 из 17 записей с FS8 блоки показывают) ⇒ «кандидат: путь импорта» ⇒ пункт лида (пара тегов `KYTY_HOST_IMPORT_MIN_KB`
большим значением / умолчание под замком), не `ТУПИК`.

**RC10 (тайлинг — исход по построению; §4.3 «T», §6).** «Раскладку тайлинга PS5 своим кодом снять [U]: … М2б «не определено»». Если T# тайловый
(у PS5 — норма), класс T уходит в «не определено» ⇒ §5 п. 5 `ТУПИК` с вероятностью, которую F47a не оценил. **Сценарий отказа:** тег, 4–8 ч
разбора, итог `ТУПИК` по известной заранее причине. **Изменить:** до тега назвать независимый первоисточник раскладки (уравнения swizzle GFX10 из
открытого AMD addrlib) и члены своего детайлера (фикстура на линейном T# и на одном тайловом образе с известным содержимым), либо записать
`ТУПИК` класса T тайлового как ожидаемый исход в кандидат правила и цену.

**RC11 (текст: охват записей; §0 п. 1).** `:18` — «стоит **во всех 17 записях Sky Garden на бинарях с FS8**», а `:45` — «Уровни: Sky Garden 77»;
детектор прошёл 17 выбранных (по одной на бинарь). **Сценарий отказа:** лид цитирует «все записи с FS8» в строке реестра, а в 60 непрогнанных
записях блоков может не быть (замысел со случайностью или гонка) — вывод о постоянстве шире данных. **Изменить:** «17 из 17 выбранных (по
одной на бинарь) из 77 записей с FS8», либо прогнать детектор на всех 77. Также «Реплей воспроизводит» (`:216`) — член годности снимка, не довод
провенанса (реплей воспроизводит и неверный вход — RC14): сказать это в §5 п. 3.
