### 2.3 Снимки на диске [c]

**Активность члена по снимку не определяется.** Условие каждого члена — значение регистра гостя (`DCC_ENABLE`, адреса метаданных, `ROUND_MODE`, включённая глубина при формате `kInvalid`, `GE_STEREO_CNTL`, нулевой размер диспатча), а решение эмулятора принимается до первого вызова Vulkan: член 6 вызова не порождает вовсе, члены 3 и 5 на вызовы не влияют, член 4 даёт draw без вложения глубины и с выключенным тестом — неотличимый от draw, где гость глубину выключил. Отладочных меток в поток команд эмулятор не пишет (в `src/` нет вызовов `DebugUtilsLabel` / `DebugMarker`). Структурное чтение (форма F12f ред. 2) видит только вызовы Vulkan.

Новых чтений 12 снимков (0,4–5,9 ГБ; `f12_rd_k01`…`k08`, `f13_rd`, `rd2_f3951`, `rd2_f4191`, `enemy_final_600`) не делал: довода выше достаточно, а чтение снимка дольше 60 с запрещено общим правилом 30, пока идёт серия FS5c (`HPP-511`). Из готовых выводов F12f: в `rdcs_f12_rd_k01.txt` (полный, со строкой `SUMMARY`) 86 диспатчей, с нулевым измерением 0; в неполных `k02`, `k03` — 3 476 и 55 строк `DISPATCH`, с нулём 0 — согласуется с членом 6 (нулевой диспатч до Vulkan не доходит), активности не показывает.

Следствие для правила: ветки «(б) активен в снимке» и «(в) в снимках не активен» по снимкам неразличимы. «Не наблюдаем» — не «не активен». Положительное свидетельство активности есть в журнале: строки членов 1, 2, 3, 5, 6 — в 282 логах из 282 с игрой, члена 4 — в 268.

### 2.4 Проект свидетеля: счётчики `KYTY_DIAG_F5` (умолчание 0, только измерение)

Назначение — различить для членов 1–3 «ветка, меняющая кадр, исполняется» и «не исполняется» на сценах со снимками. Кадр не меняет, вызовов Vulkan не добавляет. До кода — отзыв Red Team и решение лида по константам (имена, шаг печати).

1. **Что меряется.** Число событий процесса по веткам (штуки, `uint64`, нарастающим итогом). Вывод на член — «счётчик ветки > 0 на сцене» или «= 0 при живом положительном контроле».
2. **Сайты** (поток — исполнитель рендера гостя; сайты кэша — под `m_lock` кэша текстур; подтверждает Emu Engineer):

| Счётчик | Сайт | Смысл |
|---|---|---|
| `rt_draws` | разрешение цветовой цели draw, `colorRenderTarget.cpp` рядом с `:431` | все разрешения цветовой цели — положительный контроль |
| `dcc_rt` | там же, `has_dcc` | цели с DCC |
| `dcc_fill`, `dcc_fill_unknown` | `textureCache.cpp:3204` | заполнения метаданных; из них с кодом не из пяти |
| `dcc_skip_levels`, `dcc_skip_partial`, `dcc_skip_decode` | `textureCache.cpp:1916`–`1926` | очистка не исполнена при ненулевой маске — по причине |
| `meta_write_refused` | `textureCache.cpp:3184`–`3191` | запись в метаданные DCC / CMASK не заполнением |
| `cmask_rt`, `cmask_rt_unsupported` | `colorRenderTarget.cpp:441` | цели с `fast_clear` и адресом CMASK; из них не прошедшие условие |
| `fmask_rt` | `debug.cpp:211` | цели с `fmask_compression_enable` |
| `round_unorm`, `round_float`, `round_other` | `debug.cpp:246` | цели с `round_mode` по типу канала |
| `ds_unbound`, `ds_unbound_clear` | `depthRenderTarget.cpp:355` | draw с включённой глубиной без цели; из них с очисткой |
| `stereo_writes`, `stereo_nonzero` | `pm4Handlers.cpp:4014` | записи регистра; из них ненулевые |
| `zero_disp` | `renderCompute.cpp:936` | диспатчи нулевого размера |

3. **Чтение ручки** — раз на процесс (`static const bool`, `Common::EnvValueOn`: нет переменной или пусто — выключено). Плечом расписания быть не может и не задумана.
4. **Печать.** `DiagF5: mode=1` один раз при инициализации; `DiagF5: frame=<n> <имя>=<значение> …` при росте любого счётчика, не чаще раза в 2 с (форма `DiagBvhNodes` F11d). **Тождества для скорера:** `dcc_fill_unknown ≤ dcc_fill`; `cmask_rt_unsupported ≤ cmask_rt ≤ rt_draws`; `dcc_rt ≤ rt_draws`; `stereo_nonzero ≤ stereo_writes`; `ds_unbound_clear ≤ ds_unbound`; значения не убывают от строки к строке. **Инварианты, обязанные быть 0** (считает скорер, сверяя счётчик со строкой журнала того же сайта): `line_mismatch_dcc` (`dcc_rt` ≥ 1 ⇔ строка `ignoring PS5 color metadata … dcc=true`), `line_mismatch_round` (сумма `round_*` ≥ 1 ⇔ строка `color round mode`), `line_mismatch_ds` (`ds_unbound` ≥ 1 ⇔ строка `without a bound attachment`), `line_mismatch_stereo` (min(`stereo_writes`, 16) = числу строк `GE_STEREO_CNTL`), `line_mismatch_zero` (min(`zero_disp`, 32) = числу строк `skipping zero-sized dispatch`).
5. **Контроли.** Положительный: строка `DiagF5: mode=1`, `rt_draws` > 0, а на Sky Garden — `dcc_rt` ≥ 1, `stereo_writes` ≥ 16, `zero_disp` ≥ 1 (эти строки есть в 282 логах из 282). Нулевой: без переменной и при `=0` строк `DiagF5` нет; вызовы Vulkan одинаковы в обоих режимах (счётчик не ветвит исполнение); сайты вне `src/graphics/shader/**` — подпись трансляции и каталог варианта не меняются [I, проверяет ревью].

**Цена.** Приращение счётчика на сайтах, исполняемых раз на draw или реже; без чтения часов. Оценка — единицы наносекунд на draw [I], не измерялась.

**Теги** (Harness Engineer, под замком; бинарь диагностики из чистого worktree на базе п. 410(г)(6), установленный не меняется): форма V при `KYTY_DIAG_F5=1` на сценах со снимками — Sky Garden, `enemy_final`, `big_hand_pirate_island`, `ending_boss_after_credit`. Чтение: счётчики веток членов 1–2 (`dcc_fill_unknown`, `dcc_skip_*`, `meta_write_refused`, `cmask_rt_unsupported`, `fmask_rt`) и `round_unorm`.

**Редкое событие.** `dcc_rt`, `round_*`, `stereo_writes`, `zero_disp` нулём не будут (признак есть в каждом процессе). Счётчики веток могут быть 0; P(0) до данных — [U] (прежних прогонов с такими счётчиками нет). Ноль при живом положительном контроле читается «на этих четырёх сценах ветка не исполняется», не «в игре не исполняется».

**Второй шаг** — кадр-свидетель для члена с ненулевым счётчиком ветки: реплей снимка кадра с подменой (форма F12g) либо пара V с правкой под ручкой; проектируется после данных счётчиков.

**Чего проект не доказывает:** что ненулевой счётчик меняет картинку; что нулевой — свойство игры, а не четырёх сцен; что железо округляет иначе, чем хост; что поведение члена 4 на железе совпадает с хостом.
