## 2. Правка индексом против F20j4 — построчно (п. 600(б)(1))

### 2.1 Снятие открытых записей (`CloseWindow`)

F20j4: для каждой закрытой записи окна из `m_recent` по порядку — `remove_if` открытых (`open != 0`) с тем же (`slot1`,
`start_ns`), затем `push_back` закрытой. B: ключи закрытых записей окна (тот же фильтр `end > start && start < flip`),
сортировка, один `remove_if` открытых по `binary_search`, затем все закрытые по порядку `m_recent`.

Равенство держится на двух посылках — обе проверены по коду: (а) до этого места `r.waits` содержит только открытые записи —
единственный `push_back` выше — открытая метка (`35b454c6:src/common/diagB32.cpp:1877`, якорь «w.open     = 1;»; +1 —
«r.waits.push_back(w);»); (б) все записи `m_recent` — закрытые (`open` = 0): они приходят только из `WaitRing::Drain`, который
строит `WaitRec r` по умолчанию (`35b454c6:src/common/diagB32.cpp:383`, якорь «WaitRec r;»; +1 — «r.start_ns     =
x.start.load(std::memory_order_relaxed);») и поля `open` не пишет. Отсюда в F20j4 вставленные закрытые записи поздними
`remove_if` не снимаются, и открытая снимается ⇔ её ключ есть среди закрытых окна — порядок оставшихся открытых сохраняется
(`remove_if` устойчив), закрытые идут следом в порядке `m_recent`. **Тот же список, тот же порядок.** Ничьих нет (точное
сравнение пары).

### 2.2 `PickWaits`

Условие F20j4 `find(set, slot) && !find(must, i)` → B `in_must[i] == 0 && find(set, slot)`
(`35b454c6:src/common/diagB32.cpp:473`, якорь «if (in_must[i] == 0 && std::find(set.begin(), set.end(), r.waits[i].slot1) !=
set.end()) {»; +1 — «in_must[i] = 1;»): оба члена без побочных действий, флаг ставится ровно там, где F20j4 делал `push_back`
в `must` ⇒ та же конъюнкция; порядок обхода, вызовы `add` и их порядок, ветвь `rest` (`in_must == 0` ⇔ `!find(must, i)`),
сортировка `rest` по перекрытию и срез `kWLinesCap` — без изменений. Замечание без дефекта: `out = must` не срезается
(`35b454c6:src/common/diagB32.cpp:493`, якорь «std::vector<size_t> out = must;»; +1 — «*cut                    = 0;») — число
строк `-w` ограничено только числом записей окна (≤ ≈ 65 536 + открытые), это свойство F20j4, `w_cut` его не видит; вход §4.

### 2.3 `NearestSnapshot`

Внутренний цикл по `snaps` — индексы `j` с `kq[j] != 0` по возрастанию, то есть ровно те `j`, что F20j4 не пропускал, в том же
порядке; сравнение строгое `d < best_d` ⇒ при ничьей остаётся ранний (`35b454c6:src/common/diagB32.cpp:230`, якорь «for (const
size_t j: snaps) {»; +1 — «const auto d = t[i] > kq_t[j] ? t[i] - kq_t[j] : kq_t[j] - t[i];»). **Та же ближайшая, та же ничья.**

### 2.4 `RowOf` / `GidOf`

`RowIndex` хранит позицию **первой** строки с данным `slot1` (`35b454c6:src/common/diagB32.cpp:428`, якорь «if
(m_pos[static_cast<size_t>(s)] < 0) {»; +1 — «m_pos[static_cast<size_t>(s)] = static_cast<int32_t>(i);») = ответ линейного
поиска F20j4. `slot1 ≤ 0`: `RowOf` F20j4 возвращал `nullptr` — B тоже (`Pos` = −1); `GidOf` F20j4 искал линейно — B ищет
линейно, только если такие строки есть, иначе 0 (линейный поиск без совпадений тоже дал бы 0). Индекс строится после всех
изменений `r.threads` в своей функции (`MarkMandatory` — после `PickWaits`, `Format` — после сборки указателей `must`/`others`;
`r.threads` дальше не меняется) ⇒ указатели и позиции действительны. **Тот же ответ.**
