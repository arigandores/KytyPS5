### 2.3. Как игра обходит BVH [c по дизассемблеру `380bb9d6…`]

- Корень — узел 37 (тип 5, смещение `0x100`; pc `0x2a8`).
- Цикл верхнего уровня (pc `0x2c4`–`0x2d0`) и цикл нижнего (pc `0x40c`–`0x418`): `S_AND_B32 vcc_lo, ptr, 7` → `S_ADD_I32 vcc_lo, vcc_lo, -4` →
  `S_CMP_LE_U32 vcc_lo, 2` → **типы 4, 5, 6 идут в `IMAGE_BVH_INTERSECT_RAY`** (pc `0x8f8`, `0x52c`). Типы 0–3 и 7 — путь листьев.
- Лист верхнего уровня — запись экземпляра: `S_LOAD_DWORDX16` по `TLAS + [TLAS+48] + (ptr >> 3) × 128` либо `TLAS + 0x80` для типа 7
  (pc `0x2f0`–`0x314`); база нижнего уровня — поле записи `<< 3` (pc `0x380`).
- Лист нижнего уровня — список пар `(s26, s27)` в памяти BLAS с байтового смещения `ptr & ~7` (pc `0x42c`–`0x454`). `s26` — указатель
  треугольного узла, он идёт в `IMAGE_BVH_INTERSECT_RAY` (pc `0x474`), если `s26 & 7 ≠ 7`; конец списка — `s27 < 0` (pc `0x4e4`).
  **Тип треугольного узла (0–3) берётся из данных списка листьев, которые пишет построитель игры.**
- `S_TRAP 1` (pc `0x104`) исполняется, если `[TLAS+24] & 0x00040000 ≠ 0` (pc `0x0b8`, `0x0d0`, `0x0fc`, `0x100`).

Остальные 19 BVH-программ по циклам не разобраны [U]. Форма дескриптора у всех 60 инструкций одна (F3b §1), в 13 из 14 программ
T1 перед `S_TRAP` стоит та же проверка бита 18 (§7).

## 3. Почему не на стороне хоста (вариант H) — разбор

| что нужно правилу п. 369(д) | вариант H: перепись дерева хостом по памяти гостя | вариант E: счётчик в трансляторе |
|---|---|---|
| посещения узлов типов 0–7 | **нет**: хост не видит, какие указатели дошли до инструкции; перепись даёт число узлов в дереве — верхнюю границу. «0 в дереве» ⇒ «0 посещений» [c по включению], «> 0 в дереве» посещений не доказывает | **да**, по определению: счёт на самой инструкции |
| положительный контроль «посещений коробок > 0 и треугольников 0–1 > 0 в том же теге» | только «узлы есть в дереве» — иная величина, чем требует правило | **да** |
| нарушения `size` | только по узлам дерева, при верном разборе формата | **да**: то же поле, что видит инструкция |
| разбор формата | собственный формат игры: записи экземпляров 128 Б, указатель BLAS `<< 3`, списки листьев (§2.3); для 19 программ из 20 формат не разобран [U] | не нужен |
| свежесть данных | память BVH, возможно, пишет ГП [U] (F3a §3.5) — тогда копия ЦП устарела, нужна выгрузка с ГП с синхронизацией | данные те же, что читает инструкция |
| подпись трансляции | не меняется | меняется (§4.7) |
| код [I] | обход и выгрузка ≈ 300–500 строк, высокий риск ошибки разбора | ≈ 200–260 строк (§6) |

**Вывод [I]:** под правило п. 369(д) годится только E. H — перепись, которая может лишь подтвердить «0» и не даёт положительного
контроля в форме правила. Если лид требует неизменной подписи, H возможен как отдельное звено с чтением «в дереве», но правило
к нему придётся применять новым пунктом лида (проект правило не меняет).

### 4.4. Эмиттер (SPIR-V)

`EmitBvhNodeDiag`: `type = node_lo & 7`; `node64` — по правилу эмиттера (`spirvEmitterMemory.cpp:2144`: аргумент 1 не непосредственный
или ≠ 0); `idx = node_lo >> 3`; `size64 = desc2 | (desc3 & 0x3ff) << 32`; `viol = active ∧ ¬node64 ∧ (idx > size64)`;
`over = viol ? min(idx − size64, 0xffffffff) : 0`. Агрегация на волну без конфликтов атомиков:
для `t = 0…7` — `n_t = OpGroupNonUniformBallotBitCount(Reduce, OpGroupNonUniformBallot(active ∧ type = t))`; плюс
`n_viol`, `n_off` (`size64 = 2⁴² − 1`), `n_64` (`active ∧ node64`). Одна дорожка (`OpGroupNonUniformElect`) делает `OpAtomicIAdd` в
слова хвоста буфера промахов для ненулевых счётчиков и `OpAtomicUMax` для `over`; слово `waves` += 1. Если `fault_buffer_variable == 0` —
ничего, как у `EmitLoopCapTrip` (`df2b3179:src/graphics/shader/recompiler/backend/spirv/spirvEmitterMemory.cpp:1939`, якорь
«void EmitLoopCapTrip(EmitterState& state, uint32_t budget) {»; +1 — «if (state.fault_buffer_variable == 0) {»). Возможность
`GroupNonUniformBallot` в модуле уже бывает (`spirvEmitterModule.cpp:766`); эмиттер требует её при первом `BvhNodeDiag`.
`EmitDiagTrap` — то же для одного слова `traps` (дорожки с `active`).

### 4.6. Строки лога

- Один раз до первой `GuestOut`: `DiagBvhNodes: mode=1 words=16`. Читатель отличает «диагностика выключена» от «BVH не исполнялся».
