## 5. The report (report only)

### 5.1 Units

`a_hold_us`, `a_wait_us`, `mh_*_us`, `semwait_gpu_us`, `prio_us` are µs as printed. Every `pl_*_ns`, `gw_*_ns` and
`flip_rsv_wait_ns` is raw ns and is divided by 1000 **once**, into a key without the suffix (`pl_proc_ns` → `pl_proc`,
µs). A formula taken straight off the line without this is out by three orders of magnitude (session 96).

### 5.2 Per scene row (one flip)

`hold` = `mh_pro + mh_rt + mh_prog + mh_bind + mh_emit + mh_tail + mh_disp` (the render mutex on GuestGpu, draws and
dispatches); `emit_split` = Σ`pl_em_*` (inside `mh_emit`); `named` = `pl_pref + pl_eop + pl_bar + pl_sub + pl_gc +
pl_cmd`; `outside` = `pl_proc − a_hold_us − a_wait_us`; `residue` = `outside − named`; `residue_noflip` = `residue −
gw_flip` (`R_WAIT_FLIP_DONE` is a PM4 handler inside `Process`, in no named span); `residue_s96` = `pl_proc − (a_hold_us
− mh_pres_us) − named` (session 96's sealed form, for comparison only — see §8); `attributed` = `hold + a_wait_us +
named`; `remainder` = `cpu_gpu_us − attributed`; `thread_unwalled` = `dt_us − (gw_idle + gw_blk + gw_proc + gw_cmd)`;
`offcpu` = `dt_us − cpu_gpu_us`; `offcpu_unexplained` = `offcpu − (gw_idle + gw_blk + gw_flip)`; `ops` = `draws +
dispatches`; `cpu_per_op` = `cpu_gpu_us / ops` (also as the ratio of sums). `pl_look` (guest submit thread) is reported
and in no sum.

### 5.3 Columns

For every key: **mean** over the scene rows and **run sum**; the **per-row median only for keys that are not span keys**.
**Span keys** — every `pl_*`, every `gw_*`, `flip_rsv_wait`, `semwait_gpu_us`, `prio_us`, and every key built from them
(`emit_split`, `named`, `outside`, `residue`, `residue_noflip`, `residue_s96`, `attributed`, `remainder`,
`thread_unwalled`, `offcpu_unexplained`) — get **no median** (dropped, not computed over blocks; caveat (f)). For every
time key also: **share** = Σkey / Σ`cpu_gpu_us`, **per_op** = Σkey / Σ`ops`, **per_unit** = Σkey / Σ(own population:
`mh_draws` for the draw phases — caveat (g) —, `mh_n` for `mh_tail`, `mh_disp_n`, `a_hold_n`, `mh_pres_n`, each `pl_*_n`,
`pl_em_n`, each `gw_*_n`, `flip_rsv_wait_n`, `prios`). Consistency (report only, no check): Σ`hold`/Σ`a_hold_us`,
**Σ`emit_split`/Σ`mh_emit_us`** (not measured before — no untested bar is set on it), Σ`pl_proc`/Σ`gw_proc`,
Σ`mh_n`/Σ`draws`, Σ`mh_disp_n`/Σ`dispatches`, and the three count differences. BDA regime: median `bda_scan` of the
scene rows, labelled NEW (≤ 300), OLD (≥ 600), else UNCLEAR (a label for the reader; NEW ≈ 50, OLD ≈ 1 000+).

### 5.4 Caveats printed with every report

(a) Instruments on: `mutsite` ≈ 0.10 ms a frame (session 69, +0.312 % ± 0.294 % `cpu/draw`), `pathlap` +362.9 ± 80.8 µs
a flip on top of `mutsite=1` (session 96, `pl96a`), `KYTY_GPU_WALL` not priced — levels are instrumented and compare with
no uninstrumented run. (b) Every phase is a WALL interval (rdtsc) of the GuestGpu thread; `cpu_gpu_us` is its CPU cycle
time; shares are wall over CPU, `remainder` and `residue` are signed. (c) `mh_pres_us`/`mh_pres_wait_us` are both
threads: `PrepareFrame`/`PrepareBlankFrame` run at the flip packet on GuestGpu (inside `residue`), `Present` on the
present thread — not separable by these counters; `pl_look` runs on the guest submit thread and is in no sum. (d) The
named outside spans are taken as disjoint from each other and from the render-mutex holds (session 96 design;
`PathSpan` refuses to arm inside a hold, the reverse — a hold taken inside `pl_cmd` — is not checked here). (e) One entry,
one launch state; no A/B; nothing here is a speed effect. **(f)** `PathSpan`, `WallSpan` and `PathLap` marks (every
`pl_*`, `gw_*`) and the waits `flip_rsv_wait`, `semwait_gpu_us`, `prio_us` add their whole interval to the flip in which
they **end** — a `Process` slice can last ~58 ms (`pl96a`) — so a flip can carry a neighbour's span; for these keys and
every key built from them only means and run sums are reported, no per-row medians. **(g)** `per_unit` of `mh_pro`,
`mh_rt`, `mh_prog`, `mh_bind`, `mh_emit` divides by `mh_draws`, which excludes the ~20 draws a frame that return early
(session 71: Σ`rpd_aN` is 20.000 a frame short of `draws`) although their holds up to the return sit in those phases — a
slight overstatement per draw; `mh_tail` is divided by `mh_n`. **(h)** `prio_us` is timed by a `Scope`
(`commandScheduler.cpp:682`) and reads 0 in a `lite` run (its count `prios` is live); `semwait_gpu_us` and
`flip_rsv_wait` are live.

## 7. Must not be claimed

Any speed effect, any "faster/slower", any ship decision from this run; 60 FPS; that the phase levels hold without the
instruments; that a phase share is a CPU share (it is wall over CPU); that `mh_pres_us` belongs to GuestGpu; that the named
outside spans are disjoint; a per-row distribution (median, percentile) of a span key; anything about another scene or
launch state (BDA regime); any number of a NOT_ADMITTED run; that the report shows where to cut — the choice is step
(3)'s, by its own rule.
