## 2. Пункты

### CR5б-1 (MAJOR, BLOCKING для шага 6) — флаг `nomap` переживает вызов и перекрашивает настоящий `PATH` следующего вызова в `NOMAP`

**Что не так.** `nomap` снимается только в `End()` (`descriptors.cpp:266`). `End()` вызывает `CallScope::~CallScope` лишь при
`t_b2r.pend != Pend::None` (`frameStats.h:3962–3969`, `CallScope`). Есть путь, на котором флаг поставлен, а `pend` обнуляется без `End()`:

1. Значение 2 (или 3). Проба П — промах: `pend = Miss`, `kind = P` (`Probe`, `:195–196`); `arm_p = true` (`:575`).
2. Внешний `ObtainBuffer`: ветка кольца, `m_stream_buffer.Map(size, alignment, false)` вернул nullptr (занятое кольцо — ровно случай CR1)
   ⇒ `nomap = true` (`bufferCache.cpp:1565`), медленная ветка, возврат буфера кэша (не кольца).
3. `:583` снимает `arm_p`; `buffer` — не кольцо ⇒ `Insert(P)` не зовётся; `pend` остаётся `Miss(P)`, `nomap` — true.
4. Смещение медленного буфера не выровнено под `PackedStrideBaseAlignment` и `PackedStrideAlignedCopy` (`:603–604`) — ветка А
   (для этого перехода П→медленный путь→А проба А и введена, s.3.3). `Probe(A)` (`:613`): `pend != Hit` ⇒ состояние перезаписано
   (`kind = A`), промах ⇒ `pend = Miss(A)`. Копия CPU: `ReadRing(A)` пишет тень; `Insert(A)` (`:669`) ставит `pend = None` (`:206`).
5. Возврат: `CallScope` видит `pend == None` ⇒ `End()` **не вызывается** ⇒ `nomap == true` остаётся в TLS потока.

**Сценарий отказа.** Следующий вызов `NativeStorageBuffer` того же потока, заканчивающийся с `pend != None`: попадание П при 2, путь 0
которого ушёл в `Slow` по настоящей причине — диапазон стал не CPU-грязным или GPU-грязным без сдвига поколения (то, ради чего
условие п. 151(д)(3)(а) `b2r_path = 0` существует), или `ReadRing` вернул false на нечитаемом источнике при успешном `Map`. `End()` читает
устаревший `nomap = true` и `slow = true` ⇒ **`b2r_nomap += 1` вместо `b2r_path`**, строка `NOMAP … path=slow` вместо `PATH`. По п. 158(б)(4)
`b2r_nomap` — ряд, не условие ⇒ дым корректности при 2 читает `b2r_path = 0` и проходит там, где путь 0 и механизм разошлись. Строка
`NOMAP` этот случай не отличает (печатает те же `path=slow gen_moved=`). Сверка байт такого попадания при 2 не выключена (`MISMATCH` при
реальном расхождении байт останется), но `b2r_path` — отдельное условие именно для расхождения ПУТИ при равных байтах, и оно теряется.
Флаг живёт до ближайшего `End()` этого потока — в том числе через интервалы 0/1 (там `End()` не зовётся или не доходит до развилки) до
первого попадания при 2. Частота [U]: произведение занятого кольца на промахе П, ветки А после медленного пути и следующего `PATH`-случая;
редкость не довод — условие (а) ловит именно редкие события.

**Что изменить (правит автор, Emu Engineer; вариант выбирает лид).** Снимать `nomap` везде, где снимается `pend` без `End()`:
(а) `t.nomap = false;` в `Insert()` рядом с `t.pend = Pend::None;` (`:206`) — закрывает шаг 5; и/или
(б) `t.nomap = false;` в `Probe()` при переинициализации состояния (после раннего возврата `pend == Hit`, `:145–147`) — флаг П не
переживает перезапись состояния пробой А/D; при 0 оба места не исполняются (путь 0 не меняется), при 1 — запись ложного значения.
Плюс статическая проверка (фикстура `rst134.py` или отдельный скрипт шага 6): каждое присваивание `pend = Pend::None` вне `End()` —
рядом с `nomap = false`, либо в ветке, где `nomap` недостижим (`:172`, значение 1). Правка — код ⇒ пересборка: `8110ecb0` не
запускалась ни в одном прогоне игры, замена по той же логике, что п. 156(в)/158(б)(5) для `63b43a80`, — **решение лида пунктом
`ROADMAP.md` до правки** (константа «одна измерительная сборка сессии»). Шагу 6 это BLOCKING, потому что его первое действие — закрепить
sha сборки в `go134a.sh` и прогнать `rst134.py --code`; сборка после `s1s134` сломала бы «одну сборку сессии» для дыма убийства.

Если лид правку не примет — единственное чтение без кода: считать `b2r_path + b2r_nomap = 0` условием (а) при 2; это возвращает ложную
тревогу CR1 и противоречит п. 158(б) — не рекомендую.
