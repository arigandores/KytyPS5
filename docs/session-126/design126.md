### 1.2 Доказательство «нет»

R_K3⁺ — время `pl_em_rt` (и резолюции, п. 63(в)) на множестве S_K3 (draw, где с прошлого draw не было записи
регистров-зависимостей и прочих источников §3). Сверху его даёт только время на доказуемом НАДМНОЖЕСТВЕ S_K3. В `cen120`
время известно для двух множеств: всех draw (1 359,7) и would-hit S_A (1 001,2); время промахов по причинам не разделено
(только счёты). S_K3 ⊄ S_A: (а) промах `memo` — прошлый draw не записал память (например, взял медленный путь `Find*`), а
регистры с тех пор не писались; (б) промах `pass` — между draw проход закрыт диспатчем/копией без записи CB/DB; (в) промах
`dsmp` — глубина сэмплируется. Такие draw лежат в S_K3 (или могут лежать), но не в S_A. Значит, наименьшее надмножество с
известным временем — все draw: **≤ 1 359,7 ≥ 500**. `obs116` даёт то же: ≤ 1 599,9 ≥ 500. Остальные логи фазу не
разбивают. Вывод: без нового счётчика R_K3⁺ < 500 недоказуемо; (ж)(3) шаги 3–7 не отменяет.

### 1.3 Попутная находка: прочтение «по значению» в NEW — [c], не результат `[RC10]`

S_A (would-hit A) ⊆ R0 ∪ V (draw, у которого ключи memo резолюции всех целей, сравниваемых A, побайтно равны прошлому
draw) — доказательство §7.3 (с построением V по RC5). Отсюда для механизма, пропускающего захват при РАВНЫХ значениях
входов, время фазы на снимаемом множестве ≥ `pl_em_rt_hit`, которое в `cen120` ≈ 1 001,2 мкс/кадр. **Это число — [c]:**
перепись в инструментированном плече P (R1/R2) другой сборки (`15cdbfc6`), в режиме NEW, при опоре курса OLD; нижней
границей для опоры оно не доказано и в печати и выводах сессии как результат НЕ цитируется `[RC10, п. 64(ж)]`. Решение
В1 («по записи», п. 63(б)) стоит на своём основании — таблице п. 62(е) (K3 — «по грязным битам», механизм «по значению» —
K7), а не на этой находке.

## 2. Что меряется и каким числом

### 2.1 Механизм, который ограничивается сверху

**K3 (гипотетический):** для draw d на контексте регистров C (объект `HW::Context` процессора, `buffer.GetRegisters()`)
резолюция `PrepareDrawRenderState` и захват `AcquireRenderTargets` не выполняются и берётся `RenderState` прошлого draw на
C, если с прошлого draw на C не было ЗАПИСИ ни одного регистра из ОТНОСИМОЙ для d группы (§3.1) любым путём и не сработал
ни один нерегистровый источник §3.2. Запись того же значения — запись (п. 63(б)). Цена проверки механизма не вычитается
((ж)(1)).

**Группы и относимость** `[RC1, п. 64(б)]`: `G_mask` (`CB_TARGET_MASK`), `G_slot[n]` (`CB_COLORn_*`, n = 0..7), `G_dact`
(регистры с процитированным чтением в решении присутствия глубины/трафарета: `DB_DEPTH_CONTROL`, `DB_RENDER_CONTROL`,
`DB_STENCIL_INFO`, §3.1), `G_depth` (прочие регистры D_census по DB, в том числе `DB_SHADING_RATE_ENCODING` `[RC6]`).
Группа относима для draw d, если: `G_mask`, `G_dact` — всегда; `G_slot[n]` — слот n дал цель (n = `colors[i].target_slot`
для некоторого i < `color_count` ПОСЛЕ захвата) в d ИЛИ в записанном прошлом draw контекста; `G_depth` — `depth.image_id
≠ 0` после захвата в d ИЛИ в записанном draw. Нерегистровые источники — как в ред. 1 (§3.2). Довод стороны — §5 Н3.

### 2.2 Число `[п. 63(в), п. 63(д), п. 64(г)]`

R_K3⁺ (мкс/кадр опоры) = ⟨ `rk3_rt_r_ns` + `rk3_res_r_ns` + `rk3_res_x_ns` ⟩_окно / 1000 + 2·SE, где:

- S_R = R0 ∪ WI ⊇ S_K3 строится переписью (§4) так, что каждое исключение из «всех draw» доказано необходимым (§5): R0 —
  draw без записи для своего контекста (входят целиком); WI — draw класса W (ни одна ОТНОСИМАЯ группа не сдвинулась,
  §4.3), у которых идентичность целей равна записи (E1, §3.4).
- `rk3_rt_r_ns` (T0) — сумма спанов `pl_em_rt`(d) по d ∈ S_R: спан цепочки `pathlap` от отметки `pl_em_vtx` до отметки
  `pl_em_rt` (сегодня: `DrawStatTail`, конструктор `SpDrawScope`, `AcquireRenderTargets`, проверка `G3ApplyAttach`,
  `lap.Mark`) — шире, чем снимет пропуск.
- `rk3_res_r_ns` (T13) — сумма спанов С4 (резолюция целей `PrepareDrawRenderState`) по d ∈ S_R (п. 63(в)).
- `rk3_res_x_ns` (T13x) — сумма спанов С4 вооружённых draw, НЕ дошедших до поста С6, входит целиком `[RC3, п. 64(г)]`.
- ⟨·⟩_окно — среднее строк плеча переписи, кадры 10–88 блока п. 55(б), блоки по строкам `GateArm:`; сумма трёх членов
  берётся построчно; SE — по средним блоков суммы (статистика уровня — среднее строк; медиана средних блоков печатается
  рядом, MINOR-3 п. 62(б)).
- «+2·SE» — выборочная сторона вверх; порог (ж)(2) сравнивается с числом уже с +2·SE (п. 63(д)).
- Режим BDA — п. 63(ж): при блоках обоих режимов R_K3⁺ = максимум из R по подмножествам NEW и OLD (каждое со своим 2·SE);
  подмножество с менее чем 4 окнами плеча C входит максимумом средних своих блоков; блоки «между» не входят.

Рядом (не число чтения, справка): T0 отдельно («только фаза `pl_em_rt`», п. 63(в)); R_W⁺ (S = R0 ∪ W, без E1); **R_r1⁺ —
R по правилу ред. 1** (одно поколение на контекст: S = R0 ∪ (WI ∖ XW_irr), счётчики `rk3_rt_r1_ns` + `rk3_res_r1_ns` +
`rk3_res_x_ns`) и доля `rk3_xw_irr/rk3_n` `[RC1, п. 64(б)]`; доли `rk3_w/rk3_n`, `rk3_wi/rk3_n`. R_V⁺ и `rk3_v` — только из
дыма значения 3 (§4.1, §7.3) `[п. 64(в)]`.

(1) Поля D_census — приватные члены `HW::Context` (`hardwareContext.h`, секция `private:` с `:1133`; `friend` в файле

место (`graphicsRun.cpp:393`); `sp.m_ctx = m_ctx` (`:1662`) и `:1885` пишут теневой процессор спины, который не рисует

### 3.4 Исключение E1 (единственное нерегистровое исключение)

Draw из W исключается, если его `color_count`, наличие глубины, или у любой цели `image_id`, `target_slot`,
`desc.view_info` отличаются от записи прошлого draw этого контекста; сравниваются значения ПОСЛЕ захвата (повторный поиск
`renderDraw.cpp:1273–1290` меняет `image_id`). Довод: вид вложения в `RenderState` (`attachment.image_view`,
`renderDraw.cpp:1355`, `:1484`) — функция пары (образ, `view_info`) (`AcquireTargetView` → `FindRenderTarget`/`FindDepthTarget`
или вид из записи `rtfast` того же образа); другой образ или другой вид ⇒ другой `RenderState` ⇒ повтор прошлого результата
неверен ⇒ ни один корректный механизм такой draw не пропустит. Отзыв E1 принял (`review126.md`, «Проверено»). R_W⁺
(без E1) печатается всегда. Все поля E1 — ВЫХОДЫ резолюции, которые только что читал захват того же draw (Н10).

### 4.1 Значения, чтение, защёлка

- `{"KYTY_RK3_CENSUS", "rk3cen", 0, 3}` `[п. 64(в)]` — ПОСЛЕДНЯЯ строка `KNOB_DEFINITIONS` и последний `Knob` перед `Count`;

- **0** — ничего (см. §4.6). **1** — перепись (§4.2–4.3), **не читает ни одного входа резолюции** `[RC2]`: ни байтов
  `HW::Context`, ни ключей memo; только поколения групп (своя TLS-таблица), выходы захвата того же draw (`colors[0..
  color_count)`, `depth`), адрес контекста и свои счётчики. **2** — 1 + разбиение `pl_em_rt` внутри захвата (§4.4; только
  дым, п. 63(з)). **3** `[п. 64(в)]` — 1 + свидетели по значению (V_D, V_key, классы V/VW/WMISS, §4.3), только дым шага 5,
  в печать и чтение не идёт.
- Читается **на каждый draw** на входе `RenderExecutor::DrawIndex`/`DrawAuto` (до `PrepareDrawRenderState`,
  `renderDraw.cpp:3655`, `:3825`) и защёлкивается в TLS `t_rk3` на этот draw — может быть плечом расписания. Вооружается,
  только если: поток — GuestGpu, `FrameStats::Enabled()`, `PathLap` вооружён (`pathlap=1`, иначе `rk3_nt`), `spcen`,

  раздували `rk3_wr_*`.
- Переход защёлки из вооружённого состояния в 0 (или отказ) **обнуляет все записи** и сбрасывает отложенное время С4 в
  `rk3_res_x_ns` (§4.2 С4); первая вооружённая после этого draw каждого контекста — R0. Крючки сеттеров проверяют ту же

  Смена значения между 1, 2, 3 записи не обнуляет (классификация одна).

### 4.3 Классификация в посте (С6)

Запись на контекст (TLS-таблица ≤ 8 контекстов по адресу `HW::Context`, выделяется при первом вооружённом draw;
переполнение — `rk3_ovf`, draw ⇒ R0): 11 поколений групп (`G_mask`, `G_slot[0..7]`, `G_dact`, `G_depth`) на момент записи,
`color_count`, маска слотов, давших цель (`target_slot` у `colors[0..color_count)`), `has_depth` (`depth.image_id ≠ 0`), по
каждой цели `image_id` (индекс + поколение), `target_slot`, `desc.view_info` — все после захвата. **Значение 3**
дополнительно: V_D (байты полей D_census по группам: `HW::RenderTarget` слотов 0..7, `CB_TARGET_MASK`, `dc`, `rc`,
`z.stencil_info`, прочие поля `z`, `sc`, `sm`, две очистки) и V_key (ниже).

Относимое множество Rel(d) = {`G_mask`, `G_dact`} ∪ {`G_slot[n]` : n в маске слотов d или записи} ∪ {`G_depth` : `has_depth`
у d или записи} `[RC1]`.

Порядок (первое сработавшее, разбиение): **R0** — записи нет / контекст новый / переполнение; **XW** — сдвинулась хоть одна
группа из Rel(d); **W** — иначе; внутри W: **XID** — E1 нарушено; **WI** — иначе. Отдельно (не разбиение): **XW_irr** —
W ∧ сдвинулась хоть одна группа вне Rel(d) (класс XW по правилу ред. 1; `rk3_xw_irr`, справка `[п. 64(б)]`); множество
правила ред. 1 для R_r1⁺ — R0 ∪ (WI ∖ XW_irr). Затем запись обновляется текущим draw. Поколения, снятые в С4, сравниваются
с поколениями в С6 — сдвиг за время захвата — `rk3_acqw` (обязан 0: захват регистров не пишет).

**Только значение 3** `[RC2, RC5, п. 64(в), (е)]`: **V** — V_key равен записи; **VW** = V ∧ XW; **WMISS** — draw не R0, у
которого для некоторой группы (любой, не только относимой) поколение не сдвинулось, а её байты V_D отличаются от записи.
**V_key** — последовательность ключей memo, построенных ТЕМ ЖЕ кодом, что в резолюции: общая функция ключа цвета
(`memo_regs` = байты `HW::RenderTarget` слота + `memo_extra` из маски слота, `render_target_slice_offset`, слота и флагов,
`colorRenderTarget.cpp:123–129`) и ключа глубины (`DepthTargetMemoKey`, обнулённая структура с присвоенными членами,
`depthRenderTarget.cpp:283–293`); Emu Engineer выносит построение в общие функции, которые резолюция зовёт побайтно так же,
как сегодня. Ключи строятся только для целей, которые сравнивает A (`renderDraw.cpp:991–1002`): `colors[0..color_count)` (по
`target_slot`) и глубина при `depth.image_id ≠ 0`; сравнение — `memcmp` последовательности (длина и порядок — часть
сравнения). База V — прошлый draw того же контекста, база A — прошлый draw исполнителя; для любого утверждения о K7 —
страж `rk3_xctx = 0` на всех строках окна.

### 4.6 Тождества (для скорера) и контроли `[RC4, п. 64(д)]`

**Все тождества — на СУММАХ окна 10–88 п. 55(б) каждого блока** (блоки по строкам `GateArm:`), не построчно:
`FrameStats::Read` суммирует шарды счётчик за счётчиком (`frameStats.cpp:214–224`), флип забирает `rk3_n` и `rk3_rec0` в
разные мгновения — строка рвётся на draw (прецедент с. 116: перекос до ±60). Обозначения: Σx — сумма x по строкам окна
блока; допуск штук **Tol_n = 256**; допуск нс **Tol_ns = 256 × max(`rk3_c5_max_ns` строки 10, `rk3_c5_max_ns` строки 88)**
(больший из двух краевых строк окна). «a = b» значит |Σa − Σb| ≤ Tol; «a ≤ b» значит Σa ≤ Σb + Tol.

- **Т1** `rk3_n = rk3_rec0 + rk3_xw + rk3_w` (Tol_n). **Т2** `rk3_w = rk3_wi + rk3_xid` (Tol_n).
- **Т3** (Tol_ns для нс, Tol_n для штук): `rk3_rt_rec0_ns ≤ rk3_rt_r1_ns ≤ rk3_rt_r_ns ≤ rk3_rt_w_ns ≤ rk3_rt_ns`;
  `rk3_res_r1_ns ≤ rk3_res_r_ns ≤ rk3_res_ns`; `rk3_xw_irr ≤ rk3_w`; `rk3_r_* ≤ rk3_*`. Значение 3 (дым) дополнительно:
  `rk3_rt_rec0_ns ≤ rk3_rt_v_ns ≤ rk3_rt_ns`, `rk3_res_v_ns ≤ rk3_res_ns`, `rk3_wmiss ≤ rk3_n`, `rk3_vw ≤ rk3_xw`.
- **Т4** плечо переписи: `rk3_rt_ns = pl_em_rt_ns` (Tol_ns; одно и то же потраченное, между счётом `pl_em_n` и С5 возвратов
  нет — отзыв, «Проверено»); `rk3_n = pl_em_n` (Tol_n).
- **Т5** `[RC3]` `rk3_c4_n = rk3_n + rk3_res_x_n` (Tol_n; отложенный С4 на краю окна — ±1).
- **Фикстуры скорера** на каждый допуск: ровно на допуске — проходит, на единицу за ним — падает (п. 64(д)); на выбор
  краевых строк Tol_ns (строка 10 и 88, не 9 и 89).
- **Нулевой контроль:** на строках окна 10–88 плеча `rk3cen=0` (только они; строка на границе блока несёт хвост плеча C)
  каждый `rk3_*`, `pl_em_rk3_ns` и датчик `rk3_c5_max_ns` = 0 (защёлка 0 ⇒ ни крючков, ни поста, ни датчика).
  **Нулевой контроль RC2:** на строках окна плеча C (`rk3cen=1`) `rk3_v`, `rk3_vw`, `rk3_wmiss`, `rk3_rt_v_ns`,
  `rk3_res_v_ns` = 0 — значение 1 не строило V_D/V_key.
- **Положительный контроль:** в каждом окне блока переписи Σ`rk3_n` > 0, Σ(`rk3_wr_set` + `rk3_wr_obj`) > 0, Σ`rk3_xw` > 0
  (классификатор видит записи), `rk3_c5_max_ns` > 0 на каждой строке окна. Полнота D (`rk3_wmiss = 0`) — только дым
  значения 3 (§3.3); в печать не входит `[п. 64(в)]`.
- **Стражи 0:** `rk3_nt`, `rk3_xthr`, `rk3_acqw` на каждой строке; `Rk3Census: refused` в плече переписи — провал допуска.

### 4.7 Цена и почему поведение не меняется

**Ни при каком значении эмуляция не меняется:** перепись читает только свою TLS-таблицу, выходы захвата (`colors[]`,

Раскладка `HW::Context` не меняется (§4.2, RC8). Вынос построения ключей memo в общие функции (для значения 3) обязан

**Цена [I], меряется в дыме (шаг 5), в вердикт не входит:** при 1 — пост ≈ 30–80 нс/draw (11 поколений контекста + ≤ 9
целей по id/слоту/виду; без V) ≈ 0,15–0,4 мс/кадр в `pl_em_rk3_ns`, С4 ≈ 40 нс/draw ≈ 0,2 мс, крючки ≈ 3 нс × число

`DepthTargetMemoKey`) и V_D. При 0 — на draw одно чтение ручки и TLS-запись, на сеттер D одна TLS-проверка; отдельно не
измеряется (плечо базы — ручка 0 на измерительной сборке, не `d3a981a2`).

### 7.2 K7: включение для R_K3⁺ «по записи» не доказуемо

Контрпример: would-hit A, перед которым гость переписал `CB_COLOR0_INFO` тем же значением (слот 0 дал цель — `G_slot[0]`

### 7.3 K7 через R_V⁺ — доказательство готово к будущему измерению, в с. 126 не читается `[RC5, п. 64(в), (е)]`

(`colors[0..color_count)`, глубина при `image_id ≠ 0`) равных `memo_slot` и `memo_version` с прошлым draw исполнителя
(`renderDraw.cpp:991–1002`); попадание memo — побайтное равенство построенного ключа (`colorRenderTarget.cpp:134`: `regs` и
`extra`; `depthRenderTarget.cpp:299`: весь ключ), а версия не растёт, пока запись memo не переписана (`colorRenderTarget.cpp:150`,
`:170`; `depthRenderTarget.cpp:314`, `:332`); значит, ключи всех сравниваемых A целей у двух draw побайтно равны — ровно V_key
(те же функции построения, те же цели, `memcmp`; разрывы (а)–(в) отзыва RC5 — слот без образа, NaN через `operator==`,
паддинг — этим построением исключены). База A — прошлый draw исполнителя, база V — прошлый draw того же контекста;
