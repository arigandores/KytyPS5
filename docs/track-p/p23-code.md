**Формат** (п. 333(д)): строка на директиву; `#` — комментарий до конца строки; пустые строки, пробелы/табы, CRLF, верхний регистр hex допускаются.
`sha256 <64 hex>` — ровно одна и первая директива; `poke <смещение hex ≤ 8 цифр>:<байты hex, чётное число цифр>` — смещение от базы главного модуля;
`pvar 2`, `audio_sync 0` — не более одного раза, иные значения — отказ.

**Порядок решения** (`gamePatchFile.h` `Decide`, `:403`): файл не читается → `open`; разбор (`Parse`, `:253`) — неизвестная директива, лишний/нет
аргумента, `sha256` не первая или вторая, `pvar`≠2, `audio_sync`≠0, повтор → `directive`; плохой hex смещения/байтов/sha → `hex`; перекрытие диапазонов
`poke` файла → `overlap` (**хэш `eboot.bin` при отказе разбора не считается**); затем sha256 загружаемого `eboot.bin` (потоково, 1 МиБ) ≠ файла → `sha`;
затем окружение (`CheckEnv`, `:363`): явный `KYTY_PVAR` ≠ `"2"` при `pvar 2` → `env`; явный `KYTY_AUDIO_SYNC` с `atoi ≠ 0` (чтение `GuestSpeedEnabled`)
при `audio_sync 0` → `env`; элемент `KYTY_POKE`, разобранный как цикл `KYTY_POKE` (`Common::Split` без пустых частей, ровно 2 части, `strtoull`, целые
пары цифр), перекрывающий `poke` файла → `overlap`, по абсолютному адресу (≥ 0x100000000, с файлом не сравним) → `env`. Любой отказ — ничего из файла
не применяется (ни `poke`, ни `pvar`, ни темп); `KYTY_POKE` и `KYTY_PVAR` из окружения работают как без файла.

**Строки лога:** `GamePatch: file <путь> eboot <путь>`; отказ — `GamePatch: refused reason=<open|directive|hex|overlap|sha|env>` и отдельной строкой
`GamePatch: detail <строка=N …>`; применение — `GamePatch: applied sha=<16 hex> pokes=<N> pvar=2 audio_sync=0` (N — `poke` файла; без директивы —
`pvar=none`/`audio_sync=none`), затем на `Execute` — `GamePatch: poke 0x<адрес> <- <hex>` на каждый `poke` файла, потом прежние `KYTY_POKE:`,
потом `PVar: armed …` (проверка 25 байт ограничителя и 4 байт Havok — после записи `poke` файла).
