### MINOR-1 — строка `LEFT` с `perms=1` в `ack129` не выведена отчётом шага 7, вопрос п. 101(б) остался с неполным фактом

**Что.** Правило п. 101(б): `ac_jleft` > 0, целиком из `ac_jremark`, — вопрос лиду **со сверкой строк `ArmCopyVerify: LEFT`**, где
`perms=` различает пометку объявления записи (`ReadWrite` = 3) и оставленное вооружение (`Read`/`NoAccess`). §Step 7 `FACTS.md`
называет «LEFT 10» без разбора `perms`; скорер печатает вопрос `JLEFT_ALL_REMARK`, но не `perms`. Сверка аудита: 9 из 10 строк —
`perms=3`, **одна строка ветки куска — `pages=16 perms=1 rm=1`**. Довод, которым лид закрыл тот же вопрос по `s3s129` в п. 104(в)
(«у всех 7 строк `perms=3` — пометка объявления записи»), на `ack129` без оговорки не переносится.

**Чтение аудита по коду [I, `pageManager.cpp:1320–1340`, `:1440–1470`; не измерено]:** `rm=1` — страница из множества T, которое
кусок сам взял `TakePendingRun` (биты сняты) и применил под своей хваткой `apply`; `pending` в снимке детектора выставлен заново
после этого — чужая пометка (её можно ставить под `lock` без `apply`, п. 101(б)). `perms=1` тогда — желаемое разрешение этой новой
пометки (очередное вооружение «только чтение» другой операцией), а не вооружение, которое кусок взял и оставил. Детектор по
состоянию (`watched ∧ ¬pend ∧ host_w`) на всём прогоне — 0 (Σ`ac_bad` 0). Это прочтение класса «чужая пометка», а не доказательство:
положительного контроля у стражей долга нет (§7.2 проекта, п. 101(ж)).

**Последствие для вердикта:** не меняется — строгая часть `ac_jleft − ac_jremark` = 0 выполнена, `SELFCHECK_CLEAN` стоит; по п. 101(б)
это вопрос, не провал. **Для отгрузки:** лид отвечает строкой ROADMAP на вопрос `JLEFT_ALL_REMARK:ack129` с этим фактом (16 страниц,
`perms=1`, `rm=1`) до смены умолчания; если ответ — «оставленное вооружение возможно», отгрузка ждёт проверки (например, повторный
