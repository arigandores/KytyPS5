## 4. Состояние, которое вводит правка (форма п. 160(а)(4))

- **Метка М1** (`m_f26_marks[адрес]`, `m_f26_marks_count`): ставится — `F26MarkLocked` из `F26Scope::Report` (под `m_lock` сайта; места — §3.2);
  снимается — `F26ExecLocked` (И1 под `m_lock`; И2 через `F26Exec`, замок внутри), `F26DropLocked` (`TrackDccFill`, `UnmapMemory`, `DeleteImage`,
  смена типа на CMASK и HTile, вторая метка; места — §3.2). Выходы, где снятия нет: метка переживает вызов
  сайта **намеренно** — до исполнения, новой заливки, стирания или смены типа записи; если ничего из этого не наступает — живёт до конца процесса
  (событие «`NO_APPLY`» п. 702(д)(2)). `declined` метку оставляет (флаг `declined` — только «строка уже напечатана»). Тестовый помощник
  `F16kEraseMeta` стирает метку и взведённые события без строки (граница сценария теста, не путь эмулятора).
- **Взведённые события** (`m_f26_first[адрес]`, `m_f26_first_count`): ставятся — `F26ArmFirstExecLocked` из `Report` (§3.3); снимаются только
  `F26ExecLocked` (первое исполнение адреса). Не исполненное до конца процесса событие живёт до конца процесса (строки нет — «конец удержания»
  п. 702(г)(3)); объём ограничен: взводятся только `n` ≤ 256. Новая заливка, стирание и смена типа событие не разряжают (по букве (е)(3) — «первое
  исполнение после события»).
- **`F26Scope::m_cache`, `F26ApplyScope`** — поля локальных объектов вызова; не переживают вызов.
- **Ручки и строка режима** — статические локальные, читаются раз на процесс; `logged` — атомик раз на процесс.
- **Замки [c]:** `F26MarkLocked`, `F26ArmFirstExecLocked`, `F26ExecLocked`, `F26DropLocked`, `F26HasMarkLocked` — под `m_lock`, который держит
  вызывающий (сайты `PrepareDccClear` / `AdoptPendingDccForTexture` / `TrackDccFill` / `UnmapMemory` / `DeleteImage` / `PrepareCmaskClear` / HTile — все
  уже под `m_lock`); `F26Exec`, `F26Declined`, `F26HasMark` берут `m_lock` сами и зовутся из `MaterializeDeferredDccClear` вне замков кэша (как
  соседние `MetaClearMask`/`TouchMeta`; блок `aliased` берёт `m_lock` в своей области и отпускает до вызова). Без меток и событий замок не берётся
  (атомики). Строки печатаются под `m_lock` через `EmitLine` (лист) — как прежняя `dcc_stale`.

## 6. Решения исполнителя (толкования; F46b проверяет)

1. **Режим 1 красит и исполнение `kept_applied` в вызове события.** Буква (е)(4) «исполнение, снимающее метку Ф26»; у событий `kept_applied`
   (ожидаемые S1, S3 — F45a §2.1) метки М1 нет — заливка исполняется в том же вызове. Без этого `f26s_t<k>` таких событий не красит ничего и
   `V(e)` = нет по построению. Читаю решение `kept` этого же вызова (`KeptNow`) как метку Ф26, снятую его циклом слоёв — форма F45a §2.2 (М2:
   «`kept_applied` на И1 того же вызова или `dcc_stale_apply result=cleared`»). Строки `cleared` для `kept_applied` нет (тождество F16o2
   `kept_applied` + `cleared` = `f26_kept_applied` сохраняется).
2. **`declined` оставляет метку** — значит метка может дать `declined`, а потом `cleared`: тождество F16o2 «`f26_kept_applied` +
   `f26_deferred_declined` ≤ `f26_kept`» заменено двумя «≤ `f26_kept`» (сумма может превысить); строка и счёт `declined` — первая на метку.
3. **Сброс метки шире буквы П1/С4:** стирание записи в `DeleteImage` и смена типа записи (CMASK, HTile) тоже теряют заливку адреса — строка
   `dropped` с `site=delete` / `retype`; иначе метка жила бы без записи и `NO_APPLY` смешивался бы со стиранием. `remark` — защита, не достижимо.
4. **Порядок полей строки `dcc_stale_apply`** прежний (`image=` до `dcc=`), `site=` — последним; буква (е)(2) порядка не задаёт («…»).
5. **`f26_first_exec` взводится каждым событием** (любой `fix`, оба плеча), несколько событий адреса — по строке на каждое при одном исполнении;
   новая заливка событие не разряжает. Поле `gpu=` в строку не добавлено (буква — `n= present= dcc= image= site=`).
6. **Формат «без такой кодировки»** — `DccFixedClearSupported(format)` ложно или компонент < 3 (одно-/двухканальные пурпур не несут — F45b RC3);
   целочисленные форматы — `Skip`. Окраска И1 решается один раз на вызов (все слои вызова — одним значением); счёт — один на исполнение (вызов).
7. **Счётчики окраски** считаются при любом `KYTY_DIAG_F5` (видны только в строке `DiagF5:`); метки — только при `KYTY_DIAG_F5=1` (как F16o2), значит
   режим 1 на метках М1 требует `KYTY_DIAG_F5=1` (у тегов F46c он есть, п. 702(г)(1)); `kept_applied` (решение 1) — без него.
