## 4. (2) Член «вход блока = данные игры, декодированные независимо» (М2) и контроли

### 4.1 Точки

В годном снимке (§3.2): по каждому блоку (чёрный 1, белый, чёрный 2 — сколько есть) — 4 точки внутри блока (углы, отступ 2 пикселя от края по маске
миниатюры, перевод в координаты конечной цели гостя) и 1 точка рядом вне блока (контроль: у неё цепочка не обязана вести в тот же draw).

### 4.2 Цепочка писателей и класс

История пикселя в каждой точке на конечной цели → последний писатель W₁ → его вход по координате точки → … до **draw блока D_b** — события, после
которого значение в точке (в цели D_b) даёт блок в конечной цели. Класс входа D_b в точке:
- **T** — цвет определяет выборка текстуры (тексель по UV точки);
- **C** — цвет из констант / вершинного цвета / непосредственных значений программы (выборка не участвует или умножена на 0);
- **R** — выборка цели, которую записал проход ГП (продукт ГП, не ассет);
- **N** — писателя в снимке нет: значение — начальное содержимое ресурса снимка, а draw гостя его читает.

### 4.3 Член М2 по классам

- **T.** М2а (байты): байты T# в памяти гостя (`_tex_<n>.bin` тега `f47_dt`, последняя загрузка до показа блока) **равны** байтам файла игры, который
  игра открыла в логе (строки `Open:` / `Read … from:`), — sha256 полезной части или окна ≥ 4 КиБ по смещению; М2б (декодирование): тексели в точках,
  декодированные **своим скриптом** из этих байт (формат и раскладка — из полей T# снимка; свой разбор BC / UNORM / sRGB), равны текселям, которые
  читает D_b в снимке (UNORM — 0 LSB, sRGB — ≤ 1 LSB, BC — точно по блоку). Раскладку тайлинга PS5 своим кодом снять [U]: если T# тайловый и своего
  детайлера нет — М2б «не определено» для класса T. Текстуры игры лежат файлами `.gnfp` с заголовком `GNF ` (`data/prein/common/gfx/
  secret_exit_e.gnfp`: байты 0–3 `47 4e 46 20`, 5 701 632 байт) [c]; сжата ли полезная часть — [I: размер файла похож на несжатый BC], проверка — М2а.
- **C.** Значения входа (байты буфера / регистры констант снимка) **своим разбором** по раскладке из снимка дают цвет точки (арифметика программы
  своими словами или отладкой шейдера RenderDoc, если интерпретатор его берёт); член провенанса: значения — точные 0 / 1 (чёрный / белый) в каналах
  цвета [I: стечение устаревших байт в точные 0 / 1 маловероятно]; иначе «не определено».
- **R.** Цепочка продолжается на продукт ГП до T / C / N внутри снимка; выход за снимок (цель записана до снимка) — «не определено».
- **N.** М2 = «не равно» по определению (вход не создан игрой в снимке, а читается) — если игра в том же снимке эту область не очищает и не пишет.

**Реплей воспроизводит** (член исхода): реплей снимка (`rd_list.py` / сохранение конечной цели) даёт блок в тех же точках — детектор §1.3 на
сохранённой конечной цели (K ≥ 150 / Wt ≥ 1 000 по классу снимка).

### 4.4 Контроли (RC14)

- **П1 (положительный):** значок HUD в левом верхнем углу (контроллер на синем, виден во всех кадрах окна, лист `fs12_v_1100.jpg`) — тот же разбор
  §4.2–§4.3; ожидается класс T и М2 = «равно». П1 «не равно» или «не определено» ⇒ компаратор не умеет сказать «да» — исход «не определено».
- **Н1 (мутант байта):** байты входа блока с одним изменённым байтом (для BC — один блок 4×4) ⇒ М2а «не равно», М2б «не равно» ровно в текселях
  изменённого блока.
- **Н2 (чужой вход):** тот же компаратор на соседнем мипе / UV, сдвинутой на ≥ 1 блок, ⇒ «не равно».
- **Н3 (продукт ГП):** цель того же снимка, записанная проходом ГП (например, G-буфер сцены) ⇒ М2а «нет в файлах игры» — поиск по файлам умеет
  сказать «нет».

Контроль жив, если даёт ожидаемый ответ; любой мёртвый ⇒ М2 не читается («не определено»).

## 5. (3) Кандидат правила исхода (не вердикт; решает F47c после F47b)

1. Тег не годен после повтора (§3.3) ⇒ **`ТУПИК`** («снимок не годен»; переоткрытие — эталон PS5 или кадр пользователя).
2. Контроль П1 или Н1–Н3 мёртв ⇒ «не определено» ⇒ **`ТУПИК`** (форма п. 698(з)(3)).
3. Во всех точках блоков цепочка кончается на D_b класса T или C с М2 = «равно», и реплей воспроизводит ⇒ **`НЕ ДЕФЕКТ`** (переоткрытие — эталон PS5,
   кадр пользователя, другой класс входа на новом бинаре).
4. Хотя бы в одной точке: М2а «не равно» (байты ≠ файлу игры), М2б «не равно» (своё декодирование ≠ текселю снимка) или класс N ⇒ **`дефект`** с
   названным местом (событие, ресурс, адрес) и итерация кода пунктом лида.
5. Иначе (точки «не определено» — R за снимок, тайлинг без своего детайлера, C не 0 / 1) — без «не равно» ⇒ **`ТУПИК`** с основанием; смешение
   «равно» и «не определено» — пунктом лида.

Блоков на текущем бинаре нет — исход не применяется: блоки есть на FS12 и FS13 (§1.3).
