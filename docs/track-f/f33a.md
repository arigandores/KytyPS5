## 3. Проект `KYTY_FIX_F21` (умолчание 0; текст, кода нет)

**Вариант A (рекомендуемый): один владелец аварийной последовательности с ограниченным ожиданием.**
1. Ручка читается один раз на главном потоке до потоков гостя — в конструкторе `Subsystems` (`ee9632be:src/common/subsystems.cpp:7`) или
   строкой в `Run` после `Init`; печать `FixF21: mode=<0|1>` в лог после `Log::Initialize`. Чтение — форма FS4a (`0/false/off/no` = выкл.).
   `=0` — код FS11 байт в байт, кроме одной проверки статического флага в `EmergencyShutdownActive`.
2. `=1`: `EmergencyShutdownActive` (`ee9632be:src/common/subsystems.cpp:37`) — атомарное поле владельца (id потока, 0 — нет) и флаг «обход
   закончен». Первый вошедший (`compare_exchange`) — владелец: обходит `m_active` как сейчас, затем публикует «закончен» (release).
   **Повторный вход того же потока** (фатал внутри колбэка, `DbgExit` после `DbgReport`) — сразу возврат, без вложенного обхода.
   **Другой поток** (гость при фатале во время обхода главного) — не обходит, ждёт «закончен» не дольше `T` и возвращается; дальше `DbgExit`
   ⇒ `_Exit(321)` как сейчас.
3. `T` — больше нормального обхода владельца: два стока лога по ≤ 5 с (`kDrainNs`, `ee9632be:src/common/logging/log.cpp:114`) и задержка
   `ReleaseHostPads` ⇒ предлагается `T` = 12 с (константа — пунктом лида). Ограничение `T` снимает взаимную блокировку §1 п. 5 [I] (гость держит
   замок, нужный колбэку владельца): по истечении `T` гость кончает процесс `_Exit(321)`, как сейчас без правки.
4. Что правка не меняет: путь без гостя (`Destroy`, тесты), код 0/321 при гонке двух `_Exit` (владелец кончает 0, гость — 321 после конца
   обхода), `KytyClose` через `atexit` (тот же владелец).

**Отклонённые варианты:** B — не-владелец сразу `_Exit` без ожидания: может оборвать запись сохранения и сток лога владельца [I];
C — мьютекс вокруг обхода: не-владелец ждёт без предела (взаимная блокировка из §1 п. 5 становится зависанием), затем обходит пустой вектор.

**Стенд для итерации кода (поправка к стенду F33a — до кода):** при `=1` гость не входит в `EmergencyShutdown` ⇒ контроль по событию 0
мёртв по построению. Наблюдатель переносится на вход `EmergencyShutdownActive` (событие «вход потока, обход владельца идёт»), плечо P ждёт
этого входа; классы: `second` (колбэки двумя потоками), `crash`, `hang`, новый счётчик «ожидание `T` истекло». Критерий — форма Б12/Б13 по
