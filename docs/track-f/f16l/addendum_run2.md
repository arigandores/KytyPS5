## RC5. Решения `KYTY_FIX_F5CMU` на FCE-захватах без `Hit` Б42 не видны ни строкой события, ни отдельным счётчиком

*Что не так [c].* Точная проверка решает на каждом входе в `FindRenderTarget(…, fce_materialize = true)`, то есть при
`color.image_id && kind == Cmask`. Сайт — `810909e3:src/graphics/host_gpu/renderer/pipeline/descriptors.cpp:3922` (якорь «if (color.image_id &&
color.desc.info.metadata.kind == ImageMetadataKind::Cmask) {»; +1 — комментарий «Session 71, candidate C3»).

Вид `Cmask` бывает двух происхождений:
- (i) `Hit` Б42 с `FixB42Enabled()`;
- (ii) цель уже пришла с метаданными: `FixB42Probe` отвечает `None`, счёт идёт в `cmask_fce_meta` (`810909e3:…/descriptors.cpp:3973`).

Строка `DiagF5Ev:` печатается только для `Hit` (`…/descriptors.cpp:3955`). Счётчики `f5cmu_*` считают решения обоих происхождений
(`810909e3:…/cache/textureCache.cpp:1898`). На `f5_ef` F16f захватов пути (ii) — 20 163 против 353 `Hit`
(`a6114045:docs/track-f/f16f/runs/f5_ef/read.json:106`). Доходит ли путь (ii) до ветки `PendingDcc` с устаревшей корзиной — [I]: нужна запись
`PendingDcc` по адресу CMASK цели, уже несущей метаданные. Код этого не исключает. В тест-сайте F16k такого случая нет: K1–K5 — только `Hit`,
K6 — захват отрисовки.

*Сценарий отказа.* В плече `f5cmu_1` на захвате пути (ii) корзинная проверка устарела из-за соседа, точная — нет. Получаем `kept_applied`:
слой очищен, в плече `=0` — нет. Строки события и номера показа нет. Отличие листа ляжет вне окон p − 1 … p + 2 событий (п. 495(г)). По
п. 492(е)(6) это «помеха»: повтор пары, на повторе то же, исход «не определено». Эффект правки потерян как помеха. Другой вариант: отличие
попадает в окно события `Hit` с `fix=fresh` и читается как «расхождение прогонов». Разрыв «`f5cmu_kept_applied` > строк
`fix=kept_applied`» правило п. 492(е) не читает.

*Что изменить* (форма — решение лида, одна из двух — до первого тега F16m):
- (а) **Кодом (Emu Engineer):** строка на каждое решение пути (ii) с `fix` ∉ {`off`, `fresh`}. Форма `DiagF5Ev: cmask_fce_meta n=… present=… gpu=… image=… cmask=… extent=… fix=… [why=…]`, свой предел 64. Плюс случай K7 тест-сайта: цель с CMASK-метаданными без `Hit`, сосед в корзине; `=1` → `kept_applied` и строка, `=0` → прежнее. Новый бинарь из чистого worktree — его можно собрать вместе с правками RC1–RC3.
- (б) **Правилом чтения (лид), без кода:** печать F16m считает тождество «Σ строк `DiagF5Ev:` плеча `=1` по `fix` = `f5cmu_kept` / `f5cmu_kept_applied` / `f5cmu_exact_stale` / `f5cmu_fallback` последней строки `DiagF5:`» (при n ≤ 64). Разрыв > 0 означает, что решения вне событий есть. Тогда отличие листа вне окон событий — «не определено (решение вне события)» без повтора, а не помеха п. 492(е)(6). Вывод «ветвь 1 `НЕ ДЕФЕКТ`» по п. 492(е)(5) при разрыве > 0 не делается.
