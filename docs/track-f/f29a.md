## 1. Код: **дыра есть** [c]

**Цепочка обхода.** `PrepareBda` после трёхэпохального кэша обходит каждый отображённый диапазон отдельно:
`73a6e411:src/graphics/host_gpu/renderer/renderContext.cpp:380`. Порядок обхода — по возрастанию адреса (`std::map`,
`73a6e411:src/graphics/host_gpu/rangeSet.h:64`, `73a6e411:src/graphics/host_gpu/rangeSet.h:114`). `RangeSet::Add`
сливает только пересекающиеся или касающиеся диапазоны (`it->first <= last`,
`73a6e411:src/graphics/host_gpu/rangeSet.h:31`). Два диапазона с зазором хотя бы в 1 байт остаются раздельными, даже
если лежат в одном регионе 4 МиБ.

**Границы одного обхода.** `SynchronizeBuffersInRange` сужает обход диапазона до его зарегистрированных буферов: от
первого до конца последнего (`73a6e411:src/graphics/host_gpu/renderer/cache/bufferCache.cpp:3628`,
`73a6e411:src/graphics/host_gpu/renderer/cache/bufferCache.cpp:3630`). При гейте `bdastamp` (по умолчанию включён,
`73a6e411:src/common/gates.cpp:28`) он вызывает `SynchronizeBuffersByRegion(scan_begin, scan_end)`
(`73a6e411:src/graphics/host_gpu/renderer/cache/bufferCache.cpp:3641`).

**Место дыры.** `SynchronizeBuffersByRegion` идёт по регионам куска `[scan_begin, scan_end)`
(`73a6e411:src/graphics/host_gpu/renderer/cache/bufferCache.cpp:3497`). Регион пропускается, если его свидетель
`m_bda_region_stamps[index]` равен штампу и поколение текущее
(`73a6e411:src/graphics/host_gpu/renderer/cache/bufferCache.cpp:3530`,
`73a6e411:src/graphics/host_gpu/renderer/cache/bufferCache.cpp:3532`). При `bdabits` пропуск идёт ещё раньше, по снятому
биту (`73a6e411:src/graphics/host_gpu/renderer/cache/bufferCache.cpp:3507`). Иначе свидетель **всего региона**
перезаписывается (`73a6e411:src/graphics/host_gpu/renderer/cache/bufferCache.cpp:3539`). Но собираются только грязные
диапазоны **куска этого обхода** `[cursor, cursor + bytes)`
(`73a6e411:src/graphics/host_gpu/renderer/cache/bufferCache.cpp:3571`). Свидетель — один на регион
(`73a6e411:src/graphics/host_gpu/renderer/cache/bufferCache.h:380`), отметки «уже пройден в этом проходе» нет.

**Следствие.** Пусть M1 < M2 — два отображённых диапазона с зазором в одном регионе R, и в обоих есть
зарегистрированные буферы, доходящие до R. Тогда в каждом проходе:
1. Обход M1 приходит в R первым, забирает сдвиг штампа, бит `bdabits` и сдвиг поколения, пишет свидетеля и собирает
   только M1∩R.
2. Обход M2 в том же проходе находит свидетеля равным штампу и пропускает R.

Грязные страницы буфера в M2∩R BDA-обход **не собирает никогда**, пока раскладка держится: и записанные до регистрации,
и новые. Каждая новая запись сдвигает штамп, но его снова первым забирает обход M1. Синхронизировать эти страницы может
только другой путь (`SynchronizeBuffer` при привязке дескриптора). Для чтения GPU по адресу (BDA) другого пути нет [I].
Следствие в игре — устаревшие данные буфера на GPU [U]: раскладка в игре не установлена (§3).

**Условия дыры** (все три нужны, стенд проверяет каждое контролем):
- (а) M1 и M2 не касаются и лежат в одном регионе. Касающиеся диапазоны сливаются — контроль `touch`.
- (б) У M1 есть зарегистрированный буфер, доходящий до R. Иначе обход M1 кончается раньше R, и R обходит M2 —
  контроль `nob1`.
- (в) Грязные страницы M2∩R принадлежат зарегистрированному буферу. Иначе их и не нужно синхронизировать.

**Что меняют ручки.**
- `bdanarrow` (по умолчанию 0, `73a6e411:src/common/gates.cpp:404`):
  - 0 и 2 — регистрация сдвигает глобальное поколение
    (`73a6e411:src/graphics/host_gpu/renderer/renderContext.cpp:361`);
  - 1 — регистрация только помечает свои регионы поколением 0
    (`73a6e411:src/graphics/host_gpu/renderer/cache/bufferCache.cpp:3441`, вызов —
    `73a6e411:src/graphics/host_gpu/renderer/cache/bufferCache.cpp:174`);
  - смена карты отображений сдвигает поколение при любом значении
    (`73a6e411:src/graphics/host_gpu/renderer/renderContext.cpp:357`).

  Во всех трёх случаях первым в R приходит обход M1, и он потребляет сдвиг — **дыру не закрывает ни одно значение**.
  Проверка ручки 2 (`bda_nwould` / `bda_nmiss`) стоит после пропуска
  (`73a6e411:src/graphics/host_gpu/renderer/cache/bufferCache.cpp:3543`), поэтому **дыру не видит**: стенд, B12-8,
  `nmiss` = 0. Уточнение аудита с. 113 (снятие с регистрации единственного буфера M1 при ручке 1) — частный случай
  того же места, здесь не измерялся.
- `KYTY_FIX_B13=1` (умолчание с FS9) меняет только порядок публикации у пишущего: эпоха региона, бит `bdabits`,
  затем глобальная эпоха (`73a6e411:src/graphics/host_gpu/regionManager.h:262`,
  `73a6e411:src/graphics/host_gpu/regionManager.h:267`). Решение «пропустить регион» у читателя он не трогает:
  стенд, плечи `f0`/`f1` одинаковы.
- `bdabits` (по умолчанию выключен, `73a6e411:src/common/gates.cpp:199`): при включении бит забирает обход M1, обход M2
  пропускает R по чистому биту — та же дыра (стенд, плечи `b1`, `bit_skips` = 10 000).
- `bdastamp=0`: сбор по всему куску без свидетелей
  (`73a6e411:src/graphics/host_gpu/renderer/cache/bufferCache.cpp:3645`) — дыры нет (стенд, B12-6).

**Ответ (1): дыра есть** — `SynchronizeBuffersByRegion`, свидетель всего региона пишется при обходе одного куска
(`73a6e411:src/graphics/host_gpu/renderer/cache/bufferCache.cpp:3539` против `:3571`); код FS10 тот же (§0).

## 4. Кандидат исхода и проект правки

**Кандидат исхода — п. 638(е)(2):** дыра есть в коде [c] (§1), стенд её воспроизводит (§2, ALL OK) ⇒ Б12 `дефект` K4;
итерация кода 1 `KYTY_FIX_B12` (умолчание 0) с критерием F29b до кода в форме п. 595(е). Раскладка в игре для (2) не
обязательна (как у Б13); в игре она «не различить» (§3).

**Проект правки `KYTY_FIX_B12` (только текст; решает лид).** Вариант аудита с. 113 «счётчик прохода в штампе региона»:
1. Ручка `KYTY_FIX_B12` читается один раз на процесс, как `FixB13Enabled`. Умолчание 0. При 0 путь — нынешний текст,
   дословно.
2. `BufferCache` получает номер прохода `m_bda_pass` (uint64). `RenderContext::PrepareBda` увеличивает его вызовом
   `m_buffer_cache.BeginBdaPass()` после ветки сдвигов поколения, перед `m_mapped_ranges.ForEach(...)` — только при `=1`
   (при `=0` вызова нет). `BdaRegionStamp` получает поле `walked_pass` (0 — не пройден).
3. В `SynchronizeBuffersByRegion` при `=1`:
   - (а) регион с `walked_pass == m_bda_pass` уже пройден другим куском в этом проходе. Пропуск по биту `bdabits` и по
     штампу для него не применяется, свидетель не перезаписывается. Собирается свой кусок `[cursor, cursor + bytes)`
     (`CollectCpuModifiedRanges`, без учёта ручки 2), затем `SynchronizeBuffersOfDirtyRanges`, и строка
     `bda_b12_rewalk` +1;
   - (б) первый визит прохода — как сейчас, плюс `walked_pass = m_bda_pass` вместе с `seen = {stamp, generation}`.

   Довод верности [I, до ревью]. Свидетель первого визита прочитан до его сбора. Запись между ним и сбором второго куска
   либо попадает во второй сбор, либо сдвигает штамп, и следующий проход обойдёт регион снова (консервативно). Проход без
   записей пропускает регион у обоих кусков: `walked_pass` старый, свидетель равен штампу. Цена — один лишний визит на
   регион, общий для нескольких непустых кусков, на сканирующий проход: не больше числа диапазонов минус 1 (в сцене
   ≤ 11).
4. Счётчик `bda_b12_rewalk` в `FrameTrace-x` — визиты по (а), у которых собранный кусок пересёк зарегистрированный буфер.
   Это свидетель [c] того, что игра даёт раскладку дыры (ответ на §3 тегами `b12_v`/`b12_w`). Только счёт, решений не
   меняет.
5. Подпись трансляции шейдеров правка не меняет (код вне `src/graphics/shader/**`), каталоги и кэши не трогает.

**Критерий стенда для F29b (предложение; принимает лид).** Стенд получает ветку `=1` модели — построчную копию правки,
как ветки `KYTY_FIX_B13` в стенде Б13. Члены:
- (с1) `=1`: B12-1 — `lost` = `dirty` = 0 во всех 12 плечах;
- (с2) `=0`: B12-1 — 10 000 из 10 000, то есть воспроизводит;
- (с3) `=1`: B12-2…B12-6 — 0;
- (с4) `=1`, `KYTY_BDA_EPOCH_CACHE=0`, `hole`, проходы без объявлений: `region_scans` = 0 — правка не обходит регион
  без записи;
- (с5) `=1`: число повторных визитов на проход в `hole` = 1, в `split`/`nob1`/`touch` = 0;
- (с6) ревью Red Team с построчной сверкой ветки `=1` модели против кода правки.
