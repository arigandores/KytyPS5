### RC1 (м2: `=4` исполняет пропуск `=1`) — член печати «`=4` сравнивает, а не пропускает»

Плюс `c4` с пропуском меняет картинку (путь `=1`) без записи. То же при `fslean` в гейт-файле: все `rts_*` = 0, `c4` «мёртв» молча.

Фикстуры: строка `FrameTrace-x` с `rts_skip=1` у `c4` → провал; строка с `rts_chk=0 rts_chk_b=5` → провал.

### RC2 (м1: `=4` снимает ещё PB 2 или 5) — член печати «сняты только 3–4»

**Сценарий отказа.** Мутант снимает при 4 ещё PB 2 (`rts_xb_live`) или PB 5 (`rts_xb_bound`): расхождения от устаревших `bind_stamp`/`backing` или петли обратной связи (`is_bound`) попадают в R/X → К_B «жив» по предикату, которого п. 643(в) в контроль не включал → половина B Б14/Б28 читается `НЕ ДЕФЕКТ` по контролю чужой формы. Ни один член (д) этого не видит: (д)(5) смотрит только на `rts_bad_rx ≥ 1`.
**Изменение.** Члены печати у `c4`: (а) **«`=4` вооружён»** — строка `RtSkip: mode 4` в логе, 0 строк `RtSkip: mode 3`/`mode 2`, Σ `rts_xb_meta` = Σ `rts_xb_ser` = 0 (при 4 эти причины по коду не возвращаются — `:3683`); (б) **«прочие пункты PB живы»** — для каждого из `rts_xb_ids`, `rts_xb_live`, `rts_xb_bound`, `rts_xb_pass`: если у `v` той же сцены Σ ≥ 100, то у `c4` Σ ≥ 1; иначе член печатается «не проверен» с числом. ### RC3 (м3: `rts_bad_rx` считает S/M/P/L) — К_B по строкам, не только по счётчику

**Сценарий отказа.** По §3 у `c4` ожидаемы расхождения с одним битом L. **Изменение.** К_B в печати — два прочтения, оба печатаются: (i) по счётчику — Σ `rts_bad_rx` процесса ≥ 1; (ii) по строкам — ≥ 1 строка `RtSkipVerify: MISMATCH … mode=4` с `bits & 0x030 ≠ 0`. Тождество `rts_bad_rx ≤ rts_bad_b ≤ rts_bad` — на каждой строке `FrameTrace-x`, нарушение — дефект разбора.
