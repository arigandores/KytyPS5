## 2. Верность обхода

### 2.1 Код [c] — `f70a2232:src/kernel/fileSystem.cpp:762` (якорь «void ReadGuestWithRetry(File* file, void* buf, size_t nbytes, uint64_t pos, uint64_t remaining,»; +1 — «uint32_t* bytes_read) {»)

1. **Условие обхода** — `f70a2232:src/kernel/fileSystem.cpp:764` (якорь «file->f.Read(buf, static_cast<uint32_t>(nbytes), bytes_read);»; +1 — «if (*bytes_read != 0 || nbytes == 0 || remaining == 0) {»): обход берётся, только если прямое чтение вернуло 0 байт при ненулевом запросе и `remaining` > 0. `remaining` — байты от позиции до конца файла, считаны под `file->mutex` до чтения (`f70a2232:src/kernel/fileSystem.cpp:831`, якорь «const auto remaining  = pos < file_size ? file_size - pos : 0;»; +1 — «auto stream_read = StreamTraceBegin(buf, std::min<uint64_t>(nbytes, remaining),»; у `KernelPread` — от `offset`). Чтение с `remaining` = 0 — конец файла: 0 байт верен, обход не нужен (стенд `at_eof_bad`: `ReadFile` на конце файла с защищённой страницей возвращает FALSE/998, эмулятор отдаёт 0 — семантика POSIX сохранена).
2. **Повторный `Seek`** — `f70a2232:src/kernel/fileSystem.cpp:775` (якорь «file->f.Seek(pos);»; +1 — «file->f.Read(temporary.data(), static_cast<uint32_t>(nbytes), bytes_read);»): возврат на позицию до чтения (у `KernelRead` — `Tell()` до чтения, у `KernelPread` — `offset`). Нужен ли он: отказавший `ReadFile` указатель не двигает (стенд: `pos_after` = позиции до чтения во всех 76 случаях) — `Seek` избыточен, но верен. Результат `Seek` не проверяется (`SetFilePointerEx` на открытом дескрипторе с позицией ≤ размера файла не отказывает — [I]).
3. **Повторное чтение с результатом 0** — второе чтение идёт в буфер хоста (`std::vector`, не защищён), его 0 — настоящий отказ устройства или закрытый дескриптор; гость получает 0 (как без обхода), а не код ошибки: `KernelRead` возвращает `EIO` только при `IsInvalid()` (дескриптор хоста пуст), а не при отказе `ReadFile`. Это дефект **сообщения об ошибке ввода-вывода**, не обхода защиты; в логах выборки повторных отказов 0 (п. 3.2).
4. **`memcpy` в гостя** (`f70a2232:src/kernel/fileSystem.cpp:778`, якорь «std::memcpy(buf, temporary.data(), *bytes_read);»; +1 — «}») — запись пользовательского режима: отказ страницы ловит обработчик трекера и снимает защиту (комментарий над `ReadGuestWithRetry`; тот же путь, что у любой записи гостя). Повторная пометка «CPU-dirty» после чтения (второй вызов `Memory::InvalidateMemory` по `bytes_read` в `KernelRead` и `KernelPread`) после обхода тоже исполняется.
5. **Частичное прямое чтение** (вернуло > 0, но меньше запрошенного, при защищённой странице внутри буфера): обход его **не ловит** (условие — ровно 0). По документации `ReadFile` (Microsoft Learn, «ReadFile function (fileapi.h)», параметр `lpNumberOfBytesRead`: «ReadFile sets this value to zero before doing any work or error checking»; синхронное чтение файла возвращает меньше запрошенного только на конце файла) отказ даёт FALSE и 0 байт; частичный счёт при отказе документом не обещан и не исключён явно — проверено стендами (2.2).
6. **Попутно (не дефекты обхода, записываю для F22b):** (i) буфер обхода — `nbytes` байт целиком (`:774`, якорь «std::vector<uint8_t> temporary(nbytes);»; +1 — «file->f.Seek(pos);»), до `INT_MAX` у `KernelRead` и `UINT_MAX` у `KernelPread`; при нехватке памяти — `std::bad_alloc` и падение [I]; наибольший запрос в логах — 40 627 200 байт; (ii) счётчик печати `static int logged` (`:768`, якорь «static int logged = 0;»; +1 — «if (logged++ < 32) {») — неатомарный, гонка только на числе строк печати; (iii) пред-инвалидация `:834` (якорь «Memory::InvalidateMemory(reinterpret_cast<uint64_t>(buf),»; +1 — «std::min<uint64_t>(nbytes, remaining));») снимает защиту только с `min(nbytes, remaining)` — защищённая страница буфера за концом файла всё равно роняет прямое чтение (стенд `eof_tail_bad`: FALSE/998), обход его восстанавливает; цена — лишнее чтение.
