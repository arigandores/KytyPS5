## RC1 (MAJOR; меняет член `hit` п. 353(г)(2) — сначала пункт лида)

**Что не так.** `TrackDccFill` значением 0 ставит записи маску `UINT32_MAX` — и `PendingDcc` (`dcc_clear_mask` кода `0x00`,
`2da00d80:src/graphics/host_gpu/renderer/cache/textureCache.cpp:3216`, `:3231`), и `CMask` (`:3231`); переход `PendingDcc` → `CMask` маску при
заливке 0 не трогает (`:1992`). `PrepareCmaskClear` снимает только биты слоёв вида (`:2009–2013`) — у T6 (`layers=1`) один бит 0. После
первой очистки запись `CMask` держит `clear_mask = 0xfffffffe` до удаления образа (других записей маски `CMask` нет: `ClearMeta` `CMask`
пропускает, `:3187–3190`; `TouchMeta` зовут только с `is_clear=false`). Проба считает такую запись взведённой:
`const bool armed = fill.pending || (fill.cmask && fill.clear_mask != 0);` (`2da00d80:src/graphics/host_gpu/renderer/pipeline/descriptors.cpp:3668`).

**Сценарий отказа** [c кодом, модель `docs/track-f/f9f2/model_rearm.py`]: `=1`, T6 960×540: заливка → FCE₁ (`hit=1 applied=1`, маска
`0xfffffffe`) → FCE₂ без новой заливки: `armed`, `fill_value 0`, `fill_size 0x2000 ≥ 4050`, `draw_seq` < `fill_seq` ⇒ `Hit`, `rearm=1`;
`FindRenderTarget` → `PrepareCmaskClear` бит 0 не видит (`:2010`) — `ClearImage` нет; `applied` = `0xfffffffe & ~0xfffffffe` = 0 (`:3771`) ⇒
строка `extent=960x540 hit=2 applied=1 rearm=1`. Каждое следующее FCE до новой заливки — ещё `+1 hit`, `+1 rearm`, `applied` не растёт
(S1 модели: 4 FCE на 1 заливку → `hit=4 applied=1 rearm=3`). Член (д)(1) п. 353 «между любыми двумя строками `extent=960x540` рост `hit` не
больше роста `applied`» проваливается по букве на исправном пути, и F9g читает провал целостности (или «не исправлено») там, где очистка
сделана; поле `rearm` считает FCE, а не повторные заливки. Тот же корень даёт ложный `drawn`: FCE₁ (очищено) → draw в цель → FCE₂ без
заливки ⇒ `drawn=1` (S3 модели), а по (д)(3) это строка «не исправлено, T6 получил draw» и вопрос лиду. На F9e2 (`55490711`, член
требовал `PendingDcc`) сценарий S1 даёт `hit=1 applied=1` — регрессия счёта внесена F9e2b. Картинку RC1 не портит (лишнего `ClearImage` нет).

**Наступает ли в игре** — [I]/[U]: нужно ≥ 2 FCE цели T6 на одну заливку. Заливок CMASK T6 в F9d 20 и 18 — «по одной на смену раскладки,
не каждый кадр» (`7f293250:docs/track-f/f9e.md`, (1)); число FCE T6 лог F9d не печатает (`Push marker` — только первые, строки FCE нет).
Сам лид в п. 353(д) Н2 исходит из того, что при `=0` `hit` растёт «на каждом FCE», а при `=1` — «на заливку»; F9e2b даёт при `=1` рост на
каждом FCE после первой очистки — расходится с Н2 по коду.

**Что изменить** (пункт лида до кода, затем новое звено кода): для записи `CMask` взведённость — по битам слоёв цели, а не по всей маске,
например `fill.cmask && (fill.clear_mask & layer_bits) != 0`, где `layer_bits` — биты `[0, layers)` (то, что `PrepareCmaskClear` может снять
для вида FCE), **или** «`b42_fill_seq` новее последней применённой очистки этой записи». Тот же член — для `drawn` (FCE после очистки без
новой заливки не должен давать ни `hit`, ни `drawn`). Фикстура/модель на S1–S3: S1 `hit=1 applied=1 rearm=0`, S2 `hit=2 applied=2 rearm=1`,
S3 `hit=1 applied=1 drawn=0`. Если пункт лида не вносится — печать F9g обязана читать (д)(1) только по ростам `rearm=0`, иначе член
проваливается без дефекта исправления.
