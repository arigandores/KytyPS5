2. **Отметки значения 1 (§3).** Неразделённый остаток `mh_bind` делится **цепочкой** отметок на потоке GuestGpu, начало и конец
   которой — не свои `NowNs`, а заимствованные отметки `mutsite` (`HoldProgramsNs` → `HoldBindingsNs`): цепочка покрывает ровно
   `mh_bind` одного draw, без краевых щелей (§3.1). Каждая своя отметка стоит **между** вызовами, никогда внутри интервала, который
   она делит. Фазы `RebindBuffers` делятся **выборкой 1/8 итераций** цикла слотов (решение — детерминированная последовательность Вейля
   по счётчику вызовов, без алиасинга с раскладкой слотов), класс итерации — по точке выхода вызова, записанной в TLS (§3.3).
3. **Две находки против текста п. 141(в)(2), без которых тождество строки не проверяемо (§4):**
   (а) **`bl_prep`/`bl_img`/`bl_buf` включают dispatch** (`renderCompute.cpp:1005`, `:1036`, `:1042` зовут те же `PrepareBindings`,
   `RebindImages`, `RebindBuffers`), а `mh_bind` — только draw. Доля dispatch по переписи `dd131` плечо 0: `dc_ph_prep` 202,1 +
   `dc_ph_img` 106,0 + `dc_ph_buf` 506,6 = **814,7 мкс/кадр [c, `d19a4f8a`, `bindlap=0`]** ≈ 7,2 % `mh_bind`. Остаток тождества по
   тексту = щели вызовов (+2…+5 %) − доля dispatch (−6…−7 %) — **может пройти ±5 % взаимным сокращением двух ошибок**. Проект
   вычитает долю dispatch тремя парами на пути dispatch (`rb_xprep_ns`, `rb_ximg_ns`, `rb_xbuf_ns`) — **[В 1]**. Следствие для отбора:
   «неразделённые 1 770,8» `spk118` — не остаток draw; остаток draw ≈ 1 770,8 + доля dispatch в `bl_*` ≈ **2,4–2,6 мс [I]**.
   (б) **Оценщик «время × 8» без поправки на цену отметки завышает каждый слотовый уровень на n × ĉ**: пара `NowNs` вокруг интервала
   добавляет к нему ĉ ≈ 8 нс [M `rdtsc_gap_ns` 8,0, с. 122], а умножение на 8 разносит цену выбранных итераций на все. На `bl_buf`
   это ≈ 47 696 × 8 нс ≈ **0,38 мс фантома**, на кольцо потока ≈ 13 966 × 8 ≈ **0,11 мс** (28 % порога 400 п. 141(в)(6)). Проект

## 1. Назначение и что меряется

Сегмент `mh_bind` (подготовка привязок draw, `HoldBindingsNs`, `renderDraw.cpp:4171`) — **11 286,1 мкс/кадр [c `dd131` плечо 0,
`bindlap=0`]**, в `spk118` M (`bindlap=1`) 10 968,5 = `bl_prep` 4 235,0 + `bl_img` 1 094,7 + `bl_buf` 3 868,1 + «неразделено»
1 770,8 [c]. Перепись отвечает на два вопроса отбора с. 134 (п. 141(в)(6)):

- **где лежит «неразделённое»** — голова до `PrepareBindings`, обвязка стадий, `FindBuffers`, `PrepareBda` пути draw, повторный
  поиск целей рендера, хвост до метки `mh_bind` — в мкс/кадр плеча 1 со SE по блокам;
- **сколько стоит каждая популяция слотов `RebindBuffers`** (кольцо потока, const-bank, быстрый путь эпохи, медленный путь с
  загрузками и ожиданиями, `NativeUpload` полезной нагрузки) и **какая доля копий в кольцо повторилась бы в интервале без
  синхронизации** (B2) с долей расхождения байт.

Формулы (все члены — средние по строкам окна 10–88 п. 55(б) плеча 1 или 2; «Σ» — сумма сырых нс строки):

## 2. Ручка: значения, чтение, защёлка, отказ

### 2.1 Значения

- **0** — прежний путь (§9.1): ни одной отметки, ни одного `Add`, ни одной записи TLS кроме защёлки; хуки сбросов читают один
  атомарный флаг и выходят.
- **1** — цепочка draw (§3.1), пары dispatch (§3.2, **[В 1]**), выборка слотов 1/8 с калибровкой (§3.3), точные подчасти (§3.4).
- **2** — 1 + перепись B2 (§5). Таблица и тени — в частной памяти процесса (2 МиБ таблица + 32 МиБ кольцо теней + 64 КиБ буфер
  сверки в куче, указатель — в TLS потока защёлки).
- **Выделение — [RC8]:** ОДИН раз, при первой защёлке **любого значения ≥ 1** (не значения 2), до первой отметки этой операции;
  выделенное сразу касается целиком (заполнение нулями), чтобы первые касания страниц (обнуление ОС) не легли в кадры плеча 2. В ABBA
  `rbcen=1|2` это первая операция первого блока с ручкой ≥ 1 — какое бы плечо ни шло первым, цена выделения ложится в один кадр на
  позиции 0 этого блока (вне окна 10–88 п. 55(б)) и одинаково для обоих плеч по построению (оба плеча работают на уже выделенной и
  тронутой памяти). Буфер сверки выделяется на каждом потоке, впервые защёлкнувшем значение ≥ 1 (в `bc133` — один поток GuestGpu,
  `m4baton` = 0). Отказ выделения — строка `RbCen: refused reason=b2alloc` раз (**[В 11]**, принято п. 142(б)); после отказа значение 1
  работает целиком, значение 2 работает как 1 (заметки и `Census` не исполняются, `g_rb_b2_live` остаётся false, все `rb_b2_*` = 0)
  — отказ виден в обоих плечах (строка печатается при первой защёлке ≥ 1, не при первой защёлке 2).

**Флаг `g_rb_b2_live` и поколение при включении — [RC2], [RC3].** `g_rb_b2_live` (atomic bool) пишет ТОЛЬКО защёлка (draw или
dispatch) и ТОЛЬКО при смене значения: `SetLive(v)` = `if (g_rb_b2_live.load(relaxed) != v) { if (v) g_rb_gen.fetch_add(1, release);
g_rb_b2_live.store(v, release); }`. Снятие защёлки dispatch и конец draw флаг не пишут: между двумя операциями одного плеча 2 (например,
dispatch → EVENT_WRITE CS_PARTIAL_FLUSH `pm4Handlers.cpp:1831` / ACQUIRE_MEM `:1318` → dispatch) хук видит `true` и сдвигает поколение
— пакет синхронизации между двумя compute рвёт интервал, как и должен. Переход false → true (граница блоков плеча 1 → плеча 2, первая
защёлка 2 в процессе) делает `g_rb_gen.fetch_add(1)` без счётчика причины: записи таблицы прошлого блока плеча 2 (поколение N,
которое плечо 1 не двигало) мертвы с первой копии нового блока, независимо от окна 10–88 п. 55(б). Сдвиг — до `store(true)`: хук,
увидевший `false` между ними, ничего не теряет (копий нового блока ещё нет). Переход true → false поколение не двигает (записи не
читаются, пока флаг false; следующий переход false → true их убьёт). **Защёлка draw не снимается:** её значение после F (§3.1) не
читает никто — классы, пары и заметки требуют `t_rb.slot ≠ 0`, а слот ставится только внутри `RebindBuffers` латченной операции;
следующая операция защёлкивается заново.

Чтение — одна загрузка значения гейта на операцию, ДО первой отметки операции: первая отметка цепочки draw — заимствованная
`HoldProgramsNs` (§3.1), и защёлка стоит перед ней, поэтому цена чтения падает в `mh_prog`, не в `mh_bind`. Все отметки, классы и
перепись B2 одной операции читают `t_rb.mode`, а не гейт ⇒ смена значения на потоке презентации посреди операции её не рвёт.
**Ручка может быть плечом расписания** (п. 141(в)(4): ABBA `rbcen=1|2`): каждая операция защёлкивается заново. Хуки сбросов на
всех потоках (§5.2) читают `g_rb_b2_live` — флаг последней смены значения защёлкой; на границе плеч возможна одна запаздывающая
операция — позиции 0–9 блока вне окна 10–88 п. 55(б). Хук, увидевший `false` в плече 2 до первой защёлки блока, пропускает сброс,
который и так покрыт сдвигом RC3 при этой защёлке.

### 3.3 Слоты `RebindBuffers`: выборка 1/8, классы, оценщик, калибровка

**Где:** `descriptors.cpp` `RebindBuffers` `:3803–3914`, цикл слотов `:3839–3867`; оба пути (draw и dispatch — **[В 1]**; популяция
= `bl_buf_n`, `BindLapBuffers`, `:3815`). Поток GuestGpu.

**Решение выборки** — детерминированное, по счётчику вызовов (п. 141(в)(2) «выборка 1/8 по счётчику вызовов»): TLS `k` += 1 на
каждой итерации латченной операции; выбрана ⇔ `(k · 0x9E3779B97F4A7C15) >> 61 == 0`. Последовательность Вейля равнораспределена и
**не периодична** — у `k mod 8` периодическая раскладка слотов (одинаковое число слотов у подряд идущих draw) давала бы выборку
всегда одной позиции слота, т. е. одного класса. Проверка строки: 8 · `rb_samp_n` ≈ `bl_buf_n` (расхождение Вейля O(log n / n) —
доли процента).

**Итерация i латченной операции** (решение s_i вычислено в конце итерации i − 1; s_0 — в прологе):

```
  if (s_i) t0 = NowNs();                         // S0: первый оператор тела итерации (перед :3840)
  t_rb.slot = 1; t_rb.cls = None; t_rb.notes = 0;
  ... тело :3840–:3866 без изменений ...
  t_rb.slot = 0;
  Add(класс → rb_stream_n | rb_cbank_n | rb_epoch_n | rb_slow_n; None → rb_cls_bad [В 7]); // счёт — на КАЖДОЙ итерации [RC9]
  s_next = Weyl(++k);                              // решение следующей итерации — внутри пары этой
  if (s_i) { t1 = NowNs(); Add(rb_K_ns, t1 - t0); Add(rb_samp_n, 1);          // S1
             if (калибровочная) { u0 = NowNs(); u1 = NowNs(); Add(rb_cal_ns, u1 - u0); Add(rb_cal_n, 1); } }
  if (t_rb.mode == 2) Census(t_rb.notes);          // §5 — вне пары
  s_i = s_next;
```

**Почему так:** всё, что платит КАЖДАЯ итерация (класс-счёт, решение следующей итерации), стоит ВНУТРИ пары выбранной итерации ⇒
выбранная итерация несёт ту же работу, что невыбранная, и ×8 переносит её на всю популяцию честно (идиома `bindwit`/`blmove`:
цена, которую платят все, входит в меряемое одинаково). Вне пары остаются только `if (s_i)` (≈ 0,5 нс), управление циклом и то, что
платят лишь выбранные (Add времени, калибровка) — это и есть инструментальная часть остатка R2 (§4.2).

(2) цель B2 — не только `memcpy`: повтор по интервалу снимает у потокового слота и `UploadEpoch`/`HasCurrentUpload`, и совмещённый
запрос трекера, и `Map`/`TryReadBacking`/`Commit` (всё после пробы таблицы). Уровень класса ⊇ копии; снимаемое ≤ уровень − проба.

**Оценщик (п. 141(в)(2) «время × 8») с поправкой [В 3]:** уровень_K = 8 · `rb_K_ns` − n_K · ĉ, ĉ = `rb_cal_ns` / `rb_cal_n`

вызова после rdtsc + голова второго до rdtsc — ровно то, что меряет пустая пара); E[8 · Σ_выб (W + ĉ)] = Σ_все W + n · ĉ; вычитание
n · ĉ снимает фантом. Без поправки фантом ≈ 0,38 мс на `bl_buf` (§0 п. 3(б)).

## 5. Значение 2: перепись повтора B2 (без действия)

### 5.1 Правило, ключ, таблица

**Копии B2** — CPU-копии гостевых байт в кольцо потока (`m_stream_buffer`, 64 МиБ, `bufferCache.cpp:542`), сделанные ВНЕШНИМ вызовом
внутри латченного слота: потоковая `bufferCache.cpp:1515–1523` (запись заметки на `:1533`), прямая const-bank `descriptors.cpp:261–266`
(заметка на `:280`), выровненная const-bank при `!gpu` `:308–316` (заметка на `:340`). GPU-копия const-bank (`:324–330`) — не B2
(данные с GPU, не из гостя). Заметка `{vaddr, size, alignment, kind, gen0}` — TLS, до 2 на итерацию (переполнение → `rb_cls_bad`);
`gen0` — поколение ДО чтения байт копией (**[RC1]**, ниже).

**Интервал** — отрезок исполнения командного процессора между двумя сбросами §5.2. Один глобальный счётчик поколения
`g_rb_gen` (atomic u64; хук сброса: `fetch_add(1, release)` и `Add(rb_b2_rst_<причина>, 1)`; при включении переписи — ещё сдвиг без
причины, §2.2 **[RC3]**). **Два чтения поколения на копию — [RC1]:**
(1) **`gen0`** — `g_rb_gen.load(acquire)` непосредственно ПЕРЕД чтением байт копией пути: потоковая — перед `:1514` (до `stream_t0` и
`Map` `:1515`, чтение байт — `TryReadBacking` `:1516`), прямая const-bank — перед `descriptors.cpp:260` (чтение — `:263`), выровненная
const-bank — перед `:307` (чтение — `:311`, только при `!gpu`); только при `t_rb.mode == 2`, внешнем вызове и живой переписи B2;
пишется в заметку; (2) **`gen1`** — `g_rb_gen.load(acquire)` в `Census`, после S1 итерации (§3.3), т. е. ПОСЛЕ копии, на GuestGpu.
Вставка кладёт в запись `gen0`; копия B — **повтор ⇔ `entry.gen` (= `gen0` копии A) = `gen1` копии B**. Так как
`gen0(A)` ≤ `gen1(A)` ≤ `gen0(B)` ≤ `gen1(B)`, равенство значит: ни одного сброса за весь отрезок [чтение байт A; чтение байт B] —
сброс с другого потока между копией A и её `Census` (сценарий RC1: `FinishAsyncReadback` / `DownloadImageMemory` → `WriteBacking` на
потоке приоритетных операций) рвёт пару, а не склеивает интервалы. Хуки писателей стоят ДО изменения байт (§5.2: первый оператор
`TryWriteBacking`; перед сдвигом `m_map_epoch` в той же критической секции), поэтому копия, прочитавшая новые байты, видит и
сдвинутое поколение в своём `gen1` [I]: при чтении через `TryTransferBacking` / `TryGetBackingPointer` — ребром замка `m_mutex`
адресного пространства; при чтении через закэшированный указатель страницы (`memory.cpp:947–1007`, без замка) — порядком x86-TSO
(атомарный сдвиг хука виден раньше байт, записанных после него; загрузки читателя не обгоняют друг друга) и acquire-загрузкой эпохи
отображений в `CachedBackingPage`. Цена — одна загрузка атомика на копию (≈ 1 нс, в пределах цены §10).

**Таблица:** глобальная, прямого отображения, 2¹⁶ записей × 32 Б = 2 МиБ (частная память); запись `{vaddr, size:32, align:16,
gen, shadow_off, shadow_lap}` (`gen` = `gen0` вставившей копии **[RC1]**); индекс — хэш ключа. Доступ — только с потока, исполняющего
командный процессор (сериализован; при `m4baton` — поток-реле тоже сериализован, `graphicsRun.cpp:2523–2582`; в `bc133` `m4baton` = 0).
Сброс интервала — сдвиг `g_rb_gen`, таблица не чистится (запись жива ⇔ `gen` = `gen1` текущей пробы); записи прошлого блока плеча 2
убивает сдвиг при включении (**[RC3]**).

**`Census(note)`** (на каждую заметку; `rb_b2_n` += 1 — на каждой пробе, тем же кодом, что `rb_b2_would`, п. 142(б) В6 **[RC9]**):

| исход пробы (G1 = `gen1` этой копии) | действие |
|---|---|
| ключ совпал ∧ `entry.gen` = G1 | **повтор**: `rb_b2_would` += 1, `rb_b2_kb` += size; если у записи есть живая тень — `rb_b2_chk` += 1, `TryReadBacking(vaddr → буфер сверки)`, `memcmp` с тенью ⇒ `rb_b2_diff` += (≠); запись НЕ обновляется (механизм отдавал бы ПЕРВУЮ копию интервала) |
| ключ совпал ∧ `entry.gen` ≠ G1 | повтор через сброс: при живой тени — `rb_b2_xchk`/`rb_b2_xdiff` **[В 5]**; вставка заново с `gen0` этой копии |
| ключ другой ∧ `entry.gen` = G1 | вытеснение живой записи: `rb_b2_evict` += 1 **[В 6]**; вставка |
| иначе | вставка |

Вставка с `gen0` < G1 (сброс попал между чтением байт этой копии и её `Census`) даёт мёртвую с рождения запись — следующая копия ключа
пойдёт в «повтор через сброс»; это ошибка в безопасную сторону (занижает долю повтора), счётчика не требует.

**Вставка:** `gen` = `gen0` **[RC1]**; тень — у 1/16 вставок (решение Вейля по TLS-счётчику вставок): `TryReadBacking(vaddr, кольцо_теней +
off, size)`. Кольцо теней — 32 МиБ обычной кучи (≈ 16 кадров вставок при ≈ 1,9 МБ/кадр [I]); запись хранит `(off, lap)`; тень жива,
пока кольцо её не переписало. Проверка при повторе на записи с переписанной тенью — `rb_b2_shovf` += 1 **[В 6]** (в пределах одного
интервала невозможно при интервале < 16 кадров; в `xchk` — штатно, не ошибка).

**Слот кольца не читается никогда.** Байты «сейчас» и тень берутся из гостя через `LibKernel::Memory::TryReadBacking` — ту же
функцию, что делает копию пути (`bufferCache.cpp:1516`, `descriptors.cpp:263`, `:311`): чтение через бэкинг, **без фолтов защиты и
без изменения трекера** [I, Red Team `review133.md` §2]. Отказ `TryReadBacking` в переписи — сверка пропускается (не `EXIT`, не
счётчик ошибки). **Побочные эффекты есть — [RC6]:** (а) чужие счётчики `BackingPageHits`/`BackingPageMisses` (`memory.cpp:959`, `:962`)
растут от чтений переписи — они печатаются в основной строке `FrameTrace` (`videoOut.cpp:1503`); (б) чтения переписи вытесняют слоты
потоковой таблицы трансляций GuestGpu (512 слотов, `memory.cpp:937–957`) ⇒ у копий пути больше промахов и заходов в
`TryGetBackingPointer` под `m_mutex` (`memoryAddressSpace.inc:203`); (в) чтения больше 4 страниц идут в `TryTransferBacking` адресного
пространства под замком, общим с гостевыми отображениями. Всё это — время и чужие счётчики, не значения и не решения пути (§9.2).
**Чтение `bc133` поля `BackingPage*` основной строки между плечами не сравнивает** (п. 143(в)): их разность — цена переписи, не пути.

**Окно гонки — двустороннее [RC5].** Между копией пути и чтением переписи (тень при вставке, чтение «сейчас» при сверке) —
≈ 0,1–0,3 мкс (S1, счёт, решение). Запись CPU в это окно действует в обе стороны: (1) **занижение** `rb_b2_diff` (опасная сторона):
запись попала между копией A (кольцо получило старые байты) и снятием тени A (тень — новые байты), копия B интервала читает новые
байты ⇒ сверка «совпало», хотя механизм отдал бы B старые байты A; (2) **завышение**: запись между копией B и её сверкой ⇒ ложное
«расхождение». **Знак суммарного вклада неизвестен**; величина [I] ≤ (частота записей CPU в копируемые диапазоны) × (окно ≈ 0,1–0,3 мкс
на копию), не мерена. Чтение доли расхождения у порога 0,01 п. 141(в)(6) обязано называть эту оговорку (§1, правило (5)); вывод
«проходит: доля расхождения ≤ 0,01» — с ней, не без неё.

`rb_b2_kb` — байты повторов; печатается как `ob_stream_kb` (байты / 1000 с усечением по строке, `videoOut.cpp:1912`, `:1365`) —
**[В 8]**.

Решение «тенить» — у вставки, по TLS-счётчику вставок (Вейль, 1/16). Сверка — только на повторах записей с тенью ⇒ `rb_b2_chk` ≈

### 5.5 Положительный контроль сверки байт **[В 5]**

Та же сверка на повторе ключа ЧЕРЕЗ сброс (`rb_b2_xchk`, `rb_b2_xdiff`): запись CPU между двумя копиями, разделёнными сбросом, легальна

сверка мертва ⇒ доля расхождения недействительна ⇒ условие «≤ 0,01» п. 141(в)(6) **не проверено** (не «проходит»), вопрос закрытия;
в дыму `s2s133` то же — находка шага 5.

## 13. Риски и что проект НЕ доказывает

- **Не доказывает, что B2 корректен или снимаем.** Перепись меряет долю повтора по ГРУБОМУ правилу §5.2 и долю расхождения байт на
  выборке 1/16; отбор с. 134 решает по п. 141(в)(6).
- **Полнота списка сбросов** — утверждение проекта для враждебного отзыва: пропущенный писатель в гостевую память или пакет
  синхронизации завышает долю повтора; сверка байт такой пропуск видит лишь частично (она ловит изменение байт, не порядок).
  Отдельные места: GPU-запись в уже грязный образ — пути нет [I, отзыв], переход «чистый → грязный» — сброс по правилу, не по коду
  (§5.3, п. 143(а)); CPU-писатели признаны не сбросами доводом, не кодом (**[В 9]**(а), принято п. 142(б)); смена отображения —
  сброс (**[RC4]**). Полнота — для путей дерева `9bb1e2ef`; пути вне него не доказаны (п. 143(д)).
- **Уровни — [c] с выборкой** (SE выборки + SE блоков); `rb_slow`/`rb_sync_up` — тяжёлый хвост загрузок (§4.2). Уровни включают
  цену значения 1 внутри своих отрезков; к NEW без инструмента не переносятся. Ни один уровень — не потолок механизма.
- **Щели вызовов** (R1) и пролог (R2) — оценки [I]; если R1 или R2 выйдут за ±5 % — «не приняла место», вопрос закрытию.
- **Время:** значение 2 удлиняет GuestGpu на ≈ 1–1,7 мс/кадр; гонки CPU-записей с копиями сдвигаются — `rb_b2_diff` в плече 2 может быть
  смещён против пути без переписи **в любую сторону** (**[RC5]**, в ред. 1 ошибочно «завышен»).
- **Гонка «копия ↔ тень/сверка» двусторонняя [RC5]** (§5.1): занижение `rb_b2_diff` (запись между копией A и снятием её тени) — опасная
  сторона для порога 0,01; завышение (запись между копией B и сверкой) — вторая; знак суммы неизвестен, величина [I] ≤ (частота
  записей CPU в копируемые диапазоны) × (0,1–0,3 мкс на копию), не мерена. Проект её не измеряет и не исключает.
- **`TryReadBacking` переписи [RC6]:** без фолта и без трекера [I, отзыв §2], но с побочными эффектами — чужие счётчики
  `BackingPageHits`/`BackingPageMisses` основной строки, вытеснение таблицы трансляций GuestGpu (больше промахов и заходов под
  `m_mutex` у копий пути), замок адресного пространства на чтениях > 4 страниц. Поля `BackingPage*` между плечами не сравниваются;
  часть Δ `dt_us` плеча 2 − плеча 1 и роста уровней классов плеча 2 — эти эффекты, не путь.
- **Режим трейса [RC7]:** всё сказанное о R1/R2 и цене — для `lite`; при полном режиме тождества не сравнимы с прогнозом.
- **Частоты событий RC1/RC4** (сброс между копией и её `Census`; смена отображения) не мерены (п. 143(д)); закрытие RC1/RC4 делает
  их безопасными по построению, а не редкими по измерению.
- **Не доказывает:** OLD; другие сцены; время `9235a7ac`; что 51,38 % — время установленной сборки; 60 FPS.
