## 1. What is tested

Build `916f64898a5a31c697ad0d823f0795850acc160cf56271b566e8ae330c7c3b2c` (`74e2ad7`). Knob `titleasync`
(`KYTY_TITLE_ASYNC`, default 0): 1 — once the SDL main loop runs, `UpdateTitle` hands the title to the main thread without
waiting (at most one queued title task); 0 — it waits for the main thread while the present thread holds
`VideoOutConfig::mutex`. `KYTY_MAIN_STALL_TEST=3000:3000` (measurement only): at the 3 000th `UpdateTitle` call the present
thread queues a 3-s sleep on the SDL main thread. Prediction: at 0 the emulation freezes ≈ 3 s (the present thread waits
for the title task queued behind the sleep, GuestGpu waits for the config mutex); at 1 it does not, while the main thread
still sleeps (the title task's queue-to-run age shows it). This proves what the knob does, **not** that the session-113
freeze was caused by the title wait.

## 4. Rule

The stall window of a run = the first three main `FrameTrace` rows after its queued line. **PASS** if both runs are
admitted and: `ctl114a` — max `dt_us` of the window ≥ 2 500 000 and a `MainThreadWait:` line with `frame=3000` and
`us` ≥ 2 500 000; `ctl114b` — max `dt_us` of the window ≤ 500 000, no `GpuWaitSlow` line, and a `MainTaskLate:` line with
`us` ≥ 2 500 000. **FAIL** if both are admitted and any of these does not hold. **NOT_ADMITTED** otherwise. PASS is the
precondition of seal 02's SHIP.

## 6. Known limits

One scene, one injected stall per run, pinned GPU clock; the stall frame counts `UpdateTitle` calls (not guest flips), so
the two runs stall at different game moments; `titleasync=1` closes only the title path — other blocking calls under the
config mutex remain (ROADMAP item 4, F2).

## 7. Must not be claimed

That the session-113 freeze was the title wait; that `titleasync=1` removes every freeze of this class; anything about speed.
