# Сессия 44 — DualSense: датчики, хаптика, звук, триггеры

Дата: 2026-09-12. Ветка `merge-upstream`, поверх `a2d8163`.

## Задача

Пользователь подключил DualSense и сообщил, что «вибрации и прочего» нет. Требовалось
заставить работать гироскоп, вибрацию и адаптивные триггеры.

## Что было

- Кнопки, стики и аналоговые L2/R2 уже работали (SDL game controller).
- Гироскоп/акселерометр: в PadData шли только синтетические значения клавиатуры (R, Z/X, сессия 38).
- Вибрация: игра вызывает `scePadSetVibration` ~19 000 раз за прогон, **всегда с нулями**.
  Настоящая хаптика идёт отдельным потоком PCM: игра создаёт порт AudioOut2 типа 6
  (VIBRATION → `AUDIO_OUT_PORT_TYPE_VIBRATION`, 48 кГц, 2 канала, float, грейн 512).
  Эмулятор такой порт открывал без SDL-устройства и данные **выбрасывал** (`audio.cpp`).
- Триггеры: `PadSetTriggerEffect` был реализован, но не было видно, вызывает ли его игра.

## Сделано

### Реальные датчики движения

- `window.cpp`: при подключении пада включаются `SDL_SENSOR_ACCEL` и `SDL_SENSOR_GYRO`,
  добавлена обработка `SDL_CONTROLLERSENSORUPDATE`; в лог пишется имя пада, тип, наличие
  датчиков и HID-путь.
- `controller.cpp`: `GameController::MotionSample` принимает сэмплы SDL (м/с², рад/с),
  переводит ускорение в G, интегрирует ориентацию из угловой скорости (кватернион,
  нормализация, шаг ограничен 50 мс), `PadResetOrientation` сбрасывает её в единичную.
  `pad_fill_data` отдаёт реальные значения, когда они есть и не задействован клавиатурный
  ввод (R/Z/X остаются запасным путём и имеют приоритет при нажатии).
- Проверено пользователем в игре: подсказка «встряхните контроллер» в пустыне проходит
  движением самого DualSense.

### Хаптика

Три пути, переключатель `KYTY_HAPTICS_MODE` (`audio` по умолчанию, `bt`, `rumble`, `off`):

1. **audio (USB, работает):** DualSense по кабелю — 4-канальное звуковое устройство,
   каналы 3/4 — катушки. `HapticsOutput::PushAudio` открывает устройство SDL по имени
   («DualSense»/«Wireless Controller»), кладёт PCM порта вибрации в каналы 3/4 без
   ресемплинга (обе стороны 48 кГц), держит очередь не длиннее ~60 мс.
   **Пользователь подтвердил: вибрация есть и похожа на настоящую.**
2. **bt (не работает на Windows):** HID-отчёт `0x32`, 141 байт, 32 кадра int8-стерео 3 кГц,
   CRC32 с префиксом 0xA2 (формат по исследованию SAxense, https://apps.sdore.me/SAxense).
   Реализован поток с шагом 10,67 мс, децимация 48 → 3 кГц box-фильтром.
   Windows принимает записи (ошибок нет), но пад их игнорирует — см. «Bluetooth» ниже.
3. **rumble:** огибающая (RMS каждого канала) на обычные моторы. Работает и по Bluetooth.

Громкость — `KYTY_HAPTICS_GAIN` (0..8), выключение — `KYTY_HAPTICS=0`.

### Звук игры не уходит в геймпад

При подключении DualSense по USB Windows делает его устройством вывода по умолчанию, и весь
звук игры уходил в пад (в логе — открытие 4-канального устройства), то есть пропадал.
`audio.cpp:ChooseOutputDevice` теперь спрашивает устройство по умолчанию
(`SDL_GetDefaultAudioInfo`) и, если это пад, выбирает первое другое; `KYTY_AUDIO_DEVICE=<подстрока>`
задаёт устройство вручную. Проверено: звук на компьютере есть, хаптика в паде остаётся.

### Триггеры

`PadSetTriggerEffect` логирует первые 32 вызова, каждый 500-й и отказы: маску, режимы и
первые байты обеих команд, а также принял ли пад пакет. За прогон — около 4000 вызовов,
все с **режимом 0 (эффект выключен)**, отправка успешна. Значит на пройденном участке игра
тугих триггеров не задаёт; работоспособность самих эффектов не доказана.

### Диагностика в логе

- `libAudio2.cpp`: логируются все создания портов, кроме объектных (раньше только первые 16),
  с типом, форматом, частотой, флагами, пользователем и хэндлом.
- `audio.cpp`: строка при создании порта вибрации.
- `controller.cpp`: режим и громкость хаптики, открытие звукового устройства пада,
  открытие HID для `0x32`, статистика раз в 10 с (pushes/reports/peak/mode/errors).

## Bluetooth: почему настоящей хаптики нет

Пять проб (`C:\kyty\scripts\s43_ds5_haptics_test*.py`, работают без эмулятора):

- Отчёт `0x31` (лайтбар, моторы) по Bluetooth **работает** — проверено цветом и вибрацией моторов.
- Отчёт `0x32` во всех вариантах не даёт вибрации: дополненный до 547 байт, с CRC в конце
  буфера, с байтом заголовка 0x00/0x02, с растущим счётчиком, с раскладкой Linux-драйвера
  (seq<<4 + метка 0x10).
- Ровно 141 байт Windows отправить не даёт: `WriteFile` → ошибка 87, `HidD_SetOutputReport`
  требует полный размер буфера (`OutputReportByteLength` = 547).
- Отчёт `0x39` (547 байт) **разорвал Bluetooth-соединение** (далее ошибка 1167) — не повторять.
- После переподключения пад возвращается в простой режим; расширенный включается чтением
  feature-отчёта 0x05 (калибровка), как делает SDL. Без этого 0x31 тоже игнорируется —
  из-за этого проба 3 была недействительной.

- Пробы 6–8: перед потоком `0x32` звуковой тракт пада включался отчётом `0x31` (громкости
  наушников/динамика 0x7F, `ucAudioEnableBits` 0x10/0x30/0x14, разрешающие биты 0xB0/0xFC).
  **Хаптики нет ни в одной конфигурации.** В той же пробе лайтбар меняет цвет (после сброса
  битом 0x08) и моторы отрабатывают контрольный гудок — то есть `0x31` по Bluetooth доходит,
  а `0x32` пад отбрасывает.

Вывод: по Bluetooth на Windows настоящая HD-хаптика недостижима имеющимися средствами;
остаётся `KYTY_HAPTICS_MODE=rumble`. Платная DSX решает задачу собственным драйвером,
эмулирующим проводное подключение; открытых реализаций BT-хаптики для Windows нет,
SAxense проверен только на Linux (там hidraw отправляет ровно 141 байт).
