## 3. Кандидаты

### M1 — B2: повтор копии в кольцо потока внутри интервала без синхронизации

- **Источник.** `docs/session-119/designs/witness_binding.md` §2.4 B2 (≤ 0,82 мс [I], «довод неаудирован», п. 2 с. 119); общий приём
  эмуляторов с потоком команд — дедупликация загрузок констант в пределах одной отправки (кольцо загрузок живёт до ретайра отправки).
- **Что не делается и почему результат тот же (по коду).** `ObtainBuffer` (`bufferCache.cpp:1508–1534`) для CPU-грязного read-only
  диапазона ≤ `CACHING_PAGESIZE` при каждом вызове делает `m_stream_buffer.Map` → `TryReadBacking` (memcpy гостя в кольцо) → `Commit`;
  бит CPU-грязный не снимается (страница остаётся записываемой без фолта — так путь избегает вооружения). Механизм: если тот же
  `(vaddr, size, alignment)` уже скопирован в текущем интервале — вернуть прежнее смещение кольца. Интервал — отрезок одной отправки
  между точками, после которых гость вправе ожидать упорядоченную запись: WAIT_REG_MEM, RELEASE_MEM, EVENT_WRITE_EOP/EOS, WRITE_DATA,
  DMA_DATA, COND_EXEC, SET_PREDICATION, начало отправки; плюс неизменны последовательность записей GPU (`NoteGpuWrite`, копии образ →
  буфер, DMA), поколение кольца `StreamBuffer::Generation()` и КАЖДАЯ запись эмулятора в гостевую память (скачивания, метки, чтения
  назад) — точка интервала. Довод тождества: запись CPU, не упорядоченная ни одной видимой GPU синхронизацией относительно двух draw
  одного интервала, на железе может лечь после обоих — оба вправе прочесть прежние байты. Это **не** «тот же результат побайтно»,
  а «результат, который железо может дать»; именно это и должна проверить самопроверка (ниже).
- **Уровень (поправка п. 136(в)).** В NEW по времени — **[U]** (`ob_stream_us` в `lite` = 0; §2). [c-OLS] 274–432 неустойчиво.
  [c-OLD] 902,4 (`s78`). Снимаемое = d × (копия + `Map`/`Commit`) − проба таблицы (22,7 тыс. × ~5 нс ≈ 0,11 мс [I]); d [U], верхний
  прокси — доля побайтно равных предыдущей копии 84 % (`sky62a`, с. 62, OLD) ⇒ при уровне OLD **≤ ≈ 0,65 мс [I]**.
  **Уровень [U]; нужен тег переписи:** `rb_stream_ns`/`rb_stream_n` (таймер кольца в идиоме `Enabled()`) и `rb_b2_would`/`rb_b2_kb`
  (копии, которые правило интервала повторило бы) — значения 1–2 ручки §5, сборка от `d19a4f8a`. **(1) не проходит.**
- **§3 «Что закрыто».** Мемо копии кольца по гостевой памяти — закрыто с. 62 (свидетель по памяти невозможен: страница пишется без
  фолта; свидетель содержимым стоит чтения). **Новое одной строкой:** свидетель B2 — по порядку (интервал без синхронизации), не по
  памяти; основание закрытия с. 62 его не покрывает (п. 2 с. 119 назвал его неаудированным). Не вооружение, не перенос.
- **(3) самопроверка.** Значение 2: копия делается всегда; одновременно ведётся таблица B2 и тень байт прежней копии в обычной памяти
  (НЕ чтение слота кольца — BAR, 54 мс/кадр по с. 62); при попадании B2 сверяются байты гостя сейчас и тень ⇒ `b2_bad` (расхождение по
  СОСТОЯНИЮ памяти), в дескриптор идёт свежая копия. Значение 3 (положительный контроль): правило интервала без сброса на точках
  синхронизации (повтор на всю отправку) ⇒ расхождение ожидается по записям CPU между draw: в `sky62a` байты отличались у 83–102 копий
  на кадр (`cb_diff`, с. 62, OLD) ⇒ контроль живой при P(0) ≈ e^(−90·кадры) ≈ 0.
- **Риск корректности.** Средний. (а) Пропущенная точка интервала (писатель эмулятора в гостевую память, не названный проектом) ⇒
  draw читает устаревшие константы — порча картинки без сигнала. (б) Гость пишет константы «гонкой» (без синхронизации, по времени
  кадра): на железе это легально в обе стороны, но **текущий эмулятор даёт свежие байты — механизм даст прежние**; значение 2 будет
  считать это `b2_bad` > 0, и правило «bad = 0» п. 134(з)(3) это не различит. Нужно различение «записи в пределах интервала» от «ошибки
  механизма» — вопрос проекта, в критериях его нет.
- **P(0) редких событий чтения.** `b2_bad` = 0 на ≈ 10⁶–10⁷ попаданиях за 300 с — сила нуля через живой контроль 3 (выше). Событие (б)
  может быть не редким: у `sky62a` расхождений 83–102 на кадр — какая их доля внутри одного интервала, [U] (значение 2 переписи §5).
- **Сессий до отгрузки:** прототип + ABBA — 1 (с. 134 после переписи), отгрузка — следующая; но аудит всех писателей гостевой памяти и
  всех пакетов синхронизации — объём, которого 2 сессии могут не вместить ⇒ **(4) на грани**.
- **Ожидание Δ:** верх −648 × (0,75 … 0,90) ≈ **−486 … −583 мкс [I]** (0,84 × 902,4 − 110 проба; уровень OLD); реально [U] — d в
  пределах интервала и уровень в NEW неизвестны.
- **Вердикт:** (1) — нет (уровень [U]). **Не проходит.** Самый сильный вход переписи `bc133` (§5).
