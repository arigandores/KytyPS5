## 4. Вариант исполнителя 1 — сдвиг запросов ровно на подстановку (член п. 539(б)), свой разбор

**Где корректность стоит на самом деле [c кода].** Ответ обхода при проигрыше — по позиции, адрес запроса не читается
(`Answer`, `9635cb0f:…/shaderReplay.cpp:408–423`: `requested->push_back(address)`, затем `reads[next++]`); перестройка
`Specialize` (`:788–793`) — тот же позиционный проигрыш слов каталога; самопроверка (`:726`, `:737`) — та же функция
`MaterializeResources` над полным каноническим путём с требованием `ok`, `complete`, специализация = живой. Значит, ошибочный
допуск сдвига в `SubstitutionHolds` может дать только одно из двух: (а) самопроверка проходит — в каталоге запись, чья
перестройка даёт ровно живую специализацию (неверного пайплайна нет); (б) не проходит — отказ `self`, член К3. Пути «неверная
специализация в каталоге» через вариант 1 нет. Проверка запросов определяет только, какие слова канонизируются (покрытие и
отсутствие адресов), не верность записи.

**Арифметика сдвига [c кода `9635cb0f:src/graphics/shader/recompiler/ir/passes/SrtWalker.cpp:1870, 1904, 1927`].**
`difference = (u64)value − (u64)raw` по модулю 2^64 (`:594`), для `*_HI` — `difference << 32` по модулю 2^64 (`:600`);
`now.requested[j] − base.requested[j]` — тоже `uint64_t` по модулю 2^64 (`:604`).

1. **Перенос в старшую половину.** База обхода — `((high << 32) | low) & AddressMask` (`:1904`), к ней адрес чтения
   прибавляется 64-битно (`((base & ~3) + byte_offset) & ~3`, `:1927`). Замена `low` → `low′` меняет 64-битную базу ровно на
   `low′ − low` (маска 48 бит не трогает младшие 32 бита), сложение со смещением линейно, перенос из бита 31 в бит 32 при сырой
   базе и его отсутствие при канонической учитываются самой разностью: пример `low = 0xFFFFFF00`, смещение `0x200`, `low′ =
   0x100` — сырой адрес `hi·2^32 + 0x1_0000_0100`, канонический `hi·2^32 + 0x300`, разность `−0xFFFFFE00` = `difference` ✓.
   Если адрес собирает сама программа гостя 32-битным сложением без переноса (`s_add_u32` без `s_addc_u32`) и сырой путь
   переносит, а канонический нет, — разность `difference ± 2^32` ≠ сдвигу ⇒ `KEEP` ⇒ отказ `residual` по варианту 2.
   Исход безопасный (запись не попадает в каталог), цена — покрытие и член К3 [I: частота в игре неизвестна].
2. **Маска адреса.** `AddressMask & ~3` (`:1870`) и `& ~3` (`:1927`): канонические формы `PTR_LO`/`V_LO` = `0x100 | (v &
   0xF)` хранят биты 0..3, `difference` кратна 16, маска `~3` сдвиг не меняет ✓. `PTR_HI`/`V_HI` = `v & 0xFFFF0000`: обнуляются
   биты адреса 32..47, биты 48..63 сохраняются, но маска 48 бит их и так снимает — фактическая разность после маски
   `−(raw & 0xFFFF) << 32` = `difference << 32` по модулю 2^64 ✓ (в т. ч. при ненулевых старших 16 битах сырого слова).
3. **Смесь равных и сдвинутых запросов.** Допуск по позициям независим: равный — запрос не через это слово, сдвинутый ровно —
   через него. Опасный случай — запрос, зависящий от слова нелинейно (например, `P + (P & 0xF0)`): канон обнуляет биты 4..7,
   разность ≠ `difference` ⇒ `KEEP` ⇒ `residual` ✓. Совпадение «нелинейный путь дал ровно `difference`» по §4 первому абзацу
   неверной записи не даёт (самопроверка). Число запросов сравнивается до цикла (`:591`) — пропавший или лишний запрос ловится ✓.
4. `shift == 0` для `INERT`/`T_*` — только равенство ✓; для адресных ролей `shift ≠ 0` всегда: `value ≠ raw`, `|difference| <
   2^32`, `difference << 32` ≠ 0 по модулю 2^64 ✓.

**Вывод:** вариант 1 корректен; RC нет.

`R_ADDR` их не считает, точная проверка видит только значения, равные младшему слову адреса запроса или базы дескриптора;
частоту 32-битной адресной арифметики без переноса в программах игры; что S-replay выполним или даст тёплый первый вход; что
К3–К6 пройдут; что `R_B` 0,9865 — польза; что каталог верен для первого входа пользователя; что S-replay закрывает промах
`u_06`; что фризы входа вызваны шейдерами; полноту корпуса, каталога и `eboot.bin`; ни одно число — не выигрыш; 60 FPS не
