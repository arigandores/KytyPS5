Чтение — одна загрузка значения гейта на операцию, ДО первой отметки операции: первая отметка цепочки draw — заимствованная
`HoldProgramsNs` (§3.1), и защёлка стоит перед ней, поэтому цена чтения падает в `mh_prog`, не в `mh_bind`. Все отметки, классы и
перепись B2 одной операции читают `t_rb.mode`, а не гейт ⇒ смена значения на потоке презентации посреди операции её не рвёт.
**Ручка может быть плечом расписания** (п. 141(в)(4): ABBA `rbcen=1|2`): каждая операция защёлкивается заново. Хуки сбросов на
других потоках (§5.2) читают `g_rb_b2_live` — флаг последней защёлки; на границе плеч возможна одна запаздывающая операция —
позиции 0–9 блока вне окна 10–88 п. 55(б).

### 2.3 Отказ и строки лога

- Без `KYTY_FRAME_TRACE` (`FS::Enabled()` ложно): `RbCen: refused reason=notrace` раз, `rb_refuse` += 1, операция идёт путём 0.
  **Ловушка:** без `FRAME_TRACE` `FS::Add` ничего не пишет (`g_count_limit` = 0, `frameStats.cpp:172`), поэтому `rb_refuse` в этом
  случае физически ненаблюдаем; наблюдаема только строка — **[В 13]**.
- `RbCen: mode N` — при первой защёлке каждого значения N ≥ 1 (в ABBA `1|2` — две строки) — **[В 12]**.
- Счётчики `rb_*` стоят после `LogNs` в `enum Counter` ⇒ при гейте `fslean=1` (`SetLean`, `frameStats.cpp:191–197`) они молча
  отбрасываются. Харнесс ставит `fslean=0` явно; дымы проверяют «живы» (§12) — **[В 14]**.

**Где:** `descriptors.cpp` `RebindBuffers` `:3803–3914`, цикл слотов `:3839–3867`; оба пути (draw и dispatch — **[В 1]**; популяция

**Решение выборки** — детерминированное, по счётчику вызовов (п. 141(в)(2) «выборка 1/8 по счётчику вызовов»): TLS `k` += 1 на
каждой итерации латченной операции; выбрана ⇔ `(k · 0x9E3779B97F4A7C15) >> 61 == 0`. Последовательность Вейля равнораспределена и
**не периодична** — у `k mod 8` периодическая раскладка слотов (одинаковое число слотов у подряд идущих draw) давала бы выборку
всегда одной позиции слота, т. е. одного класса. Проверка строки: 8 · `rb_samp_n` ≈ `bl_buf_n` (расхождение Вейля O(log n / n) —
доли процента).

**Итерация i латченной операции** (решение s_i вычислено в конце итерации i − 1; s_0 — в прологе):

```
  if (s_i) t0 = NowNs();                         // S0: первый оператор тела итерации (перед :3840)
  t_rb.slot = 1; t_rb.cls = None; t_rb.notes = 0;
  ... тело :3840–:3866 без изменений ...
  t_rb.slot = 0;
  Add(класс → rb_stream_n | rb_epoch_n | rb_slow_n; None → rb_cls_bad [В 7]); // счёт — на КАЖДОЙ итерации
  s_next = Weyl(++k);                              // решение следующей итерации — внутри пары этой
  if (s_i) { t1 = NowNs(); Add(rb_K_ns, t1 - t0); Add(rb_samp_n, 1);          // S1
             if (калибровочная) { u0 = NowNs(); u1 = NowNs(); Add(rb_cal_ns, u1 - u0); Add(rb_cal_n, 1); } }
  if (t_rb.mode == 2) Census(t_rb.notes);          // §5 — вне пары
  s_i = s_next;
```

**Почему так:** всё, что платит КАЖДАЯ итерация (класс-счёт, решение следующей итерации), стоит ВНУТРИ пары выбранной итерации ⇒
выбранная итерация несёт ту же работу, что невыбранная, и ×8 переносит её на всю популяцию честно (идиома `bindwit`/`blmove`:
цена, которую платят все, входит в меряемое одинаково). Вне пары остаются только `if (s_i)` (≈ 0,5 нс), управление циклом и то, что
платят лишь выбранные (Add времени, калибровка) — это и есть инструментальная часть остатка R2 (§4.2).

**Класс итерации** — последняя запись `t_rb.cls` до конца тела (TLS, пишется только при `t_rb.slot ≠ 0`):

| класс | где пишется (перед `return`) | населяет |
|---|---|---|
| Null | `descriptors.cpp:213` | остаток R2 (≈ 1 129 слотов/кадр, 2,37 % [c s93]) |
| Cbank | `:280` (прямая копия), `:340` (выровненная, CPU и GPU) | `rb_cbank_ns` |
| Stream | `bufferCache.cpp:1533` (внешний вызов) | `rb_stream_ns`, `rb_stream_n` |
| Epoch | `:1501` (внешний вызов) | `rb_epoch_ns`, `rb_epoch_n` |

**Вложенные `ObtainBuffer`** (например, `SynchronizeBufferFromImage` → `ObtainBufferForImage` → `ObtainBuffer` `:1669`) класс не
пишут: на входе `ObtainBuffer` при `t_rb.slot == 1` ставит `t_rb.slot = 2` и помнит «внешний»; вложенный видит 2 и молчит. Внешний
пишет класс на своём `return` ПОСЛЕ вложенных; выровненная const-bank копия `:298–340` идёт после возврата внешнего `ObtainBuffer` и
переписывает класс на Cbank. Поток `ObtainBuffer` выравнивает смещение по `minUniformBufferOffsetAlignment` (`:1512–1515`), поэтому
выровненная копия после потоковой невозможна (`adjustment` = 0) [I] ⇒ `rb_stream_n` = число потоковых копий внешних вызовов.

**Семантика классов — вся итерация, а не только копия — [В 2].** `levers133.md` §5 назвал места `rb_stream`/`rb_cbank` строками
копий (`bufferCache.cpp:1514–1523`, `descriptors.cpp:259–267`, `:307–320`). Проект меряет классом ВСЮ итерацию слота этого класса:
(1) только так сумма классов плюс пролог и хвост покрывает `bl_buf` с остатком ≤ 5 % (копийные места оставили бы вне себя проверки
грязности, `UploadEpoch`, `Map`/`Commit` потоковых слотов и `TouchReadOnlyBuffer` const-bank ≈ 0,6–0,8 мс [I] — R2 ≈ 15–20 %);
(2) цель B2 — не только `memcpy`: повтор по интервалу снимает у потокового слота и `UploadEpoch`/`HasCurrentUpload`, и совмещённый
запрос трекера, и `Map`/`TryReadBacking`/`Commit` (всё после пробы таблицы). Уровень класса ⊇ копии; снимаемое ≤ уровень − проба.

**Оценщик (п. 141(в)(2) «время × 8») с поправкой [В 3]:** уровень_K = 8 · `rb_K_ns` − n_K · ĉ, ĉ = `rb_cal_ns` / `rb_cal_n`
(калибровочная пара — на каждой 64-й выбранной итерации, по `k`; ≈ 93 пары/кадр). Вывод: выбранный интервал = W + ĉ (хвост первого
вызова после rdtsc + голова второго до rdtsc — ровно то, что меряет пустая пара); E[8 · Σ_выб (W + ĉ)] = Σ_все W + n · ĉ; вычитание
n · ĉ снимает фантом. Без поправки фантом ≈ 0,38 мс на `bl_buf` (§0 п. 3(б)).

## 4. Тождества строки и почему остаток ≤ 5 %

Уровень тождества — **строка** `FrameTrace` (кадр), п. 141(в)(2); плечо 1. Единицы: `mh_bind_us`, `bl_*_us` печатаются в мкс с

## 5. Значение 2: перепись повтора B2 (без действия)

### 5.1 Правило, ключ, таблица

**Копии B2** — CPU-копии гостевых байт в кольцо потока (`m_stream_buffer`, 64 МиБ, `bufferCache.cpp:542`), сделанные ВНЕШНИМ вызовом
внутри латченного слота: потоковая `bufferCache.cpp:1515–1523` (запись заметки на `:1533`), прямая const-bank `descriptors.cpp:261–266`
(заметка на `:280`), выровненная const-bank при `!gpu` `:308–316` (заметка на `:340`). GPU-копия const-bank (`:324–330`) — не B2
(данные с GPU, не из гостя). Заметка `{vaddr, size, alignment, kind}` — TLS, до 2 на итерацию (переполнение → `rb_cls_bad`).

**Интервал** — отрезок исполнения командного процессора между двумя сбросами §5.2. Один глобальный счётчик поколения
`g_rb_gen` (atomic u64; хук сброса: `fetch_add(1, release)` и `Add(rb_b2_rst_<причина>, 1)`). Перепись читает `g_rb_gen` (acquire)
в `Census`, т. е. после S1 итерации (§3.3), на GuestGpu.

**Таблица:** глобальная, прямого отображения, 2¹⁶ записей × 32 Б = 2 МиБ (частная память); запись `{vaddr, size:32, align:16,
gen, shadow_off, shadow_lap}`; индекс — хэш ключа. Доступ — только с потока, исполняющего командный процессор (сериализован; при
`m4baton` — поток-реле тоже сериализован, `graphicsRun.cpp:2523–2582`; в `bc133` `m4baton` = 0). Сброс интервала — сдвиг `g_rb_gen`,
таблица не чистится (запись жива ⇔ `gen` = текущее).

**`Census(note)`** (на каждую заметку):

| исход пробы | действие |
|---|---|
| ключ совпал ∧ `gen` = текущее | **повтор**: `rb_b2_would` += 1, `rb_b2_kb` += size; если у записи есть живая тень — `rb_b2_chk` += 1, `TryReadBacking(vaddr → TLS-буфер)`, `memcmp` с тенью ⇒ `rb_b2_diff` += (≠); запись НЕ обновляется (механизм отдавал бы ПЕРВУЮ копию интервала) |
| ключ совпал ∧ `gen` старое | повтор через сброс: при живой тени — `rb_b2_xchk`/`rb_b2_xdiff` **[В 5]**; вставка заново |
| ключ другой ∧ `gen` = текущее | вытеснение живой записи: `rb_b2_evict` += 1 **[В 6]**; вставка |
| иначе | вставка |

**Вставка:** `gen` = текущее; тень — у 1/16 вставок (решение Вейля по TLS-счётчику вставок): `TryReadBacking(vaddr, кольцо_теней +
off, size)`. Кольцо теней — 32 МиБ обычной кучи (≈ 16 кадров вставок при ≈ 1,9 МБ/кадр [I]); запись хранит `(off, lap)`; тень жива,
пока кольцо её не переписало. Проверка при повторе на записи с переписанной тенью — `rb_b2_shovf` += 1 **[В 6]** (в пределах одного
интервала невозможно при интервале < 16 кадров; в `xchk` — штатно, не ошибка).

**Слот кольца не читается никогда.** Байты «сейчас» и тень берутся из гостя через `LibKernel::Memory::TryReadBacking` — ту же
функцию, что делает копию пути (`bufferCache.cpp:1516`, `descriptors.cpp:263`, `:311`): чтение через бэкинг, без фолтов защиты и
без изменения трекера [I — проверить Red Team]. Отказ `TryReadBacking` в переписи — сверка пропускается (не `EXIT`, не счётчик ошибки).
Окно гонки: между копией пути и чтением «сейчас» — ≈ 0,1–0,3 мкс (S1, счёт, решение); запись CPU в это окно даёт ложное
«расхождение» (или ложное «совпадение») — направление в сторону завышения `rb_b2_diff` (консервативно для порога 0,01), вероятность
[I] мала.

`rb_b2_kb` — байты повторов; печатается как `ob_stream_kb` (байты / 1000 с усечением по строке, `videoOut.cpp:1912`, `:1365`) —
**[В 8]**.

### 5.4 Тень 1/16

Решение «тенить» — у вставки, по TLS-счётчику вставок (Вейль, 1/16). Сверка — только на повторах записей с тенью ⇒ `rb_b2_chk` ≈
`rb_b2_would` / 16 со взвешиванием по числу повторов записи; оценщик доли расхождения `rb_b2_diff` / `rb_b2_chk` не смещён относительно
«доли повторов, отдавших бы устаревшие байты» при равновероятном выборе записей. Тень — байты ПЕРВОЙ копии интервала (запись не
обновляется при повторе), т. е. ровно то, что отдал бы механизм.

### 5.5 Положительный контроль сверки байт **[В 5]**

Та же сверка на повторе ключа ЧЕРЕЗ сброс (`rb_b2_xchk`, `rb_b2_xdiff`): запись CPU между двумя копиями, разделёнными сбросом, легальна
и ожидаема (константы кадра переписываются каждый кадр). По с. 62 (OLD) 83–102 копии на кадр отличались от прошлой копии того же
диапазона [c-OLD, `cb_diff`] ⇒ `rb_b2_xdiff` > 0 ожидается уверенно (§11). Контроль проверяет весь путь сверки (тень, чтение гостя,
`memcmp`, счёт) на настоящих данных тем же кодом. `rb_b2_xdiff` = 0 при `rb_b2_xchk` ≥ 10³ — сверка мертва, чтение `rb_b2_diff`
недействительно.

## 9. «0 — прежний путь побайтно»; «1/2 не меняют ни значения, ни решения, ни побочного эффекта»

### 9.1 При 0

Всё добавленное при `rbcen=0` исполняет только: (а) защёлку — одно `Gates::Value` + запись TLS на draw/dispatch; (б) проверки
`if (t_rb.mode)` / `if (t_rb.slot)` — ложны: цепочка, пары, выборка, классы, заметки, перепись не исполняются; (в) хуки сбросов —
одна `relaxed`-загрузка `g_rb_b2_live` (false) и выход. Ни одна проверка не меняет порядка вызовов пути, аргументов, возвращаемых
значений, веток пути, выделений памяти пути, записей в память гостя или кэши. Код вне этих проверок — побайтно прежний.
Правка не трогает `src/graphics/shader/**` ⇒ подпись кэша трансляции не меняется, кэш остаётся тёплым.

## 13. Риски и что проект НЕ доказывает

- **Не доказывает, что B2 корректен или снимаем.** Перепись меряет долю повтора по ГРУБОМУ правилу §5.2 и долю расхождения байт на
  выборке 1/16; отбор с. 134 решает по п. 141(в)(6).
- **Полнота списка сбросов** — утверждение проекта для враждебного отзыва: пропущенный писатель в гостевую память или пакет
  синхронизации завышает долю повтора; сверка байт такой пропуск видит лишь частично (она ловит изменение байт, не порядок).
  Отдельные дыры: GPU-запись в уже грязный образ (§5.3); CPU-писатели признаны не сбросами доводом, не кодом (**[В 9]**).
- **Уровни — [c] с выборкой** (SE выборки + SE блоков); `rb_slow`/`rb_sync_up` — тяжёлый хвост загрузок (§4.2). Уровни включают
  цену значения 1 внутри своих отрезков; к NEW без инструмента не переносятся. Ни один уровень — не потолок механизма.
- **Щели вызовов** (R1) и пролог (R2) — оценки [I]; если R1 или R2 выйдут за ±5 % — «не приняла место», вопрос закрытию.
- **Время:** значение 2 удлиняет GuestGpu на ≈ 1–1,7 мс/кадр; гонки CPU-записей с копиями сдвигаются — `rb_b2_diff` в плече 2 может быть
  завышен против пути без переписи.
- **`TryReadBacking` без побочных эффектов** — [I] по тому, что путь уже зовёт его на тех же диапазонах; Red Team проверить по коду.
- **Не доказывает:** OLD; другие сцены; время `9235a7ac`; что 51,38 % — время установленной сборки; 60 FPS.

## 14. Вопросы лиду (решения — пунктом `ROADMAP.md`; проект констант не меняет)

- **В1. Доля dispatch в `bl_*`: три пары `rb_xprep_ns`, `rb_ximg_ns`, `rb_xbuf_ns` и защёлка dispatch (§3.2).** `bl_prep`/`bl_img`/`bl_buf`
  включают dispatch (`renderCompute.cpp:1005`, `:1036`, `:1042`), `mh_bind` — нет; доля ≈ 0,7–0,8 мс [c `dd131`, форма] ≈ 7 %. Без пар
  тождество R1 по тексту п. 141(в)(2) может пройти взаимным сокращением ошибок (§4.1). Альтернатива — книжить отрезки-в-скобках
  цепочки draw именами (тогда R1 ≡ 0 по построению и ничего не проверяет). Рекомендую пары. Слоты `RebindBuffers` dispatch — в выборке
  (популяция = `bl_buf_n`), для этого нужна защёлка dispatch.
- **В2. Семантика `rb_stream`/`rb_cbank`/`rb_epoch`/`rb_slow` — вся итерация слота класса, а не строки копии `levers133.md` §5 (§3.3).**
  Для порога 400 п. 141(в)(6) уровень становится «целью B2 целиком» (⊇ копии). Если лиду нужна именно копия — ещё два имени
  (`rb_stream_cp_ns`, `rb_cbank_cp_ns`, вложенные пары на выбранных итерациях) и поправка их фантома.
- **В3. Калибровка `rb_cal_ns`/`rb_cal_n` и оценщик 8·Σ − n·ĉ (§3.3).** Без неё ×8 завышает слотовые уровни на n·ĉ (≈ 0,38 мс на
  `bl_buf`, ≈ 0,11 мс на кольцо — 28 % порога 400), R2 ≈ −6…−7 % по построению.
- **В4. `rb_bpro_ns` — пролог `RebindBuffers` (§3.4).** Без него прогноз R2 ≈ 5–8 % — вероятно «не приняла место».
- **В5. Положительный контроль сверки байт `rb_b2_xchk`/`rb_b2_xdiff` (§5.5).** Без него «`diff` ≈ 0» не отличить от мёртвой сверки.
- **В6. `rb_b2_evict`, `rb_b2_shovf` (§5.1)** — счётчики молчаливых потерь (вытеснение живой записи занижает долю повтора; тень потеряна).
- **В7. `rb_cls_bad` — инвариант 0 (§3.3, §7)**: латченная итерация без класса или с > 2 заметками.
- **В8. Единица `rb_b2_kb`:** байты / 1000 с усечением по строке, как `ob_stream_kb` (проект), или сырые байты под другим именем.
- **В9. Правило сбросов (§5.2–§5.3):** (а) CPU-писатели на гостевых потоках (HLE, декодеры AvPlayer) — не сбросы; (б) все EVENT_WRITE,
  ACQUIRE_MEM, PFP_SYNC_ME, INCREMENT_CE/DE — сбросы (в списке `witness_binding.md` §2.4 их нет); (в) INDIRECT_BUFFER — только условная
  форма; (г) дыра «GPU-запись в грязный образ»; (д) GPU-запись буфера — грубо, любая (`NoteGpuWrite`), как в тексте B2.
- **В10. `rb_find_n` = число draw с книжной цепочкой** (один цикл `FindBuffers` на draw) ⇒ тождество `rb_find_n` = `mh_draws`.
- **В11. Новые причины отказа:** `mutsite` (цепочка draw без `mutsite=1` не книжится) и `b2alloc` (не выделилась таблица/тени).
- **В12. `RbCen: mode N`** — раз на каждое значение (в ABBA две строки), не раз на процесс.
- **В13. `rb_refuse` ненаблюдаем без `KYTY_FRAME_TRACE`** (`FS::Add` пишет только при `Enabled()`); наблюдаема только строка.
- **В14. `fslean=0` в `gates_base.txt`** (при `fslean=1` все `rb_*` молча отбрасываются, `SetLean` → предел `LogNs`).
