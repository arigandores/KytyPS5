## 4. Проходы IR (п. 773(г)(1)) [c кода `91a46dc5`]

Порядок: `RewriteToSsa` → `ConstantPropagationPass` → `ResolveControlFlowIdentities`/`RemoveIdentities`/`EliminateDeadCode` → `EliminatePredication` → (снова свёртка) → `EliminateReadLane` → `BuildSrtPlan` → `TrackResources`; при эмиссии `ApplyResourceSpecialization` (`ShaderRecompiler.cpp:663–729`). IR не сериализуется: каждая трансляция строит его из слов GCN (`pipelineCache.cpp` → `TranslateProgram(code)`).

- **Пересоздают ли проходы `SelectU32` без флагов?** Новые `SelectU32` с флагами 0 создают только `ResourceTracking.cpp:291` и `ResourceMaterialization.cpp:1252` (индекс дескриптора). Обёртку они не трогают. Клон `ResourceMaterialization.cpp:1031` копирует флаги (`source->Flags<uint64_t>()`). `EquivalentValue` (`Program.cpp:84`) различает инструкции по флагам — обёртку не слить с select без флагов.
- **`ConstantPropagation::FoldSelect`** снимает обёртку только при константном условии или равных плечах. Обёртка заменяется своим операндом — литералом или записью без флагов, то есть запасным путём. Флаги не переносятся.
- **`PredicationElimination` (умолчание `KYTY_PRED_MODE` = все биты).**
  - `FoldSelectChain` меняет у обёртки аргумент 1 на литерал записи только при `ImpliesPredicate(exec выборки, маска записи)`, то есть exec ⊆ маске. Тогда все исполняющие линии держат литерал, и `ConstOffset` верен.
  - Удаление select записи (`Discardable`) идёт по тому же условию импликации. Обёртку не удаляет: её потребитель — образная инструкция, а не lane-local pure.
  - Других мест, меняющих аргументы `SelectU32`, нет: grep по `ir/passes`, `backend` и `frontend`.
- **Чужие `SelectU32` с флагами `0x3630335447`** — только клоны обёртки.
- **Итог:** ни один проход не делает так, чтобы флаги стояли на select с другим смыслом. Потеря флагов уводит в запасной путь со строкой — дыры п. 762(б) нет.
- **Наблюдение (не RC).** Форма «смещение под A, выборка под A∧B» (exec = `LogicalAnd(A, …)`) при `=1` получает `ConstOffset` через `FoldSelectChain`, а не через `MResolveSampleOffset`. Это верно по смыслу, но ни тестом, ни корпусом не закреплено.

## 7. RC

**RC1 — член «ровно одна строка запасного пути» (п. 767(г)(3)) доказан счётчиком, а не строкой.**
- **Что не так.** Тест читает `MTexOffsetFallbacks().nonconstant`. Связь «счёт ⇔ строка» держится только соседством в одной ветви [c кода]. Мутант `k3b_line_only` (строка `LOGF` убрана, счёт оставлен) проходит все члены.
- **Сценарий отказа.** Правка ветви переносит `LOGF` под условие (предел строк, `IsSilent`, другой уровень журнала) или удаляет её, а счёт оставляет. Тесты PASS, а свип логов по сигнатуре (M5b RC3(в): «это сигнатура для свипа») молча теряет запасной путь T306 в игре.
- **Изменить (без кода).** Пункт приёмки M7 читает член (г)(3) так: «ровно один счёт в ветви строки [c теста] + строка в той же ветви без условия [c кода `91a46dc5`: `LOGF` и `MTexOffsetCount(0u)` подряд, `spirvEmitterImage.cpp:899–902`]».
- Любая правка этой ветви повторяет M7b или добавляет член теста, читающий сам журнал.
- Без этого член (г)(3) по строке — [I].

**RC2 — форма игры «wave64 на подгруппе 32» (две выборки на pc) закреплена только разовой перекомпиляцией, не тестом и не корпусом гейта.**
- **Что не так.** `TestMWave1T306EbootPrograms` транслирует CS с `ComputeInputInfo` по умолчанию: одна эмиссия на инструкцию, 3 записи. Корпус T1 этой CS не содержит. Мутант `k8_lane_half` проходит все тесты и корпус, ловит его только `KYTY_RECOMPILE` записи кэша игры.
- Кроме того, без `KYTY_TEST_T306_EBOOT` тест печатает `SKIP`. Обычный прогон тестов член (г)(2) не исполняет.
- **Сценарий отказа.** Правка эмиттера по половинам линий (или кэширование результата `MResolveSampleOffset` по `lane_half`) оставляет смещение только у первой половины. 32 линии из 64 выбирают без смещения — видимый дефект CS игры. G2 корпуса T1 и тесты PASS.
- **Изменить (текст пункта M3 волны 2, без кода M7a).** В гейт T306 M3 волны 2 (G1/G2) входят:
  - прогон тестов `MWave1T306` с `KYTY_TEST_T306_EBOOT=<слова из eboot.bin>`; член — строка `matched=3`/`matched=8`, не `SKIP`;
