## 2. Требуемые изменения

**RC1 — T021: поле расхождения `minlod_div` шире расхождения (ложное «А» по п. 767(к)(1)).**
- Что не так. `MinLodDiverges` = `base_level > 0 и min_lod > (level_count − 1)·256` (буква п. 767(и) и условия парковки M5a). Это необходимое,
  но не достаточное условие: при `M/256 ≤ B` наш `minLod` = `count − 1` и железо (`max(B, M/256)`) оба ниже `base_level`, низший читаемый
  уровень у обоих = `B` — ответы совпадают [c модели M5a, `minlod_model_m5a.py`: `lowest = max(B, minlod)`].
- Сценарий отказа. Вид T# `B` = 2, `count` = 2, MIN_LOD = 384 (1,5): наш `minLod` = min(1,5; 1) = 1 → уровень max(2; 1) = 2; железо — max(2; 1,5)
  = 2; `minlod_div` += 1 ⇒ по п. 767(к)(1) T021 «А» и порт `f38d738ee` под `KYTY_M_T021` при отсутствии расхождения в игре. На сетке M5a
  16 из 96 клеток поля — такие (`minlod_rc.out.txt`).
- Что изменить (кодом, M6a2): добавить поле `minlod_div_x` — `B > 0 и M > 256·max(B, count − 1)` (точная область расхождения [c модели]),
  `minlod_div` оставить по букве п. 767(и) справкой; стенд — случай `B` = 2, `count` = 2, `M` = 384 (`minlod_div` 1, `minlod_div_x` 0) и
  случай M5a `B` = 1, `count` = 3, `M` = 768 (оба 1); мутант «`minlod_div_x` = условию `minlod_div`» обязан ловиться. Поле расхождения T021
  в правиле п. 767(к) — `minlod_div_x` (пункт лида). Если лид оставляет `minlod_div` полем расхождения — записать, что исход «А» T021 по
  нему — кандидат, который M2 волны 2 подтверждает стендом до кода порта.

**RC2 — T313 + T179: классы M5a (а3) `R8Unorm` / `R8G8Unorm` не считаются; исход «`НЕ ДЕФЕКТ`» по `clr_dw_div` = 0 о них молчит.**
- Что не так. Условие парковки M5a (`gfx/section_gfx.md`, T313 + T179, «Исход: паркуется») — принятые заливки по классу слова, включая
  «`R8Unorm` без повтора байта; `R8G8` при `lo ≠ hi`»; декодер принимает их без проверки (`imageInfo.h`, ветки `eR8Unorm`, `eR8G8Unorm`).
  `ClearDwordDiverges` считает только классы upstream (п. 767(и)). `M5W2Clr` даёт число заливок по формату (`fmt=9`, `fmt=16`), но не класс слова.
- Сценарий отказа. Игра заливает цель `R8_UNORM` словом `0x00ff00ff`: память — чередование `ff 00`, мы заливаем всю поверхность 1,0
  (`unorm8(packed)`), `clr_dw_div` = 0 ⇒ T313 + T179 «`НЕ ДЕФЕКТ` на наблюдённых сценах», а наш дефект (а3) исполнен и не виден — его
  измерение потребует ещё одного тега под замком.
- Что изменить (кодом, тем же M6a2): поле `clr_dw_div8` (справка, не поле темы): `R8Unorm` при `W ≠ (W & 0xff)·0x01010101`, `R8G8Unorm` при
  `(W & 0xffff) ≠ (W >> 16)`; столбец в `M5W2Clr`; стенд — по случаю «≥ 1» и «0» на формат; мутант «счётчик не растёт». Правило чтения
  (пункт лида): `clr_dw_div8` ≥ 1 ⇒ строка реестра (класс (а3), вне темы upstream). Допустимая замена без кода — запись лида, что
  «`НЕ ДЕФЕКТ` T313 + T179» не распространяется на (а3) и (а3) паркуется до следующего звена измерения.
