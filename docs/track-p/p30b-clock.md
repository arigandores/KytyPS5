## RC1 — одни часы хоста

**Выбор источника (исполнитель):** `std::chrono::steady_clock` — монотонные по стандарту; в библиотеке MSVC — `QueryPerformanceCounter`. Перевод в
мкс — `duration_cast<microseconds>` разности с моментом старта: переполнения нет при любом аптайме машины (вариант с `QueryPerformanceCounter × 10⁶ /
частота` от нуля счётчика переполнял бы `uint64` на ≈ 21 сутках аптайма при частоте 10 МГц).

- `HostUs()` — `9d6f2f26:src/kernel/pvar.cpp:51` `uint64_t HostUs() {` (+1 `	return static_cast<uint64_t>(`); начало отсчёта — `g_host_start`
  (`:49` `const std::chrono::steady_clock::time_point g_host_start = std::chrono::steady_clock::now();`), динамическая инициализация файла до `main`
  = «от старта процесса» с точностью до статической инициализации. Замка нет, заморозок и скорости гостя нет.
- **Время вблэнка** — `PublishVblank`, `:336` `	const uint64_t t = HostUs();` (+1 `	const uint64_t s = g_vb_seq.load(std::memory_order_relaxed);`).
- **`t0` (M0, он же `t_us=`)** — `:145` `	const uint64_t t0 = HostUs();` (+1 `	Vblank         vb = ReadVblank();`).
- **`slack_us`** — `:157` `	const int64_t  slack   = VblankTimeUs(vb.t, vb.v, target) - static_cast<int64_t>(t0);` — время вблэнка и `t0` теперь одной шкалы.
- **`now`, дедлайн, `wait_us`, `exit_us`** — внутри `HoldWait`, часы подставляет вызов `:162` `		const HoldWaitResult r = HoldWait(` (+1
  `		    static_cast<int64_t>(t0), vb, target, kt, [] { return static_cast<int64_t>(HostUs()); },`).
- **`KernelGetProcessTime()` в `pvar.cpp` больше не вызывается** (единственное упоминание — комментарий `:48`); значит, на M0 (поток гостя) и в
  `PublishVblank` (поток Present) замок заморозки `state.mutex` не берётся. Обёртка `GetProcessTimeCounter` по-прежнему возвращает гостю
  `KernelGetProcessTimeCounter()` (P23, не тронуто). Строка `processTime` вблэнка в `videoOut.cpp:803` — P23, не тронута.
- Следствие по построению [c]: вблэнк публикуется со временем, взятым ДО публикации, а `now` читается ПОСЛЕ чтения счётчика, на одних монотонных
