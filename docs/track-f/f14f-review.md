## 2. Член (г)(0) — своим чтением кода

**(а) Происхождение `D32_SFLOAT` на ручных местах [c кода].**
- Вид глубины образу сравнения рендер даёт только по `FindGuestDepthFormatPolicy(format)` при `resource.depth_compare` (`descriptors.cpp:3073`). Значит, вид `D32_SFLOAT` значит гостевой `k32Float`.
- Пустой T# получает `D32` только как нативное место (`082d1612:src/graphics/host_gpu/renderer/pipeline/descriptors.cpp:1336`, якорь «const bool native_compare = binding == TextureCache::BindingType::Texture &&»; +1 — «resource.depth_compare && !resource.manual_depth_compare;»). У ручного пустого T# вид — цветовой `R32F`.
- Ручным `k32Float` делает только цикл общего сэмплера (`:1207`, якорь «for (bool changed = true; changed;) {»; +1 — «changed = false;»): сэмплер, общий с ручным образом, сбрасывает `depth_compare`, и тогда каждый образ на этом сэмплере становится ручным.
- Данные F14e (60 753 из 60 753 записей `D32` — на той же привязке сэмплера, что и `D16`) я не пересчитывал: их пересчитал лид (п. 415(а)).

**(б) Массивы и VUID-06479 [c кода].**
- **Прямые места.** Решение принимается на каждый образ специализации. При `=1` нативным становится только образ с форматом из таблицы или пустой (заглушка `D32`). Поэтому `Dref` по цветовому виду на прямом месте не создаётся.
- **Косвенная таблица.** Опкод выбирает корень (`082d1612:src/graphics/shader/recompiler/backend/spirv/spirvEmitterImage.cpp:683`, якорь «const bool  manual_dref    = dref && image.manual_depth_compare;»; +1 — «const bool  native_dref    = dref && !manual_dref;»). После О1 флаги всех членов одинаковы.
- **Цикл сэмплера после О1.** Он ходит только по `sampled_pairs` прямых образов, то есть по корню. Он может только *поставить* «ручной», и только корню. Тогда таблица идёт ручным путём (по корню), а виды кандидатов остаются по формату — ручная выборка по виду глубины. VUID-06479 касается только `Dref` по цветовому виду, а такой путь при `=1` не открывается.
- Пустой кандидат входит в «или» с флагом `false` (нативный). Если таблица ручная, он тоже ручной и получает цветовую заглушку `R32F` — безопасно.

**(в) Причина ручного пути для 2-байтного формата.** Своим поиском я её не проверял. Опираюсь на отчёт F14e и п. 415(а) (`05565b59`: тогдашний рендер давал цветовой `R16_UNORM`; довода против нативного `D16` в записях нет) [I — без своего `git log`].

**(г) Хост-сэмплер нативного места [c кода].**
- `samplers[pair.sampler].depth_compare |= images[pair.image].depth_compare` (`ResourceMaterialization.cpp:1201` и дальше) сохраняет сравнение, если на сэмплере нет ручного образа.

- Кэш сэмплеров берёт `compareEnable` и `compareOp` из поля гостя (`082d1612:src/graphics/host_gpu/renderer/cache/samplerCache.cpp:160`, якорь «sampler_info.compareEnable           = (r.DepthCompareFunc() != 0 ?
