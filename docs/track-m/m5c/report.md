### 1.2 Источник Z [c] (`t109_zsrc_m5c.out.txt`, декод — `dec/ps_<hash>.txt`)

Метод. Программа декодируется декодером транслятора. Из экспорта target 8 с битом 0 маски берётся регистр Z. Затем
перечисляются **все** инструкции программы, чья цель накрывает этот регистр: VALU; MIMG по `dmask`; загрузки по
`dwords`; VINTRP. Писатель помечается SAT, если у цели стоит `.clamp` или это `V_MED3_F32` с 0 и 1,0. Для двух программ T1
сделан ещё срез значения SPIR-V трансляции корпуса M2a (`base/out.spv`): от `OpStore %gl_FragDepth` назад через
`OpPhi`/`OpSelect` (без условия)/`OpCompositeExtract` по индексу.

| PS | регистр Z | писатели (все) | путь входного VGPR | SPIR-V: листья среза | `FClamp`/`NClamp`/`FMin`/`FMax`/`NMin`/`NMax` на срезе | насыщен в [0, 1] |
|---|---|---|---|---|---|---|
| `be4c35a2` | `v4` | 1: `V_CNDMASK_B32 v4, v4, 1.000000` (pc `0xb4`, NOSAT, за `S_CBRANCH_SCC0`) | да | `gl_FragCoord.z` и константа `0x3f800000` (1,0) | 0 | **нет** |
| `f25acd91` | `v0` | 2: `V_CVT_I32_F32 v0, v2`, `IMAGE_LOAD v0 … dmask=0x1 2d` (NOSAT) | нет | `OpImageFetch` (тексель по `int(gl_FragCoord.xy)`) и нулевой вектор ветви помощника | 0 | **нет** |
| `5514e10f` | `v18` | 6 VALU, последние `V_RCP_F32 v18, v18` → `V_MUL_F32 v18, v18, v19` (NOSAT) | да (2 ветви до первого писателя) | — (вне T1, трансляции корпуса нет) | — | **нет** |
| `c6773466` | `v58` | 1: `image_sample v58 … dmask=0x1 2d` (NOSAT) | нет | — (вне T1) | — | **нет** |

Чтение `be4c35a2` [c GCN + SPIR-V]. Флаг из буфера констант (смещение 412) может быть ненулевым. Тогда Z = 1,0 там, где
радиус `sqrt((2u−1)² + (2v−1)²) ≥ 1` по атрибуту 3 (вне круга). В остальных случаях Z — нетронутая глубина растеризации
`gl_FragCoord.z` (входной VGPR `v4`). Экспорт идёт под исходной маской `exec` (`s88`).

`f25acd91` — копия глубины из образа: тексель по целым координатам пикселя.
`c6773466` — Z из выборки текстуры, со сравнением `V_CMP_EQ_F32 s16, 1.0, v58`.
`5514e10f` — своя проективная глубина: делитель через `V_RCP_F32`.

### 1.3 Смещение полигона в рецептах [c] (`t109_join_m5c.out.txt`)

`PipelineStaticParameters` (23 члена) и `PipelineRenderingState` (4 члена) на `f7a5e258` не несут поля смещения глубины. Из
слов bias/offset/poly совпадает только `polygon_mode` — это режим заливки, не смещение. Пайплайны создаются с динамическими
`eDepthBias` и `eDepthBiasEnable` (`shaders.cpp`). Значение ставится на draw: `renderDraw.cpp:500–517`, по
`poly_offset_front/back_enable` и отбраковке.

Поэтому «число рецептов D32 с включённым смещением полигона» по каталогу **не определяется**: поля в записи нет. Это не 0.
Член правила по букве не закрыт.

### 1.4 Исход по п. 767(е) и остаток

Член «Z обеих PS насыщен» не выполнен [c]. Член «рецептов D32 со смещением 0» не определяется по каталогу [c]. По правилу
это ветвь «иначе» — T109 не получает `НЕ ДЕФЕКТ`.

Когда наш ответ (зажима нет) отличается от железа (DB зажимает в [ZMIN, ZMAX], пока `DB_RENDER_OVERRIDE.DISABLE_VIEWPORT_CLAMP` = 0;
M5a — [I]):

- `be4c35a2`: если 1,0 ∉ [minDepth, maxDepth], то есть `maxDepth` < 1 при Z = 1,0. Ветвь `gl_FragCoord.z` при включённом
  отсечении лежит в диапазоне вьюпорта [I].
- `f25acd91`, `c6773466`: тексель вне [minDepth, maxDepth]. Содержимое образа — [U].
- `5514e10f`: вычисленная глубина вне диапазона [U].
- Любой draw на D32 с включённым смещением: z + смещение вне диапазона [I по смыслу; для глубины, записанной шейдером,
  смещение не применяется — I].

Остаток — счётчики. Это предложение звена; имена, место и правило чтения решает и записывает лид до кода. Все счётчики
считаются на draw с целью D32 и включённым тестом или записью глубины, тип — штуки:

- `t109_zx_d32` — draw, у PS которого экспорт MRTZ с битом Z. Знаменатель.
- `t109_zx_narrow` — из них draw с `minDepth > 0` или `maxDepth < 1` у любого вьюпорта. Поле расхождения для `be4c35a2`.
- `t109_bias_d32` — draw с `depth_bias_enable` = 1. Знаменатель смещения.
- `t109_vpclamp_off` — draw с битом 16 `DB_RENDER_OVERRIDE` = 1. Отдельно: при нём железо тоже не зажимает, и тогда наш
  ответ совпадает с железом.

Инвариант: `t109_zx_narrow ≤ t109_zx_d32` (подмножество). Живой контроль `t109_zx_d32` > 0 на сцене с `be4c35a2`;
по каталогу такая сцена есть [c], какая именно — [U].

Тексели `f25acd91`/`c6773466` и глубина `5514e10f` счётчиком на ЦП не видны. Для них нужен снимок с текселем глубины вне
[minDepth, maxDepth] — та же форма, что в M5a.

## 2. T055 `6b79b7a00` — `IsActive` и `JumpToTime`

### 2.1 Импорт и место вызова [c] (`t055_vt_m5c.out.txt`; импорт — `m5a/hle1/imp_m5a.out.txt`)

- `XC9wM+xULz8` `JumpToTime` импортирован из `libSceAvPlayer_v1`. Место вызова одно: `0x1055037`. Оно в обёртке
  `0x1055010`, которая переводит время (`[rdx]·1000 / [0x8350d70]`) и вызывает `JumpToTime([this+0x60], ms)`.
- Обёртка `IsActive` — `0x1055230`: `AvPlayerIsActive([this+0x60]) && [this+0x290]`.
- Обе обёртки — виртуальные методы одной таблицы. По перемещениям `R_X86_64_RELATIVE` её начало `0x89207b8`, 39 слотов;
  `lea` таблицы стоят в конструкторе и деструкторе (`0x10537ab`, `0x10539c0`).
- Слоты: `JumpToTime` +0xa0, `IsActive` +0xb8, `Start` +0x60, `Stop` +0x70, `Pause` +0x80, `Resume` +0x88,
  `SetLooping` +0xb0, `SetTrickSpeed` +0x108, `SetAvSyncMode` (открытие источника) +0x110, `Close` +0x118.
- Прямых вызовов `call`/`jmp rel32` у любой обёртки 0.

### 2.2 Вызывается ли `JumpToTime` [c кода и лога] (`t055_log_m5c.out.txt`)

Код `f7a5e258`, `src/libs/avPlayer.cpp`:

- `AvPlayerJumpToTime` → `Source::Jump` → `StartImpl(ms, was_paused, true)`. `StartImpl` перезапускает воркеры:
  `StopWorkers()`, затем `StartWorkers()`. `StartWorkers()` создаёт гостевые потоки `AvPlayerVideoDecoder` (если есть видео)
  и `AvPlayerDemuxer` через `LibKernel::PthreadCreate`. Тот всегда пишет строку `\tthread create: <имя>, id = …`
  (`src/kernel/pthread.cpp:3519`).
- `WARNING` (`event_id = 32`) с `JUMP_COMPLETE` шлётся только при успешном `Jump` (rc 0). Другой источник `WARNING` —
  `pump_warnings` (`LOOPING_BACK`).

Три лога с роликом `data/prein/video/06_nx_controller_ship.mp4` — `log_m3_sg_v_r1`, `log_m3_i`, `log_f8_s1` (в `hb_f`/`hb_w`
ролика нет, M5a). В каждом одинаково:

| лог | READY | создано `AvPlayerDemuxer` / `AvPlayerVideoDecoder` | PLAY | PAUSE | WARNING | STOP | верхняя граница успешных `Jump` |
|---|---|---|---|---|---|---|---|
| `log_m3_sg_v_r1` | 1 | 1 / 1 | 3 | 2 | 1 | 1 | 0 |
| `log_m3_i` | 1 | 1 / 1 | 3 | 2 | 1 | 1 | 0 |
| `log_f8_s1` | 1 | 1 / 1 | 3 | 2 | 1 | 1 | 0 |

Воркеры созданы один раз, между READY и первым PLAY, то есть из `Start` [c порядка строк]. Значит успешных `JumpToTime` 0
во всех трёх логах [c]. Единственный `WARNING` каждого лога — `LOOPING_BACK`: это следует по исключению [c]; игра
зацикливает ролик через `SetLooping`.

Чего лог не исключает [I]: неуспешный вызов, когда `StartImpl` возвращает ошибку до `StartWorkers`. Строки у него нет. После
него воркеров нет, `stopped` = 1, и `IsActive` у нас возвращал бы 0 до конца ролика. Признака такого вызова в логах нет.

### 2.3 Поток опроса `0x1055230` относительно `0x1055037` — [U] (`t055_vt_m5c.out.txt`)

Оба вызова виртуальные. Смещения +0xa0 и +0xb8 встречаются у вызовов через любой интерфейс: 138 и 2 289 мест
`call [reg + disp]` по всему коду. Это верхняя граница, а не множество вызывающих. Статически вызывающих не развести, потоков
— тем более. Для исхода это не нужно: на наблюдённом пути вызова нет.

### 2.4 Исход по п. 767(ж)

`JumpToTime` на наблюдённом пути не вызывается [c]. ⇒ **`НЕ ДЕФЕКТ` возвращается** для `6b79b7a00`.

Область: один ролик в трёх логах. Другие ролики игры и путь вне трёх сессий — [U].

Условия переоткрытия:

- в любом логе строк `thread create: AvPlayerDemuxer` больше, чем `event_id = 2` (READY), — это перезапуск воркеров без
  нового источника, то есть `Jump`;
- или строка `AvPlayer::…::AvPlayerJumpToTime()` при `KYTY_PRINT_NAMES`.

Тогда идёт проверка потока: `[tid]` строк `AvPlayerJumpToTime()` и `AvPlayerIsActive()` в том же логе при
`KYTY_PRINT_NAMES` (имя печатается с номером потока, `src/libs/libs.h:53`).

## 3. Что звено НЕ доказывает

- что T109 — дефект в игре: расхождение не показано, только не исключено;
- что `gl_FragCoord.z` в диапазоне вьюпорта и что смещение не применяется к глубине из шейдера — оба [I];
- что 4 PS с экспортом Z — все такие PS игры: в каталоге их 4 из 8 [c], 4 программы с экспортом Z в каталогах не встречались;

- верность декодера транслятора и трансляции корпуса железу;
- ни одно число не выигрыш; 60 FPS не обещаются.
