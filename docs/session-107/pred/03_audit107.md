## Findings and what is done with each

1. **MAJOR — the spin-share bias runs DOWNWARD.** Each contended acquisition adds two `QueryThreadCycleTime` costs to
   the wall but about one to the CPU numerator, pulling the share toward 0.5; so 0.75 is a LOWER bound. Since the
   true share ≤ 1, the per-call cost is ≤ 0.33 µs (benchmark ≈ 0.39 µs via ctypes, an upper bound); for 0.2–0.33 µs
   the true share is 0.86–1.0; a `CRITICAL_SECTION` with spin count 4 000 and ~1 µs waits is expected to be nearly
   pure spin. → FACTS: "spin share ≥ 0.75, likely ≈ 1"; O1 a genuine HIT; the session's "biased upward, not a
   measurement" withdrawn.
2. **MAJOR — `dapin=3` is the shipped default since session 82** (`gates.cpp:304`, `e092382`; `gates_base.txt` pins
   `dapin=3`; every session-107 run shows `mode=3 mask=0x5555`). FACTS §5 ("never shipped") and the draft
   `next-session-108.md` ("default 1") were false. → rewritten: the next track-1 step is a code candidate on the
   walker's compute prefetch; `dapin=1|3` under the pin is only the old §7 re-measure debt, its SHIP branch a no-op.
3. **"98.6 % walker" survives, scoped:** at the three instrumented sites, holder named at the first failed try
