# Сессия 60 — B3 (memo поиска программ) включён, `dawalk` закрыт, защита страниц после загрузки измерена и закрыта

База: `merge-upstream`, HEAD сессии 59 — `e58cde3`. Итоговый коммит — см. HANDOFF. Push нет.

## 1. Главный результат

- **B3 реализован и включён** — гейт `progmemo` (`KYTY_PROG_MEMO`, **по умолчанию 1**): draw,
  чьи регистровые входы `PrepareProgram` байт в байт равны предыдущему, не строит статический ключ

  `dawalklead=2` −1,1 / −0,3 / −1,4 %, `dawalklead=1` +2,4 / −0,4 / −1,6 % (три повтора каждая).
  Остаётся 0.

  (5 % потока); реализация `armdefer` (вооружение воркером, страница остаётся грязной до

  загружаются дважды (`sync_up_kb` 3,2 → 5,5 МБ, загрузок 46 → 68 на кадр, каждая рвёт render pass).
  Гейт остаётся **0**, в Sky Garden не мерился (§4).
- B6 (дайджест `static_state` в хэше `ProgramKey`) — без гейта времени выполнения

- Базы свипа `sky60`: **6,79–6,93 мкс CPU на draw (полоса 4700–5100), CPU потока 32,3–34,5 мс,
  GPU 14,1–14,9 мс, 29,2–30,3 FPS** при ~4 850 draw. 60 FPS нет.

## 2. B3 — memo поиска программ по неизменным регистрам

Профиль `sky1` (сессия 57): `PrepareProgram` 2,7 %, `GetGraphicsPrograms` 2,1 %, сравнения ключей
0,8 + 0,9 %, `BuildStageStaticKey` 0,7 %, `GetGraphicsPipeline` 0,9 % — ≈9 % потока на работу,
результат которой у большинства draw совпадает с предыдущим (`e9_adj` 79 %).

**Что memo пропускает.** В `PipelineCache::GetGraphicsPrograms` для каждой стадии строится
свидетель — все входы `PrepareProgram` байтами: регистры стадии (`data_addr`, `rsrc1/2`, число
user SGPR; для VS — `gs_regs`, стадии шейдеров, `ClipControl`, viewport 0 при `clip_disable`,
`provoking_vtx_last`, тип примитива, `GeControl`; для PS — `target_export_mapping`),
`HW::ShaderRegisters` целиком и эпоха регистрации шейдеров (`PipelineCache::ShaderRegistrations()`,
двигается в `libs/agc.cpp` после `ShaderMapUserData` — свидетель `ShaderGetMappedData`). Для VS со
встроенным fetch'ем дополнительно записываются слова таблицы атрибутов и V#, которые прочитал
`ShaderApplyAttribSemantics` (семантика ресурса i — `resources_dst[i].attr_id`, индекс V# — в её
слове), и на попадании перечитываются тем же деревом чтения (backing для префикса атрибутов, backing
для V# только после него, иначе прямой указатель). Попадание: `PrepareProgram` не вызывается,
входная информация стадии остаётся такой, какой её оставил предыдущий draw (для PS
`RefreshShaders` больше не обнуляет её при активной стадии), `ShaderParams` берётся из memo с
user data, перечитанными из живых регистров (для NGG — с префиксом из 8 нулей и указателем GS
back half в s0:s1), а `ProgramCache::Get` берёт ключ своего слота (`lookup_keys[0/1]`) и
итератор `programs.find` предыдущего вызова (свидетель — `programs_epoch`, двигается на каждой
вставке/извлечении). Отдельно memo ключа пайплайна: построенный `GraphicsPipelineKey`, равный
предыдущему, отдаёт тот же `GraphicsPipelineEntry` без хэша и поиска (записи не удаляются никогда).
Memo привязано к объекту состояния draw (`DrawRenderState::prog_memo_serial`): вложенный draw на
стековом состоянии попадания не получает; нужен `drawstate`, поток — роль GuestGpu.

**Что не входит в свидетель — значения user SGPR** (кроме двух пар указателей таблиц): они не
влияют на поиск программы, а на попадании копируются заново, поэтому draw'ы одного материала с
разными константами — попадания. Без этого memo не имело бы смысла: `pmemo_eq_*` считает именно
равенство остальных входов.

**Самопроверка `progmemocheck`** (`KYTY_PROG_MEMO_VERIFY`): на попадании выполняется настоящий
`PrepareProgram` в отдельную информацию, сравниваются параметры (хэш, код, user data, back code),
статические ключи и ресурсы/буферы VS; расхождение — `ProgMemoVerify: MISMATCH` и `pmemo_bad`.
Первая версия проверки давала 1 ложное расхождение на кадр — `mesh.host_subgroup_size` ставится
вызывающим после `PrepareProgram`; проверка берёт его и `clip_space` из обслуженной информации.

**Ревью (агентом) — 5 замечаний, все исправлены до свипа:** (1) вложенный draw на стековом
`DrawRenderState` по тому же адресу мог быть обслужен из записи другого объекта — memo привязано
к `prog_memo_serial` объекта; (2) слова таблиц записывались после того, как их прочитал
`PrepareProgram` — запись валидируется против построенных ресурсов (`fetch_index` из слова,
V# с преобразованием формата/смещения как в `shader.cpp`), при расхождении memo недействительно;
(3) дерево чтения таблиц повторяет оригинал точно (V# через backing только после успешного чтения
префикса атрибутов, иначе — только использованные записи через указатель); (4) ложное
расхождение самопроверки на mesh-стадиях (`host_subgroup_size`); (5) memo требует роли GuestGpu.

**B6.** `ProgramKeyHash` дополнительно мешает XXH3 содержимого `static_state`, чтобы статические
варианты одного шейдера не сидели в одной цепочке бакета и не сравнивались пословно на каждом
промахе. Хэш карты нельзя менять на лету — переменная читается один раз (`KYTY_PROG_KEY_DIGEST`,
по умолчанию 1). С memo поиск идёт только на промахах, поэтому отдельно не мерится.

## 4. Пункт 4 — защита страниц после загрузки: потолок и реализация `armdefer`

**Потолок (Sky Garden, `sky60`, на кадр):** `prot_gpu` 195 вызовов `VirtualProtect` на потоке
GuestGpu / 6 500 страниц / **1,6 мс**; из них RO-вооружение после загрузки только для чтения —
159 вызовов / 5 900 страниц (≈90 %); ожидания `ApplyGuard` на GuestGpu `pb_wait_gpu_us` ≈0,1 мс;
загрузок буферов 72 на кадр, 23 МБ. Потолок ≈1,5 мс, ≈5 % потока.

**Реализация (гейт `armdefer`, `KYTY_ARM_DEFER`, самопроверка `armcheck`).** Протокол «вооружить →
эпоха → снять грязные биты, чьи эпохи не сдвинулись» в терминах трекера: загрузка только для чтения
копирует грязные страницы и **не снимает** грязный бит; их write watcher добавляется в состояние
страниц сразу, а `VirtualProtect` делает воркер `KytyPageProtect` (pending-биты, как у отложенной
защиты кэша текстур); множество таких страниц — `RegionManager::m_armed`, формула защиты записи
`m_cpu_dirty & ~m_armed`. На следующей синхронизации страница «грязная, запрошена, защита в силе»
(`PageManager::KeepApplied`: pending-бит снят и страница не внутри `applying_run`) копируется ещё раз
и только тогда чистится; запись, попавшая до вступления защиты, есть в одной из двух копий, запись
после неё бьёт fault, и `ChangeState<Cpu, true>` снимает вооружение. Синхронные пути (записываемые
загрузки, GPU-запись в такую страницу, выключенный гейт) сначала применяют ожидающую защиту
(`SettleArmedSync`). Буфер после такой загрузки не записывает текущую эпоху (`provisional`), чтобы
вторая синхронизация состоялась. Тест `MemoryTrackerTests` знает протокол при `KYTY_ARM_DEFER=1`.

**Замер (пустыня `arm1`, соседние базы):**

| | базы | `armdefer=1` |
|---|---:|---:|
| `prot_gpu_us` / `prot_ro` вызовов / страниц | 270–302 мкс / 54 / 850–870 | **111–113 мкс / 4 / 77** |
| `arm_req` / `arm_settled` / `arm_wait` на кадр | — | 780–788 / 521–535 / 32 |
| `sync_ups` / `sync_up_kb` | 46 / 3 160–3 230 | **67–68 / 5 450–5 550** |
| CPU на draw | — | **+7,8 % (с самопроверками), +4,5 %** |

Механизм делает то, что задумано (RO-вызовов на GuestGpu 54 → 4), но две трети запрошенных страниц
(521 из 780) не переписываются гостем до следующей синхронизации — это стриминг констант, записанных
один раз, и каждая такая страница уезжает на GPU дважды: +2,3 МБ копий и +22 загрузки на кадр,
каждая с разрывом render pass. Вторая копия дороже сэкономленного `VirtualProtect`; в Sky Garden
23 МБ загрузок на кадр того же рода, поэтому свип там не делался. **Гейт остаётся 0.** Что могло бы
это спасти: вторую копию заменить сравнением на воркере (после `VirtualProtect` сравнить страницу с
её staging-копией и осесть равные — нужны адрес копии в staging-кольце и гарантия, что кольцо её не
перезаписало) или ограничить отложенное вооружение «горячими» страницами (переписываемыми каждый
кадр; по счётчикам A1 их мало). Обе — отдельная работа с малым потолком (≈1 мс).

## 5. Проверки

- **Самопроверка `progmemo`:** пустыня 840 + 10 562 кадра (`chk1`, `val`) и фаза `pmchk` в Sky
  Garden — `pmemo_bad` = 0, `ProgMemoVerify` в логах нет.
- **Vulkan + sync-валидация** на пустыне (`val`, `progmemo=1 progmemocheck=1 dawalk=1 rtfast=1`,
  `texfastcheck sfcheck pbcheck buffastcheck smemocheck drawstat`), интро и ~10 500 кадров:
  **0 ошибок, 0 sync hazards**, известное предупреждение о лимите 10 повторов;
  `texfast_bad`/`sf_bad`/`pb_bad`/`bfast_bad`/`da_wdrop` = 0. Проведена до `armdefer`; `armdefer`
  по умолчанию выключен и в валидации не участвовал.
- **`armdefer` на пустыне** (`arm1`, `arm2`): `arm_bad`/`pb_bad`/`pb_bad_rw`/`sf_bad` = 0,
  `ArmDeferVerify`/`PbCheck` в логах нет, 0 `GpuWaitSlow`/`GpuHangAbort`. Дефект, найденный тестом
  с гейтом: GPU-запись (`MarkRegionAsGpuModified`) в вооружённую грязную страницу била `EXIT`
  «GPU dirty state conflicts with CPU dirty state» — исправлено (страница оседает синхронно).
- **Видео:** `rec_pm1` 12 330, `rec_val` 10 592, `rec_sky60` (весь заход и свип) — **0 однокадровых
  глитчей**.
- **Sky Garden:** 0 `GpuWaitSlow`/`GpuHangAbort` за весь заход (~13 000 кадров в сцене), подпись
  кэша трансляции не менялась, холодного входа не было.
- **Тесты:** пять бинарей проходят, `resource_tracking_tests` падает как прежде (лог побайтно тот же);
  `memory_tracker_tests` проходит и с `KYTY_ARM_DEFER=1` (11 тестов старой семантики «немедленного
  снятия» под гейтом пропускаются, два новых случая протокола выполняются).
- **Ревью агентами:** `progmemo` — 5 замечаний (§2), все исправлены до свипа; `armdefer` — 2
  замечания, оба исправлены: (1) существенное — при `bdastamp` (по умолчанию 1) регион без сдвига
  эпохи пропускается сканом BDA, и вторая синхронизация страницы, оставленной грязной, могла не
  состояться (запись в окне между копией и защитой терялась до чужого fault'а в регионе) — теперь
  предварительная загрузка двигает эпоху региона (`m_epoch`, не глобальную); (2) формальное — в
  `TakePendingRun` между публикацией `applying_run` и сбросом pending-битов добавлен release-fence,
  на который опирается безлоковый `KeepApplied` (и `FlushBlocker`). Остальное ревью признало
  корректным: осадка только при снятом pending-бите вне `applying_run`, `m_armed ⊆ m_cpu_dirty`,
  порядок замков tracker → `apply` → pm lock, переключения гейта на лету.
- **Финальный прогон пустыни `arm3`** (финальный бинарь; `armdefer=1 armcheck=1 pbcheck=1
  sfcheck=1 progmemocheck=1`, затем умолчания с `progmemocheck drawstat`): `arm_bad`/`pb_bad`/
  `pb_bad_rw`/`sf_bad`/`pmemo_bad` = 0, `MISMATCH` нет, 0 `GpuWaitSlow`/`GpuHangAbort`; после
  правки эпохи скан BDA возвращается за осадкой чаще — `arm_settled` 507 → 716, `sync_up_kb`
  5,3 → 6,1 МБ на кадр (цена протокола выросла, вывод §4 тот же).
- Бинарь установлен, SHA256 **274BEB8F6A0A647596DFAC15DA371D6EF8607AD7A58309B9D8A053518BB45926**.
