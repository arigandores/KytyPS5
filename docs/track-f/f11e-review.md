## 5. Требования и вопросы

**RC1 — нумерация корзин расходится между пунктами; ридер, читающий номер, а не предикат, даст ложный «достижим».** (владелец — Harness Engineer, печать
F11f; принятие — лид) Что не так: п. 376(в)/(г)(2)/(е) нумерует корзины с 1 («`idx = size64 + 1` — … корзина 1», «`idx > 2·size64 + 1` — корзина 4», «корзины
1–3 — данные отчёта, в правило не входят»), а п. 381(б)(1)–(2), отчёт F11d и код — с 0 («корзина 3 = `idx > 2·size64 + 1`», «нарушение `size` = сумма
корзины 3 по всем трём классам»); строка лога — позиционная `b_tri=b0/b1/b2/b3`. Сценарий: ридер F11f берёт «корзину 3» п. 381(б) в счёте с 1 (третье поле,
`over` 17…`2·size64 + 1`); у BLAS, где игра пишет `size` = число узлов − 1, а узлы fp32 по 128 Б (F11b RC5), третье поле > 0 ⇒ «достижим по `size`» и звено
поиска первоисточника при законном обходе; или берёт «корзину 4» п. 376(е) в счёте с 0 — поля нет, ридер падает или печатает 0 ⇒ «не нарушено».
Что изменить: печать F11f называет член правила предикатом «`idx > 2·size64 + 1` = **четвёртое (последнее) поле** `b_tri`, `b_box`, `b_t7`», не номером;
фикстура ридера на строку, где в третьем поле > 0, а в четвёртом 0 (слово «не нарушено»), и наоборот.

**RC2 — хостовый разбор (`ProcessDiagWords`, печать строки) ни одним тестом не покрыт; ридер F11f должен проверять тождества строки.** (владелец — Harness
Engineer, печать F11f) Что не так: GPU-гейт сравнивает слова хвоста ГП, а модульная разность, `over_max`, порядок полей в `LOGF` и `slots` проверены только
чтением кода (верны [c]). Сценарий: ошибка индекса в печати (например, `bucket(1, x)` вместо `bucket(2, x)`) или неверный `max_step` прошли бы гейт и дали
бы F11g неверное слово по правилу. Что изменить: ридер на каждой строке `DiagBvhNodes: lanes=…` проверяет `lanes = t0 + … + t7`, `size_viol` = сумме всех 12
полей корзин, `size_viol + node64 ≤ lanes`, а по паре строк — сумма `slots` + `other` = `lanes` (каждое исполнение добавляет активные дорожки ровно в один
слот — `spirvEmitterMemory.cpp:2061`); нарушение — тег «не определено» и строка отчёта; `max_step ≥ 2³¹` — то же (отчёт F11d §8). Фикстуры — на каждое
тождество и на его нарушение.

**В1 (лиду; решение — не моё).** Буква п. 376(и) «сборка из чистого worktree на коммите диагностики — sha = копии F11d» допускает два прочтения: (1)

исполнителя: прочтение (1) достаточно (подпись трансляции пересчитана своим кодом, строки версии и `-dirty` нет); если лид требует (2) — сборка и сравнение

## 6. Замечания без RC

- **З1.** Гейт — только программы из одного блока; BVH-программы игры обходят дерево в цикле (F11a §2.3), часть — возможно, через `dispatcher_fallback` [U].
  Сходимость подгруппы хоста в цикле не гарантирована спецификацией без maximal reconvergence [I]. Для дорожек это не важно (§«Итог», `Elect`), для
