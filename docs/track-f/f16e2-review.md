## 2. Согласованность снимка (форма (а))

- **Тик** (`56b04817:src/graphics/presentation/videoOut.cpp:1246`, якорь «Graphics::DiagF5::Tick(static_cast<uint32_t>(r.cfg->flip_status.count));»; +1 — «Graphics::DiagF6::Tick(static_cast<uint32_t>(r.cfg->flip_status.count));») вызывает `TickAt` → `PublishSet` (`56b04817:src/graphics/host_gpu/renderer/diagF5.cpp:74`, якорь «bool PublishSet(bool on, DiagSet<CounterEnum>& set, uint32_t frame, uint64_t now_ms) {»; +1 — «if (!on) {»). Тик только записывает кадр, время и `has_request` под `request_mutex` и ни одного счётчика не читает.
- **Печать.** Копирует и печатает только `ServiceSet` (`56b04817:src/graphics/host_gpu/renderer/diagF5.cpp:89`, якорь «bool ServiceSet(bool on, const char* tag, DiagSet<CounterEnum>& set, const char* const* names) {»; +1 — «if (!on) {»): забирает запрос, затем под `print_mutex` делает `CopySet` и проверяет условие п. 427(е) по этой копии. Вызывают `ServiceSet` только `DiagF5::Service`/`DiagF6::Service`, а их — только верх цикла `GuestGpu::ThreadRun` (`56b04817:src/graphics/guest_gpu/graphicsRun.cpp:709`, якорь «(void)DiagF5::Service();»; +1 — «(void)DiagF6::Service();»). В этой точке не идёт ни команда, ни срез сабмита, ни диапазон `m4baton` этого потока.
- **Окна.** Каждое окно «родитель прибавлен, дети ещё нет» из §2 F16e открывается и закрывается внутри одного вызова функции сайта из тела цикла. Это пары B, вложенное `cmask_fce` ⊃ `cmask_rt_pending`, `meta_refused_known` ⊃ `dcc_fill_meta` (до 32 отказов, родители открыты вместе — тест-сайт: «open meta parents max 3») и `NoteDraw` целиком (`56b04817:src/graphics/host_gpu/renderer/diagF5.cpp:439`, якорь «set.counters[i].fetch_add(add[i], std::memory_order_relaxed);»; +1 — «}»). Реле `m4baton` пишет счётчики, пока GuestGpu припаркован в `BatonRelayRun`. Возврат GuestGpu из ожидания реле идёт через общий mutex реле, поэтому записи реле видны до следующего верха цикла (happens-before). Итог: при копировании открытых окон k = 0 по построению.
- **Других потоков печати нет:** в `56b04817` вызовов `Service`/`ServiceSet`, кроме `graphicsRun.cpp:709–710` и тест-сайта, нет.
- **Не доказано:** что все сайты Ф5/Ф6 вызываются только с GuestGpu или реле при его парковке. Перечень сайтов взят из F16e §2 [c ревью F16e], заново по всему коду не обходился.

## 3. Вблэнк

`PublishSet` держит только `request_mutex`, внутри — три присваивания. `ServiceSet` держит `request_mutex` только на чтение и сброс запроса, а копию и строку делает под `print_mutex`, который тик не берёт. Поэтому вблэнк ждёт на GuestGpu не дольше трёх присваиваний под `request_mutex` — меньше одного копирования счётчиков ✓.

## 4. Путь `=0`

Добавки в отчёте F16d2 §3 сверены с диффом, список полон. В `ThreadRun` при старте потока два чтения `On()` (`const bool diag_f56`), на каждой итерации — проверка локального `bool` без вызова. В тике `PublishSet` выходит по `!on` до замка. `NoteDraw` и сайты выходят по `On()` как в F16d. Новых атомарных операций на пути `=0` нет ✓.

## 6. Бинарь: своя сборка против копии F16d2

- Своя `kyty_emulator.exe` — `6749a7d8d8d7b9fed1569b29b9adf92e3911e16f3b9e85b5bde3d52c52ad34f4`, копия F16d2 — `4ad735ad…09f6`, размер у обеих 24 689 664. **sha256 ≠.**
- **Причина [c].** Путь worktree `C:\kyty\f287\f16d2\wt` → `C:\kyty\f287\f16e2\wt` (одна длина) меняет две вещи:
  - строки `__FILE__` — 139 байт в `.rdata`;
  - хэши анонимных пространств имён `?A0x…` (236 вхождений в обоих бинарях). В A 222 тега из 8 цифр и 14 из 7, в B 45 из 8 и 191 из 7: сумма короче на 177 символов. Имена дескрипторов RTTI в `.data` выровнены, и после выравнивания `.data` B короче на 0x140 (`VirtualSize` 0x22e2e60 → 0x22e2d20; `tags_emu.txt`).

  Сдвиг данных меняет смещения rel32 в `.text`, указатели в `.data`/`.rdata` (41 019 + 318 байт) и `.reloc` (659 байт). У F16e (пути `f16d`/`f16e`) длины тегов после выравнивания совпали — отсюда там `.text` 0.
- **`.text` — 123 714 байт отличий** (`residual_emu.txt`: всё в классе OTHER `.text`; Н2 F16e — `residual.py` не знает класса «смещение»).
- **Проверка «только сдвиг данных»** (`disp2.py`, `disp2_emu.txt`). Все 61 677 групп отличающихся байт укладываются в одно 4-байтовое поле rel32, которое в обоих файлах указывает вне `.text`. Отображение 12 342 целей A → B однозначно (0 нарушений), инъективно (0) и монотонно (0). Различных сдвигов 18, от −0x30 до −0x140, основной −0x140. Вердикт `LAYOUT-SHIFT-ONLY`.
  - Отрицательный контроль 1 — 16 байт `.text` в середине изменены: `NOT-LAYOUT-SHIFT-ONLY`, 4 группы без окна (`disp2_emu_negctl.txt`).
  - Отрицательный контроль 2 — два поля rel32 с разными целями переставлены («ссылка не на тот глобал», каждая группа остаётся 4-байтовой): `NOT-LAYOUT-SHIFT-ONLY`, однозначность 2, инъективность 2, монотонность 1 (`disp2_emu_swap.txt`).
  - Нулевой контроль — `4ad735ad` против себя: 0 байт (`disp2_self.txt`).
- **Чего проверка не видит:** изменение кода, которое попало точно в поле с одинаковыми байтами в A и B, невидимо любому побайтовому сравнению. Перестановка ссылок внутри одного блока сдвига без нарушения монотонности — тоже, если обе цели сдвинуты одинаково и обе ссылки переставлены согласованно [I].
