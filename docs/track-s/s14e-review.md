R6 зависит от того, как события собраны в серии. Блокирующие цели компилируются в первом кадре своей серии, остальные кадры серии — удержания. Посчитано своим кодом (`c0_out.txt`, `evl_out.txt`):

| **По событиям:** удержания трёх блокирующих серий неустранимы, всё остальное (включая все строки пропуска в них) устранимо | **0,6699** (103 − 34) |

**Атрибуция по кадрам неверна [c лога].** Каждая блокирующая серия длится ровно до создания пайплайна, который содержит блокирующий модуль:
- `t2_1` 317..334 — после компиляции `828215ad` / `acee300d` (строки 305712, 309830) идёт одно асинхронное создание `pipeline gfx vs=1202 ps=1201 us=286490` (строка 312589); удержания `AsyncPipelines: flip 319…334 held (incomplete frame)` кончаются на нём. Других созданий в окне нет;

## 6. Требуемые изменения

**RC1 (к пункту лида о приёмке S14e).** Пункт исхода «убит» должен называть устойчивость к атрибуции: правило серии S14k — 0,3883; без склейки и по событиям — 0,6699; атрибуция по кадрам (0,9515) отвергнута по трём фактам лога §3. *Сценарий отказа:* скорер S10 сам начинает серию `t2_1` с кадра 319 (`fin_summary`), а не с 317. Позднее чтение по скореру или по кадрам получит 0,67 или 0,95 и заявит, что «граница не верхняя» — переоткрытие S-early без нового свидетельства. *Что изменить:* в пункт приёмки — строка с тремя числами и тремя созданиями пайплайнов (`1202/1201` 286 490 мкс, `1192/1191` 261 200 мкс, `1193/1192` 243 708 мкс), со ссылкой на `docs/track-s/s14e/`.

**RC2 (к пункту отмены S14f–S14i).** Отмена S14h убирает единственный запланированный источник числа формы «по опережению PM4» (п. 430(д)(4): `KYTY_LAG_TRACE=1` на пяти плечах DIAG=1). По п. 423(г) форма паркуется «до этого числа». *Сценарий отказа:* звенья отменены, форма остаётся припаркованной без звена, которое когда-либо даст число, — тихий тупик, не записанный ни как `ТУПИК`, ни как «застопились» п. 229(з). *Что изменить:* пункт отмены называет судьбу формы — либо отдельное звено без кода (ручка уже есть в установленном дереве, `4d9e8ab7:src/graphics/guest_gpu/graphicsRun.cpp:951`, якорь «static const bool trace_lag = Common::EnvFlagOn("KYTY_LAG_TRACE");»; +1 — «if (trace_lag && first_slice) {»; это только чтение часов и строка лога при лаге ≥ 2 000 мкс, отметка `enqueue_ns` ставится и без ручки, `:670`), либо явную парковку с условием переоткрытия.

**RC3 (к пункту исхода, «не заявляется»).** Убийство относится к предсказателю B (таблица ключей процесса) на стенде (е)(2): `snap0` подписи `699c1e4b`, пять уровней п. 408(в). Предсказатель, который берёт специализации из файлов **старших подписей** (474 файла в `snap0`; штатный `Load` их отвергает, а читатель теста падает на `ReadPlan`), этим числом не ограничен: их специализации неизвестны [U]. *Сценарий отказа:* после каждой отгрузки со сменой подписи (FS5 — п. 418(в): «первый вход каждого уровня холоден целиком») все файлы пользователя становятся файлами старшей подписи. Проект «S-early со сбором специализаций из старого кэша» будут отклонять ссылкой на этот исход, хотя его множество кандидатов другое. Обратно: строки трёх блокирующих целей в старших файлах невозможны только для своего хэша (0 из 1 186), чужие хэши — [U]. *Что изменить:* одна строка в «не заявляется» пункта исхода.
