## BLOCKING

### B1. Статистика LOD текстур — класс, наблюдаемый гостем, пропускается режимом 1 и нигде не учтён

**Что не так.** `LodStats::Touch` (`descriptors.cpp:2184`, внутри `ResolveTextureWith`) считает каждую сэмплируемую привязку T#
с `MipStatsCntEn` в банк счётчиков. Пакет `IT_GET_LOD_STATS` (`pm4Handlers.cpp:1379-1427`, CP, исполняется в любом кадре)
пишет банки **в память гостя** (256 qword: число выборок и минимальный мип, `0xF` — «не сэмплировался») и по флагу сбрасывает
их. `ResolveTextureWith` зовётся из `PrepareBindings`/`RebindImages` — ниже сайта пропуска §1.4. В режиме 1 draw пропускаемого
кадра до него не доходят: банки, которые трогают только draw, в отчёте этого интервала — `NO_SAMPLES`, остальные — с
заниженными счётами. Контракт п. 25(г) («всё наблюдаемое гостем исполняется») нарушен; проект (§2, K1–K15), `code_sites.md`
и ROADMAP этот класс не называют (поиск `lod`/`GET_LOD` по `docs/session-123/` и `ROADMAP.md` — пусто). Перепись режима 2 его
тоже не видит.

**Сценарий отказа.** Игра (менеджер `GfxMipStatsManager`, `lodStats.h:12-15`) решает стриминг мипов по этому отчёту; с. 8
зафиксировала, что заглушка с нулями вешала загрузку. Если отчёт идёт раз в кадр со сбросом, в каждом втором отчёте плеча 1
текстуры, видимые только draw, выглядят невидимыми: стример снижает/выгружает их мипы → в переведённых кадрах плеча 1 другая
работа (меньше `img_up_kb`, другие привязки), а смена состояния стримера переносится в следующий блок плеча 0 (гистерезис
стримера длиннее блока 90). Δ перестаёт быть ценой перевода draw: в него входит изменённая игрой нагрузка — в любую сторону,
от ложного (ii) до ложного (i). Хуже — повтор с. 8 (зависон стриминга) → G2 FAIL, который будет приписан K2/K3. Частота
отчётов на Sky Garden не измерена **[I]**.

**Что изменить (решение лида до дыма, одно из):**
(а) в режиме 1 на сайте пропуска исполнять для draw ТОЛЬКО `Touch` его сэмплируемых T# (нужна та часть разрешения SRT, что
даёт дескрипторы; эту цену платит и плечо 1, поэтому Δ занижается на неё — записать направление);
(б) принять класс как K16 с измерением: в режиме 2 счётчики `skc_lod_d`/`skc_lod_all` (вызовы `Touch` из операций D / всех) и
ряд печати «отчёты `GET_LOD_STATS` на кадр и `sampled_banks` по плечам» (строка `LodStats: report` сейчас только при
`KYTY_LOD_STATS_TRACE`) — с правилом НЕ ДОПУЩЕН при расхождении плеч больше порога A/A Д4;
(в) иное — но записанное строкой ROADMAP до дыма. Без решения дым Д1 проверяет не то, что заявлено.

### B2. `skc_x1_wd` / `skc_x1_wp` считают пары (писатель, образ), а не писателей: Т7 ложно по построению, направление §11 неверно

**Что не так.** `SkcStampImage` (`textureCache.cpp:3566-3593`) ведёт `skc_wdraws`/`skc_wpass` **на каждом образе**; один D-draw
с MRT и записью глубины штампует W1 каждое вложение (`renderDraw.cpp:1522-1528`) и растит `skc_wdraws` каждого. `SkcX1Image`
(`:3602`) складывает `skc_wdraws` по различным образам. Определение §3.3 — «сумма `skc_wdraws` по различным образам» — код
выполняет буквально, но:
* Т7 (§4.5) требует `skc_x1_wd ≤ skc_c_dd` — неверно при двух и более образах одного писателя;
* §0(2) называет `skc_x1_wd / skc_c_dd` главной долей («объём работы, который корректная версия обязана исполнить»), §11 —
  «НИЖНЯЯ граница объёма»; при k образах на писателя это до k-кратная переоценка, то есть направление не определено;
* то же для `skc_x1_wp / skc_c_dp` (проход с 4 целями даёт 4).

**Сценарий отказа.** Кадр N: 2 000 D-draw геометрии пишут цвет, скорость и глубину (3 вложения). Кадр N+1: TAA читает
историю цвета, репроекция — глубину и скорость. `skc_x1_wd` ≈ 6 000 > `skc_c_dd` ≈ 2 500 → Т7 в Д2 падает, перепись НЕ
ДОПУЩЕНА либо (если Т7 ослабят молча) доля > 1 уходит в проект с. 124 как «нижняя граница».

**Что изменить (решение лида до дыма, одно из):** (а) считать различных писателей: у образа в режиме 2 — список серийных
номеров D-операций кадра `skc_wframe` (перепись не хронометрируется, память не важна), при чтении k = 1 — множество уже
учтённых серий кадра; то же для проходов по `t_pass`; тогда Т7 и «нижняя» верны; (б) оставить пары, переименовать смысл
(«пары писатель×образ»), снять Т7 `skc_x1_wd ≤ skc_c_dd`, в §11 направление «не граница числа писателей», доля не цитируется
как объём. Вариант (а) — правка шага 5, (б) — только строка ROADMAP и скорер шага 7.

## Non-blocking

**N1. `skc_bad` тавтологичен; настоящий отказ «пропущенный кадр показан» — `skc_mark_miss`, и его не запрещает ни один страж.**
Оба условия `skc_bad` (`videoOut.cpp:1207`, `:1212`) недостижимы по построению ветки (решение 21 это признаёт). Кадр, чьи draw
пропущены, показывается, только если `MarkSkipCeil` не нашёл запрос (`graphicsRun.cpp:3823-3824`, отмена/сброс видеовыхода);
это `skc_mark_miss`, а Т2 включает его в сумму (`skipf − (mark + mark_miss) ∈ [0;1]`), G7 его не называет. Сценарий: сброс
очереди флипов → кадр без draw показан, строка попадает в страту «не удержан» с малым `dt` → стратифицированная оценка
плеча 1 занижена, Δ завышен. Изменить: в предрегистрации шага 7 — `Σskc_mark_miss = 0` за прогон (или в окнах) в G7; строка ROADMAP.

**N2. Залипание вида операции вне операции (скрытый дефект).** `ReadImage`/`ReadBuffer`/`ReadIndirectArgs` (`textureCache.cpp:3721`,
`:3796`, `:3831`) ставят `t_kind = T` по `t_skc_op.dispatch`, не проверяя, что операция вооружена; после `OpEnd` флаг `dispatch`
последней операции остаётся. Сегодня все вызывающие (`RebindImages` — только из `PrepareGraphicsBindings`/`DispatchDirect`,
`ExecutePreparedDraw` — только из `DrawIndex`/`DrawAuto`) идут внутри `OpScope`, поэтому недостижимо. Сценарий на будущее: любой
вызов этих сайтов вне операции после dispatch → `t_kind = T` навсегда → каждый `OpBegin` возвращает false, перепись молча
мертва (`skc_x1_*` = 0, все W3 штампуют T). Изменить (шаг 5, дёшево): выходить, если `t_skc_op.serial == 0`.

**N3. W1/W2 применяются и к draw, которые затем не исполняются (`pipeline_ptr == nullptr`, `renderDraw.cpp:2927`).** `ApplyW2`
(`descriptors.cpp:4219`) и W1 (`:1522`) стоят раньше отказа `AsyncPipelines`. D-штампы неисполненной записи — верхняя сторона;
R-штамп W1 стирает D образа, которого draw не писал, — нижняя сторона `skc_x1_*`. Только в кадрах с маркером
`AsyncPipelines: skipped draw` (в Д2 не фатален). Изменить: строка направления в §11 или счётчик; кода не требует.

**N4. Цена при 0 вне GuestGpu — не «один тест».** `t_w3 = true` на всех потоках, кроме GuestGpu (`frameStats.h`, решение 2), поэтому
каждый `MarkGpuModified`/`UploadImage`/`CopyImage*` с чужого потока при любом значении ручки — внешний вызов + TLS + атомарная
загрузка `g_mode`; так же `SkcEraseCpu` — внешний вызов на каждую `InvalidateMemory`/`InvalidateWriteFault`. Симметрично в обоих
плечах ABBA и сокращается (§9), поэтому не влияет на Δ; §9 «один тест» для этих сайтов неточен — поправить текст или принять.

**N5. Стирание CPU в режиме 2 командами GuestGpu меняет расписание переписи.** `SkcEraseCpu` (`bufferCache.cpp`, конец файла) на
каждый отказ записи гостя ставит `SendCommand`; команды обрабатываются между подачами. Режим 2 не хронометрируется, но это
сдвигает порядок работы GuestGpu в прогоне переписи; N3 (`Σrpd_a*` 2/0 в [0,98; 1,02]) это ловит. Кода не требует; в отчёт дыма —
число таких команд, если N3 на грани.
