## 3. (г)(2) Правило правки [c кода]

`SubstitutionHolds` (`9635cb0f:src/graphics/host_gpu/renderer/pipeline/shaderReplay.cpp:586`): слово получает роль с
каноническим значением, отличным от сырого, только если обход с **одним этим словом** в каноническом значении (остальные
сырые) — `ok`, `complete`, специализация = живой, число запросов то же и каждый запрос тот же. Иначе — `ROLE_KEEP`, значение
сырое. Правило — для всех ролей с канонизацией (`INERT`, `PTR_*`, `V_*`, `T_*`), проверка только при значении ≠ сырому
(`:700`).

**Вариант исполнителя (запросы адресного слова):** для `PTR_LO`/`V_LO` запрос может сдвинуться ровно на (канон − сырое), для
`PTR_HI`/`V_HI` — на (канон − сырое) << 32 (по модулю 2^64); для `INERT` и `T_*` — только равенство. Основание: слово-указатель и
есть адрес — замена его канонической формой сдвигает все чтения через него по построению, буквальное «те же `requested`»
сделало бы `KEEP` каждый указатель и (по п. (г)(3)) отвергло бы каждую запись с указателем. Синтетический runtime перестройки
адреса не смотрит (`Answer`, `shaderReplay.cpp:408`), поэтому сдвиг ровно на подстановку — тот же обход. Канонические формы
сохраняют биты 0..3, маски обхода (`& ~3`, `AddressMask`) сдвиг не меняют [c кода `SrtWalker.cpp:1870`, `:1904`, `:1927`].
Проверка набором: тест (2) `TestShaderReplayCanonicalPath` (указатель на таблицу V#) по-прежнему даёт `PTR_LO`/`PTR_HI`.

## 4. (г)(3) Безопасность адресов [c]

- Слово, ставшее `ROLE_KEEP`, проходит прежнюю проверку `residual` (значение ≥ `0x10000`, совпадающее с младшим словом адреса
  запроса или базы дескриптора, — отказ записи) без изменений.
- **Вариант исполнителя (строже):** слово, которое классификатор счёл адресом (любая роль, кроме `INERT`), а каноническая
  замена не прошла, отвергает запись как `residual` при любом значении (`kept_address`, `:703`, `:778`). Основание:
  проверка `residual` сравнивает значения точно, а указатель, через который читают только со смещением ≠ 0, ни с одним
  запросом не совпадает — без этой строки сырой адрес ушёл бы в каталог (`ROLE_KEEP` сканер `R_ADDR` не считает). Счётчик —
  `canon_residual`, то есть `canon_mismatch` (член К3). Фикстура — часть (б): младшее слово указателя `s28` служит и
  `num_records`; на `a2fee0d9` — `self ok=0 complete=0 culprit=30:role2:…->00000100`, на `9635cb0f` — `why=residual`; чтений
  по адресу, равному `s28`, нет (`exact=0`).
- **`R_ADDR` = 0 и стенд `addr` > 0** — фикстура в части (а): на канонической записи слов вне канонической формы по правилу
  сканера (`WordCanonical`) 0, на той же записи со значениями «как прочитано» (форма стенда `addr` в `HandleSpec`) — 6
  (`r_addr=0 stand_addr=6`). Формат каталога не менялся: строка `ShaderReplayLayout:` = S17a2 (`layout_S17a3.txt`, `cmp`
  совпадает); `test_r_addr.py layout_S17a3.txt` — `test_r_addr.out.txt`.
- **Стенд `canon` по п. 536(б)** — часть (в): форма теста (1) `TestShaderReplayCanonicalPath` с T# целочисленного формата
  (`k32UInt`; нулевой T# специализируется как Float): без стенда запись принята, со стендом —
  `self ok=1 complete=1 culprit=2:role6:00001000->00000000` (`rejected=1` следует из отказа). Та же строка на `a2fee0d9` и
  на `9635cb0f`.
