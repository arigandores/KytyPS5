### 0.3 (iii) Метод — чем он отличается от F23f

- **(α) — принят.** Событие-кандидат — первое исполнение программы в кадре (номер 1 описи; 7 событий): до него ни одно исполнение
  модуля не идёт, значит состояние на `eid − 1` от замены не зависит **по построению**; Г1 это проверяет числом (`Npre` по каждому
  плечу), а не предполагает. Остальные 31 событие реплеются тем же методом — для них Г1 решает данными (ожидается провал у `sens` и у
  `def`, если ранние исполнения пишут, — это и есть RC1 F23g).
- **(β) — отказ, [U].** В API RenderDoc 1.46 замена ресурса (`ReplayController.ReplaceResource`) действует на весь последующий реплей
  (все пайплайны, созданные из модуля, на всех EID), замены «на одном EID» в API нет; эмулировать её ветвлением внутри модуля по
  признаку события — значит менять сверяемую SPIR-V. (β) не используется.
- **(γ) — принят в форме «вычитание под той же заменой».** Слоты счётчиков RC4 (`n_t`, `n_f` на место, `n_entry` на вход) — в конце
  наибольшего диапазона `buffers` для чтения-записи, связанного на событии (форма F23f). Отличие от F23f: значение слотов **до** события
  читается на `eid − 1` **при той же замене диагностическим модулем** (у F23f — без замены, `11311fb1:docs/track-f/f23f/rd_f23f.py:291`,
  якорь «ctrl.SetFrameEvent(eid - 1, True)»; +1 — «before = bytes(ctrl.GetBufferData(»), после — на `eid` при ней же; атомики только
  прибавляют, значит разность = вклад только этого события (равносильно обнулению непосредственно перед EID). Г2 проверяет это числом:
  `n_entry` = PSInvocations события из описи [c запроса GPU]. Самопроверка диагностического модуля (все выходы, кроме слов слотов, =
  `def`) — условие чтения `n_t`/`n_f`: при самопроверке ≠ 0 счётчики события не читаются (форма F23f), событие по членам (ж) не
  несёт `n_t` > 0.
- Состояние до события читается **в каждом плече при его замене** (у F23f — только без замены, `11311fb1:docs/track-f/f23f/rd_f23f.py:192`,
  якорь «def run_state(nid):»; +1 — «if nid is not None:»): это и есть `Npre` члена Г1.
