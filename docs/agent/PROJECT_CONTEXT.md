## Правила работы

- **Решения принимает исполнитель (постоянное делегирование пользователя, 2026-09-23):** «пиши в
  роадмап так, как рекомендуешь, главное достичь цели… я не советчик». Решать по цели, записывать каждое
  решение в `ROADMAP.md` ДО действия, пользователю вопросов не задавать; он может отменить любое решение.

- **Обязательный коммит в конце каждой сессии (прямое указание пользователя, 2026-09-10).**
  До итогового ответа коммитить изменения по текущей задаче и относящиеся к ней накопленные
  изменения предыдущих сессий. Дополнительного разрешения на такой коммит не спрашивать.
  Перед коммитом нормализовать окончания строк, проверить состав diff и выполнить необходимые
  проверки; уже завершённые проверки без изменений кода не повторять ради коммита.
  Незавершённую работу сохранять явно обозначенным WIP-коммитом с описанием ограничений;
  не выдавать её за проверенное исправление. Посторонние изменения/подмодули не захватывать.
  Если изменений нет — пустой коммит не создавать. Если коммит не удался — исправить причину
  либо явно сообщить препятствие. В финальном ответе указывать хэш и обновлять HANDOFF.
  Push выполнять только по отдельному указанию пользователя; коммит не означает публикацию.

- Инструментация в hook переписывает команды в `rtk ...`. В heredoc'ах bash последовательность `\\n` превращается в реальный
  перевод строки: **не писать C-строки и python-строки с `\n` через heredoc** (за сессию ломалось дважды). Патчи класть в
  файл через инструмент Write или писать `chr(92)+'n'` в python. `grep`/`sed` через хук режут вывод — для поиска по
  исходникам и логам использовать python-скрипты (heredoc `python - <<'PYEOF'` без `\n` в строках). Ловилось и в
  тринадцатой сессии (дважды): любой патч с C-строками — только файлом через Write; если сломалось —
  `python C:\kyty\scripts\fix_nl.py <файл>` склеивает разорванные литералы.
- Патчи исходников делать python-скриптом, записанным через Write: файлы могут быть в CRLF (Edit переписывает их так),
  скрипт должен снимать `\r` перед поиском и возвращать обратно.
- Логи огромные (1-15 млн строк, с `KYTY_PRINT_NAMES` — 50 млн). Не читать целиком: фильтровать python-скриптом в бинарном
  режиме (`open(path,'rb')`) по маркерам. Пути в python писать как `C:/...`, не `/c/...`. Сообщения разных потоков
  перемешаны; заголовок `[tid][HH:MM:SS.fff] lib::func()` есть только у вызовов с `PRINT_NAME`.
- Прогон занимает от 10 с (логотип PlayStation, видео) до 4-5 мин; окно игры в это время не закрывать и не запускать
  свой экземпляр параллельно (общий `_kyty.txt`, кэши, GPU). Мои прогоны завершаются по `timeout` — закрытие окна
  через N секунд не крэш. Максимальный таймаут одной команды инструмента — 600 с: серии из нескольких прогонов
  уходят в фон, результат читать из файла задачи. `qrenderdoc.exe` может зависнуть при выходе (8 ГБ RAM) —
  `taskkill //F //IM qrenderdoc.exe`.
- Скриншот/клавиши и прогон — в одной bash-команде (`run & (sleep N; powershell ...); wait`). `sendkey2.ps1` сначала
  делает окно активным; первое нажатие иногда теряется — закладывать два нажатия (`-Repeat 2 -Gap 5`) или проверять
  скриншотом. `Get-Process kyty_emulator` из отдельной команды процесс не видит. Под RenderDoc клавиши не доходят —
  просить пользователя нажать J (он у экрана).
- **Проверка картинки — только видео (`KYTY_REC`), не скриншоты** (решение пользователя, двадцать пятая сессия): запись
  показанных кадров силами эмулятора + `s20_vidglitch.py` (одно-кадровые дефекты) + лист кадров из видео через ffmpeg.
  Скриншоты (`snap.sh`, `KYTY_SHOT_TIMES`) для проверок не использовать. `screenshot.ps1` снимает экран, не окно: вердикты
  `load_test*.sh` «LEVEL STARTED» по среднему цвету ложные. Загрузился ли уровень — определять по логу:
  `FiberTrace: switch ... -> LevelContextFiber` (при `KYTY_FIBER_TRACE=1`) или сигнатура зависания (файл `*_n.gnfp`
  прочитан целиком ≥6 раз, последний раз в конце лога) — скрипт `C:\kyty\scripts\s7_runstat.py`.
- **Пользователь смотрит на экран: не запускать игру лишний раз.** Серии — только по явному согласию и с остановкой

  продолжают и запускают игру снова. Останавливать так: `ps -ef | grep -E "series|load_test|run_dbg"` → `kill -9 <pid>`
