## 1. Где мы стоим

Sky Garden (`sky62`, полоса 5150–5400 draw, 7 базовых фаз): **8,77–9,24 мкс CPU на draw против
12,12–12,43 базы, CPU 46,3–48,3 мс, FPS 19,6–20,2.** Всё, что ниже, включено по умолчанию:
`dapin=1`, `daclass`, `daprefetch`, `recordthread`, `recpack`, `syncfree`, `protbatch`,
`texfaulthint`, `trackfree`, `texfast`, `texlru`, `clampvma`, `smpmemo`, `dsring`.

**Три вывода, которые не переоткрывать:**
1. Размещение потоков решает больше, чем половина правок: GuestGpu и воркеры `DrawAhead` должны быть
   на одной L3-группе (`dapin`). До этого сцена «имела два режима» — это был чужой кэш.
2. Веер задач M1 был артефактом сериализации плана, а не разными планами (`daclass`).
3. **Весь драйвер `nvoglv64` — 7,3 % времени потока (в базе; 2,8 % после правок).** Перенос записи
   Vulkan-команд не может дать больше этого: M3 шаги 1–2 дали −1,5 % в Sky Garden, −5 % на пустыне.
   Планировать шаги M3 3–7 как «главный рычаг» больше нельзя.

## 2. Работы сессии (приоритет сверху вниз)

1. **Снять две новые статьи, которые сама сессия 56 и добавила (~9 % времени потока, риск низкий):**
   - `ApplyGuard` 4,2 % — замок применения защиты страниц (`pageManager.cpp`) берётся на каждом
     изменении, в том числе когда `protbatch` выключен, и удерживается под `RegionManager::lock`.
     Ревью предупредило об инверсии: держатель `RegionManager::lock` крутится на `apply`, а его ждут
     гостевые потоки спин-локом без yield. Сделать пакетирование безусловным для синхронного пути
     или убрать замок оттуда.
   - `CommandRecorder::EndRecord` 4,8 % — публикация пакета будит потребителя через мьютекс на каждую
     запись (~5 тыс. на кадр). Нужен протокол без мьютекса в общем случае (потребитель крутится
     `recspin`, флаг «спит» проверяется до захвата) либо реже будить.
2. **M2 — предразрешение привязок на воркерах** (`docs/parallel-draw-path.md` §5 M2): единственный
   оставшийся механизм с кратным потенциалом. Привязки в профиле ≈10 % даже после правок, и это
   только видимая часть: `ResolveTexture` 4,1 %, `PrepareBindings` 2,2 %, `RebindBuffers` 1,3 %,
   `ObtainBuffer` 1,4 %, `TryReadBacking` 2,9 %. Считать на воркере только по немутирующим путям,
   промах — обычный путь.
3. **Компактная таблица M1** (шаг 2 разбора сессии 56): индекс из маленьких записей плюс арена
   вместо 32 768 слотов по 504 Б; M1 сейчас 6,4 % времени потока.
4. **`VirtualProtect` 5,8 %** — `protbatch` фаза 2: слить защиты всей
   `SynchronizeBuffersOfDirtyRanges` в один флаш (из ~8 мкс на вызов ~7 фиксированы).
5. **GPU 16 мс** — в бюджет 16,6 влезает еле-еле; разобрать простой между отправками внутри кадра
   (`KYTY_GPU_TIME=1`, `s14_gputime.py`).
6. Остаток §6.1: ~16 полных перезаливок образов (100 МБ) на кадр в Sky Garden.

  одинаковым знаком; смотреть разброс базовых фаз.

  `KYTY_GPU_TIME=1` (каждая метка сливает очередь записи).

  строки дампа с сессии 56; в более старых логах доли завышены вдвое).
- Картинку проверять самому: `KYTY_REC` включён в обоих лаунчерах, дальше
  `python C:/kyty/scripts/s51_vidglitch.py <rec>.mp4 4 6 <dir>`.

  проверять самому.
