## 1. Ридер `f11f_read.py` (`docs/track-f/f11f/`, sha256 — раздел 7)

Лог читается потоком в бинарном режиме. Правило читает **последнюю** строку `DiagBvhNodes: lanes=…` и её строку `slots`
(первая `DiagBvhNodes: slots…` после неё и до следующей `lanes=`; строки других потоков между ними допускаются).

**RC2 (п. 384(г)) — тождества на КАЖДОЙ строке `lanes=`:** (1) `lanes = t0 + … + t7`; (2) `size_viol` = сумме 12 полей
`b_tri`, `b_box`, `b_t7`; (3) `size_viol + node64 ≤ lanes`; (4) сумма слотов + `other` = `lanes`; (5) `max_step < 2³¹`. Нарушение
любого, строка `lanes=` не полной формы или без строки `slots` — тег «не определено» и строка отчёта (`identities FAIL` с номером строки
и именем тождества). Нарушение тождества стоит в порядке слова раньше положительного счёта.

**RC1 (п. 384(в)) — нарушение `size` правила:** предикат `idx > 2·size64 + 1` = **четвёртое (последнее) поле** каждого из `b_tri`,
`b_box`, `b_t7`; нарушение `size` = сумма этих трёх полей; номер корзины ридер не читает. Тип 7 — отдельная строка (п. 381(б)(2)).
Поля 2–3 > 0 — только строка отчёта «в пределах удвоенной единицы» (п. 376(е)); поле 1 — данные.

**Положительный контроль (п. 369(д)):** посещений узлов-коробок > 0 и треугольных типов 0–1 > 0 (`t0 + t1 > 0`) в том же теге.
Коробка — класс RC5 «типы 4–6» (`t4 + t5 + t6 > 0`) — по букве; **вариант исполнителя** — `t4 + t5 > 0` (тип 6 у эмулятора —
«нет детей»): печатается рядом строкой `WORD376 box 4-5 … DIFFERS`, если слово отличается.
