### 0.4. Мера «Dref по цветовому виду» — определение

Для строки (форма таблицы × значение `KYTY_FIX_F19`): `dref` — число инструкций `OpImageSampleDrefImplicitLod` (89) и
`OpImageSampleDrefExplicitLod` (90) в SPIR-V программы. В каждой форме программа — одна инструкция выборки
`image_sample_c_lz` через таблицу, прямых образов нет, поэтому любая `OpImageSampleDref*` — по образу таблицы. Вид члена
`i` — **зеркало пути привязки 0.1** в тесте (функция `F22MemberView`): входы — те же, что у привязки, —
`result.program.info.images[i]` (после `ApplyResourceSpecialization`, это `program.info.images` привязки, D1) и
`result.resources.images[i]` (снимок специализации, `snapshot.images` привязки); `FindGuestDepthFormatPolicy` вызывается
из кода (`imageInfo.h`), зеркалом повторены только ветви D3, D5–D7 (пустой T#) и D8–D9 (непустой). Путь привязки сам не
вызываем без устройства Vulkan: `ResolveTextureWith` — метод `RenderExecutor` с контекстом и кэшем текстур,
`NullTextureDesc` — `static` в `descriptors.cpp`. Зеркало — член отзыва F35b. Виды: `null_D32` (заглушка глубины),
`null_R32F` (цветовая заглушка), `tsharp_depth` (формат политики), `tsharp_color` (цветовой формат T#). **Цветовой вид** —
`null_R32F` или `tsharp_color`. **Мера строки = 1**, если `dref` ≥ 1 и в таблице ≥ 1 член цветового вида, иначе 0;
итог M при значении — сумма меры по строкам M1–M5.

### 0.5. Кандидаты, формы таблицы, строки

Форма программы — как `CompileF19IndirectTable` (`ee9632be:tests/shaderCfgTests.cpp`, F14e): ключ записи материала по

и S# в `user_data` через `RecompileForTest` (`MaterializeResources` по снимку → `CompileProgram`), не готовая специализация
(RC11 F32b).

Цветовые кандидаты (вне `DEPTH_FORMAT_POLICIES`, класс Float, без формата преобразования): `k8UNorm`, `k16Float`,
`k8_8_8_8UNorm`.

Годность (тест падает только по ней): `images` = число членов формы и `members` (= `indirect_resources` корня) = число
членов; корень (`indirect_resources[0]`) — T# формы (пустой / `k32Float`); мультимножество (пустой / формат) кандидатов =
форме; SPIR-V проходит `CheckSpirvBinaryValidates`. Мера тест не валит.

Печать на строку: `[f22] <строка> KYTY_FIX_F19=<v>: images=<n> members=<n> dref=<d> manual=<m> plain_explicit=<p>
root_manual=<0|1> views=<i>:<T#>:<вид>,… measure=<0|1>`, где `manual` — ручные сравнения по `OpPhi` членов
(`SpirvManualDepthComparePhiCount`, F14e), `plain_explicit` — `OpImageSampleExplicitLod`; итог —
`[f22] total KYTY_FIX_F19=<v>: K1=<мера K1> K2=<мера M1> M=<сумма M1–M5>`.

Ожидание лида и исполнителя [I кода, до данных]: при `=0` корень пустой или `k32Float` не ручной (R10) ⇒ `OpImageSampleDref*`
для всех членов, цветовой кандидат — `tsharp_color` ⇒ мера 1 у K1 и M1–M5; при `=1` цветовой кандидат ручной (R3) ⇒ О1
