## 1. Назначение и что меряется

`b2reuse` — **не инструмент измерения, а прототип механизма** (значение 1 меняет, что видит GPU: смещение в кольце и, возможно, число
оборотов кольца; байты — нет, если выполнены условия §11). Измерительные части — значения 2 и 3 (самопроверка и контроль) и счётчики
`b2r_*`. Цель рычага — **L = `rb_stream` + `rb_cbank`** переписи `rbcen=1` (уровни класса = 8 · Σ − n · ĉ, `design133.md` §3.3),
1 133,0 ± 6,0 мкс/кадр [c, верхняя граница снимаемого].

| величина | формула | тип | где читается |
|---|---|---|---|
| снижение L (строка убийства п. 151(д)(2), 152(б)) | среднее по парам (L плеча 0 − L плеча 1), окно 10–88 п. 55(б), блоки по `GateArm:` | мкс/кадр [c] | шаг 6, `s1s134` |
| доля попаданий | `b2r_hit` / `b2r_n` против 0,647 (п. 150(а)) | доля [c] | шаг 6, `s1s134`; ряд |
| доля попаданий в том же draw | `b2r_hit_draw` / `b2r_hit` (`b2r_hit_x` — остальное) | доля [c] | ряд (запасная область механизма, п. 151(г)(1)) |
| причины промаха | `b2r_miss_new`, `_gen`, `_evict`, `_kind` / (`b2r_n` − `b2r_hit`) | доли [c] | ряд |
| доля расхождения байт | `b2r_bad` / `b2r_chk` при 2 (правило: `b2r_bad` = 0) и при 3 (правило: > 0) | доля [c] | шаг 6, `kk134` |
| доля смены пути | `b2r_path` / `b2r_hit` при 2 (правило: `b2r_path` = 0) | доля [c] | шаг 6, `kk134` |
| цена поиска вне L **[В 2]** | Δ(уровень `epoch` + уровень `slow`) плеча 1 − плеча 0 по парам | мкс/кадр [c] | ряд рядом со строкой убийства |

**Ступень вблэнка.** Квантуется кадр, а не среднее (`sky122`, п. 55); снижение L на дыме — не скорость, Δ `dt_us` читает только
`kp134`. Проект не утверждает, что B2 изменит FPS.

### 2.2 Защёлка на поколении интервала

- **Где.** Одна точка: сброс `sub`, `graphicsRun.cpp:992` (`Common::RbCen::Reset(Cause::Sub)` перед `cp.BufferInit()` в
  `GuestGpu::Process`), поток GuestGpu. Перед хуком — `B2Reuse::LatchSub()`: `v = Gates::Value(Knob::B2Reuse)`; отказы §2.3;
  запись слова состояния `g_b2r` (атомик, `release`): значение 0..3 и идентификатор потока-защёлки; затем хук `Reset(Sub)`.
- **Сдвиг поколения на защёлке.** Если новое значение ≥ 1 — `g_rb_gen.fetch_add(1)` **всегда** (даже если старое тоже было ≥ 1 и
  хук `Sub` его и так сдвинул бы): записи, вставленные в любом прежнем периоде, мертвы с первой пробы — аналог RC3 с. 133 (там же
  опасность: при значении 0 поколение не двигается, и запись периода ≥ 1 могла бы дожить с тем же `gen` до следующего включения).
- **Почему это «защёлка на поколении».** Значение меняется только на `sub`; `sub` — сброс интервала при любом значении ≥ 1
  (включая 3); значит интервал (отрезок между двумя сдвигами поколения, видимыми пробе) целиком лежит под одним значением. Проба
  читает значение из `g_b2r` (`relaxed`; пишет его только тот же поток), а не гейт.
- **Плечо расписания.** ABBA `b2reuse=0|1` (`s1s134`, `kp134`): смена плеча на потоке презентации (`GateArm:`) вступает на первом
  `sub` после неё — внутри позиций 0–9 блока, вне окна 10–88 п. 55(б). Слайсов ≈ 12,6 на кадр [c `rb_b2_rst_sub`] ⇒ задержка < 1
  кадра. **Ручка может быть плечом расписания.**
- **Поток.** Таблицу читает и пишет только поток, исполняющий командный процессор (тот, что сделал `LatchSub`; в тегах с. 134
  `m4baton` = 0 ⇒ GuestGpu). Проба на другом потоке — отказ этой пробы (`b2r_refuse` += 1, путь 0, строка `reason=thread` раз) —
  **[В 4]**. Хуки на других потоках (`Submit` потока презентации, `TryWriteBacking`/`BumpMapEpoch` потока приоритетных операций и
  гостевых потоков) трогают только атомик `g_rb_gen` — как в с. 133.
- **Защёлка операции для `b2r_hit_draw`.** Рядом с каждой защёлкой `rbcen` — `renderDraw.cpp:5146` (`DrawIndex`), `:5338`
  (`DrawAuto`), `renderCompute.cpp:1002` (dispatch) — `B2Reuse::OpBegin()`: при значении ≥ 1 `++t_b2r_op` (TLS, 32 бита); при 0 —
  одна загрузка `g_b2r` и выход. Номер операции пишется во вставку; попадание с `entry.op` = `t_b2r_op` — `b2r_hit_draw`, иначе
  `b2r_hit_x`.

## 4. Ключ, запись, таблица, классификация пробы

### 4.1 Ключ и запись

Ключ — `(vaddr, size, alignment, kind)` (п. 151(д)(1)); `alignment` — выравнивание `Map` кольца, которым копия этого вида
выравнивает смещение (П — `A_s`, Д и В — `alignment` `NativeStorageBuffer`). Индекс — хэш `(vaddr, size, alignment)` **без** `kind`:
виды одного диапазона делят ячейку, и промах по виду различим (`b2r_miss_kind`); цена — взаимное вытеснение видов одного диапазона
(меряется тем же счётчиком).

**Горячая запись — 32 Б** (кэш-строка на две записи):

| поле | бит | смысл |
|---|---:|---|
| `vaddr` | 64 | адрес гостя |
| `size` | 32 | байт |
| `align` | 16 | выравнивание `Map` |
| `kind` | 8 | П / Д / В (0 — пустая) |
| — | 8 | запас |
| `gen` | 64 | поколение, прочитанное пробой вставившего вызова (≤ поколения перед чтением байт его копией — §5.1) |
| `off` | 32 | смещение первой копии в кольце (кольцо 64 МиБ `bufferCache.cpp:542` ⇒ 26 бит) |
| `op` | 32 | номер операции вставки (`t_b2r_op`, §2.2) |

**Холодная запись — 16 Б, отдельный массив той же длины, только при 2/3:** `{shadow_off: 64, shadow_lap: 64}` — место байт первой
копии в кольце теней и номер его оборота (§6.1).

### 4.2 Таблица — **[В 1]**

Прямого отображения, **2¹² записей** (горячая 128 КиБ, холодная 64 КиБ). Довод: живы только записи текущего интервала; интервал —
≈ 5,0 проб в среднем [c: 17 542,6 проб / 3 538,2 сброса] ⇒ одновременно живых ключей — единицы–сотни; таблица переписи с. 133 (2¹⁶ ×
32 Б = 2 МиБ) давала промах кэша на каждой пробе (там это цена значения 2, здесь — цена механизма, п. 150(б)(4)). 128 КиБ помещается в
L2 ⇒ проба ≈ 3–6 нс [I] против 5–10 (центр `levers134.md`). Вытеснение меряется (`b2r_miss_evict`); у переписи с 2¹⁶ доля вытеснения
0,00103 [c]. **Если лид отклонит [В 1]** — 2¹⁶ записей как у переписи (цена поиска — верх `levers134.md`).

Таблица не чистится: запись жива ⇔ `entry.gen` = поколение текущей пробы. Сброс интервала — только сдвиг `g_rb_gen` (§5).

### 4.3 Выделение

Горячая и холодная таблицы, кольцо теней 32 МиБ (как у переписи, `ShadowBytes`) и буфер сверки 64 КиБ — ОДИН раз, при первом
`LatchSub` любого значения ≥ 1, до первой пробы; выделенное касается целиком (нули) — идиома RC8 с. 133: цена первого касания
ложится в слайс позиции 0–9 блока, одинаково для обоих плеч ABBA. Отказ — `reason=alloc`, значение 0. Память — частная куча процесса;
гостю не видна.

### 4.4 Проба и классификация (на каждой итерации с условиями точки)

`g_probe = g_rb_gen.load(acquire)` — одно чтение на пробу. `e = table[hash & mask]`.

| исход | условие | действие при 1 | при 2/3 |
|---|---|---|---|
| **попадание** | `(e.vaddr, e.size, e.align, e.kind)` = ключ ∧ `e.gen` = `g_probe` | `b2r_hit` += 1, `b2r_hit_draw` или `b2r_hit_x`; вернуть `e.off` (§3); запись НЕ обновляется (механизм отдаёт ПЕРВУЮ копию) | те же счётчики; путь 0 идёт дальше; сверка §6 |
| промах по виду | `(vaddr, size, align)` совпали, `e.gen` = `g_probe`, `kind` другой | путь 0; при копии — `b2r_miss_kind`, вставка (замещение) | то же + тень |
| промах по сбросу | `(vaddr, size, align)` совпали, `e.gen` ≠ `g_probe` | путь 0; при копии — `b2r_miss_gen`, вставка | то же + тень |
| вытеснение | ключ другой, `e.gen` = `g_probe` (живая чужая запись) | путь 0; при копии — `b2r_miss_evict`, вставка | то же + тень |
| новый | иначе (пусто или мёртвая чужая) | путь 0; при копии — `b2r_miss_new`, вставка | то же + тень |

**Счёт — только на итерациях, которые сделали CPU-копию нужного вида или попали:** `b2r_n` += 1 на каждом попадании и на каждой
вставке (промахи без копии — слоты `epoch`/`slow`, GPU-копии В — не считаются нигде). Тождество строки: **`b2r_n` = `b2r_hit` +
`b2r_miss_new` + `b2r_miss_gen` + `b2r_miss_evict` + `b2r_miss_kind`**. Знаменатель совпадает по смыслу с `rb_b2_n` переписи
(копии, включая повторы); отличия от 0,647 — вид в ключе (`_kind`), размер таблицы (`_evict`), исключение texel (не в `b2r_n` вовсе),
поколение читается до копии B, а не после (§5.1).

## 5. Поколение интервала и сбросы

### 5.1 Поколение

Один глобальный `g_rb_gen` (atomic u64, `frameStats.h:3562`) — общий с переписью `rbcen=2` (они взаимоисключены отказом §2.3).
**Правило попадания:** `e.gen` (чтение пробой вставившего вызова A, ДО чтения байт его копией) = `g_probe` (чтение пробой вызова B).
Так как чтение поколения A ≤ чтение байт A ≤ … ≤ проба B, равенство значит: ни одного сброса на отрезке [перед чтением байт A;
проба B]. Хуки писателей стоят ДО изменения байт (`design133.md` §5.1–5.2: первый оператор `TryWriteBacking`, `BumpMapEpoch` до сдвига
`m_map_epoch` в той же критической секции). Если сброс пришёл между чтением поколения A и чтением байт A, запись A несёт устаревшее
`gen` и мертва с рождения — ошибка в безопасную сторону (меньше попаданий), как у переписи (RC1 с. 133). Сброс после пробы B попадания
не отменяет: при 1 B гостя не читает, и ответ механизма — байты A; при 2 такое событие видно полем `gen_moved=1` строки `MISMATCH`
(§6.4).

### 5.2 Хуки: 37 мест, живы при `b2reuse` ≥ 1 независимо от `rbcen`

Места — ровно список `design133.md` §5.2 ред. 2 в коде `0f539e02` (сверено grep’ом `RbCen::Reset` / `BumpMapEpoch` по HEAD): 22
обработчика `pm4Handlers.cpp` (`:1319`, `:1381`, `:1448`, `:1459`, `:1468`, `:1480`, `:1513`, `:1540`, `:1614`, `:1655`, `:1824`,

`:4067`, `:4096`, `commandScheduler.cpp:782`, `bufferCache.cpp:2558`, `streamBuffer.cpp:304`, `image/image.h:168`,
`kernel/memory.cpp:926`, шесть вызовов `BumpMapEpoch()` в `kernel/memoryAddressSpace.inc` (`:327`, `:339`, `:433`, `:453`, `:502`,
`:522`; функция `:167–168`). **Новых мест проект не ставит** (кроме **[В 6]**); сброс `imgw` остаётся (п. 151(г)(2)).

**Семантика хука `Reset(cause)` (`frameStats.h:3616–3623`) после правки:**


`relaxed`-загрузок, как сейчас. **Хуки не зависят от `rbcen`:** бит `b2reuse` ставит только `LatchSub`, он не читает `rbcen`, кроме

## 6. Значения 2 и 3: самопроверка по состоянию

### 6.1 Тень на каждой вставке

При 2/3 каждая вставка (§4.4) кладёт байты своей копии в кольцо теней (32 МиБ обычной кучи; ≈ 6 200 вставок × ≈ 0,94 КБ ≈ 5,8 МБ/кадр
[I] ⇒ оборот ≈ 5 кадров ≫ интервала). Запись хранит `(shadow_off, shadow_lap)`. **Слот кольца не читается никогда** (память BAR/WC,
с. 62).

### 6.2 Сверка без окна гонки — байты копии, а не повторное чтение гостя

Перепись с. 133 снимала тень ВТОРЫМ `TryReadBacking` после копии — двусторонняя гонка RC5 (запись CPU между копией и тенью прячет
расхождение). Проект её закрывает построением: **при 2/3 копия пути 0 читает гостя не прямо в слот кольца, а в обычную память, и
копирует оттуда в слот** (`memcpy`); байты в кольце те же, что прочитаны, по построению.

- **Вставка:** чтение `TryReadBacking(vaddr → тень)`, затем `memcpy(слот ← тень)`. Тень ≡ байты первой копии в кольце.
- **Попадание:** чтение свежей копии `TryReadBacking(vaddr → буфер сверки)`, `memcpy(слот ← буфер)`, затем `memcmp(буфер, тень)` ⇒
  `b2r_chk` += 1, при ≠ `b2r_bad` += 1. Сравниваются ровно байты, которые путь 0 положил бы в дескриптор сейчас, и байты, которые отдал
  бы механизм, — «ответ механизма против ответа пути 0» без окна.
- **Места** — три CPU-копии: Д `descriptors.cpp:267`, В `:323`, П `bufferCache.cpp:1535` (внутри `ObtainBuffer`, по флагу TLS,
  выставленному точкой П при 2/3; вложенный вызов флага не видит — идиома `ObtainScope`). Отказ `TryReadBacking` — прежняя реакция
  пути 0 (Д и В — `EXIT`, П — уход в медленный путь `:1535–1558`), `memcpy` не делается.
- При 1 копия пути 0 — прежняя (прямо в слот), тени нет.

### 6.3 Сверка выбора пути `b2r_path` — на каждом попадании при 2/3

Путь 0, реально пройденный вызовом после попадания, классифицируется на каждом возврате `NativeStorageBuffer` (`:214`, `:289`, `:357`,
`:400`; RAII-область, открытая пробой):

| вид попадания | путь 0 кончился | `b2r_path` | байты для сверки |
|---|---|---|---|
| П, Д, В | CPU-копией гостя в кольцо (любой из трёх видов — смена вида между кольцевыми копиями байт не меняет) | 0 | байты этой копии (§6.2) |
| П | `ObtainBuffer` вернул не кольцо, выровненной CPU-копии нет (`epoch`, `slow`, `adjustment` кратен базе) | **+1** | отдельный `TryReadBacking(vaddr → буфер сверки)` |
| В | `gpu` = true (GPU-копия `:336–342`) | **+1** | отдельное чтение |
| Д | запросы ложны и дальше не кольцевая CPU-копия | **+1** | отдельное чтение |
| любой | чтение гостя не удалось | **+1** | — (`b2r_bad` += 1: непроверяемое считается расхождением, строка `read=0`) |

## 14. Риски и что проект НЕ доказывает

- **Не доказывает, что B2 корректен** — это условия п. 151(д)(3)(а)–(и), каждое своим прогоном или ревью. Нуль `b2r_bad` без живого
  контроля 3 ничего не доказывает (§9).
- **Правило `b2r_path` = 0 строже корректности байт:** смена пути с равными байтами (§11 (а)) валит отгрузку по п. 151(д)(3)(а).
  Проект это правило не меняет; вопрос **[В 6]** — сделать такую смену невозможной, а не переписать правило.
- **Контроль 3 может быть мёртв по определению «только `sub`»** (§0 п. 8(б), §13) — **[В 5]**.
- **Цена поиска на некопиях — вне L** (§12); снижение L переоценивает чистое действие на ≤ 0,1–0,2 мс [I].
- **Полнота 37 мест** — для путей дерева `0f539e02`; новые пути записи в гостя вне него не доказаны (п. 143(д) с. 133, п. 151(д)(3)(и)).
- **Живость слота (§11 (б))** доказана чтением кода [I], не прогоном; свидетель — валидация `s6s134` и видео `kv134`.
- **Потребители `(handle, offset)`** — перечень §11 (б) не исчерпывающий; он — вход ревью, не вывод.
