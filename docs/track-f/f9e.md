## Что нужно для кода (предложение лиду; решение — п. лида)

Вариант **M2c** (вне F9b §7) под `KYTY_FIX_B42` (умолчание 0), счётная строка `FixB42:` п. 349(в′)(2):

- **Условие `hit`:** привязка цвет-цели с `cmask_fast_clear_enable`, `cmask.addr != 0`, без DCC, `samples == 1`, 1 уровень, не volume, экстент
  **не** кратен 1024 (то, что сейчас отсекает `colorRenderTarget.cpp:441–442`), и по `cmask.addr` лежит отложенная заливка
  (`PendingDcc`, `fill_value == 0`) с `fill_size ≥ width·height·layers/128`. Для T6: 960·540/128 = 4 050 ≤ 0x2000, 480·270/128 = 1 012 ≤ 0x1000 [c по
  числам (1)].
- **При `=1` (`applied`):** поставить `metadata.kind = Cmask` с этим диапазоном — дальше существующий путь `FindRenderTarget` →
  `PrepareCmaskClear` → `ClearImage` цветом `CB_COLOR_CLEAR_WORD0/1`.
- **Место:** `colorRenderTarget.cpp:441–450` (файл **вне** списка п. 349(в′)(2)) или ветка CMASK `MaterializeBoundTargetDccClears`
  (`descriptors.cpp:3637–3657`, файл в списке, но вариант вне F9b §7). Транслятор шейдеров не трогается; путь `=0` — тот же.
- **Риски [U]:** (а) цвет очистки T6 (`CB_COLOR_CLEAR_WORD0/1`) в логе F9d не печатается — норма F9b (T6 = 0) с нулевым цветом согласуется,
  но это [I]; ненулевой цвет изменит и окна 480×270 (критерий (г)(3)); (б) раскладка CMASK для некратного 1024 экстента не проверена
  (комментарий `colorRenderTarget.cpp:443–445`) — правка предполагает, что заливка целиком значением 0 означает «весь образ очищен», что
  верно для любой раскладки, если заливка покрывает весь CMASK цели; (в) связь адреса `0x571728000` с CMASK именно T6 — по порядку строк
  (37 из 38) [I], адрес `CB_COLOR_CMASK` T6 в лог не выводится; строка `FixB42:` (`hit` с адресом) дала бы [c] в прогоне F9g.
