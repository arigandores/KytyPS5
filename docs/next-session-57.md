## 2. Работы сессии

**Главное: трек A из §3 плана целиком — он самодостаточен и не требует параллелизма (~11 мс, 47 → ~36 мс).**
Порядок по отношению выгода/риск (якоря — в §3 плана):

1. **A5 — счётчики** (`frameStats.cpp:150-186`, `pipelineCache.cpp:397-400`): инлайновый `Add` без
   magic-static и TLS-guard, агрегировать `ProgReads` (сейчас +1 на каждое из 440 тыс. слов).
   Делать **первым**: 1,8 мс сидят в каждой фазе всех будущих замеров.
2. **A2 + A3** (`pageManager.cpp:616-618`, `memoryTracker.h:186-197`, `renderContext.cpp:64-66`):
   не брать `ApplyGuard` при пустом pending, не звать `FlushProtection` безусловно, гранулярность
   fault'а 64 КиБ вместо 4 КиБ. Низкий риск, −1,5…3 мс.
3. **A4 — `EndRecord`** (`commandRecorder.cpp:150-272`): убрать диагностическое чтение `m_tail`,
   развести `m_consumer_waiting` и мьютекс по кэш-линиям, публиковать раз на draw. −1,5…2 мс.
4. **A1 — «липкие» страницы** (`bufferCache.cpp:619-643`, `memoryTracker.h:164-209`): страница,
   дающая write-fault каждый кадр, не перевзводится в RO. Самая жирная (−3…4 мс) и самая рискованная
   в треке: ошибка даёт лишнюю заливку, а не потерю записи, но протокол грязи надо проверить
   самопроверкой и валидацией.
5. **A6, A7** (`textureCache.cpp:475-493`, `bufferCache.cpp:132-137`): не писать LRU-поля, когда
   значение не меняется. Дёшево, и снимает будущий false sharing.

**Если останется время — B1, B2, B4, B5, B6, B7 из §4 плана** (~6 мс, механические): не обнулять
25 КБ на draw, `ImageDesc` не по значению, пул для `ResourceSnapshot`, inline-буфер user data,
дайджест `static_state`, убрать `lock xadd` в цикле атрибутов.

**Измерения (§6 плана), их стоит поставить в этой же сессии, они дешёвые:**
- **E1** — доля **draw'ов**, где ни одна привязка не потребовала мутации, плюс гистограмма длин
  серий. **Без этого числа нельзя начинать M2:** по привязкам известно 91,8 % чистых, по draw'ам
  нет, и если промахи независимы, чистых draw'ов будет только ~40 %.
- **E8** — одна фаза совсем без `KYTY_FRAME_TRACE` (сравнение по FPS из `AvTrace: flip`): проверка
  налога инструментации, заодно валидация правки A5.
- **E2** — длины серий между жёсткими границами (проход, dispatch, барьер, загрузка).

**Не начинать в этой сессии:** трек C (приватизация скрэтча, локи на объект, M2). Он идёт после
трека A, и первым его шагом должен быть эксперимент E4 (`shadowresolve`) — репетиция конкуренции без
реализации.

## 3. Методика (переработана, §7 плана — соблюдать)

- **Фазы по 600 present, а не 300.** У коротких фаз дрейф внутри фазы до 5 %, у длинных его нет.
  В прогон влезает ~10 фаз — конфигурации отбирать заранее.
- **Парные фазы A B A B**, решение по разности с средним двух соседних базовых.
- **Эмпирический порог ±1,4 %.** 5 % виден одной парой, 2 % требует трёх повторов, меньше 1 % в этой
  сцене не мерится. Не заявлять эффекты ниже порога.
- Нормировка — `cpu_gpu_us/draws` в узкой полосе по числу draw (5150–5400). Регрессия по draw хуже.
- Печатать в сводке `cpu_proc_us/dt` (занятые ядра) и браковать фазы, ушедшие на 10 % от медианы.
- Семплер — второй независимый отсчёт: для правки конкретного механизма сдвиг **доли категории**
  надёжнее, чем сдвиг общего CPU/draw. Включать в каждой ключевой конфигурации.
- **Мерить потолок правки счётчиком до её включения.** Три ожидания подряд (M1, M3, веер задач)
  оказались неверными именно потому, что этого не делали.
- Не брать размер оптимизации из профиля с `KYTY_FRAME_TRACE=1`; не мерить M3 с `KYTY_GPU_TIME=1`.
