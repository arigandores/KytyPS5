## 1. Код [c]

### 1.1 Откуда берётся текст строки

Строку печатает `QueueSdlAudio` при отрицательном ответе `SDL_QueueAudio` (`audio.cpp:640`). Текст «Invalid audio device ID» в SDL2 ставит одна функция — `get_audio_device`, когда ячейка `open_devices[id − 1]` пуста или номер вне массива из 16 ячеек (`SDL_audio.c:231`, `:41`). Ячейку обнуляют два места: закрытие устройства `close_audio_device` (`SDL_audio.c:1224`; его зовут `SDL_CloseAudioDevice` — `:1682` — и `SDL_AudioQuit` — `:1698`) и `SDL_AudioInit`, который сначала вызывает `SDL_AudioQuit`, если драйвер уже запущен, а затем обнуляет весь массив (`SDL_audio.c:966`, `:970`).

Отключение устройства хоста ячейку **не** обнуляет: `SDL_OpenedAudioDeviceDisconnected` только снимает флаг `enabled` и шлёт событие (`SDL_audio.c:467`, `:482`, `:486`) — см. §1.5. ⇒ строка Ф8 означает ровно одно: **номер, который хранит порт, закрыт внутри процесса эмулятора**.

### 1.2 Кто двигает счётчик ссылок звуковой подсистемы

SDL2 считает ссылки подсистемы в `Uint8 SDL_SubsystemRefCount[32]` (`SDL.c:119`). `SDL_InitSubSystem(SDL_INIT_AUDIO)`: если счётчик равен 0 — `SDL_AudioInit(NULL)` (`SDL.c:292`, `:298`), затем `++` (`SDL.c:302`, `:127`). Проверка «счётчик < 255» — `SDL_assert` (`SDL.c:125`); сборка эмулятора — `CMAKE_BUILD_TYPE=Release`, `SDL_ASSERTIONS=auto` (`C:/kyty/build/CMakeCache.txt`), при `auto` уровень берётся из заголовка (`3rdparty/SDL2/CMakeLists.txt:565`): без `_DEBUG` — уровень 1 (`SDL_assert.h:40`), на котором `SDL_assert` выключен (`SDL_assert.h:173`). ⇒ **256-й вызов без парного выхода переворачивает счётчик в 0** [c кода SDL; уровень проверок бинарей отгрузки — [I] по тому же `CMakeCache.txt`, их сборочные каталоги не читались].

`SDL_QuitSubSystem(SDL_INIT_AUDIO)`: при счётчике 1 — `SDL_AudioQuit`, затем `--`; при счётчике 0 — ничего (`SDL.c:444`, `:152`, `:159`).

### 1.3 Путь отказа: утечка С2 переворачивает счётчик, повторная инициализация закрывает все устройства

Пусть до первой подачи вибрации открыто `A` выходных портов с устройством (счётчик = `A`). Устройства пада (USB DualSense как звуковая карта) нет ⇒ каждая попытка С2 прибавляет 1 и ничего не открывает. После попытки `256 − A` счётчик равен 0. Следующая попытка (`257 − A`-я) входит в `SDL_InitSubSystem` при счётчике 0 ⇒ `SDL_AudioInit` ⇒ `SDL_AudioQuit` ⇒ `close_audio_device` для каждой из 16 ячеек ⇒ **все выходные устройства портов закрыты, номера в `PortOut::audio_device` (`audio.cpp:212`) остались прежними**. С этого момента каждый `SDL_QueueAudio` порта возвращает −1 с текстом Ф8.

Время события по коду: первая попытка — на первой подаче вибрации (`m_retry_us == 0`), каждая следующая — не раньше чем через 3 с после предыдущей ⇒ попытка `257 − A` — не раньше `T₁ + 3·(256 − A)` с, где `T₁` — первая подача в порт вибрации. Запаздывание сверх этого — до одного периода подачи на попытку (попытка идёт на первой подаче после истечения 3 с). При `A = 3`: **не раньше 759 с после первой подачи вибрации**.

Условия пути: (i) игра открыла порт вибрации на 48 кГц и подаёт в него PCM (`controller.cpp:183`); (ii) вибрация не выключена `KYTY_HAPTICS=0` (`controller.cpp:128`); (iii) звукового устройства пада нет (`controller.cpp:160` не открыл ни одного); (iv) процесс живёт дольше `T₁ + 3·(256 − A)` с. Ни одно из условий не зависит от устройства звука хоста.

Тот же переворот дают 256 открытий выходных портов (С1 без пары) — игра, которая открывает и закрывает порты, дойдёт до него без вибрации; в логах ASTRO BOT открытий на процесс — 3 (§2), этот вариант здесь не срабатывает.

Отсюда сотни тысяч строк на лог (§2.2: в логе со счётчиком подач — рост частоты в 22–46 раз).

### 1.8 Следствия для правки: старые номера после повторной инициализации

`SDL_AudioInit` обнуляет таблицу, новые устройства получают номера с 2 (`SDL_audio.c:970`, `:1528`) — те же, что хранят порты. Порт со старым номером после чужого открытия пишет в чужое устройство без ошибки; список паузы `g_frozen_devices` (`audio.cpp:258`, `:265`) держит старые номера. Правка, которая переоткрывает устройства по одному, обязана сначала снять номера у всех портов (§5).

## 4. Проект стенда `KYTY_TEST_AUDIOLOSS=<с>[:<режим>]` (только стенд; умолчание — выключен)

Стенд — не измерение: он меняет состояние звука хоста внутри процесса эмулятора. Память гостя и видимое гостю состояние он не пишет; устройство звука хоста (настройки Windows, оборудование) не трогает.

1. **Что воспроизводится.** Наблюдаемая форма Ф8 — «порт хранит ненулевой номер, SDL считает его закрытым» — в заданный момент, без ожидания 759 с и без оборудования. Числом выражается не стенд, а счётчики §5.3.
2. **Сайт.** `Audio::AudioOutOutputs` (`audio.cpp:778`), первая строка тела, до расчёта времени ожидания. Поток — поток звука гостя, тот же, на котором идут попытка С2 и `QueueSdlAudio`; замков в этой точке нет (`m_mutex` берётся только внутри `AudioOutValid`). Естественное событие §1.3 происходит на этом же потоке между подачами портов — стенд повторяет поток и порядок.
3. **Чтение.** Раз на процесс (`static const` структура, один `getenv`; образец — `KYTY_TEST_MINIMIZE`, `window.cpp:1047`); на каждом вызове `AudioOutOutputs` — одна проверка «включён и ещё не сработал». Срабатывание одно на процесс. Плечом расписания не служит. `<с>` — секунды процессного времени (`KernelGetProcessTime`) от взвода; взвод — первый вызов `AudioOutOutputs`, в пакете которого есть порт с устройством.
4. **Режимы.**

   | Режим | Действие | Что воспроизводит | Достижимо без оборудования |
   |---|---|---|---|
   | `wrap` (по умолчанию) | `SDL_InitSubSystem(SDL_INIT_AUDIO)` в цикле, пока `SDL_WasInit(SDL_INIT_AUDIO) ≠ 0` (не более 256 раз), затем ещё один вызов | **сам механизм §1.3**: переворот счётчика и повторную инициализацию, которая закрывает все устройства и обнуляет таблицу номеров | да [c: `SDL.c:292`–`:302`, `:492`; `SDL_audio.c:966`–`:970`] |

## 5. Проект правки `KYTY_FIX_F8` (умолчание 0; чтение раз на процесс)

### 5.1 Член А — причина: один владелец звуковой подсистемы

Функция `SdlAudioAcquire()`: `SDL_InitSubSystem(SDL_INIT_AUDIO)` не более одного успешного раза на процесс (флаг под мьютексом; неуспех не запоминается). При `=1` места С1, С2, С3 (§1.2) зовут её вместо прямого вызова, оба `SDL_QuitSubSystem(SDL_INIT_AUDIO)` входного порта (`audio.cpp:846`, `:854`+1) не вызываются. При `=0` — прежние вызовы. Итог: счётчик SDL равен 1 всю жизнь процесса ⇒ путь §1.3 и пути П-А, П-Б §1.4 закрыты.

### 5.2 Член Б — реакция: переоткрытие с ограничением частоты

- **Обнаружение** — в `QueueSdlAudio` перед очередью: `SDL_GetAudioDeviceStatus(номер) == SDL_AUDIO_STOPPED` (ответ и для закрытого номера, и для отключённого устройства: `SDL_audio.c:1622`) либо отрицательный ответ `SDL_QueueAudio`. Отдельный обработчик события удаления не нужен: статус читается на каждой подаче, задержка обнаружения — не больше периода подачи; пути между главным потоком и потоком звука не появляется. Цена — один вызов SDL на подачу (индекс массива и чтение атомарного флага).
- **Снятие номеров — всех сразу, до первого переоткрытия** (следствие §1.8): под замком таблицы портов для каждого выходного порта, чей номер отвечает `STOPPED`: убрать номер из `g_frozen_devices`; пробой `SDL_QueueAudio(номер, nullptr, 0)` различить «номер закрыт» (ответ −1: закрывать нечего) и «устройство отключено» (ответ 0: `SDL_ClearQueuedAudio` + `SDL_CloseAudioDevice`) [c: `SDL_audio.c:592`–`:605` — при длине 0 ошибка только у закрытого номера]; `audio_device = 0`, порт помечен потерянным. Устройство вибрации и входные порты после повторной инициализации обнуляют свой номер тем же правилом, **не** закрывая его (иначе путь П-Б).
- **Переоткрытие** — на следующей подаче потерянного порта, первая попытка сразу, следующие не чаще раза в `REOPEN_MIN_US` (предложение — 1 000 000 мкс; константу решает лид): `OpenSdlDevice(port)` печатает существующую строку `AudioOut: opened SDL device …` (`audio.cpp:461`). Если устройство выбиралось по имени и по имени не открылось (выбор кэшируется раз на процесс, `audio.cpp:378`) — повтор с устройством по умолчанию.
- **Темп, пока порт потерян:** `audio_device == 0` ⇒ включаются уже существующие запасные пути — сон по времени блока (`audio.cpp:806`) и ограничение глубины очереди (`libAudio2.cpp:525`, `:532`) [c]: поток звука гостя идёт с темпом, даже если переоткрыть не удаётся.
- **Строки:** `AudioOut: device lost port=<i> dev=<номер> cause=<invalid|stopped>` — раз на потерю порта; `AudioOut: reopened port=<i> dev=<номер> tries=<штук> lost_us=<мкс>`; строка `AudioOut: SDL_QueueAudio failed: …` — не больше одной на потерю порта.

Сайты правки — `src/libs/audio.cpp`, `src/libs/controller.cpp`: вне набора подписи трансляции шейдеров, каталог варианта и кэши не меняются.

### 5.3 Счётчики `AudioStat` (под `KYTY_AV_TRACE=1` или при включённом стенде; в `FrameTrace-x` не входят)

Строка на выходной порт с устройством (и на порт, помеченный потерянным), печатается на потоке подачи не чаще раза в секунду на порт и сразу после `fire`, `device lost`, `reopened`:

`AudioStat: t_us=… port=… type=… dev=… status=… queued=… pushes=… q_fail=… lost=… reopen_try=… reopen_ok=… lost_us=… init_calls=…`

| Поле | Тип | Что |
|---|---|---|
| `t_us` | мкс, `uint64`, процессное время | момент строки |
| `port`, `type` | номер, тип порта гостя | — |
| `dev` | номер SDL, `uint32`; 0 — устройства нет | — |
| `status` | перечисление SDL: 0 `STOPPED`, 1 `PLAYING`, 2 `PAUSED` | `SDL_GetAudioDeviceStatus(dev)` |
| `queued` | байты формата устройства, `uint32` | `SDL_GetQueuedAudioSize(dev)` |
| `pushes` | штуки, `uint64`, сумма с начала процесса | подачи порта, дошедшие до очереди (успешные и нет) |
| `q_fail` | штуки | отрицательные ответы `SDL_QueueAudio` |
| `lost` | штуки | потери порта (снятия номера) |
| `reopen_try`, `reopen_ok` | штуки | попытки и успехи переоткрытия |
| `lost_us` | мкс, сумма | время порта без устройства |
| `init_calls` | штуки, одно число на процесс | вызовы `SDL_InitSubSystem(SDL_INIT_AUDIO)` эмулятором (С1 + С2 + С3 + стенд) — прямой свидетель утечки |

**Обязаны быть 0 при `=1` без стенда:** `q_fail`, `lost`, `reopen_try`; `init_calls ≤ 1`. **Тождества для ридера:** `reopen_ok ≤ reopen_try`; `lost − reopen_ok ∈ {0, 1}`, причём 1 ⇔ `dev == 0` в этой строке; при `=1` `q_fail ≤ lost`; `pushes`, `q_fail`, `lost`, `reopen_*`, `lost_us`, `init_calls` не убывают от строки к строке порта. Подмножество, не разбиение: `q_fail ≤ pushes`.

**Цена.** Выключено — одна проверка статического флага на подачу.
