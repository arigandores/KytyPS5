### 1.2 Набор цветовых вложений draw

`PrepareDrawRenderState` (`renderDraw.cpp:2884`) обходит 8 слотов. Слот идёт в разрешение, если он нулевой **или** `маска слота ≠ 0 && base.addr ≠ 0`. `ResolveRenderColorTarget` возвращает пустое описание (без образа), если `base.addr == 0 || маска == 0` (`colorRenderTarget.cpp:113`, `:184`); слот попадает в набор только с образом (`renderDraw.cpp:2892`). Итог:

> слот N привязан ⇔ `маска_N ≠ 0` **и** `base_N ≠ 0`.

Формат в это условие не входит. Для слота, прошедшего условие, дальше — только `EXIT` (остановка процесса) на всём, что эмулятор не умеет: число сэмплов (`colorRenderTarget.cpp:201`), диапазон mip, размерность, режим плиток, формат (`:300`–`:303`, `textureCommon.cpp:137`), раскладка, нулевой или недопустимый размер (`:392`). `FindImage` возвращает пустой образ только при пустом диапазоне данных (`textureCache.cpp:2105`, `:2107`), а пустой диапазон отсечён `EXIT` выше ⇒ после полного разрешения образ есть всегда (`colorRenderTarget.cpp:493`).

### 1.3 Проход хоста, пайплайн и маска записи

- Вложения хоста индексируются **слотом гостя**, не плотно: `num_color_attachments = max(slot) + 1` (`renderDraw.cpp:2068`), вид — в `color_attachments[target_slot]` (`:2162`), непривязанные слоты ниже максимума остаются дырами (`VK_NULL_HANDLE`); `colorAttachmentCount` — `context.cpp:442`. Пайплайн — так же: `color_count = max(slot) + 1`, `color_formats[slot]` (`pipelineCache.cpp:5330`, `:5333`), `colorAttachmentCount` — `shaders.cpp:696`. ⇒ `Location N` шейдера = слот гостя N = вложение хоста N; сдвига индексов нет.
- Маска записи пайплайна: `color_mask[slot] = export_mapping.ApplyMask(маска_слота)` (`pipelineCache.cpp:5330`+1, `gpu_defs.h:122`) → `colorWriteMask` (`shaders.cpp:550`). `ApplyMask` переставляет 4 бита маски по перестановке каналов формата; обнулить ненулевую маску перестановка не может.
- Динамическое `setColorWriteEnableEXT`: `enable[slot] = маска_слота ≠ 0` (`renderDraw.cpp:535`) — для привязанного слота всегда истина.
- Повторный поиск образа в `AcquireRenderTargets` (`renderDraw.cpp:2092`) идёт по тому же описанию; пустой образ — `EXIT_IF` (`:2065`, `:2125`).

### 1.4 Экспорты PS `out_mrt_N`

Выход `out_mrt_N` с `Location N` создаётся на каждый экспорт программы в цель MRT с ненулевым `en` (`ShaderInfoCollection.cpp:336`, `:378`). Набор выходов зависит только от байт-кода шейдера. `CB_SHADER_MASK`, `CB_TARGET_MASK` и `SPI_SHADER_COL_FORMAT` (`target_output_mode`) его не меняют: последний выбирает лишь перестановку каналов (`shader.cpp:833`, `spirvEmitterFlow.cpp:532`; таблица перестановок собирается по привязанным слотам, `renderDraw.cpp:2948`). | (а) «каждый слот гостя с допустимым форматом и ненулевой маской привязывается, путей пропуска нет или в логах W они не срабатывают» | при `маска ≠ 0 && base ≠ 0` — да, без исключений, иначе `EXIT` (0 в логах) [c]. При `маска ≠ 0 && base == 0` — нет: слот молча не привязывается (П1), формат не читается |
| (б) «путь пропуска есть и срабатывает в логе W» | срабатывание П1 не показано ни в одном логе; П2 взведён в 70 из 70, но это повтор той же привязки, а не пропуск слота [c кода] |
| (в) «путь есть, срабатывание по логам не различить» | **П1 — да** [c кода и лога]; у П2 не различить равенство повтора полному разрешению |

**Кандидат — (в) «не определено», следующий шаг — диагностика §4.** Решает лид; развилка названа в начале отчёта: при чтении «база 0 = пустой слот» П1 выбывает и остаётся (а) с оговоркой П2.

Оценка автора [I], не довод: P(П1 срабатывает хоть на одном draw) — мала. Слот, который библиотека гостя не настраивала, несёт нулевой `CB_COLORn_INFO` (формат `kInvalid` = 0) вместе с нулевой базой; чтобы П1 сработал как пропуск, гость должен записать допустимый формат и ненулевую маску при нулевой базе. Проверить это офлайн нечем.

## 4. Проект диагностики `KYTY_DIAG_F6` (умолчание 0; только измерение)

1. **Что меряется.** На каждом draw, дошедшем до сайта: класс каждого из 8 слотов гостя по тройке (`маска_N ≠ 0`, `base_N ≠ 0`, `формат_N ≠ kInvalid`); класс слота, в который пишет каждый экспорт MRT программы PS; расхождение набора хоста с критерием гостя. Вывод выражается тремя числами: `s_addr0_fmt` (слото-draw с маской, допустимым форматом и базой 0 — срабатывания П1), `w_addr0_fmt` (из них те, куда PS пишет, — П1 со строкой Ф6), `bound_missing + bound_extra` (расхождение набора — П2 и само условие §1.2).
2. **Сайты.** `renderDraw.cpp`, путь индексного draw — сразу после `RefreshShaders` (`renderDraw.cpp:5142`; набор целей готов после `:5126`, программа PS — после `:5142`); путь `DrawAuto` — то же место после `:5314` (строку `RefreshShaders` этого пути называет Emu Engineer). Одна функция `DiagF6Draw(buffer, state)`, только чтение: `GetRenderTargetMask()`, `GetRenderTarget(n).base.addr`, `.info.format`, `state.color_info[0..color_count).target_slot`, `state.ps_active`, выходы вида `Mrt` программы PS (поле называет Emu Engineer; источник — `ShaderInfoCollection.cpp:378`). Поток — поток исполнения draw (GuestGpu), под замком рендера, там же, где места A и B `rtskip`. Сайт стоит **после** развилки `PrepareDrawRenderState` / `RtsPlaceA`, поэтому видит и повтор.
3. **Чтение ручки.** Раз на процесс (`static const bool`, `Common::EnvValueOn`: нет или пусто — ВЫКЛ). Плечом расписания не служит. Строка `DiagF6: mode=1` один раз при инициализации.
4. **Счётчики** — все сырые штуки, `uint64_t`, сумма с начала процесса; печать `DiagF6: frame=<n> <имя>=<значение> …` при росте любого, не чаще раза в 2 с (форма `DiagBvhNodes`, `DiagF5`); в `FrameTrace-x` не входят.

   | Имя | Что считает |
   |---|---|
   | `draws` | draw, дошедшие до сайта |
   | `ps_draws` | из них с активным PS и программой |
   | `s_bound` | слото-draw: маска ≠ 0, база ≠ 0 |
   | `s_addr0_fmt` | маска ≠ 0, база 0, формат ≠ `kInvalid` — **ветвь П1** |
   | `s_addr0_nofmt` | маска ≠ 0, база 0, формат `kInvalid` |
   | `s_mask0_addr` | маска 0, база ≠ 0 |
   | `s_empty` | маска 0, база 0 |
   | `h_bound` | Σ `color_count` (вложений хоста) |
   | `bound_missing` | слот с маской и базой, которого нет в `color_info` |
   | `bound_extra` | слот в `color_info` при нулевой маске или базе |
   | `w_total` | экспортов MRT программы PS (по draw с `ps_draws`) |
   | `w_bound`, `w_mask0`, `w_addr0_fmt`, `w_addr0_nofmt` | те же экспорты по классу слота; `w_addr0_fmt` — **ветвь П1 со строкой Ф6** |
   | `w_ge8` | экспорт с индексом ≥ 8 |

   **Обязаны быть 0:** `bound_missing`, `bound_extra`, `w_ge8`. **Тождества скорера:** `s_bound + s_addr0_fmt + s_addr0_nofmt + s_mask0_addr + s_empty == 8 · draws`; `h_bound == s_bound − bound_missing + bound_extra`; `w_total == w_bound + w_mask0 + w_addr0_fmt + w_addr0_nofmt + w_ge8`. Подмножество, не разбиение: `ps_draws ≤ draws`.
5. **Контроли.** Положительный: `DiagF6: mode=1` до первой `GuestOut`; `draws > 0`, `s_bound > 0`; `w_mask0 + w_addr0_fmt + w_addr0_nofmt > 0` — счётчик видит ту же совокупность, что строки Ф6 (в логах W её 12 217 … 2 807 552 строк на прогон, на всех 50 сценах, так что нулевой положительный контроль — отказ инструмента, а не свойство сцены). Нулевой: без переменной строк `DiagF6` нет; счётчик не ветвит исполнение; сайты вне `src/graphics/shader/**` — подпись трансляции и каталог варианта не меняются. Справка (не гейт): на теге формы W без фильтра число строк Ф6 в логе ≤ `w_total − w_bound`; равенства нет — вариант двухисточникового смешивания снимает `Location 1`, а draw, отброшенный после сайта, строки не даёт.

**Цена.** На draw — 8 чтений тройки регистров, до 8 элементов `color_info`, до 8 выходов программы; без QPC, без замков, без записи в состояние гостя и хоста.

**Правило чтения — предложение лиду (константы решает он).** (i) `s_addr0_fmt == 0` и инварианты 0 на всех тегах с живым положительным контролем ⇒ член (а) правила п. 421(е) на этих сценах. (ii) `s_addr0_fmt > 0` ⇒ П1 срабатывает: при `w_addr0_fmt > 0` — со строкой Ф6; критерий до кода требует ответа, что делает железо со слотом без базы [U]. (iii) `bound_missing + bound_extra > 0` ⇒ расхождение набора хоста с регистрами гостя — отдельная строка реестра (повтор `rtskip`), не Ф6. (iv) мёртвый положительный контроль ⇒ «не определено», попытка не засчитывается.

**Теги — предложение** (покрывают семейства наборов §2.3): Sky Garden; `rocket_hourglass` (максимум строк Ф6 на лог); `rocket_space_station` (`DrawIndexedIndirect: 0n,1n,2n,4`); `spring_punch_monster_cave` (`DrawIndexedIndirect: 0n,1n,3,4`); `booster_construction` (`DrawIndexed: 2,3,4`); нулевой контроль — Sky Garden без переменной.

**Редкое событие.** Чтение (i) — «плохого 0». Его сила — в живом положительном контроле той же совокупности draw, а не в длине удержания; ноль на пяти сценах — «не наблюдалось на этих сценах», не свойство игры.

**Дешёвая замена без кода — не рекомендую:** тег с `--graphics-debug-dump true` даёт ≤ 128 строк `no color output` и ≤ 32 блоков `MrtState` — только первые draw процесса; дамп сам снимает быстрый путь разрешения и повтор `rtskip` (условие `RtsXaCfg`), то есть меряет другой путь кода.
