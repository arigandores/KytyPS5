**RC2 (`meta_write_refused` — неверный сайт; член 1).** `ClearMeta` возвращает `false` и для адреса, которого нет в таблице (`R/cache/textureCache.cpp:3184`–`:3188`), а `TryConsumeComputeMetaClear` зовёт её для каждого записываемого буфера (`R/renderCompute.cpp:103`, `:114`). Порядок диспатча — сначала `TryConsumeComputeMetaClear` (`:551`), затем `TryConsumeComputeImageClear` с `TrackDccFill` (`:560` → `:245`): каждый повторный fill метаданных, уже известных как `Dcc`/`CMask`/`PendingDcc`, сперва получает отказ `ClearMeta`, а затем отслеживается как заполнение. **Сценарий отказа:** Sky Garden заполняет метаданные DCC повторно [I: повтор fill по одному адресу журналом не проверялся — строка `metadata fill` печатается 32 раза на процесс] ⇒ `meta_write_refused` растёт каждый кадр без единой потерянной очистки ⇒ п. 421(г)(ii) «кандидат кадра-свидетеля» на событие, которого нет. **Изменить:** событие ветки = отказ на адресе, чей тип `Dcc`/`CMask`/`PendingDcc`, **и** запись не стала отслеженным заполнением: для диспатча — отказ без последующего `TrackDccFill` на тот же адрес в том же диспатче (`meta_cs_untracked`); для DMA-fill (`R/cache/bufferCache.cpp:2262`) — отказ на известном адресе со значением, классифицированным как в RC3 (`meta_dma_untracked`; DMA-fill `TrackDccFill` не зовёт вовсе, так что DMA-очистка метаданных — ветка, где очистка не исполняется [c]). Ограничение — в «не доказывает»: `ClearMeta` сравнивает адрес точно; запись, накрывающая метаданные со смещённого начала, не видна ни счётчику, ни эмулятору.

**RC3 (`dcc_fill_unknown` — считает не-метаданные и законную инициализацию; член 1).** `TrackDccFill` заводит запись `PendingDcc` для любого адреса fill-диспатча, не ставшего очисткой образа (`R/cache/textureCache.cpp:3227`, `R/cache/textureCache.h:188`); код «не из пяти» получает и fill обычного буфера (например, `0xffffffff` или `1.0f`), и fill метаданных DCC кодом `0xff` («не сжато» [I: открытые заголовки AMD, первоисточника на диске нет]) — гость так инициализирует DCC, и прежнее содержимое там **верно**; для записи типа `CMask` ненулевой fill — тоже не очистка. **Сценарий отказа:** любой fill ненулевым значением буфера индексов или счётчиков ⇒ `dcc_fill_unknown` > 0 ⇒ (ii). **Изменить:** считать в момент, когда адрес подтверждён как DCC: при `TrackDccFill` на записи с типом `Dcc` и при переходе `PendingDcc → Dcc` (`R/cache/textureCache.cpp:1890`–`:1897`, `AdoptPendingDccForTexture`) по сохранённому `fill_value`; разбиение `dcc_fill_meta = clear + uncompressed (0xff) + unknown`; `dcc_fill_all` (все вызовы `TrackDccFill`) — справка с инвариантом `line_mismatch_fill`: min(`dcc_fill_all`, 32) = числу строк `GraphicsRenderDispatchDirect: metadata fill` (`R/renderCompute.cpp:248`; предел 32 на процесс) — это единственная строка журнала на пути сайта B, она ловит мёртвый `dcc_fill_all`.

**RC4 (`dcc_skip_*` — считает привязки текстур, которые очистит другой путь; член 1).** `PrepareDccClear` зовётся и из привязки текстуры (`R/cache/textureCache.cpp:2297`), и из получения цели (`:2420`). Для привязки текстуры после неё идёт `MaterializeDeferredDccClear` (`R/pipeline/descriptors.cpp:6498`), которая очищает **все** уровни (`:3596`) без проверки длины заполнения и раскодирует код `0x20` по регистрам слота (`:3541`). **Сценарий отказа:** текстура с mip-уровнями и отложенной очисткой DCC читается шейдером ⇒ `dcc_skip_levels` +1 в `PrepareDccClear`, затем очистка исполнена `MaterializeDeferredDccClear` ⇒ B > 0 без ветки ⇒ (ii). **Изменить:** `dcc_rt_skip_*` — только на пути `FindRenderTarget` (`desc.type == RenderTarget`) и только при `clear_mask ∩ биты слоёв вида ≠ 0`; для пути текстуры событие ветки — отказ `MaterializeDeferredDccClear` при ненулевой маске (`decoded == false`, `R/pipeline/descriptors.cpp:3578`) — `dcc_mat_undecoded`. **RC7 (FMASK: сайт чтения гостем есть; член проверки 3).** F16a §2.1 «FMASK не используется» неверно по букве: транслятор распознаёт образ формата FMASK (`src/graphics/shader/recompiler/ir/passes/ResourceMaterialization.cpp:599`) и заменяет чтение гостем FMASK как текстуры тождественной картой фрагментов (`:1197`–`:1212`: сэмпл s → фрагмент s, образ не привязывается). Ответ — по замыслу согласован с хранением хоста (каждый сэмпл MSAA хранится отдельно) [I]; гость, читающий FMASK не только для выборки фрагмента (например, «все сэмплы в одном фрагменте ⇒ не край»), получит на хосте «все фрагменты разные» — картинка того же цвета при усреднении, другая ветка шейдера [I]. По букве п. 421(г) сайт назван ⇒ `fmask_rt` входит в B. Но `fmask_rt` F16a (`R/debug.cpp:210`) считает существование цели с FMASK-сжатием в первом слоте, а не чтение: он > 0 на любой сцене с MSAA-целью и ничего не говорит о ветке. Счётчик на сайте чтения внутри `src/graphics/shader/**` сменит подпись трансляции (запрещено п. 421(г)); вычисление при трансляции к тому же раз на шейдер, а не на draw. **Сценарий отказа:** `fmask_rt` по букве в B ⇒ (ii) на любой MSAA-сцене без события ветки. **Изменить:** вопрос лиду В2 (§4).

Цена F16a «без чтения часов» неверна — ограничение частоты читает часы; на тике кадра — раз на кадр.

**RC10 (потоки, замок, побочные действия; член проверки 1, 5).** Сайты под `m_lock` кэша (`PrepareDccClear`, `PrepareCmaskClear`, `ClearMeta`, `TrackDccFill`) и без него (`colorRenderTarget`, `debug`, `depthRenderTarget`, `MaterializeBoundTargetDccClears`, `pm4Handlers` — поток [I]). `m_lock` — `TrackingSpinLock` (`R/cache/textureCache.h:312`), повторный захват тем же потоком — `EXIT("recursive region tracking lock")` (`src/graphics/host_gpu/regionManager.h:38`). **Сценарий отказа:** чтобы проверить «маску слоёв вида» или «отслеженный fill» по RC4/RC5, код счётчика внутри `PrepareDccClear` зовёт `QueryMetaFill`/`MetaClearMask`/`IsMetaCleared` ⇒ K1 «recursive region tracking lock» только при `=1`; или зовёт `FindDccSurfaceImage`, которая через `AdoptPendingDccForTexture` меняет тип записи ⇒ счётчик ветвит исполнение. **Изменить:** таблица записей в состояние в проекте F16d — «0 записей»: счётчики читают только локальные значения в области видимости (`metadata`, `view`, `b42`, `applied`); ни одного вызова функций кэша, берущих замок или меняющих LRU/эпоху/тип; все счётчики — `std::atomic<uint64_t>` с `relaxed`, инкремент под `if (DiagF5On())` (при `=0` — ни одной атомарной операции); печать читает атомики.

**RC11 (набор подписи трансляции шире `src/graphics/shader/**`).** Хэш подписи берёт и `R/pipeline/shaderTranslationCache.cpp`, `src/graphics/guest_gpu/gpu_format.h`, `src/graphics/guest_gpu/gpu_defs.h` (`CMakeLists.txt:156`, `src/generate_version.cmake:43`). **Сценарий отказа:** F16d добавляет помощник классификации кода DCC или FMASK в `gpu_format.h` ⇒ новая подпись, холодный каталог варианта на тегах `f5_*` ⇒ кадры ≥ 1 с и K2 на входе, расхождение с установленным кэшем. **Изменить:** п. 421(г) «сайты вне `src/graphics/shader/**`» читать как «вне набора подписи (дерево + 3 файла)»; член ревью F16e — равенство `KYTY_SHADER_SOURCE_HASH` базы и бинаря диагностики.

**RC12 (кратность и тождества `≤`).** Тождества F16a §2.4 п. 4 `cmask_rt_unsupported ≤ cmask_rt ≤ rt_draws`, `dcc_rt ≤ rt_draws` верны, только пока все три на одном сайте промаха memo; после RC5 CMASK считается на FCE, и `cmask_* ≤ rt_draws` перестаёт быть тождеством. **Сценарий отказа:** скорер печатает нарушение тождества на верном коде ⇒ (iii). **Изменить:** тождества выводятся заново из итогового набора сайтов F16d и проверяются тест-сайтом (RC1(б)); `rt_draws` переименовать по смыслу (`rt_resolves` — промахи memo) или поставить на вход `ResolveRenderColorTarget` (вопрос лиду В4 — имя — константа (г)).

**RC13 (нулевой контроль доказывает только печать; член проверки 5).** `f5_sg0` без переменной показывает лишь отсутствие строк `DiagF5`. «Вызовы Vulkan одинаковы в обоих режимах» (F16a §2.4 п. 5) тегами не проверяется. **Сценарий отказа:** счётчик с побочным действием (RC10) проходит нулевой контроль, а `=1` меняет исполнение — показания (i)/(ii) сняты на другом исполнении. **Изменить:** в отчёте F16f и правиле F16g назвать, что «не ветвит» доказывает только ревью F16e по коду (член: при `=0` и `=1` исполняется тот же набор вызовов, кроме атомиков и печати), а не тег; в F16a §2.4 п. 5 — пометка [c ревью], не [c тега].

## 6. Цена (член проверки 6)

При `=0` — одна проверка `static const bool` на сайт [c замысла F16a]; после RC10 — без атомарных операций. При `=1` — атомарный инкремент на каждом прохождении родительских сайтов (промах memo, медленное получение цели, привязка текстуры, fill, FCE, записываемый буфер диспатча, флип для печати); частота привязок текстур — сотни–тысячи на кадр [I], цена — единицы–десятки мкс на кадр [I, не измерялась]. Тег диагностики — не прогон скорости; никакое время тегов `f5_*` не читается как цена или выигрыш.

## 7. Чек-лист Red Team

- Положительный контроль не тавтологичен — **нет** для B (RC1).
- Нулевой контроль — доказывает только печать (RC13).
- Типы счётчиков — штуки, `uint64`, смешения единиц нет ✓.
- Тождества суммы — у F16a только подмножества `≤`; разбиений нет (RC1(а), RC12).
- Ручка — одно чтение `static const bool` ✓; рваться внутри операции не может ✓.
- Новое имя — последняя строка таблиц: ручка не гейт, `check_gate_order.py` не нужен ✓.
- Подпись трансляции — набор шире дерева `shader` (RC11).
- Только измерение — да при RC10 (таблица записей: 0).
- Что не доказывает — у F16a есть; дополнить (§8).

## 8. Не доказывает (дополнение к F16a §2.4)

Что ненулевой счётчик ветки меняет картинку; что ноль — свойство игры, а не четырёх сцен; что запись, накрывающая метаданные со смещённого адреса, и DMA-fill неизвестного адреса учтены (RC2); что код `0xff` — «не сжато» на кремнии PS5 [I]; что тождественная карта FMASK верна для всех шейдеров гостя [I]; что Б42 `Drawn` меняет кадр; что члены 1–2 меняют или не меняют кадр до F16g; ни одно число — не выигрыш.
