## 2. Acceptance — M3.1 PASSES only if every item holds

* **P1 checks (`ctx105`):** Σ`ctx_chk_bad` = 0; Σ`ctx_rec_block` = 0; no `CtxCheck:` line; median over the
  scene window of `ctx_chk_n` per flip ≥ median `draws + dispatches` per flip. `ctx_midsub` per flip
  (mean, and the `ctx-mid:` site table) is published, never deciding.
* **P2 A/A (`abb105`, scorer `ctx105.py` derived from `lead105.py`):** ADMITTED under the session-104
  controls (pairs ≥ 60, work split, area verdict, pin once, record thread two, no fatal marker incl.
  `AsyncPipelines: skipped draw`, instruments dark incl. `ctx_chk_n` = 0 in both arms), and the POINT
  estimate |Δ`cpu_net_us`| (arm `ctxtick=1` − arm `ctxtick=0`) ≤ 90 µs. Δ mean `dt` and both 2·SE are reported.
  A true zero fails this about 6 % of the time [I]; this is not a proof of equivalence.
* **P3 video (`vct105`):** ≥ 3 000 frames, 0 one-frame glitches (`s51_vidglitch.py`), decodes.
* **P4 entries (`ect105_*`):** 10 entries reach the scene; Σ`ctx_chk_bad` = 0 in each; a hang with the known
  BVH entry signature (`GpuHangAbort` with `role=4`) does not fail the milestone, any other hang or device
  loss does.
* **Screen (reported, flag only):** CPU per draw (Σ`cpu_gpu_us` / Σ`draws`, middle third of rows)
  `reg105b` vs `reg105a` — flag if > +2 %; inter-run, never deciding.

On PASS: ROADMAP first, then the default `ctxtick=1` in `gates.cpp` (the old branch goes in M3.2), a new
build and its video pass. On FAIL: the default stays 0 and the failing item is published.
